# PMM v2 项目扩展格式

MikuMikuStudio 的项目设置随 PMM 文件保存。普通工程优先使用 `Polygon Movie maker 0002`，新增显示设置不单独增加版本号。当前源码的自动扩容改动尚未发布：只有实际内容超出旧版能力时，才使用 `Polygon Movie maker 0003`。

标准 PMM 数据布局保持不变。扩展记录位于完整标准数据之后，文件末尾的固定尾标记录标准数据长度和扩展长度。长度字段用于划分数据范围；保存时重建标准部分和扩展部分，不按这个边界删除未知记录。

相关实现为 `pmm_extension.hpp`、`src/io/pmm_extension.cpp` 和 `src/io/pmm_project_settings.cpp`。

## 兼容范围

| 程序或操作 | 行为 |
| --- | --- |
| 本程序读取带扩展的 PMM v2 | 读取标准工程，恢复支持的项目设置，保留未知记录。 |
| 本程序再次保存或另存 | 写出完整标准数据、已更新的设置及未知记录，重新计算长度和校验值。 |
| 本程序读取无扩展的 PMM v1 或 v2 | 保持本机运算器设置，透明排序上限恢复关闭，清空上一个工程的扩展数据。 |
| 新建工程 | 保持本机运算器设置，透明排序上限恢复关闭，清空扩展数据。 |
| 原版 MMD 9.32 x64 读取 `0002` | 标准数据读完后关闭文件，忽略附加数据。此行为来自静态反汇编核对，不代表所有第三方读取器都兼容；不适用于 `0003`。 |
| 原版 MMD 再次保存 | 截断并重建标准 PMM，不保留扩展数据。 |

EMM 不承担本程序的项目扩展。已核查的 MME 0.37 会拒绝未知配置段和字段；注释虽可读取，但重新保存时会丢失。

## 自动扩容与格式选择

保存器先检查实际使用的关键帧、显示计数、帧号和引用路径。仅分配了更多空槽不会触发 `0003`。高位槽位中只有少量有效关键帧时，保存器会在输出文件中重排槽位及前后链接，不改动当前工程的内存索引。

原版范围内仍使用 `0002`。实际内容超出原版关键帧池、显示计数或帧号范围，或路径不能用 CP932 表示时，完整包使用 `0003`。`0003` 沿用 v2 的记录布局和尾部扩展容器，读取器按实际索引扩容。原版 MMD 和最小包拒绝该文件头，避免按旧容量读取超出范围的数据。

名称不能在旧字段内无损表示时，完整文本保存在 `org.mikudancestudio.model.<slot>.unicode.v1`。记录包含版本、模型名称、骨骼名称、表情名称、完整显示计数和全部分组的名称与展开状态。文字使用带无符号 32 位字节长度的 UTF-8 字符串。模型、骨骼、表情和分组均保留原名与英文名。

名称扩展本身不强制切换 `0003`。保存成功后显示兼容提示；旧格式可用时，在主文件旁自动生成 `.compat.pmm`，已有同名副本则添加序号。该副本只有标准部分，名称采用旧字段中的短名称。超出旧容量、短名称冲突或引用路径不兼容时，不生成会丢内容或错误匹配的副本，并在提示中说明。

### 骨骼与表情的旧版绑定名

PMM v2 按模型文件中的固定 CP932 镜像匹配骨骼和表情关键帧。PMX 载入器把完整名称编码为 CP932，再截取前 19 字节并在末尾补 NUL；因此 21 字节的 `+FlycloakRootB CB A01` 在 PMM 标准字段中是 19 字节的 `+FlycloakRootB CB A`。PMD 直接使用自身的 20 字节名称字段。PMM 读取器用 `strcmp` 比较这些字节，不会重新解码，所以这种截断本身不构成不兼容：只要镜像正好是完整名称的前 19 字节，原版 MMD 仍把关键帧绑定到正确的骨骼。第 19 字节可能落在 CP932 双字节字符的中间，保存器仍按这 19 字节写入，绑定结果不变。

以下情况仍会把完整名称写入扩展，并在保存后显示提示；它们仍使用 `0002`，不会因此选择 `0003`：

- 完整名称不能用 CP932 无损编码。
- 记录中的镜像不是完整名称的前 19 字节，也就是任意短别名。
- 两个不同完整名称共用同一个 19 字节镜像，旧字段无法区分。

这些情况仍按原规则决定是否生成 `.compat.pmm`；不能生成不会错误绑定或丢内容的副本时，保存器只保留完整名称扩展并说明原因。

### `0003` 的严格边界

`0003` 只由实际内容超出旧版容量触发。仅扩大空池、只有名称扩展或生成兼容副本都不会触发。边界如下：

- 相机、光源、阴影、重力和配件轨道：每个轨道 10000 个有效关键帧仍为 `0002`，第 10001 个使用 `0003`。
- 模型骨骼关键帧池：x64 为 600000 个有效关键帧，x86 为 300000 个；超过后使用 `0003`。
- 模型表情关键帧池：20000 个有效关键帧；第 20001 个使用 `0003`。
- 模型显示与 IK 关键帧池：1000 个有效关键帧；第 1001 个使用 `0003`。
- 模型时间轴、当前帧和播放范围：10000000 仍为 `0002`，10000001 使用 `0003`。
- 显示分组或表情帧行：255 仍为 `0002`，256 使用 `0003`。
- 模型、配件和背景路径：必须能无损编码为 CP932 且不超过 255 字节；任一条件不满足就使用 `0003`。

关键帧引用或帧号超出可表示范围属于无效数据。保存器拒绝写入，不会把它改写成 `0003`。

完整包的 VMD 使用校验绑定的 `MDSNAME1` 名称扩展，将标准骨骼、表情与 IK 记录对应到完整名称。缩放和自由曲线也沿用该名称对应关系。标准 VMD 字段保持原布局，`.compat.vmd` 只包含标准数据。旧程序重新保存文件会丢弃完整名称和其他 MMS 扩展。

## 文件布局

文件按顺序包含标准 PMM、扩展记录串、32 字节尾标。整数均为无符号小端数，不直接序列化 C++ 结构体。标准 PMM 必须包含当前写入器生成的完整尾部，不能在旧文件缺省的可选字段前直接追加扩展。

尾标位于文件最后 32 字节：

| 偏移 | 长度 | 字段 | 定义 |
| --- | --- | --- | --- |
| 0 | 8 | `magic` | ASCII `MDSXPMM2`。 |
| 8 | 8 | `standardSize` | 标准 PMM 的字节数，也是扩展记录串的起始偏移。 |
| 16 | 8 | `extensionSize` | 扩展记录串的字节数，不含尾标。 |
| 24 | 4 | `crc32` | 扩展记录串的 IEEE CRC32，反射多项式为 `0xEDB88320`。空串校验值为 0。 |
| 28 | 4 | `reserved` | 固定为 0，不作为功能版本号。 |

有效文件满足 `standardSize + extensionSize + 32 == 文件大小`。读取器同时检查标准读取结束位置是否等于 `standardSize`。`standardSize` 至少为 30 字节。当前源码取消扩展容器原有的 16 MiB 和 16384 条固定上限，按文件长度、地址空间和可用内存检查。单条内容仍受 `valueSize` 的无符号 32 位字段约束。

每条扩展记录依次包含：

| 字段 | 长度 | 定义 |
| --- | --- | --- |
| `keySize` | 4 字节 | 标识的字节数，范围为 1 至 255。 |
| `valueSize` | 4 字节 | 内容的字节数。 |
| `key` | `keySize` 字节 | UTF-8 命名空间标识，区分大小写，不含 NUL。 |
| `value` | `valueSize` 字节 | 由该标识定义的内容，允许包含零字节。 |

同一文件中标识唯一，重复标识使扩展无效。记录之间不插入对齐填充。扩展容器和记录都没有随功能递增的版本字段。

## 已定义的项目设置

### 已停用的运算器字段

`org.mikudancestudio.skinning.processor` 不再是项目设置。加载时忽略其内容，保存时移除该记录，包括未知取值；这是用户批准的运算器设置迁移规则。其他未知记录仍按下文规则保留。

主渲染、顶点计算和 MMV 处理设备改为当前程序目录的通用配置，保存在 `data/processor.ini`，不写入 PMM、VMM 或 VEM。新建、打开或切换工程均不改变当前和待生效的设备选择。菜单修改在下次启动生效。实施状态与验收范围见[通用运算器方案](../records/performance/devices.md#record-processor-settings-proposal)。

### 透明排序上限

菜单为「显示 → 透明排序上限」，五个互斥选项依次为关闭（默认）、低、标准、高、最高。运行时只有一个枚举值，没有单独的开启标志，也不记住关闭前的档位。

复用标识 `org.mikudancestudio.view.transparent_sort_precision`，内容固定为 1 字节，取值就是档位编号：

| 值 | 菜单选项 | 排序方式 |
| --- | --- | --- |
| 0 | 低 | 16 桶计数排序，按三角形中心深度从远到近；同桶保持提交顺序。 |
| 1 | 标准 | 64 桶计数排序，从远到近，同桶保持提交顺序。 |
| 2 | 高 | 按三角形中心深度稳定排序，同深度按原始三角形序号。 |
| 3 | 最高 | 逐像素分层，上限为当前参与排序的裁剪后三角形数量加一。 |
| 4 | 关闭（默认） | 不执行自动透明排序。 |

只有「最高」会打开逐像素分层。不支持分层时，最高档回退到 BSP 近似排序，预算为额外 4,000,000 个三角形、深度 512、epsilon 2e-13。低、标准和高三档只重排完整三角形，不分层、不分割，每个有效输入三角形只返回一次。桶内保持输入顺序，因此同桶中的近面可能先于远面。

本次下调保留原有档位字节和菜单 ID，不迁移已保存的档位。旧工程选中的低、标准、高会分别采用新的强度，最高和关闭不变。详见[三档强度下调](../records/rendering/transparency.md#record-transparent-sort-strengths)。

每档的分层上限不等于必定执行的次数。分层时复用现有遮挡查询，没有片段就提前结束；完整完成后才提交累积结果。最高档的上限按「一个三角形在一个像素最多贡献一层」推导，多出的一次用于空查询确认完成，属于安全上界，不做计数预扫描。实际层数、相机统计、桶数量和三角形数量不存入 PMM，每帧重新计算。档位语义与回退边界见[五档上限与 PMM 保存](../records/rendering/transparency.md#record-transparent-sort-five-tiers)。

选择关闭会将唯一字段写为 `4`，原档位被覆盖。例如最高 → 关闭 → 保存 → 重开，恢复的是关闭，文件中不会留下“上次最高”。更改选项会标记工程未保存；重复选择当前项不会重复标脏；只有当文件里存着本程序读不出的档位字节时，把当前档位再选一次才算一次修改。新建工程、没有该字段的工程以及无效扩展均使用默认的关闭档。工程原本没有该字段时，保存会补写当前档位。

#### 与旧记录的关系

本程序不与更早的排序格式做字节映射，只按上表的新语义读写同一个字段。

旧标识 `org.mikudancestudio.view.transparent_sort` 不再是本程序的设置。它按普通未知记录处理：加载时不查询、也不参与档位判断，保存时原样写回，不会被删除。

早期六档测试格式写出的同一字段不做换算：数值 0 到 4 按上表解释，所以字节 3 在这里是最高、字节 4 是关闭。取值大于 4 或长度不为 1 的记录，运行时使用标准，原始字节在用户未编辑该字段时原样保留。用户明确选择一个档位后，写入该值；同一个文件里的旧开关记录和其他未知记录仍然保留，运算器设置也不受影响。

其他写入器（包括早期的六档测试 build）按各自的语义命名同一字节，本程序不做换算。原版 MMD 没有此选项，也不会应用排序行为，重新保存时还会丢失扩展。文件头仍为 PMM v2，`MDSXPMM2` 容器和 EMM 均不改变。

### 抗锯齿与 SMAA 选择

`org.mikudancestudio.view.antialiasing` 固定为 3 字节，依次为启用状态（0 或 1）、
当前算法、上次选择的 SMAA 档位。算法编号保持稳定：

| 值 | 算法 |
| --- | --- |
| 0 | MMD 原始 |
| 1、2、3 | MSAA 2x、4x、8x |
| 4 | FXAA |
| 5 | TAA |
| 6 | SMAA 1x（斜线与拐角增强），保留早期单档 SMAA 的编号 |
| 7 | SMAA 1x（标准） |
| 8 | SMAA T2x（标准） |
| 9 | SMAA T2x（斜线与拐角增强） |

第三字节只接受 6 至 9。关闭抗锯齿仍保存算法和上次 SMAA 选择。
新建工程、旧工程及无效扩展从本机默认抗锯齿设置开始。打开带有效字段的工程时，
工程设置覆盖本次运行状态，不改写本机默认值。

字段长度或取值未知时，原记录随工程保留。硬件不支持所选算法而临时回退时，
保存仍保留原选择。用户明确选择新的抗锯齿设置后才替换该字段。
NVIDIA 驱动修复的安装记录、GPU 身份、运动矢量和历史图像不写入 PMM。

### 骨骼缩放

每个模型槽使用 `org.mikudancestudio.model.<slot>.boneScale.v1` 记录当前姿态和缩放关键帧。记录内先写两个 uint32 计数，再写姿态项和关键帧项，全部使用小端格式：

- 姿态项为骨骼索引 int32、20 字节 SJIS 骨名、9 个 float32 矩阵分量，共 60 字节。
- 关键帧项在骨名之后增加 uint32 帧号，共 64 字节。保存骨骼及帧号，不保存运行时关键帧池槽号。

矩阵按行存储完整 3×3 线性变换，单位变换省略。读入时检查骨骼身份、帧号对应的有效轨道、重复项、有限值和正行列式；整条记录通过后才应用。具体操作、VMD 尾部扩展以及物理边界见[原生骨骼缩放](../guides/bone-scaling.md)。

缩放数据同样受扩展容器总计 16 MiB 的限制。保存前检查整个容器是否合法、是否超限，检查失败时不打开或截断原 PMM。

## 后续扩展规则

本次五档重排按用户明确要求，直接调整尚未投入实际使用的排序测试字段，不迁移早期测试格式；这是本次重排的特例。其他已稳定字段仍遵守下述规则。

新增需要随工程恢复的状态时，继续使用 PMM v2 的这套扩展容器。新功能使用新的命名空间标识，不改变已有标识的字节含义，不改变标准 PMM 字段的位置，也不递增文件头版本。后续修改程序的人可以使用自己的命名空间增加记录。

读取器按记录长度跳过未知标识，并保留标识、内容和原始顺序。再次保存时，未知记录原样写回。只跳过而不保存，不能满足向前兼容。

对已知标识的不支持取值或内容长度，本程序使用默认运行状态，但保留原始记录。只在用户明确修改对应设置时替换该记录。修改一个设置不会丢弃另一个设置的未来取值。

## 无效扩展与保存失败

没有尾标时按普通 PMM 处理。尾标、长度、校验值、保留字段或记录不合法时，不应用部分设置；标准工程仍按现有加载流程读取，扩展错误记入运行日志。损坏的扩展不属于可透传的未知记录，重新保存不会保留它。

所有标准字段、扩展记录及尾标写入成功，且文件成功关闭后，才清除工程未保存标记并通知 MME 保存同名 EMM。写入或关闭失败时报告保存错误，不报告成功。

## 验证入口

`pmm_extension_tests` 覆盖编解码、边界、校验值、未知记录和文件位置恢复。`pmm_project_settings_tests` 用隐藏窗口调用实际保存、加载及新建流程，覆盖五档菜单状态、单一档位字段、未知档位字节的保留与替换、旧开关记录不参与档位判断、类型匹配、缺失设备回退、旧工程默认值、未知数据另存和损坏扩展。

扩展容器与读写流程的运行结果记录在 [PMM v2 扩展验证记录](../records/formats/projects.md#record-pmm-v2-extensions-validation)，该记录对应最初的独立排序开关时期；五档格式的档位与存档边界见[五档上限与 PMM 保存](../records/rendering/transparency.md#record-transparent-sort-five-tiers)。
