# 原版兼容构建档

`MIKUMIKUSTUDIO_PROFILE=mmd932` 从同一份源码生成精简的 x64 程序，对应 Release 中文件名含 `minimal` 的最小包。默认 `full` 对应完整包。两档各自生成资源文件，不覆盖源码目录的资源，也不通过运行时开关加载被移除的模块。功能对照见 [README](../../README.md#下载与版本区别)。

两档在同一分支维护，不另设最小包分支。共同功能的缺陷在共享实现中修复，并分别构建、验收 `full` 与 `mmd932`；只有功能本身不在最小档范围内时，才限定到完整档。

## 范围

| 项目 | `mmd932` |
| --- | --- |
| 原有骨骼、相机插值 | 保留原生 Bezier；骨骼“全部”为第 5 项 |
| 新曲线编辑器、表情曲线、骨骼缩放 | 不编入；导入时不应用扩展 |
| 新阴影投影、动态精度与滤波 | 使用原版投影和 SM2/SM3 着色器，包括高精度、小范围下的裁切；不启用完整包的防裁切与动态采样，保留材质标志等缺陷修复 |
| DX12、MMV 宿主、通用 mesh 捕获、Alembic、烘焙 | 不编入对应实现，不创建其菜单 |
| 音视频 | WAV 音频、AVI 背景与 AVI 输出；不编入现代媒体和 MP4/MOV 编解码实现 |
| 新透明排序 | 排序与剥层实现不编入；保留原始单遍材质顺序 |
| MME | 保留原生 DX9 接口、路径编码兼容、已验证版本的 APNG 重置修复及文件变更通知；自动重载开关仍有效 |
| 渲染计算优化 | 共享蒙皮与表情的等价计算优化、未变化模型缓存，以及 CPU 蒙皮结果不变时仅更新描边的路径；不增加设置项 |
| 语言、编码和设备设置等便利修复 | 保留；不宣称界面逐项与原版完全相同 |

这不是二进制补丁，也不是对原程序的逐字节复刻。主程序仍使用当前工具链、运行库和原生功能修复。

## 文件边界

PMM、VMD 和 VPD 仅写出标准内容，不写 MMS 扩展尾；读取完整档文件时忽略缩放、曲线、附件动作及 mesh 缓存等扩展。因此，含扩展功能的完整档工程在这里保存后不再保留这些扩展。

当前源码允许读取结构可解析的 PMD、PMX 模型。名称或引用路径超出旧格式的字符、长度限制时，加载器保留读取到的数据并警告，不因此取消整个模型导入。PMX 的完整 Unicode 名称继续保留在内存中。VMD 骨骼名的 15 字节字段属于动作保存限制，不是模型导入限制。

附件、动作、姿势和工程的导入检查没有随这项调整放宽。动作与姿势的名称检查仍在写入关键帧或撤销记录之前完成。无法安全解析的数据以及超过宿主路径缓冲区的输入仍可导致导入失败；宿主模型路径缓冲区可存 255 个 UTF-16 代码单元及结尾 NUL，与 CP932 的 255 字节保存限制不同。

保存目的地本身可以是 Unicode 路径。保存端保留校验，防止后续编辑产生无法表示的内容；拒绝时保留已有文件。

PMM 使用旧式骨骼和表情身份匹配。完整名称与旧字节镜像不同的模型可以导入，但保存 PMM 时仍检查能否保持名称与关键帧绑定。VMD、PMM 和 PMD 分别检查各自的字段限制，不共用一个名称长度上限。PMM 还检查实际写出的槽号和前后链接：x64 原版骨骼池上限为 600000，表情池为 20000；仅扩容而未使用的尾部不会导致拒绝。

PMX 可载入场景并用于动画。模型编辑仅支持 PMD，不提供 PMX 写出；PMX 在打开模型编辑窗口前即被拒绝。PMD 进入模型编辑和保存时仍检查名称、纹理引用、数量及索引。模型导入成功不保证每种输出格式都能无损保存该模型。

VMD 不保存池槽号；它使用名字与帧号，因此不能直接套用 PMM 的槽号检查。超大动作、目标原版模型已有大量关键帧、重名骨骼以及第三方效果需另行验收。

## 构建

使用项目既有 Conan 依赖和 Visual Studio 工具链，在独立目录配置：

```powershell
cmake -S . -B build-original -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=<Conan工具链绝对路径> `
  -DMIKUMIKUSTUDIO_PROFILE=mmd932
cmake --build build-original --config Release --target MikuMikuStudio --parallel 1 -- /nr:false
```

原版档强制关闭 DX12。构建需要 Python 生成独立资源；配置阶段仍使用完整项目的依赖描述，不能据此认为 Alembic 等已进入最小程序。产物保留 `MikuMikuDance.exe` 名称，以兼容原生 MME。

## 验证边界

`original_import_tests` 覆盖模型名称、CP932 字节边界、Unicode 与长路径、PMX 模型编辑拦截，以及 VMD/VPD 非法输入后的状态保留。共享代码分别验证两档，扩展曲线、缩放和烘焙测试不能作为最小包结论。

原版字段的已测边界见[旧版 MMD 格式限制](legacy-mmd-limits.md)。该参考绑定具体二进制，不代表任意原版或第三方读取器都兼容。

`tools/original_profile_interop.py` 用固定原版 9.32 x64 身份和受控进程检查单模型 PMM/VMD/VPD 双向载入及再保存。设备初始化失败不构成格式不兼容证据；当前仍不能宣称任意工程在原版中无损往返。
