# 原版兼容构建档

`MIKUDANCESTUDIO_PROFILE=mmd932` 从同一份源码生成精简的 x64 程序，对应 Release 中文件名含 `minimal` 的最小包。默认 `full` 对应完整包。两档各自生成资源文件，不覆盖源码目录的资源，也不通过运行时开关加载被移除的模块。功能对照见 [README](../../README.md#下载与版本区别)。

两档在同一分支维护，不另设最小包分支。共同功能的缺陷在共享实现中修复，并分别构建、验收 `full` 与 `mmd932`；只有功能本身不在最小档范围内时，才限定到完整档。

## 范围

| 项目 | `mmd932` |
| --- | --- |
| 原有骨骼、相机插值 | 保留原生 Bezier；骨骼“全部”为第 5 项 |
| 新曲线编辑器、表情曲线、骨骼缩放 | 不编入；导入时不应用扩展 |
| 新阴影投影、动态精度与滤波 | 使用原版投影和 SM2/SM3 着色器，包括高精度、小范围下的裁切；不启用完整包的防裁切与动态采样，保留材质标志等缺陷修复 |
| DX12、MMV 宿主、通用 mesh 捕获、Alembic、烘焙 | 不编入对应实现，不创建其菜单 |
| 音视频 | WAV 音频、AVI 背景与 AVI 输出；不编入现代媒体和 MP4/MOV 编解码实现 |
| 新透明排序 | 排序与剥层实现不编入；保留原始单遍材质顺序 |
| MME | 保留原生 DX9 接口、路径编码兼容、已验证版本的 APNG 重置修复及文件变更通知；自动重载开关仍有效 |
| 渲染计算优化 | 共享蒙皮与表情的等价计算优化、未变化模型缓存，以及 CPU 蒙皮结果不变时仅更新描边的路径；不增加设置项 |
| 语言、编码和设备设置等便利修复 | 保留；不宣称界面逐项与原版完全相同 |

这不是二进制补丁，也不是对原程序的逐字节复刻。主程序仍使用当前工具链、运行库和原生功能修复。

## 文件边界

PMM、VMD 和 VPD 仅写出标准内容，不写 MMS 扩展尾；读取完整档文件时忽略缩放、曲线、附件动作及 mesh 缓存等扩展。因此，含扩展功能的完整档工程在这里保存后不再保留这些扩展。

模型、附件、动作、姿势和工程在导入时检查标准名称与引用。名称和模型、贴图、媒体引用须能按 CP932 完整编码，并符合各字段的字节上限。骨骼和表情的日文名称还须符合 VMD 的 15 字节上限，避免导入后无法保存动作。模型验证失败时不会登记到场景，动作与姿势的名称检查在写入关键帧或撤销记录之前完成。

保存目的地本身可以是 Unicode 路径。保存端保留校验，防止后续编辑产生无法表示的内容；拒绝时保留已有文件。

PMM 使用旧式骨骼和表情身份匹配。完整 PMX 骨骼、表情名称与固定字节镜像不同的模型会在导入时拒绝。PMM 还检查实际写出的槽号和前后链接：x64 原版骨骼池上限为 600000，表情池为 20000；仅扩容而未使用的尾部不会导致拒绝。

合规 PMX 仍可载入场景并用于动画。模型编辑仅支持 PMD，不提供 PMX 写出；PMX 在打开模型编辑窗口前即被拒绝。PMD 在导入时检查名称、纹理引用、数量及索引，进入模型编辑和保存时再次检查。以上检查不能代替第三方程序对任意素材的验收。

VMD 不保存池槽号；它使用名字与帧号，因此不能直接套用 PMM 的槽号检查。超大动作、目标原版模型已有大量关键帧、重名骨骼以及第三方效果需另行验收。

## 构建

使用项目既有 Conan 依赖和 Visual Studio 工具链，在独立目录配置：

```powershell
cmake -S . -B build-original -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=<Conan工具链绝对路径> `
  -DMIKUDANCESTUDIO_PROFILE=mmd932
cmake --build build-original --config Release --target MikuMikuStudio --parallel 1 -- /nr:false
```

原版档强制关闭 DX12。构建需要 Python 生成独立资源；配置阶段仍使用完整项目的依赖描述，不能据此认为 Alembic 等已进入最小程序。产物保留 `MikuMikuDance.exe` 名称，以兼容原生 MME。

## 验收与限制

`original_import_tests` 覆盖真实 PMD/PMX 文件导入、CP932 字节边界、引用路径、PMX 模型编辑拦截，以及 VMD/VPD 非法名称拒绝后的状态保留。完整档运行同一测试，确认仍接受 Unicode 和长名称 PMX。既有专用测试覆盖文件读写、扩展尾忽略、原有插值与物理状态、PMD 保存保护。完整档的缩放、曲线及烘焙测试不适用于此档，不能直接将全量 `ctest` 的结果作为最小档结论。

`tools/original_profile_interop.py` 固定原版 9.32 x64 EXE 的 SHA256，并使用自建私有桌面及受控子进程验证单模型 PMM/VMD/VPD 的双向载入、再保存。该工具的通过范围仅限输入夹具，不是所有 PMM 属性或画面的无损保证。

本机已取得哈希为 `07516fd3bf1e6b1339836b6773a156f61bdd6f848eeb621fdda012375df313a1` 的原版。原版与候选程序在私有桌面均报告 `CreateDevice Failed!`。另一个隐藏窗口守卫探针在原版初始化时被自身严格审计中止，未进行任何文件互导；这不构成格式不兼容的证据。最小包已作为独立附件公开提供，但真实双向互导仍未完成，不能宣称已经保证任意原版互导。所有诊断子进程均已清理。
