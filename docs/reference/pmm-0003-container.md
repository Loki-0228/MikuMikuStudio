# PMM 块容器编解码器

本模块同步自 main 的 `609bf4d` 及 `b559a8b` 中的最终源码，只提供独立的块编解码。MMS 当前工程打开和保存没有调用本模块，仍使用 [PMM 扩展格式](pmm-extensions.md)。main 后续选择的 `PMM3SECT` 分节方案也尚未实现。

实现位于 `include/mikumikustudio/pmm_container.hpp` 和 `src/io/pmm_container.cpp`，验证入口为 `pmm_container_tests`。模块不依赖窗口、显卡或 `MMDApp`。

## 字节布局

所有整数按小端写入。文件由调用方提供的标准前缀、块、目录和固定 64 字节尾标组成。编解码器不解析标准前缀。

| 部分 | 布局 |
| --- | --- |
| 标准前缀 | 至少 30 字节，长度由尾标记录。 |
| 块头 | 固定 32 字节，依次为 `keySize:u32`、`version:u32`、`flags:u32`、`encoding:u32`、`payloadSize:u64`、`payloadCrc32:u32`、`reserved:u32`。其后是 key 和 payload。 |
| 目录头 | `PMM3TOC\0`、版本 `u32`、标志 `u32`、条目数 `u32`、保留字段 `u32`，共 24 字节。 |
| 目录项 | 固定 40 字节，依次为 key 长度、版本、标志、编码、块偏移 `u64`、载荷长度 `u64`、CRC32、保留字段。其后是 key。 |
| 尾标 | `PMM3END\0`、版本 `u32`、标志 `u32`、标准长度 `u64`、目录偏移 `u64`、目录长度 `u64`、文件总长度 `u64`、目录 CRC32 `u32`、保留字段 12 字节。 |

key 为 1 至 255 字节且不含 NUL。同一文档内 key 唯一。写入按 key 排序。CRC32 使用 IEEE 反射多项式 `0xEDB88320`。读取校验目录、块头、载荷边界和校验值，未知块的版本、标志、编码与载荷原样交给调用方。

## 接口行为

| 接口 | 行为 |
| --- | --- |
| `Read` | 返回无容器、既有 MMS 扩展、新块容器有效或容器无效。读取后恢复文件位置。 |
| `Representable` | 检查 key、重复项、数量和长度计算，不打开文件。 |
| `Write` | 要求文件位置在前缀末尾并等于文件长度，追加完整块、目录和尾标。临时文件及替换目标文件由调用方管理。 |
| `Find`、`Set`、`Erase` | 按区分大小写的 key 查询、替换或删除块。 |

`ReadResult::Legacy` 在 ABI 分支仅识别 `MMSXPMM2`，用于交给现有扩展解析器。旧 `MDSXPMM2` 不作为 MMS 扩展识别。该规则与 ABI 已有的标记读取规则一致。

## 模型数量边界

MMS 已能保存非标准 PMM，模型数量 255 因而不是新格式必须保留的限制。当前生产实现仍有固定模型槽、单字节选择编号和单字节排序字段；当前 `0003` 也沿用这些旧字段。本模块的存在不会自动解除它们。

解除限制需要先把内部模型集合、稳定身份、排序和跨对象引用改为可扩展表示，再为扩展 PMM 定义足够宽的数量及引用字段。标准 `0002` 导出继续检查旧字段边界，不能通过截断或取模生成错误工程。此项不改变标准 VMD 的字段及兼容指标。
