# PMM 0003 容器格式

状态：设计稿。本文只定义 0003 新容器的字节布局、兼容规则和读写流程；0002 标准布局、旧 0003 的 `MDSXPMM2` 解析保持现状，不在本文修改。

## 目标

- 新 MMS 读取 0002、旧 0003（`MDSXPMM2`）和新 0003（`PMM3END`）三种工程。
- 新 MMS 在没有触发 0003 边界时只写 0002，且该 0002 的原版 MMD 能读取标准部分。原版 MMD 读完后关闭文件，忽略 MMS 追加的扩展。
- 新 0003 的标准前缀仍按 0002 布局写入，作为新 MMS 的基础场景并复用现有 v2 读写。旧 MMS 不需要读取新 0003；相关行为不作保证。
- 未知块按原始字节保留，第三方可以在不改标准前缀的情况下追加自己的块。
- 新格式的文本块统一 UTF-8，不依赖系统 ACP、936、950、949 的猜测。
- 0003 使用运行时完整的 `int32` 帧范围；0002 保持 10,000,000 的原版兼容上界。

非目标：

- 不把帧索引改成 64 位。运行时的关键帧结构、UI、物理和动画求值仍使用 `int32`；0003 的上界是 `2,147,483,646`。
- 不改变 0002 的标准前缀布局，不要求原版 MMD 读取 0003。
- 不要求旧 MMS 读取新 0003；新 0003 不保留旧 `MDSXPMM2` 尾部。旧 0003 仍由新 MMS 读取，保证已有文件可用。
- 不在本文实现应用层集成，本文只定义格式和编解码契约。

## 术语

- **标准前缀**：从文件开头到 `standardSize` 的字节，包含 30 字节文件头和 v2 主体。
- **块**：容器里的一个带 ID、版本、编码和载荷的单元。
- **TOC**：块目录，记录每个块的位置、版本和校验值。
- **footer**：文件末尾 64 字节，定位 TOC 并声明标准前缀长度。
- **已知块**：读取器认识 ID 和版本的块。**未知块**：读取器不认识 ID 或版本的块，原样保留。

## 文件布局

```text
+------------------------------------------+ 0
| 30 字节文件头 "Polygon Movie maker ..."  |
| v2 标准主体                              |
+------------------------------------------+ standardSize
| block 0                                  |
| block 1                                  |
| ...                                      |
| TOC                                      |
| footer "PMM3END"                         |
+------------------------------------------+ EOF
```

- `standardSize` 至少 30，且不大于 `tocOffset`。
- 块从 `standardSize` 开始，按 TOC 里的偏移定位，不要求连续或有序。
- TOC 紧接在最后一个块之后，footer 是文件最后 64 字节。
- 所有整数小端。所有偏移是文件绝对偏移。块和 TOC 之间不插入对齐填充。

### 0002 与 0003 的选择

保存器先判断是否触发 0003 边界。没有触发时：

- 文件头写 `Polygon Movie maker 0002`。
- 只写 v2 标准主体；可以按现有规则追加 `MDSXPMM2` 扩展。
- 不写 `PMM3END` 容器。
- 原版 MMD 读取标准主体后忽略尾部扩展；这是现有行为。

触发 0003 边界时：

- 文件头写 `Polygon Movie maker 0003`。
- 标准前缀按 v2 布局写，字段放得下就放真实值，放不下就放截断值或占位值。
- 标准前缀之后写 `PMM3END` 容器；完整数据放块里。
- 不再写旧 `MDSXPMM2` 扩展。

0003 边界至少包括：名称或路径不能无损放进 0002 的 CP932 固定字段、显示分组或表情帧行超过 255、实际关键帧数超过 v2 池、帧号超过 10,000,000，或任何在 0002 里会丢内容的数据。

## 块格式

块头固定 32 字节，后面紧跟 key 和 payload：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `keySize` | 1 到 255 |
| 4 | 4 | `version` | 块版本，从 1 开始 |
| 8 | 4 | `flags` | 块标志，未知位保留 |
| 12 | 4 | `encoding` | 0 二进制、1 UTF-8、2 UTF-16LE、3 CP932（只读兼容） |
| 16 | 8 | `payloadSize` | 载荷字节数 |
| 24 | 4 | `payloadCrc32` | 载荷的 IEEE CRC32 |
| 28 | 4 | `reserved` | 固定 0 |
| 32 | `keySize` | `key` | UTF-8 命名空间，不含 NUL |
| 32+keySize | `payloadSize` | `payload` | 内容 |

- 新写入器只写 `encoding=1` 的文本块或 `encoding=0` 的二进制块；不写 3。
- 读取器遇到未知 `encoding` 时按未知块保留，不应用。
- 同一文件内 key 唯一；重复 key 使容器无效。
- 块版本由各块定义；读取器只应用自己支持的版本，未知版本按未知块保留。

## TOC

TOC 头 24 字节：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 8 | magic `PMM3TOC\0` |
| 8 | 4 | `version`，当前 1 |
| 12 | 4 | `flags`，当前 0 |
| 16 | 4 | `entryCount` |
| 20 | 4 | `reserved`，固定 0 |

每个 TOC 项 40 字节，后面紧跟 key：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | `keySize` |
| 4 | 4 | `version` |
| 8 | 4 | `flags` |
| 12 | 4 | `encoding` |
| 16 | 8 | `blockOffset`，指向块头 |
| 24 | 8 | `payloadSize` |
| 32 | 4 | `payloadCrc32` |
| 36 | 4 | `reserved` |
| 40 | `keySize` | `key` |

- TOC 项按 key 的无符号字节序升序排列，保证同一内容写出确定字节。
- `tocSize` 包含 TOC 头和全部项。
- 读取器必须核对 TOC 项与块头一致：key、version、flags、encoding、payloadSize、payloadCrc32 全部相等。
- `entryCount` 和 `tocSize` 必须能放进文件；任何一项越界都使容器无效。

## footer

footer 固定 64 字节：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | magic `PMM3END\0` | 区分旧 `MDSXPMM2` |
| 8 | 4 | `version` | 当前 1 |
| 12 | 4 | `flags` | 当前 0 |
| 16 | 8 | `standardSize` | 标准前缀字节数 |
| 24 | 8 | `tocOffset` | TOC 起始偏移 |
| 32 | 8 | `tocSize` | TOC 字节数 |
| 40 | 8 | `totalSize` | 文件总字节数 |
| 48 | 4 | `tocCrc32` | TOC 字节的 CRC32 |
| 52 | 4 | `reserved` | 固定 0 |
| 56 | 8 | `reserved` | 固定 0 |

有效文件满足：

- `totalSize == 文件大小`。
- `tocOffset + tocSize + 64 == totalSize`。
- `tocSize >= 24`。
- `standardSize >= 30 && standardSize <= tocOffset`。

读取器先读最后 64 字节。magic 是 `PMM3END` 时走新容器；不是时再看最后 32 字节是否为 `MDSXPMM2`，是则走旧扩展；都不是则按无扩展处理。

## 编码规则

- 标准前缀的文字字段仍用 CP932，保持 0002 兼容。
- 新块的文本统一 UTF-8，无 BOM，字符串用 u32 字节长度前缀，不要求 NUL。
- 路径块存 UTF-8 完整路径，加载器转换成宽字符；标准前缀里的路径是基础场景的兼容值，完整路径在块里。
- 名称块存 UTF-8 完整名称；标准前缀保留 CP932 截断镜像。
- 不做 Unicode 归一化，保存时按原字符串写入；路径分隔符和大小写保持原样。
- 旧 `MDSXPMM2` 仍按它自己的旧规则读取；新写入器不再产生新的 ACP/936/950/949 路径字节。

## 帧号规则

- 标准前缀的帧字段是 u32；块里的 `keys` 帧字段也是 u32。
- 0002：`0..10,000,000`。这是原版兼容上界。
- 0003：`0..2,147,483,646`，即 `int32` 最大值减一。
- 超过 `2,147,483,646` 属于无效数据，拒绝保存，不切换版本，不静默截断。
- 0003 不因为帧号超过 10,000,000 而额外拒绝；10,000,000 只是 0002 的边界。

## 读取流程

1. 读文件大小。小于 64 字节时按无新容器处理。
2. 读最后 64 字节，检查 footer magic。是 `PMM3END` 时执行第 3 步；否则检查最后 32 字节的 `MDSXPMM2`，是则交给旧扩展解析，否则按无扩展处理。
3. 校验 footer 的 `version`、`totalSize`、`standardSize`、`tocOffset`、`tocSize` 和 `tocCrc32`。
4. 读 TOC，校验 magic、版本、项数、TOC 大小和 CRC。
5. 逐项校验 key 长度、块偏移、块头一致性、载荷边界和载荷 CRC；重复 key 使容器无效。
6. 新容器无效时，标准前缀仍按现有规则读取；容器错误记入运行日志，不应用部分块。标准前缀本身损坏时按现有 PMM 错误处理。
7. 在解析标准前缀和载入模型之前，先取出 `path`、`name`、`count` 等需要的块，建立上下文；模型路径用块里的完整 UTF-8 路径，块缺失时回退到标准前缀的 CP932 路径。

## 写入流程

1. 判断 0002 边界。没有触发时按现有 0002 写入，不调用容器写入。
2. 触发时先写 0003 标准前缀到临时文件，得到 `standardSize`。
3. 收集块：已知块写新内容，未知块保留原 key、版本、flags、encoding 和载荷字节；同一 key 只保留一份。
4. 按 key 排序写块，记录每个块的偏移和 CRC。
5. 写 TOC 和 footer，刷新、关闭，原子替换目标文件。
6. 标准前缀内容没变且只是追加新块时，可以保留旧块偏移，在旧 TOC/footer 之前追加新块，再写新 TOC/footer；旧的 TOC/footer 成为垃圾，读取器只认最后一个 footer。定期保存可以压缩，压缩只改布局，不改块载荷。

## 兼容性

| 文件 | 标准前缀 | 扩展 | 原版 MMD / 最小包 | 旧 MMS | 新 MMS |
| --- | --- | --- | --- | --- | --- |
| 0002 | CP932 | 旧 `MDSXPMM2` 可选 | 可读标准部分 | 可读 | 可读 |
| 旧 0003 | CP932 | `MDSXPMM2` | 拒绝 | 可读 | 按旧规则读 |
| 新 0003 | CP932 基础值 | `PMM3END` | 拒绝 | 不需要兼容 | 读完整容器 |

- 新 MMS 必须同时支持 0002、旧 0003 和新 0003；写 0002 时不得把必需数据只放进容器。
- 旧 MMS 不需要读取新 0003，也不作为验收项；新 0003 不保留旧 `MDSXPMM2` 尾部。新 0003 的标准前缀用于新 MMS 的基础场景和现有 v2 读写复用，不承诺旧读取器可解析。
- 旧 0003（`MDSXPMM2`）仍由新 MMS 读取，保证已有工程可以继续打开。
- 原版 MMD 和最小包继续拒绝 0003 文件头，符合现有约定。

## 初始块

| key | 版本 | encoding | 内容 |
| --- | --- | --- | --- |
| `org.mikudancestudio.path.v1` | 1 | 1 | 每个模型、配件和背景槽位的 UTF-8 完整路径 |
| `org.mikudancestudio.name.v1` | 1 | 1 | 模型、骨骼、表情、显示分组的完整名称 |
| `org.mikudancestudio.count.v1` | 1 | 0 | 真实显示分组数、表情帧行数等计数 |
| `org.mikudancestudio.keys.v1` | 1 | 0 | 超出 v2 池的关键帧 |
| `org.mikudancestudio.project.v1` | 1 | 0 | 工程设置和曲线数据 |
| `org.mikudancestudio.thirdparty.*` | 任意 | 任意 | 第三方块；新 MMS 不认识时原样保留 |

各块的载荷结构由块自己的规范定义；本文只固定外层容器。新增功能使用新的 key 或提高块版本，不改标准前缀的固定字段。

## 限制与安全

- key 长度 1 到 255 字节，不含 NUL；建议只用 ASCII 字母、数字、点、下划线和连字符。
- 块数不超过 `UINT32_MAX`；单个载荷不超过文件剩余长度和 `INT64_MAX`。
- 所有偏移和长度在分配或读取前检查溢出；不按声明的值直接分配超大内存。
- 每个载荷和 TOC 都有 CRC32；CRC 或边界不通过时不应用该块。
- 写入使用临时文件、刷新、关闭后再替换，避免半写文件覆盖旧工程。

## 验证计划

编解码层：

- 已知块和未知块的写入、读取和字节级保留。
- TOC 排序、重复 key 拒绝、key 长度边界、空载荷。
- footer/TOC 的 magic、版本、大小、CRC 和越界拒绝。
- 旧 `MDSXPMM2` 的识别和无扩展文件的识别。
- UTF-8 文本块、二进制块和未知 encoding 的保留。

集成层（后续）：

- 无边界工程保存为 0002，原版 MMD 读取标准部分，MMS 重新打开完整工程。
- 非 CP932 路径和完整名称保存为 0003，新 MMS 重开恢复；旧 MMS 不参与这项验收。
- 超容量关键帧、超 255 显示计数在 0003 中重开。
- 旧 0003（`MDSXPMM2`）继续可读。
- 第三方追加未知块后，MMS 重存仍保留该块的载荷字节。
