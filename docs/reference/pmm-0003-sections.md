# PMM 0003 分节格式

状态：设计稿。本文取代 [PMM 0003 容器格式](pmm-0003-container.md) 的“标准前缀 + 末尾块容器”布局。0002 标准布局和旧 0003 的 `MDSXPMM2`/`MMSXPMM2` 尾部解析保持现状。

> 尾部标记：新写入使用 `MMSXPMM2`；读取同时接受旧的 `MDSXPMM2`，两者布局相同。下文描述已存在的旧文件时写 `MDSXPMM2`，描述新写入时写 `MMSXPMM2`。

## 目标

- 新 0003 按类别分节，不把类别数据统一堆到文件末尾。模型、相机、灯光、配件和工程设置各自成节；名称、路径、计数、关键帧曲线放在对应节内。
- 关键帧曲线直接写入关键帧部分的扩展区，不再作为文件末尾的全局记录。
- 未知节和未知扩展按原始字节保留；第三方可以只替换自己认识的节或扩展。
- 新 MMS 读取 0002、旧 0003（v2 主体 + `MDSXPMM2`/`MMSXPMM2` 尾部）和新 0003（分节）。
- 没有触发 0003 边界时只写 0002，标准部分原版 MMD 可读。0002 的标准关键帧段不插入 MMS 曲线；原版 MMD 会按 v2 记录长度解析，插入字节会错位。
- 旧 MMS 不需要读取新 0003。

非目标：

- 不改变 0002 的标准前缀布局，不要求原版 MMD 读取 0003。
- 不把帧索引改成 64 位；0003 使用运行时完整的 `int32` 帧范围。
- 不在 0002 的关键帧记录中内联曲线。0002 的曲线仍只能放在尾部 `MMSXPMM2` 扩展（读取兼容旧 `MDSXPMM2`），原版 MMD 忽略尾部。

## 0002、旧 0003 和新 0003 的区分

- 0002：30 字节文件头 `Polygon Movie maker 0002` + v2 主体 + 可选 `MMSXPMM2` 尾部（读取兼容旧 `MDSXPMM2`）。
- 旧 0003：30 字节文件头 `Polygon Movie maker 0003` + v2 主体 + `MDSXPMM2` 尾部；重新保存后尾部标记为 `MMSXPMM2`。文件偏移 30 开始是 v2 主体，不是 `PMM3SECT`。
- 新 0003：30 字节文件头 `Polygon Movie maker 0003` + 偏移 30 的 `PMM3SECT` 头 + 节表 + 分节。

读取器先看文件头的 `0002`/`0003`。`0003` 再看偏移 30 的 8 字节：是 `PMM3SECT` 就按新分节解析，否则按旧 0003 的 v2 主体解析。

## 新 0003 文件布局

```text
偏移 0
  +--------------------------------------+ 30
  | "Polygon Movie maker 0003" (30 字节) |
  +--------------------------------------+ 30
  | PMM3SECT 头（64 字节）               |
  +--------------------------------------+
  | 节表（header 里给出偏移和长度）      |
  +--------------------------------------+
  | 节 0：节头 + standardSize + 标准数据 |
  |        + 扩展区（TLV）                |
  | 节 1：...                             |
  +--------------------------------------+ totalSize
```

文件里没有末尾目录或末尾 footer。`PMM3SECT` 头在文件开头，节表也在开头附近；`totalSize`、节表 CRC 和各节 CRC 都在头部/节头里。这样新数据可以放进对应节，不需要在文件末尾再维护一个全局容器。

### PMM3SECT 头

从文件偏移 30 开始，固定 64 字节：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | magic `PMM3SECT` | 区分旧 0003 |
| 8 | 4 | `version` | 当前 1 |
| 12 | 4 | `flags` | 当前 0 |
| 16 | 4 | `headerSize` | 固定 64 |
| 20 | 4 | `sectionCount` | 节数 |
| 24 | 8 | `tableOffset` | 节表起始的绝对偏移 |
| 32 | 8 | `tableSize` | 节表字节数 |
| 40 | 8 | `totalSize` | 文件总字节数 |
| 48 | 4 | `tableCrc32` | 节表字节的 CRC32 |
| 52 | 4 | `reserved` | 固定 0 |
| 56 | 8 | `reserved` | 固定 0 |

有效文件满足：

- `totalSize == 文件大小`。
- `tableOffset >= 30 + 64`，`tableSize >= 16`。
- `tableOffset + tableSize <= totalSize`。
- 节表 CRC 匹配。

### 节表

节表头 16 字节：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 8 | magic `PMM3TAB\0` |
| 8 | 4 | `version`，当前 1 |
| 12 | 4 | `sectionCount` |

每个节表项 48 字节：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 16 | `type`，ASCII 或 UTF-8，NUL 补齐 |
| 16 | 4 | `version` |
| 20 | 4 | `flags` |
| 24 | 8 | `offset`，节头起始的绝对偏移 |
| 32 | 8 | `size`，节总字节数（节头 + 载荷） |
| 40 | 4 | `payloadCrc32` |
| 44 | 4 | `reserved`，固定 0 |

- 节表项按 `type` 的字节序升序排列；同一 type 只能出现一次，重复 type 使文件无效。
- 每个节的 `offset` 必须不小于标准头 + 节表，`offset + size` 不得越过 `totalSize`。

### 节和节载荷

节头 32 字节：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 16 | `type`，与节表项一致 |
| 16 | 4 | `version` |
| 20 | 4 | `flags` |
| 24 | 8 | `payloadSize` |
| 32 | 4 | `payloadCrc32` |
| 36 | 4 | `reserved` |
| 40 | ... | 载荷 |

节载荷固定以 `standardSize` 开头：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | `standardSize` |
| 4 | `standardSize` | 标准数据 |
| 4+standardSize | 剩余 | 分节扩展区（TLV 流，可为空） |

扩展区是一串 40 字节头 + 内容的 TLV 项：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 16 | `type` |
| 16 | 4 | `version` |
| 20 | 4 | `flags` |
| 24 | 8 | `payloadSize` |
| 32 | 4 | `payloadCrc32` |
| 36 | 4 | `reserved` |
| 40 | ... | 内容 |

扩展项按 type 排序；未知 type/版本原样保留。扩展项必须完整落在所属节内。

## 初始节

| 节 type | 标准数据 | 扩展区内容 |
| --- | --- | --- |
| `MODEL` | 现有 v2 的逐模型块（模型名、路径、名称表、图标、关键帧、姿态等） | 每模型的完整 UTF-8 名称、完整路径、显示计数、关键帧曲线、超容量关键帧 |
| `CAMERA` | 现有 v2 的相机轨道和相机杂项 | 相机曲线和相机扩展设置 |
| `LIGHT` | 现有 v2 的灯光轨道和灯光杂项 | 灯光曲线 |
| `ACCESSORY` | 现有 v2 的配件槽位、轨道和配置 | 配件曲线、完整路径、显示名 |
| `CONFIG` | 现有 v2 的工程设置块 | 抗锯齿、排序、运算器等工程设置 |
| `GLOBAL` | 现有 v2 的全局尾部状态 | 其他跨类别状态 |

节的标准数据沿用 v2 的字段，保证新 MMS 可以复用现有读取器和写入器；完整名称、完整路径、曲线和超容量数据放在该节的扩展区。标准数据里放不下的字段用截断值或占位值，新 MMS 读取时优先使用扩展区。

## 关键帧曲线

关键帧曲线放在对应的 `MODEL`、`CAMERA`、`LIGHT` 或 `ACCESSORY` 节的扩展区，紧跟该节的标准关键帧数据，不再作为文件末尾的全局记录。

- 曲线扩展项 type 使用 `org.mikudancestudio.curve.v1`。
- 内容沿用 0002 扩展里现有的曲线序列化：骨骼、表情、相机、灯光、配件各轨道的曲线数据格式不变，只改变承载位置。
- `MODEL` 节的曲线项按模型槽位和轨道分组；`CAMERA` 等节按各自轨道分组。
- 读取器解析完该节的标准数据后，立即读取扩展区的曲线项，不需要等到文件末尾。
- 写入器修改某个模型的曲线时，只重写 `MODEL` 节和节表/头部，不触碰其他节。
- 0002 的曲线仍只能放在尾部 `MMSXPMM2` 扩展（读取兼容旧 `MDSXPMM2`）。0002 标准关键帧段的记录长度是原版 MMD 解析的边界，不能插入曲线字节。

## 编码规则

- 新 0003 的节标准数据沿用 CP932，保持与 v2 字段的一致。
- 新 0003 扩展区的文本统一 UTF-8，无 BOM，字符串用 u32 长度前缀，不要求 NUL。
- 路径、名称、显示名等完整文本放在扩展区；标准数据里的同名字段只作基础值。
- 不做 Unicode 归一化，保存原字符串；路径分隔符和大小写保持原样。
- 新 `MMSXPMM2` 和旧 `MDSXPMM2` 都按同一规则读取；新写入器不再产生新的 ACP/936/950/949 路径字节。

## 帧号规则

- 0002：`0..10,000,000`。原版兼容上界。
- 0003：`0..2,147,483,646`。标准数据和曲线扩展里的帧字段都是 u32。
- 超过 `2,147,483,646` 属于无效数据，拒绝保存，不切换版本，不截断。

## 读取流程

1. 读 30 字节文件头。`0002` 走现有 v2 读取；`0003` 继续。
2. 读偏移 30 的 8 字节。不是 `PMM3SECT` 时按旧 0003 的 v2 主体和尾部扩展（`MMSXPMM2` 或旧 `MDSXPMM2`）解析；是 `PMM3SECT` 时执行第 3 步。
3. 校验 `PMM3SECT` 头的版本、`headerSize`、`totalSize`、节表偏移/长度和 CRC。
4. 读节表，校验 magic、版本、节数和每项的越界；重复 type 使文件无效。
5. 逐节读取节头，校验 type/version/size/CRC 与节表一致；读取 `standardSize` 和标准数据；再读扩展区 TLV，校验每项边界和 CRC。
6. 未知节和未知扩展项按字节保留，不应用；已知节先加载标准数据，再用扩展区覆盖完整名称、路径、计数和曲线。
7. 需要路径或完整名称时，先解析该节的扩展区，再载入该节里的模型或配件。节的顺序不要求固定，读取器按节表定位。

## 写入流程

1. 判断 0002 边界。没有触发时按现有 0002 写入，标准关键帧段不插入曲线，曲线仍写 `MMSXPMM2` 尾部。
2. 触发时写新 0003：
   - 写 30 字节文件头；
   - 预留 64 字节 `PMM3SECT` 头；
   - 按类别写节：标准数据 + 扩展区；
   - 写节表；
   - 回到偏移 30 写头部，填入节表偏移、长度、总大小和 CRC；
   - 刷新、关闭、原子替换。
3. 修改某一类数据时只重写对应节和节表/头部；其他节的字节不变。未知节和未知扩展项原样复制。
4. 追加新扩展项时，扩展项写在所属节内，TOC 和头部随之更新；不需要在文件末尾追加全局记录。

## 兼容性

| 文件 | 标准数据 | 扩展 | 原版 MMD / 最小包 | 旧 MMS | 新 MMS |
| --- | --- | --- | --- | --- | --- |
| 0002 | CP932 | 尾部 `MMSXPMM2`/旧 `MDSXPMM2` 可选 | 可读标准部分 | 可读 | 可读 |
| 旧 0003 | CP932 | 尾部 `MMSXPMM2`/旧 `MDSXPMM2` | 拒绝 | 可读 | 按旧规则读 |
| 新 0003 | CP932 | 分节扩展 | 拒绝 | 不需要兼容 | 读完整分节 |

- 新 MMS 写 0002 时，标准主体必须完整，曲线只能放 `MMSXPMM2` 尾部（读取兼容旧 `MDSXPMM2`）；原版 MMD 读取标准主体后忽略尾部。
- 新 MMS 写 0003 时，曲线放进对应节的关键帧扩展；文件末尾不再有全局曲线记录。
- 旧 MMS 不需要读取新 0003；新 0003 不保留尾部扩展。

## 限制与安全

- 节 type 和扩展 type 建议使用反向域名或稳定的 ASCII 标识，长度 1 到 16 字节，NUL 不参与比较。
- 节数、扩展项数、载荷长度和偏移都必须对照文件大小做溢出检查；不按声明值直接分配超大内存。
- 每个节和每个扩展项都有 CRC32；头部 CRC 覆盖节表。
- 写入使用临时文件、刷新、关闭后替换，避免半写文件覆盖旧工程。

## 验证计划

- 分节容器：头部/节表/节头/扩展 TLV 的字节布局、CRC、越界和重复 type 拒绝。
- 未知节和未知扩展项：读取后按字节保留，重存不丢。
- 曲线：`MODEL`、`CAMERA`、`LIGHT`、`ACCESSORY` 的曲线扩展往返；曲线数据在对应节内，不在文件末尾。
- 0002：无边界保存，原版 MMD 读取标准部分，曲线仍在 `MMSXPMM2` 尾部。
- 旧 0003：`MDSXPMM2`/`MMSXPMM2` 尾部继续可读。
- 帧号：0002 上界 10,000,000；0003 上界 2,147,483,646；超过拒绝。
