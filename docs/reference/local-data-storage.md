# 程序本地数据目录

程序生成的设置与状态保存在程序旁的 `data` 文件夹。可重新生成的 MME 编译缓存和纹理缓存保存在程序旁的 `Cache` 文件夹。两者均与程序文件同级，不创建名为 `EXE` 的目录，也不随当前工作目录变化。

以下路径对应 main。可选插件的代码与资源由各自安装包管理。

| 内容 | 相对程序目录的路径 |
| --- | --- |
| 自动备份设置 | `data/autosave.ini` |
| 默认自动备份、崩溃恢复与错误日志 | `backups/` |
| 抗锯齿设置 | `data/antialias.ini` |
| 运算器设置 | `data/processor.ini` |
| 操作柄位置 | `data/viewport.ini` |
| 最近工程记录 | `data/recent-pmm.txt` |
| 外部 MME 编译结果 | `Cache/MME/<效果名称>/<缓存键>.fxb` |
| 纹理解码与缩放结果 | `Cache/Textures/<纹理名称>/<缓存键>.mtc` |
| 缓存管理设置 | `data/cache.ini` |
| 缓存用途、最近使用与工程关联索引 | `Cache/Management/index.bin` |

插件安装包仍放在 `PLUGINS`；该目录存放代码及随包资源。main 暂无 ABI 插件宿主，插件持久数据规则适用于 ABI 分支。

上述两类缓存无需保留，删除后会在下次加载时重新生成。模型顶点与索引的解析缓存只保存在内存中，退出进程后释放，不生成模型旁文件。缓存限额、失效条件和实际加载测量见 [资源准备与缓存](../records/performance/startup.md#record-resource-reuse-20261020)。

「帮助 → 缓存管理」默认勾选「启用缓存」和「自动清理（清理可回收缓存）」。MME 和纹理磁盘缓存共用 4 GiB 上限，优先保留最近 10 个成功打开或保存的工程。窗口中的 GB 按 1024³ 字节计。容量和最近工程数量均可调整，设置在点击「应用」或执行手动清理时保存。

新增缓存将超出上限时，自动清理先删除已标记失效的文件，再删除较旧且不属于最近工程的文件，最后才考虑最近工程的较旧缓存。目标是将已有缓存减至上限的约 80%，同时为新增文件腾出足够空间。固定工程和正在使用的文件不参与自动清理。无法腾出空间时停止新增磁盘缓存，加载器继续使用原始资源。关闭自动清理后，满额时同样停止新增缓存。关闭「启用缓存」会绕过 MME 编译缓存和纹理准备缓存，现有渲染内存及显存资源继续按原逻辑管理。

手动「清理可回收缓存」保留固定工程和正在使用的文件，最近工程中已标记失效的闲置缓存仍可清理。「清理所选工程」只删除该工程独占且未使用的缓存。「清空磁盘缓存」经确认后删除可删除的已识别缓存，包括固定工程的闲置文件，但仍跳过正在使用的文件。多个工程共用的文件在磁盘上只计一份，清理单个工程不会删除其他工程引用的共享文件。缓存工程记录独立于「最近打开」菜单，清空菜单历史不会触发删除。

自动清理与手动清理只处理缓存目录中已登记或通过文件头识别的 `.fxb`、`.mtc` 文件，不扫描其他诊断、导出、备份或设置目录。目录连接与符号链接不会作为受管理缓存路径。索引损坏时停止普通清理和新增写入，可通过确认后的「清空磁盘缓存」重建索引。多进程共用容量锁，当前工程用到的文件在进程内持有禁止删除的句柄，其他进程也不能清理这些文件。

`MMS_CACHE_MEMORY_ONLY=1` 禁止上述 MME 和纹理准备缓存的磁盘读写。MME 字节码仍在进程内复用，纹理保留现有 GPU 对象池，不另存一份常驻 CPU 像素。`Cache/MemoryOnly/MMS-memory-only.cmd` 可启动这一模式，环境变量只传给该次进程，不改写正常启动的配置，也不删除已有缓存。退出后，下一次启动需要重新编译效果和解码纹理；设置与备份仍按表中的规则保存。运行时的顶点与阴影边界缓存始终保存在内存，不受这个磁盘开关影响。

仅内存模式下，正常工程载入、重置及关闭也不创建缓存索引。用户主动打开缓存管理窗口仍可查看和清理既有磁盘缓存。`MMS_EFFECT_CACHE_DIR`、`MMS_TEXTURE_CACHE_DIR` 指向管理目录以外时，诊断用缓存沿用各自原有限额，不纳入自动清理。

PMX 加载时的后台纹理解码只保留当前模型的临时准备数据，结束后释放。它也支持仅内存模式，不另建磁盘缓存类型。处理范围、预算和对照记录见 [并行资源准备](../records/performance/startup.md#record-parallel-prepare-20261021)。

默认备份位置按当前程序所在目录解析，配置不保存上一次安装目录的绝对地址。整体搬迁程序后，默认位置跟随新目录；程序改名不影响设置。用户明确选择的自定义定时备份目录继续保留。崩溃恢复使用程序同级的 `backups`；错误日志跟随用户设置的备份目录，默认为 `backups`。

不自动继承旧 AppData 设置，避免把另一份程序的绝对备份地址带入当前安装；不删除旧文件。旧设置的默认目录随新版改为 `backups`，原 `data/backups` 中的文件保留，不自动搬迁；明确选择的自定义目录保持不变。设置无法写入时保留旧值或报告失败，不回退到 AppData。测试专用的显式路径覆盖接口保留。

Windows 上已有 `Data` 与 `data` 通常指向同一个目录，无需为了大小写搬迁或删除原有文件。代码中新建的本地设置目录使用小写 `data`。
