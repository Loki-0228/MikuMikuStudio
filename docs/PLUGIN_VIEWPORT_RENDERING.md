# 插件多视口与渲染器接口方案

本文说明多视口、渲染器提供者和独立场景求值的设计边界。
除「当前实现」外，本文的服务、结构和函数均为待实现提案，尚未加入 SDK。
本方案不改变普通宿主的 `mms.edit` 开放状态，也不要求 MMS 自带下文列出的全部渲染器。
界面样式、动画和绘制层沿用[插件界面呈现方案](PLUGIN_UI_PRESENTATION.md)。本页只规定这些界面如何承载场景图像。
一套 C ABI 与多层 SDK 的共同约束见[统一扩展架构](PLUGIN_EXTENSION_ARCHITECTURE.md)；源数据与专用编辑器见[数据扩展方案](PLUGIN_DATA_EXTENSIONS.md)。

## 当前实现

现有接口已经提供稳定对象身份和只读快照，但完整的多视口渲染还需要新增服务。

`mms.render.image` 1.0 已提供[CPU 图像租约](../sdk/mms/render-image.md)：插件可复制发布 RGBA8/BGRA8 图像、读取描述、保留图像及独立读取映射。它有线程安全与内存限额，CPU 像素不随设备重置失效。此阶段没有视口挂载、GPU 图像、渲染器提供者或独立场景求值，不能将其视为完整多视口已实现。

[ImagePanel SDK](../sdk/mms/image-panel.md) 已复用原 surface 将这些图像显示在插件 PANEL 中，无需插件手写窗口绘制。此显示路径有实际挂载与像素测试；仍不等同于下述场景 view、renderer provider 或独立 3D 视口。

独立求值的前置修复见[离线曲线复制记录](records/abi-detached-curve-copy-2026-10-26.md)：骨骼自由曲线在私有候选中同步，复制不再修改源作者，失败保留目标。现有 `physics_bake::ModelCopy` 仍借用源运动关键帧及表情载荷，仅适用于当前同步调用期，不能作为跨线程或源模型删除后仍有效的场景源。

内部 [BoneMotionSnapshot](records/abi-frozen-bone-motion-2026-10-27.md) 已冻结可达原生关键帧、尺度和自由曲线，支持源删除后的并发非负时间采样。[`mms.scene.evaluate` 1.1](../sdk/mms/evaluation.md) 通过同一 C ABI 提供骨骼通道和表情直接权重，绑定原场景对象及元素身份，提供有额度限制的独立源租约。通道掩码 `1`、`2`、`3` 分别选择骨骼、表情或两者，组合捕获共享身份、计费与生命周期规则。1.0 的函数表和只捕获骨骼的创建语义保持不变。`captureId` 区分每次捕获，`hostRevision` 仅作历史元数据，不能当作动作内容版本。

旧通道入口输出模拟前的已注册局部骨骼动作及表情直接权重，对外部父级及不支持的派生骨骼明确拒绝，不包含未注册编辑姿态。1.4 另外提供独立骨架场景来源和帧租约，范围见下文。负帧、独立求值实例、动作层和物理仍须实现和验收。局部通道不能冒充 `ANIMATED` 世界矩阵或 `PHYSICS` 阶段。采样须保持主播放头、编辑姿态及历史不变。原始兼容产品配置尚未开放此求值服务。

[冻结表情权重](records/abi-frozen-morph-motion-2026-10-27.md)由内部 `morph_curve::SamplingState` 持有原生键与私有协调的自由曲线，支持源销毁后的无分配并发读取。[表情求值服务](records/abi-morph-evaluation-service-2026-10-27.md)已将它接入 `mms.scene.evaluate` 1.1，共用原源句柄、额度和停止保护。权重不夹取到 `[0, 1]`，不含组或翻转展开及最终形变。完整姿态求值、独立播放时钟和渲染器提供者继续待实现。

内部 [DisplayMotionSnapshot](records/abi-frozen-display-motion-2026-10-27.md) 已拥有可达显示键、IK 链到骨骼的映射、selector 到骨骼的映射，以及完整的原始外部父级选择对和连续有效窗口。selector 0 保留模型全局外部父级语义。快照在 CPU 上按非负时间阶梯采样，分数帧保持前键状态，源模型销毁后仍可无分配并发读取。

[`mms.scene.evaluate` 1.2](records/abi-display-evaluation-service-2026-10-27.md) 已接入显示快照。通道位 `4` 可与骨骼位 `1`、表情位 `2` 组合，读取显示状态、IK 开关及外部父级选择。捕获在 UI 安全点解析所有可达关键帧的外部目标稳定身份，包括未来键；无效目标使所选通道捕获整体失败。旧源保留目标身份和连续窗口，模型删除及槽位复用不改变旧结果。该 1.2 入口不提供目标动作或 IK 求解；1.4 骨架场景帧另行提供相关结果。

[离散时间及真实 IK 轨道验收](records/abi-display-rational-boundaries-2026-10-27.md)已修复整数键前的浮点提前舍入。显示、IK 开关和父级窗口用精确有理帧取整；骨骼、表情仍连续采样。真实含 IK 链 PMX 已验证链身份、原始开关字节、局部父级及跨删除读取。该验收不包含 IK 求解。

[父级状态 1.3](records/abi-parent-state-2026-10-27.md)在同一源和租约上追加 `sampleParentState`，区分继承、地面和模型目标。修复未来地面键被误判为过期目标的问题。旧 1.2 入口在地面状态返回不支持并保留输出，其他状态仍按旧契约返回；局部地面不再与父骨骼或全局外亲继承混淆。

[骨架场景帧 1.4](records/abi-public-scene-frame-2026-10-27.md)允许插件冻结全部模型的注册动作和身份，在后台求值并保留独立帧。帧提供骨架变形矩阵、两阶段附着矩阵、关节位置及可见字节；它不包含蒙皮几何或物理模拟。场景来源、帧与旧通道共用句柄、额度和停止保护。独立视口、渲染器、时钟和历史物理仍待接入。

骨架来源目前拒绝翻转、冲量及其他未实现的 PMX 表情类型。现有 PMX 加载和 CPU 蒙皮路径也尚未完整实现 QDEF，不能把权重类型枚举或骨架帧当作 QDEF 支持的证据。独立网格求值须对实际支持的权重类型进行能力判断。

[独立网格定义快照](records/abi-mesh-definition-snapshot-2026-10-27.md)已冻结 PMX/PMD 绑定顶点、活动权重、UV 和材质分段，并能从表情修改后的工作数组恢复私有基础数据。它不执行蒙皮，也尚未进入公开来源和帧；下阶段仍须在同一安全点组合骨架与表情数据。

| 代码入口 | 已有范围与限制 |
| --- | --- |
| `sdk/mms/include/mms/plugin.h` | 提供 `queryService`、`registerProvider`、版本头、不透明句柄和设备事件定义。V1 面向 Windows x64。 |
| `src/plugins/manager.cpp` | 已发布 UI、场景和存储服务。`registerProvider` 当前只接受 `mms.serializer`，渲染器注册尚未开放。 |
| `sdk/mms/include/mms/scene.h` | 定义对象、网格、材质、纹理描述、骨骼及各求值阶段。定义阶段枚举不等于宿主已经提供对应结果。 |
| `src/plugins/scene_host.cpp::Capture` | 当前只发布 `MMS_STAGE_BIND`。请求其他阶段或其他时间会拒绝，不临时移动主播放头。 |
| `src/plugins/scene_store.cpp` | UI 线程获取快照，冻结后用租约保留数据。读取与释放可在其他线程执行，数据不暴露原生模型指针。 |
| `sdk/mms/include/mms/evaluation.h` | `mms.scene.evaluate` 1.4：原通道采样之外，提供全模型骨架场景来源和独立帧。骨骼身份与 BIND 一致，来源和帧可跨删除读取。旧函数前缀及 1.0 骨骼创建语义不变；尚未提供蒙皮或物理帧。 |
| `sdk/mms/include/mms/surface.h` | 支持插件子窗口与多视图工厂。`MMS_SURFACE_MULTIPLE_VIEWS` 不代表多个独立 3D 渲染上下文。 |
| `src/render/frame_scene.cpp::RenderFrameScene` | 依赖活动 `MMDApp`、DX9 设备和每帧缓存，也会更新变形、效果和叠加层。不能直接当作无副作用的任意视口函数。 |
| `src/render/frame_presentation.cpp`、`viewport_render_scale.cpp` | 已区分部分场景图像与界面呈现，并支持预览缩放。渲染目标仍按 `MMDApp*` 保存。 |
| `src/render/device_reset.cpp` | Reset 前等待原 `mms.render` 设备租约安全释放，并可靠投递设备状态；新增 CPU 图像独立于设备。GPU 图像及互操作代次协议仍未开放。 |

目前的 DX12 预览、MMV 路径和默认效果入口不等于新 ABI 的渲染器提供者。
完整范围与验收状态仍以[插件 ABI 实施记录](PLUGIN_ABI_IMPLEMENTATION.md)为准。

内部 [BoneDefinitionSnapshot](records/abi-bone-definition-snapshot-2026-10-27.md) 已独立持有已加载骨架、PMX 原 IK 链、运行 IK 链及 selector 定义。保留原顺序与类型语义，父链环和非法引用在捕获时拒绝，源销毁后可并发无分配读取。真实 PMX/PMD 及 PMM 生命周期验证通过。该定义已参与内部骨架求值，并通过 1.4 场景帧发布骨架结果；完整定义仍通过 BIND 数据获取。

内部 [MorphDefinitionSnapshot](records/abi-morph-definition-snapshot-2026-10-27.md) 已独立持有 PMD 顶点表情和 PMX 0–8 类载荷，以及顶点、UV、材质恢复基准。源删除后可并发读取，PMD 已映射索引、组条目顺序及未启用浮点位保持不变。该定义本身不展开组或生成形变；其中骨骼表情数据经内部求值参与 1.4 骨架帧，其他形变尚未接入公开帧。翻转和冲量表情尚缺加载与求值实现，捕获会明确拒绝；宽字符长名仍不属于该求值载荷快照。

内部 [MorphEvaluationFrame](records/abi-morph-evaluation-2026-10-27.md) 已将冻结表情定义和直接权重计算为稀疏位置、五族 UV、骨骼表情偏移及材质通道。真实注册运动快照可在后台提供不同时间的权重，模型与输入快照销毁后结果仍可独立读取。原生运算逐位对照及真实 PMX/PMD 生命周期验证通过。其中骨骼表情已参与 1.4 骨架帧及其层级和 IK 求值；顶点、UV 和材质结果仍须与基础几何、蒙皮及物理组合并公开，不能当作最终场景或渲染图像。

独立骨架求值准备阶段已修复[根骨骼在 IK 后继承时的负索引读取](records/abi-bone-root-inheritance-2026-10-27.md)。内部 [BoneTransformContext](records/abi-bone-transform-context-2026-10-27.md) 已持有独立 CPU 数学函数，`BoneFrameTransformPrivate` 在自有工作区复用原五阶段，隔离全局数学表、尺度缓存与诊断。双配置均通过重构前源码逐位对照、并发和生命周期验证。该函数负责单层，现由内部骨架工作区安排完整层级和前后两轮。

内部 [PrepareKinematicChannels](records/abi-bone-kinematic-input-2026-10-27.md) 已从同次捕获的动作与显示快照准备局部姿态，按原生窗口边界处理 selector，并为类型 7／9 提供新工作区默认姿态。尺度与自由曲线按原顺序应用。真实 Seek 逐位对照、PMX/PMD 导入及 PMM 重载验证通过；旧公开通道接口的拒绝规则不变。此入口仍不解析外部目标矩阵，不计算层级、IK 或物理。

内部 [BonePreparePosePrivate](records/abi-bone-pose-preparation-2026-10-27.md) 已复用原姿态来源选择和骨骼表情合成循环，使用独立 CPU 数学上下文。调用方须在物理前后各轮开始时重置姿态，再执行全部层级；来源模式与模型格式字段分别控制物理备份和表情，不可混用。双配置专项及原生调用链回归通过，内部骨架工作区已按此顺序装配。

内部 [BuildTransformsPrivate](records/abi-private-bone-scale-2026-10-27.md) 已从显式刚性矩阵和完整尺度计算父子变形，不访问宿主尺度缓存或当前 matInit。专项验证缓存隔离、失败保留输出及并发，原生尺度和物理回归通过。

[BoneEvaluationSource 与 BoneEvaluationFrame](records/abi-owned-bone-evaluation-2026-10-27.md) 已按[工作区装配方案](records/abi-owned-bone-workspace-plan-2026-10-27.md)同次捕获五类数据，从确定初值执行局部动作、骨骼表情、两轮层级与 IK 和完整尺度。结果自有刚性、尺度、分阶段附着矩阵与关节位置，不修改主播放头或编辑状态。真实 PMX/PMD 及原生对照验证通过。该单模型入口由调用方显式提供外部目标的每轮矩阵，完整模型集合的组合见下述场景入口。1.4 通过场景入口公开骨架结果，1.2 的原有通道范围保持不变。

[BoneSceneSource 与 BoneSceneFrame](records/abi-bone-scene-evaluation-2026-10-27.md) 已在内部补齐完整模型集合捕获、目标动作冻结、现有对象身份复制和两轮全场调度。单模型入口继续接受显式依赖，场景入口直接连接真实自有工作区，保留原计算顺序及循环、自引用语义。三模型传递、仅目标动作改变、真实身份、PMM 重载和删除后的旧结果读取均已验证。1.4 已公开骨架来源、帧租约及骨骼身份；蒙皮、历史物理及视口渲染仍待接入。1.3 父级状态入口仍仅采样注册状态。

## 预期交互

多视口面向编辑、比较和独立预览，界面插件可以组合下列行为。

| 用例 | 场景与视口关系 |
| --- | --- |
| 正面、侧面、透视四分屏 | 共享一次已求值帧，每个视口拥有独立相机和命中结果。 |
| toon 与 PBR 并排比较 | 共享几何和姿态，各自选择渲染器、材质解释规则及曝光。 |
| 骨骼、线框、法线检查 | 读取同一帧的调试通道，独立控制显示过滤和交互工具。 |
| 当前帧与第 120 帧对照 | 当前帧可跟随主工程。第 120 帧来自独立评估实例，不修改主播放头或主物理世界。 |
| 两个工程并排预览 | 每个工程拥有独立评估实例和资源命名空间，窗口只承载对应输出。 |
| 渐进离线预览 | 固定场景修订和相机，后台任务分批增加样本，并发布完成的图像。 |
| 插件演示或复杂工具面板 | 在一个画布中合成多个视口、标注、交互手柄和过渡动画，按需联动其他控件。 |
| 二维动画式洋葱皮 | 多个过去及未来时间点各自求值；用指定颜色、透明度、轮廓或骨骼轨迹叠加，主播放头保持不变。 |
| 无限工作台 | 相机画布控制多个可见视图，只有可见区域请求图像；数据、求值实例和资源不随面板复制。 |

桌宠只是独立场景图像的一种消费者。相同接口也用于材质工作台、镜头比较、动作诊断和多工程参考窗口。

## 同一套对象与 ABI

底层沿用 `MmsHeader`、`MmsHandle`、`MmsObjectRef`、`MmsTime`、`MmsSpan`、`MmsResult` 和 `MMS_CALL`。
新增函数表通过 `queryService` 查询，保留已发布 V1 表的前缀和语义。
跨 DLL 不传 STL、异常、分配器或 `MMDApp*`。可变长度数据声明长度、步长、版本和所有权。
宿主校验插件归属、句柄类型和代次。不同项目中的对象必须同时携带场景身份，不能只按模型槽位寻址。

建议引入以下对象，每个对象都有独立寿命。

| 对象 | 所有的数据与责任 |
| --- | --- |
| 场景源 `sceneSource` | 指定活动工程、冻结工程修订或私有工程资源。只描述来源，不拥有可变播放头。 |
| 评估实例 `evaluation` | 拥有自己的物理状态和可变求值缓存，按指定时间求值。共享模式不另建物理实例。 |
| 播放时钟 `clock` | 提供时间、速率、暂停与时间映射，不持有模型或物理世界；可与主播放时间只读绑定，也可独立运行。 |
| 相机 `camera` | 保存投影、变换及修订，可独立操作或只读跟随工程相机；与播放时钟、场景和窗口分开。 |
| 帧租约 `frame` | 保留一个时间、一个修订下已经完成的只读求值结果，多个视口可以共同持有。 |
| 渲染器 `provider` | 声明输入通道、后端能力、任务线程要求，以及可创建的渲染会话。 |
| 视口 `view` | 引用帧来源、时钟和相机，保存渲染配置、尺寸、预算及输入状态，不保存主工程的编辑选择。 |
| 显示挂载 `presentationTarget` | 将视口图像挂到 UI 画布或窗口；尺寸和可见性由 UI 提供，多个目标可消费同一图像。 |
| 图像租约 `image` | 保留一个完整输出及其描述，宿主画布、窗口和显式导出任务可分别读取。 |
| 渲染任务 `job` | 保留输入帧、配置修订和输出请求，管理取消、完成和错误状态。 |

一个视口可以换渲染器，也可以换输入场景。切换先准备新会话，成功后替换当前显示，失败保留旧图像并报告原因。
界面插件销毁窗口时不必销毁仍被其他窗口使用的帧或渲染会话。
同一个时钟可驱动多个独立实例，同一个实例也可接收显式时间请求。实例决定求值状态，时钟只提供目标时间，不因多个消费者读取就重复推进物理。

## 共享快照、共享帧与独立求值

绑定态快照适合读取原始网格、骨骼定义和材质，不能冒充带表情、动画、缩放与物理的最终姿态。
共享已求值帧要求宿主在明确的求值边界冻结结果，并保留时间、阶段、场景修订和资源修订。
多个视口读取同一帧时只绘制各自相机，不再次推进物理、动作层或效果时间。
视口请求缺少的阶段或通道时返回 `UNSUPPORTED`，尚未完成的帧返回 `NOT_READY`。

同工程不同时间需要独立评估实例。实例可共享不可变几何和纹理，但骨骼矩阵、物理世界、动作状态和缓存必须隔离。
不同工程还需要独立对象身份与资源解析上下文。禁止浅拷贝 `MMDApp` 后沿用原指针和全局缓存。
私有求值按声明的初始状态、固定步长和检查点推进。任意跳帧是否需要重算物理由实例能力说明。
不能复制的插件求值状态需要明确拒绝或要求插件提供克隆接口，不能退回主工程执行。
实例跟随源工程更新时创建新输入修订，并在安全点切换。旧任务继续持有旧修订，或被明确取消。
向主工程写回姿态、相机或材质是另外的编辑命令，必须通过宿主实际开放的事务入口。

## 建议服务与函数

下表给出拟定职责和函数语义。实现时还需形成 C 头文件、布局断言和兼容测试。

| 服务 ID | 建议入口 | 责任 |
| --- | --- | --- |
| `mms.scene.evaluate` | `createSource`、`createInstance`、`requestFrame`、`requestSamples`、`queryJob`、`acquireFrame`、`cancelJob`、`release` | 创建来源与评估实例，发布完整只读帧；多时间请求共用同一求值服务。 |
| `mms.scene.clock` | `create`、`bind`、`update`、`acquireState`、`release` | 管理独立时钟，或只读跟随宿主时钟；更改独立时钟不移动主播放头。 |
| `mms.render.camera` | `create`、`update`、`bind`、`acquire`、`release` | 管理相机及修订；绑定工程相机为只读跟随，写回另走编辑。 |
| `mms.render.view` | `createView`、`updateView`、`bindCamera`、`bindClock`、`requestRender`、`acquireImage`、`destroyView` | 管理视口配置、请求渲染与保留最新结果。 |
| `mms.render.catalog` | `enumerateProviders`、`queryCapabilities`、`queryProfileSchema` | 查询已安装的渲染器及配置，不假定宿主含特定后端。 |
| `mms.render.image` | 已实现 `getCapabilities`、`createCpu`、`describe`、`retain`、`mapRead`、`unmap`、`release`；`queryInterop` 仍为提案 | 当前只支持本插件不可变 CPU 图像；没有原生资源访问与跨插件共享。 |
| `mms.render.pick` | `requestPick`、`queryResult`、`releaseResult` | 基于指定图像和相机修订返回命中信息。 |

`registerProvider("mms.render.provider", id, table, ...)` 注册渲染器函数表，需先扩展现有 manager 的白名单和生命周期管理。
建议提供者表包含 `queryCapabilities`、`createSession`、`submit`、`poll`、`cancel`、`destroySession`。
`submit` 只接收宿主保留的帧、相机和资源句柄，不取得活动工程的写权限。
便利 SDK 的 `createScene` 组合 `createSource` 与 `createInstance`，返回相同底层句柄；它不是另一项底层服务。
SDK 的 `setTime` 仅更新指定独立时钟，或发显式求值请求。共享活动帧模式下，设置不同时间返回不支持，不能移动主播放头。
函数失败不修改输出参数或已显示内容。过期修订返回 `STALE`，预算不足返回 `MEMORY` 或明确的排队状态。

## 每个视口的配置

建议 `MmsRenderViewDescV1` 保存下列字段，宿主一次验证完整描述后才发布新配置。

| 字段组 | 约定 |
| --- | --- |
| 来源 | `sceneSource`、可选 `evaluation`、输入阶段、跟随或固定时间策略、对象过滤集合。 |
| 相机与时钟 | 引用独立相机和可选时钟。相机描述包含视图与投影矩阵、投影类型、裁剪范围及坐标约定。固定图像任务直接引用相机快照和显式时间。 |
| 渲染配置 | `providerId`、profile ID、具版本的参数块、背景、灯光或环境覆盖、颜色管理。 |
| 尺寸 | 逻辑尺寸、目标像素尺寸、DPI、渲染比例和裁剪矩形。改变预览尺寸不修改工程输出尺寸。 |
| 帧预算 | 刷新上限、CPU 时间预算、GPU 时间预算、任务数上限、图像字节上限和可见优先级。 |
| 状态 | `viewGeneration`、`cameraRevision`、`profileRevision`、`sizeRevision`、最新任务序号。 |

各视口独立保存 TAA 历史、随机采样序列、累积次数和降采样状态，不能混用另一个相机的历史图像。
像素数、通道数和行跨度的乘法必须检查溢出。超预算时拒绝新目标，或按插件预先允许的策略降低预览质量。
GPU 时间预算是调度目标，不承诺抢占已经提交给驱动的工作。可分片任务需在分片边界响应取消。
隐藏窗口停止新增预览任务，保留最后一张图像。导出任务的执行不依赖窗口是否可见。

## 多时间采样与洋葱皮

洋葱皮由插件决定采样间隔、过去和未来的数量、着色、透明度、轮廓、过滤及交互。宿主提供冻结来源、独立求值、帧租约和辅助绘制。
例如插件以当前已提交时间为基准采样前后各三帧，过去显示蓝色、未来显示红色；这只是插件配置，宿主不固定数量、色彩或每秒 30 帧。
插件也可以只显示选中的骨骼、某个物体的轮廓、手部局部轨迹，或用不同渲染器比较动作。输出过滤与求值依赖分开：隐藏身体的显示不允许跳过手部姿态依赖的父骨骼和约束。

### 时间与请求结构

`MmsTime` 统一表示以秒为单位的有理数。分母必须非零，输入先规约并检查运算溢出。帧数到时间的换算使用来源明确的帧率；现有工程读取路径的 30 fps 限制不扩散成新协议的固定时间基准。
请求使用显式时间列表。SDK 可按 `baseTime + offset` 生成列表，但底层不读取正在变化的全局播放头来补齐缺失值。
来源记录明确采用已提交工程、冻结编辑候选，还是插件私有数据。当前尚未提交的编辑姿态只有通过专门的冻结候选能力才能参与，不能直接借用主模型的可变数组。
超出动画或物理可采样范围时返回逐样本状态。是否夹取到边界、循环、跳过或保留空样本，由插件显式选择，宿主不静默改时间。

以下为建议结构，尚未加入 SDK：

```c
typedef struct MmsSampleTimeV1 {
	MmsHeader h;
	uint64_t sampleId;
	MmsTime time;
} MmsSampleTimeV1;

typedef struct MmsSampleRequestV1 {
	MmsHeader h;
	MmsHandle source, evaluation;
	uint64_t expectedSourceRevision;
	MmsSpan times;
	MmsHandle objectSelection;
	uint64_t channels;
	uint32_t stage, physicsPolicy;
	MmsHandle physicsState;
	uint32_t priority, flags;
	uint64_t maximumBytes;
} MmsSampleRequestV1;
```

`times` 的元素为 `MmsSampleTimeV1`。`sampleId` 由请求方在一次请求内唯一分配，用于对应结果，不能当作帧句柄。宿主可去重相同时间的计算，但保持每个样本的结果映射。
`objectSelection` 是冻结的对象或子元素选择租约，不读取任务完成时的当前选择；零句柄表示全对象。阶段、通道和物理策略均需查询能力。
`physicsState` 引用已校验的缓存、烘焙或独立模拟描述，不能填主世界指针。`maximumBytes` 是调用方愿意使用的上限，宿主全局预算仍有约束力。
`requestSamples` 返回作业句柄，全部输出是冻结帧租约。请求结构整体无效时不排队；有效请求中的个别样本失败时保留明确状态，由插件决定显示部分结果或等待完整集合。
同一个样本只有完整帧才能发布。渐进预览允许逐个发布完成样本，不允许把半更新的骨骼与旧网格混合成一个成功帧。

### 历史物理的支持范围

绑定、动画和物理后结果是不同能力。时间可以随机查询不等于物理可以随机跳到任意时刻。

| 物理策略 | 可支持的结果与拒绝条件 |
| --- | --- |
| `NO_PHYSICS` | 独立求值动画、Morph 和受支持约束；明确标记未含物理，不能冒充最终运动。 |
| `CACHED_STATE` | 读取同来源修订、求值器版本与模拟参数下已经保留的历史状态；没有该时间或合法插值策略时返回 `NOT_READY`。 |
| `BAKED_STATE` | 读取冻结烘焙或几何缓存；注明采样步长、插值和所包含的通道，超范围或拓扑不匹配时拒绝。 |
| `INDEPENDENT_SIMULATION` | 从明确初态或检查点构造私有物理世界，以声明步长推进到目标时间；不复制未声明可克隆的外部插件状态。 |

历史缓存只覆盖实际保存的范围。未来采样不能凭过去缓存凭空生成结果，须有烘焙数据或独立模拟能力。
独立模拟把时间排序后前向推进，并保留所需结果；回到更早时间要恢复私有检查点或重建实例，不能把运行中的主世界倒退。
模拟描述记录起始时间、初态、固定步长、子步数、重力、碰撞配置、求解器版本、随机种子及外部输入。不能克隆的效果、求值插件或不可重现外部状态返回 `UNSUPPORTED`。
同参数重算的可重复程度由具体求值器报告，不承诺跨 CPU、GPU 或求解器版本逐位相同。缓存带这些能力和版本标签，不能只按帧号复用。
物理不可用时插件可以明确选择不含物理的洋葱皮或显示缺失提示，宿主不能悄悄切换策略。

### 缓存、取消与显示

求值缓存键至少包含来源身份及内容修订、结构和资源修订、精确有理时间、阶段、通道、求值器版本、物理策略与状态描述。对象过滤还须覆盖所有依赖，或在完整帧后再过滤。
渲染缓存另加入相机修订、渲染器及 profile、输出尺寸、颜色规则和设备代次。改变洋葱皮颜色只重做辅助合成，不必重新求值动作。
插件拖动播放头或调整采样数量时，递增自己的请求代次并取消旧作业。旧结果可以释放或留作带修订缓存，不能覆盖新配置的幽灵图像。
作业设置样本数、并发数、CPU 内存、图像及模拟步数上限。超预算时返回诊断；只有插件预先允许时才降低采样数量或分辨率。
任务取消在求值或模拟分片边界生效。晚到结果仍释放租约，正在执行的插件代码不能被强制终止。隐藏面板暂停新预览请求，持有结果计入预算。

插件通过共享相机的视口图像、骨骼线段或空间轨迹组成辅助层。描边可来自渲染器能力，也可来自 CPU 骨骼或几何信息，不能把任意渲染器都当作支持轮廓输出。
多时间深度合成须声明各样本与当前帧的遮挡规则。只提供颜色的图像只能按二维顺序叠加，不能声称具备正确的空间遮挡。
洋葱皮默认属于 `PREVIEW_AUXILIARY`，不写工程，不进入导出，也不改变选中对象的真实姿态。导出洋葱皮须另作显式输出任务。
若插件提供点击幽灵切换到相应时间的功能，该点击产生独立的用户命令；采样完成事件本身不移动播放头。
不得通过轮流 seek 主工程、截图再恢复来实现本接口。即使最终播放头位置相同，期间的物理、姿态、效果或历史副作用也不满足隔离要求。

## 渲染器提供者

下列提供者是接口能够承载的示例，均不是本次交付承诺。

| 提供者示例 | 输入与输出约束 |
| --- | --- |
| 原生 toon | 用 MMS 材质、toon 与描边语义生成预览。首期适配需明确与既有效果路径的差异。 |
| PBR | 声明所需法线、切线、环境贴图和材质映射。PMX 材质没有的参数来自独立 profile。 |
| 线框与调试 | 可输出拓扑、法线、骨骼或刚体诊断画面，并声明是否提供精确 ID 通道。 |
| 渐进离线预览 | 固定输入修订，按 tile 或样本批次发布完整可显示结果，返回样本数和收敛信息。 |
| 外部引擎 | 从标准帧与资源租约构建自己的场景，不读取 MMS 内存布局或假定 EXE 文件名。 |

非重入提供者按会话串行调度。可并发提供者也不得共享可变渲染状态，除非自身完成同步。

## 图像租约与资源读取

建议 `MmsRenderImageV1` 描述颜色主平面，以及可选深度平面和对象 ID 平面。
图像描述至少包含以下信息。

| 字段组 | 必须明确的内容 |
| --- | --- |
| 身份 | 图像句柄、场景身份、输入帧修订、视口代次、相机修订、任务序号。 |
| 尺寸与格式 | 宽、高、有效矩形、平面数、格式、字节数、行跨度、原点与行方向。 |
| 颜色 | 色域、传递函数、HDR 范围、是否已经色调映射。不能仅以一个「线性」标志代替完整约定。 |
| Alpha | 不透明、直通或预乘，以及预乘发生的颜色空间。合成器按声明转换。 |
| 深度 | 可空，声明数值类型、单位、近远平面、正反向深度和无效像素值。 |
| 对象 ID | 可空，整数像素索引指向同租约持有的 `MmsObjectRef` 映射，不能编码原生指针。 |
| 完成信息 | 完整或渐进结果、累积样本数、质量等级、可选错误说明。 |

默认可互通路径是 CPU 可读颜色平面。提供者内部可以用 GPU，再异步完成读回。
`mapRead` 只映射已完成的平面。尚在传输时返回 `NOT_READY`，不能在 UI 线程等待 GPU 完成。
映射数据在匹配的 `unmap` 前有效，图像在最后一个 `release` 后回收。不能向消费者交付仍在被写入的累积缓冲区。
纹理资源也需要内容租约。当前 `MmsTextureV1` 只有路径和描述，不足以保证后台任务读取的纹理与输入修订一致。
拟新增的资源读取入口需保留解码像素或不可变文件内容，并分别声明缺失纹理与读取失败。

`queryInterop` 是可选加速入口，描述后端、设备标识、设备代次、线程要求和同步协议。
DX9 纹理访问只能在双方确认同一兼容设备及同步方式后使用，不能把任意 COM 指针交给另一驱动后端。
无法互操作时走 CPU 图像复制，不能因此要求 DX12、CUDA、NVIDIA 或新系统 API。
CPU 图像复制只解决传输和界面合成，不代表 MMS 承诺提供 CPU 软件 3D 渲染器。

## 多窗口、画布与输入

同一视口图像可以挂载到插件子窗口、浮动窗口或 UI 画布。窗口管理与渲染会话分离。
窗口尺寸采用逻辑单位，渲染目标采用物理像素。DPI 变化生成新的尺寸修订，旧任务不得覆盖新尺寸图像。
Win7 路径用现有窗口与 GDI 能力完成基本呈现。较新系统的 DPI 或合成接口只作为可查询的增强能力。
画布按裁剪、变换、Alpha 和颜色空间合成图像，标注及过渡动画使用 UI 呈现服务。
视口输入先经过画布逆变换，再换算到实际图像矩形。黑边、裁剪和渲染比例不能改变命中坐标语义。
每个视口保存自己的悬停对象、操作相机和输入捕获。插件可选择把命中结果交给宿主选择命令，但不能自动改主选择。

`requestPick` 必须指定图像租约、像素坐标和目标类别，返回对象身份、子元素身份、深度或世界坐标。
ID 通道不可用时，可按同一冻结帧进行 CPU 射线查询；没有可用几何时返回不支持，不能使用另一帧代替。
异步命中结果应用前再次验证场景与对象代次。对象已删除或图像已经被替换时，由调用者决定忽略或重发请求。
相机联动、视口拆分、拖拽比较条和多个窗口同步属于插件行为，不需要另建一套输入或对象身份系统。

## 调度、线程与销毁

创建视口、修改配置和挂载窗口限定在 UI 线程。冻结后的帧与资源允许任务线程只读访问。
后台任务不能调用主工程的 seek、物理步进、选择、控件更新或修改历史。独立评估只写实例自己的状态。
DX9 设备操作继续服从设备所属线程。工作线程可以准备 CPU 数据，不能把「后台任务」等同于任意线程调用驱动。
任务状态为排队、运行、完成、取消或失败。事件通过宿主队列交付，绘制和资源释放过程中不重入插件业务回调。
多个视口请求同一帧时可合并求值。只有输入帧、相机、profile、尺寸和设备代次均相同，才可共享渲染结果。
后台完成结果必须验证视口代次与请求修订。已过期结果可以回收，不能覆盖更新后的视口。

关闭视口先禁止新任务，再取消待执行任务并解除 UI 挂载。已被消费者持有的图像按租约继续保留。
插件停止时，宿主撤销注册并等待仍会调用该插件代码的任务和租约结束，再卸载 DLL。
取消是请求，不是强制终止线程。超时任务不能阻塞 UI，也不能让宿主卸载仍在执行的 DLL。
设备丢失使相关原生访问令牌失效，并取消对应 GPU 工作；已经完成的 CPU 图像副本可继续显示。
设备恢复后使用新代次重建资源。CPU 映射不因设备重置变成悬空指针，旧原生句柄不得跨代次使用。
租约可从其他线程释放，但实际驱动对象释放排队到其所属线程，预算直到完成释放才归还。

## 导出与便利 SDK

预览图像、UI 装饰和导出输出分别管理。面板动画、比较条、桌宠、操作手柄与宿主按钮不进入视频或图片导出。
需要导出的场景标注必须作为显式的导出内容声明，不能通过截取整个编辑器窗口实现。
导出另建带确定时间、相机、尺寸、颜色与 Alpha 约定的任务，不继承预览降采样或窗口 DPI。
已有 `RenderFrameSceneForOutput` 的同时间多次抗锯齿采样约束需要保留，不能把采样次数当作物理步进次数。

便利 SDK 可提供 `ViewportSpec`、`RenderProfile` 和 RAII 租约包装，默认完成请求合并、窗口适配与旧图像保留。
这些包装调用同一 C ABI，返回同一 `view`、`evaluation`、`image` 和 `job` 句柄，不维护平行注册表。
复杂插件可以解除默认刷新和相机控制，保留底层视口，改用自有调度、输入、合成和渐进显示策略。
句柄借用与所有权移交必须分开。包装析构不应销毁已经转交给其他消费者的资源。
快捷创建不隐式启动独立物理或导入工程；描述必须区分共享活动帧与独立实例，资源费用也分别可见。
`OnionSkinSpec` 只组合时间列表、求值请求、视口和辅助层。插件可以取出相同 sample job、帧租约和 layer 句柄，改成局部轨迹或其他显示规则；不维护专用的第二套洋葱皮求值器。

## 实施边界与验收

第一阶段先补真实求值边界的只读帧与资源租约，再实现同帧、同后端的多个相机视口。
第二阶段加入提供者注册、图像传输和命中接口，验证不同渲染器并排输出。
独立时间与独立工程需要完成求值上下文隔离后再开放；此前请求必须明确拒绝，不能暂改主工程再恢复。
既有 `RenderFrameScene` 需要拆出只消费帧数据的绘制入口，并把相机、抗锯齿、阴影和目标缓存归到视口或会话。
原始 profile 保留现有入口。Win7 SP1 x64、CPU 求值及 AMD 兼容不得依赖可选加速后端才能成立。

验收覆盖同帧四视口只推进一次物理、不同相机历史隔离、独立时间不改变主工程，以及项目关闭时仍持有租约的读取。
还需覆盖设备丢失、跨 DPI 窗口、尺寸快速变化、迟到任务、插件停止、取消、内存不足和算术溢出。
洋葱皮先验收无物理的多时间姿态，再分别验收缓存、烘焙和独立模拟。过去、未来、乱序及重复时间测试均核对主播放头、主物理状态、编辑姿态、工程修订和历史不变。
选择骨骼局部轨迹仍须正确求值依赖；快速拖动、来源修改、插件关闭和样本超预算时，旧结果不得覆盖新配置。未实现的物理策略必须返回拒绝，不能自动忽略物理。
导出验收比较有无 UI 插件时的场景输出，并确认 CPU 图像回退不改变颜色、Alpha 和命中坐标。
接口测试与编译通过不能替代 Win7、AMD 和具体渲染器的实际验收；未具备环境的项目继续标为未验证。
