# 插件扩展统一架构方案

本文是 UI、交互、视口、数据格式和编辑工具的设计约定。基础 C++17 UI 包装、声明式 INPUT、工具栏及属性扩展行、SELF／注册 SUBTREE 刷新、按钮及 INPUT STATE 已实现，其余新增能力按表中状态区分。INPUT 编辑仅在受控共同历史宿主启用，普通启动仍为只读。当前可用接口以 [SDK README](../sdk/mms/README.md) 和[实施记录](PLUGIN_ABI_IMPLEMENTATION.md)为准。
现有 `MmsHostV1`、各 V1 函数表和已发布结构保持兼容。本文不开放普通宿主的 `mms.edit`，也不把内部 C++ 计划器视为公共编辑接口。

基础 UI 的类型化及声明式包装见 [C++17 界面注册 SDK](../sdk/mms/cpp-ui.md)。`UiServices`、`RegistrationBundle`、`CommandUi` 及 [INPUT 包装](../sdk/mms/input.md)均组合已有 C 服务。原元素 handle 可直接用于[界面重绘服务](../sdk/mms/refresh.md)，按钮及 INPUT 共用[状态内容服务](../sdk/mms/state-content.md)。来源自动订阅、绘制层和工具封装仍为后续设计。

[C++17 重绘 SDK](../sdk/mms/cpp-refresh.md)继续包装相同目标和票据，提供整目标、局部矩形、移动所有权与失败重试清理。后台请求与低层 C 使用同一服务 context，不创建独立队列。

## 一套 C ABI，多层 SDK

分层封装是本方案的主要约束。简单插件和完整编辑器操作同一批宿主对象。SDK 不建立另一套控件树、事件队列、场景身份或撤销系统。

| 层级 | 开发者处理的内容 | 对底层的关系 |
| --- | --- | --- |
| 稳定 C ABI | 服务查询、函数表、句柄、快照、事务、任务与能力 | 唯一的运行时协议；宿主维护对象与规则。 |
| 类型化 SDK | C 辅助函数、C++ 类型检查和 RAII 租约、错误处理 | 调用 C ABI；每个引用可取得同一底层句柄，借用与所有权移交分开。 |
| 声明式 SDK | 命令、菜单、按钮、属性、面板、视口及格式声明 | 组合类型化包装；默认排版、刷新和清理由同一宿主服务完成。 |
| 工具 SDK | 洋葱皮、权重笔刷、UV 工作区、重定向向导等可选组件 | 组合前述对象；可替换默认行为，不能调用未公开的宿主指针。 |

这些是开发便利程度，不是四个 ABI 版本。不同语言的 SDK 可有独立发布版本，但须声明所需服务和版本。不能通过更换 SDK 绕过宿主能力检查。

当前 `RegistrationBundle` 保存命令、元素、属性和 surface 工厂的原始注册引用，`CommandUi` 组合菜单、按钮、工具栏分组及默认布局提示。底层没有 `RegistrationBundle` 专属对象类型；该包装只记录本次创建的句柄和所有权。
后续服务接入后，包装可继续包含订阅及默认行为的引用。复杂插件可停止包装创建的默认刷新订阅，保留元素句柄，再为相同元素添加输入区域、呈现会话或自定义绘制层。该扩展应避免注销重建元素；当前 SDK 尚无这类订阅、输入和呈现能力。
`detach` 明确移交某个引用的所有权。普通 `get` 只借用引用，调用者不能重复销毁。SDK 析构和宿主插件停止清理均须支持重复释放的检测，不能假定析构一定先执行。

以下为流程说明，不是当前可编译接口：

```cpp
auto tool = sdk.registerCommandAndButton(spec);
auto button = tool.element();          // 借用同一个底层元素
auto command = tool.command();
tool.defaultRefresh().stop();          // 只移除便利层建立的默认行为
auto layer = paint.createLayer(button, layerSpec);
auto event = events.subscribe(topic, [=] { updateLayer(layer); });
```

`registerCommandAndButton` 组合 `mms.ui.registerCommand`、`registerElement`、布局提示及刷新绑定。复杂用法仍通过该 `command` 执行业务，不建立第二个按钮状态。
局部注册失败时逆序注销已经创建的项目。若需要保证多个新元素从未短暂显示，须由底层增加原子注册批次能力；现有逐项注册加清理不能承诺这个效果。

## 服务职责

服务按对象职责划分。一个服务可以有独立版本，但所有服务共用插件身份、句柄校验、租约计量和停止过程。

| 服务组 | 职责与状态 | 详细方案 |
| --- | --- | --- |
| `mms.ui`、`mms.ui.surface`、`mms.ui.layout` | 已有注册、挂载、属性和部分布局能力。工具栏及 `mms.properties.main.extensions` 支持原 BUTTON、GROUP、SEPARATOR、INPUT，共用注册身份、布局和刷新队列；普通 INPUT 只读。`MMS_UI_OVERFLOW_MENU=3` 及 keepTogether 命令折叠仍仅支持原工具栏。DOCK、侧栏、时间线、状态栏挂载及面板内折叠未开放。 | [UI 呈现](PLUGIN_UI_PRESENTATION.md)、[属性扩展行](records/abi-property-mount-2026-10-21.md)、[INPUT SDK](../sdk/mms/input.md)、[溢出 SDK](../sdk/mms/cpp-ui.md#工具栏命令溢出) |
| `mms.ui.refresh`、`mms.ui.refresh.bind`、`mms.ui.refresh.state` 1.0 | 已有 SELF／注册 SUBTREE 的 REPAINT、按钮及 INPUT STATE、绑定 DATA、未绑定 INPUT 的属性 DATA，以及保留布局 LAYOUT，复用同一对象、队列和票据。原内容提供者准备文案、说明及禁用原因，INPUT 可进一步收紧启用、只读和可见状态；DEPENDENTS 和来源自动订阅仍待实现。 | [刷新接口参考](../sdk/mms/refresh.md)、[状态内容](../sdk/mms/state-content.md) |
| `mms.events`、`mms.tasks` | 提案：主题订阅、受预算约束的工作任务。 | 本文及 UI 呈现 |
| `mms.ui.geometry`、`style`、`paint`、`presentation`、`input`、`overlay`、`layout.session` | 提案：坐标、样式、辅助绘制、临时外观、输入和可撤回布局。 | UI 呈现 |
| `mms.scene`、`mms.storage` | 已有绑定快照和插件工程序列化；不提供任意时间求值或模型拓扑写入。 | SDK 参考 |
| `mms.scene.evaluate`、`mms.scene.clock`、`mms.render.*` | 提案：场景来源、独立求值、时钟、相机、渲染器及图像。 | [视口与洋葱皮](PLUGIN_VIEWPORT_RENDERING.md) |
| `mms.data.schema`、`mms.data.read`、`mms.data.edit`、`mms.resources` | 提案：公共数据、私有结构、不可变资源和原子编辑候选。 | [数据扩展](PLUGIN_DATA_EXTENSIONS.md) |
| `mms.format`、`mms.tools`、`mms.selection` | 提案：格式提供者、专用工具、具版本的选择集合。 | 数据扩展 |
| `mms.edit` | 已有协议和受控宿主验证；普通宿主仍关闭。所有新工程写入最终使用同一历史。 | [编辑事务参考](../sdk/mms/edit.md) |

表中的简称 `style`、`paint` 等均保留 `mms.ui.` 前缀，不是另一组服务。`mms.render.*` 的具体服务名见视口文档。
现有 `registerProvider` 只接入 `mms.serializer`。格式、渲染及其他提供者需要逐项扩展白名单、能力查询和生命周期，不能仅凭函数名视为可用。

工具栏溢出组合原布局树、元素 handle、按钮 HWND 和命令，不新增注册身份。空间恢复后同一按钮返回工具栏。菜单沿用原状态和调用检查，已打开的项目可更新或移除，卸载不会保留可调用的旧项目。该能力仅覆盖 `mms.toolbar.main.extensions` 及其 GROUP，不提供任意位置自动迁移、面板折叠或通用菜单状态内容服务。状态：**本机已验证**（完整配置 21／21、原始兼容配置 18／18、ABI 契约重复 6／6）。实现及验收证据见 [UI 框架记录](records/abi-ui-framework-2026-10-19.md)。

属性扩展行是同一注册树的另一个真实挂载根，不增加服务版本或对象类型。默认声明和低层 C 调用都将 `parentId` 指向该根，刷新仍按目标能力提交 DATA、STATE、LAYOUT、REPAINT。无内容时高度为 0；有内容时，停靠视口及其覆盖区一同避让。跨根移动保留元素和属性身份，但重建原生视图并取消草稿。双配置挂载专项各 681 项、完整 ABI 契约各 17,565 项通过，范围见[记录](records/abi-property-mount-2026-10-21.md)。这不开放任意本体控件查询、多视口或普通编辑服务。

## 对象身份与权限

持久身份与运行时句柄分开。工程对象以工程 ID、对象 ID、子元素 ID 寻址，运行时引用另带 generation。UI 使用稳定注册字符串和宿主不透明 ID，具体实例另带 generation。
后续通用对象服务应区分描述更新与实例重建。当前刷新目标直接使用原元素 handle，并分别携带 `instanceGeneration`、`projectEpoch` 和实际 `geometryRevision`。注销、视图重建或显式失效后重新发布改变实例代次；普通移动保持实例代次。工程替换或重置使旧 epoch 失效。旧快照继续可读，旧写引用返回 `STALE`。
各服务不自行发明跨服务可互换的整数句柄。宿主统一校验类型、owner、代次和能力，图像句柄不能被当作数据对象或 UI 元素。

插件只能修改自己的对象和宿主明确开放的目标。跨插件访问须有目标提供者公开的读取或修改能力。知道 ID 不授予覆盖控件、修改工程或操作其他应用的权限。
能力分为宿主是否实现、目标是否支持、当前上下文是否允许三项。SDK 必须全部检查；静态清单不是运行期授权凭证。
原生 DLL 在宿主进程内运行。接口检查防止错误调用，不构成恶意插件沙箱，也不能隔离插件崩溃。

## 版本、内存和错误

新增服务首版建议为独立 1.0 函数表。结构沿用 `MmsHeader`、固定宽度整数、`MMS_CALL`、8 字节对齐和明确的 reserved 字段。
函数表只在尾部追加兼容字段。破坏语义或布局的改动使用新 major，不能修改旧字段含义。读取调用方提供的 size 前缀，未知必需能力返回 `UNSUPPORTED`，未知 flags 和非法输入返回 `ARGUMENT`。
除已链接 SDK 头文件中的接口外，下文新增结构和函数名均为建议名称。实现时必须同时提供 C11、C++17 布局断言和小容量输出检查，文档中的伪声明不能充当已发布头文件。

字符串为带字节数的 UTF-8，不隐含结尾零。可变数组声明数量、stride 和记录版本，校验加法与乘法溢出。浮点数据显式检查有限值和单位。
描述在成功调用时复制，回调输入仅在调用期间借用。长期读取使用租约；释放方与分配方一致，不跨 DLL 传 STL、异常或 CRT 所有权。
异步作业保留不可变输入、资源和回调所属 DLL。宿主复制出来的纯数据租约可不再依赖 DLL；仍需执行提供者释放函数的租约必须保留提供者。
失败不修改已有可见内容和普通输出参数。需要在失败后查询诊断时，诊断对象须在提交前创建，或通过明确的作业状态入口读取，不能暗中把错误码与部分成功混用。

| 错误 | 处理语义 |
| --- | --- |
| `NOT_FOUND` | 服务、注册对象或格式未提供。 |
| `UNSUPPORTED` | 已知服务缺少所请求能力；不能假装完成。 |
| `NOT_READY` | 数据或阶段尚未完成，或者服务正在停止。 |
| `STALE` | 工程、对象、资源或依赖修订不再匹配；重新读取后决定是否重算。 |
| `CONFLICT` | 事务基线变化、对象被占用或要求互相冲突。 |
| `BUSY` | 当前回调阶段、队列容量或操作状态不接受此调用。 |
| `THREAD` | 在未允许的线程调用。 |
| `MEMORY` | 输入或保留资源超过可用预算；正式状态不变。 |
| `CANCELLED`、`FAILED` | 作业取消或执行失败；完整诊断由作业记录提供。 |

## 线程、任务与刷新

注册、UI 对象修改和工程提交在 UI 安全点执行。冻结快照和宿主资源租约允许后台只读访问。图形设备操作服从后端线程约束，不因任务位于工作线程而自动获得设备访问权。
提案 `mms.tasks` 提供 `submit(desc, outJob)`、`query(job, outState)`、`cancel(job)` 和 `release(job)`。描述包含插件任务函数、context、输入租约、任务类别、取消检查点和资源上限。
回调 `run(context, cancellationToken)` 仅计算私有候选；其 UI 完成通知经已有安全队列交付。完成、取消、失败恰好有一个终态，晚到结果不得写入重建后的目标。
队列满时返回 `BUSY`，不无限保存任务和 context。CPU 时间预算用于公平调度及合作式分片，不能强行打断任意进程内插件代码。停止期间拒绝新任务，未结束的回调使插件保持 `BUSY`。

插件自建线程也必须使用宿主规定的停止和租约规则。SDK 不为一个普通菜单注册偷偷启动线程。
后台结果带工程身份、来源修订、任务代次及目标代次。结果只能在匹配的上下文发布。当前工程变化时可以丢弃或重新计算，不能将旧结果应用到同名新对象。

`mms.ui.refresh` 支持本插件目标的 REPAINT、按钮部分 STATE、绑定目标的 DATA 和保留布局的 SELF LAYOUT。UI 线程查询能力和目标，工作线程提交和管理同一票据。STATE 只读查询目标命令及可选内容提供者；纯 LAYOUT 使用缓存状态和已发布文案。单独显隐需要有效的 PRESERVE_HIDDEN_SLOT 正尺寸槽位；STATE 与 LAYOUT 组合支持收缩空位及同引用恢复。局部 DIP 矩形须带几何修订，布局失败保持未就绪，实际几何不变时保留修订。
票据的取消与释放分开，未释放引用阻止卸载。具体配额及错误见[刷新接口参考](../sdk/mms/refresh.md)。更多控件的完整 STATE、自动订阅、SUBTREE、DEPENDENTS 及插件量测提供者仍待实现，不能用一次 REPAINT 代替。
持续动画使用单次帧请求按时间推进。数据变化通过刷新请求传播，不能在 paint 回调中反复发事件、重新读取文件或提交事务。

## 同一套接口支持不同工具

| 插件 | 声明层处理 | 扩展到复杂行为时继续操作的对象 |
| --- | --- | --- |
| 分析按钮 | 命令、标签、启用条件、菜单及工具栏位置 | 同一命令和元素的状态、刷新绑定、结果面板。 |
| 属性面板 | 属性类型、范围、分组和布局偏好 | 同一属性 ID、编辑事务和 UI 元素；增加自绘操纵器。 |
| 洋葱皮 | 多时间预览配置和辅助层挂载 | 相同求值实例、帧租约、视口和选择集合；插件决定采样规则。 |
| 格式导入器 | 格式声明及读取、写入回调 | 同一候选文档、资源租约和格式 ID；增加 UV、权重或专用编辑器。 |
| 多机位工作区 | 视口声明和默认相机操作 | 同一相机、帧、图像及 UI 目标；改为自有合成和输入逻辑。 |

MMS 默认只提供即时响应的界面。复杂动画、皮肤、桌宠、无限画布和多窗口工作区由插件启用。插件关闭后，临时外观和临时布局撤回，工程数据只受已提交编辑事务影响。
界面装饰、编辑预览辅助层和最终导出内容分别声明。工具手柄、洋葱皮和桌宠默认不进入成片；导出参与须单独注册并明确支持的场景与格式。

## 实施依赖与验收

各阶段按能力开放，未完成的服务或目标继续返回明确错误。不能通过便利 SDK 提前暴露未就绪的底层能力。

| 阶段 | 前置条件和交付范围 | 必须验证的行为 |
| --- | --- | --- |
| 公共契约 | 实例身份、修订、预算和停止过程；保留现有 ABI | 旧插件加载、EXE 改名、错误代次与类型拒绝、未释放租约阻止 DLL 卸载。 |
| UI 刷新与声明封装 | 已有声明式注册及 REPAINT + SELF；后续为原生实时拖拽和依赖刷新 | 当前验证目标为跨线程票据、几何及实例过期、取消与释放、局部重绘不求值场景或写历史；依赖循环在后续扩展中验证。 |
| 样式与交互 | 目标几何、输入、CPU 绘制、临时呈现 | 后台触发另一控件；拖拽抢占；关闭插件撤回临时布局；无残影。 |
| 公共数据编辑 | 原生写入完整接入共同历史，候选和资源保留 | 混合导入、改网格、删材质及私有数据一并撤销；任一准备失败零发布。 |
| 格式与专用工具 | schema、格式诊断、选择和操纵器 | 缺失插件保存后仍保留未知数据；拓扑变化产生有效 remap；导出按具体损失方案执行。 |
| 多视口与多时间 | 冻结求值结果、渲染器状态隔离、独立求值 | 同帧多相机不重复推进物理；过去与未来采样不动主状态；取消和设备丢失安全。 |

格式读取可先发布为只读候选查看。没有公共写入和完整历史时，不能宣称已提供可编辑模型导入。
静态接口、进程内契约、真实宿主行为和硬件验收分开记录。Win7 SP1 x64、CPU 基础路径及 AMD 继续作为发布约束；缺少真机时明确保留未验收项。
基础能力不要求 DX12、CUDA、NVAPI、AVX2 或新系统接口。CPU 基础路径包括数据处理、动画求值、二维绘制与可互通的图像读取，不等于承诺所有三维渲染器都支持 CPU 软件光栅化。
