# 编辑事务内核与原生撤销接入

`src/plugins/edit_store.cpp` 已实现 `edit.h` 对应的两阶段事务内核。`src/plugins/shared_history.cpp` 实现原生与插件共用的历史队列，`src/plugins/scene_object_history.cpp` 提供模型及附件资源的保留与恢复。部分姿态命令、骨骼登记、删键、范围缩放、插值按钮、对象删除与私有导入已在显式绑定下接入并通过本机验证。隔离隐藏宿主可显式启用 `mms.edit`，用于验证真实插件与原生命令交错撤销。普通宿主尚未整体切换，查询该服务仍返回 NOT_FOUND，可写 UI 属性仍返回 NOT_READY。

## 共同历史的范围

共同历史按提交顺序记录跨模型编辑、模型及附件导入、对象删除和插件工程编辑。当前选中的模型不参与历史节点选择。删除对象本身是一条可撤销记录，不清空该对象先前的编辑历史。

导入节点须持有完整对象及其资源。撤销导入后，对象退出活跃场景；重做从历史保留的数据恢复，不重新读取源路径。删除节点须保留对象、动作键、未注册姿势、曲线侧表、物理及渲染恢复数据，并保存受影响的相机、附件、其他模型绑定和显示顺序。只有节点被截断、超出历史预算或工程关闭，且没有其他所有者时，才释放保留资源。

对象 ID 在撤销删除后保持不变，运行时代次重新分配。删除前取得的引用不能直接用于恢复后的对象；插件须重新获取场景快照。仍持有的旧快照继续只读。历史实现按稳定 ID 保留资源，不能仅依赖槽位或内存地址。

插件作者通过事务边界决定撤销粒度。多步算法先在私有候选中完成计算，再提交一个事务，用户只需撤销一次。需要逐步撤销时，每一步分别 begin、prepare、commit。多次已完成的提交不会事后合并，也不能跨越其他编辑合并。取消只丢弃当前未提交事务，不隐式撤销前面已经提交的步骤。公共接口规范见 [SDK 编辑事务参考](../sdk/mms/edit.md)。

## 共同历史内核

`SharedHistory` 实现 `EditHost`，原生操作和插件事务写入同一组 undo/redo 节点。每个节点包含标签、插件 before/after 字节及可选的 `HistoryChange`。原生服务可用内部 `EditStore::JoinNative` 将一个聚合候选加入已有插件事务；这个 C++ 指针不进入插件 ABI。

`HistoryChange::Prepare(direction)` 返回 `PreparedHistoryChange`。候选须只分配和验证；`IsCurrent` 在发布前再次核对来源；`Publish` 不得分配、抛异常、运行插件或进入消息循环。一次操作涉及多个原生对象时，由聚合候选统一准备和发布。历史撤销先准备原生候选和所有 serializer，再检查原生来源，全部成功后发布并移动节点。

历史节点在 prepare 时分配，publish 通过链表 splice 追加或移动。重做分支截断、旧节点淘汰只移入待回收队列；`Collect` 在宿主安全空闲点释放资源，避免在原子发布阶段析构模型、纹理或 Bullet 对象。当前默认最多 128 条、256 MiB 保留数据预算，内部构造参数可调整。原生候选须报告实际持有数据的大小；该预算不是进程内存上限，准备和待回收数据也会暂时占用内存。

新提交才截断重做分支。准备失败、取消或陈旧拒绝均保留该分支。Reset 清空历史并递增修订，不重新从 1 开始，使之前准备的事务失效。原生事务由历史登记；Reset 和历史析构会先释放这些事务的候选与资源，调用方遗留的空 token 只能返回 STALE。`EditStore` 必须先于它所引用的历史对象销毁。违规的 void commit 会冻结整个共同历史，包括原生入口，不把半提交状态登记为可撤销结果。

`SceneIdentity::PreparePresence` 已实现可撤销存在状态的身份候选。准备时预留新代次，取消会留下未使用的代次数值；发布只修改该对象的 present 和 generation。多个对象可以一起准备并按任意顺序发布，旧代次不会重新生效。

### 已执行原生修改的采用协议

同步数字编辑不能先改姿态，再尝试分配历史节点。内部 `AppliedTransaction` 把这个流程分为三步：

| 调用 | 调用时机和保证 |
| --- | --- |
| `ReserveAppliedNative(label, maximumNativeBytes, token)` | 修改前调用。预分配节点，检查记录上界，并保持共同历史的排他锁。存在未结束的插件事务时返回 BUSY。 |
| `PrepareAppliedNative(token, change)` | 原生修改完成后调用。检查实际记录大小不超过预留上界，准备反向候选，验证当前确实处于修改后状态。此步可以分配，不执行反向修改。 |
| `CommitAppliedNative(token)` | 再次检查候选和记录大小，只把节点加入历史，不重放修改。不分配内存，成功后才截断重做分支。 |

token 到析构才解除排他锁，因此提交成功后仍可先清理候选。准备或提交失败时，调用方先用捕获数据回滚姿态，再释放 token；token 本身只取消预留，不负责回滚原生数据。空操作直接取消，不截断重做分支。此范围内不得运行插件、进入消息循环或刷新窗口。场景切换和新的编辑操作均被历史锁拒绝。

这套接口是宿主内部的 C++ 协议，不改变插件 `edit.h`。记录大小仍是历史保留数据预算，不等于整个进程或模型资源的内存上限。

## 工程切换与关闭

`integration.cpp` 为当前 `MMDApp` 创建一个 `SharedHistory`，与插件管理器共用 `StorageStore`。内部 `NativeHistory(app)` 返回该队列。普通启动不附加编辑服务，隔离探针通过 `InitializeHistoryTestRuntime` 显式附加同一队列。

`PrepareReset` 在插件准备新工程数据前取得排他 token。此时不清历史，取消加载只释放 token。PMM v1、v2 加载器在 `pmm_settings::Reset` 前调用 `BeginProjectSceneReplacement`，提交历史清理并回收退出场景的对象，随后才清身份、曲线、模型和物理资源。token 保持到插件工程提交或取消完成，避免过程中重新写入历史。

`EditStore` 向历史登记自身。只要存在未完成编辑事务，Reset 和 PrepareReset 就返回 BUSY；宿主须先调用 `CancelPending`。该函数按原取消规则释放插件上下文、混合候选和原生资源。取消回调异常会冻结历史并返回 FAILED，不遗留剩余事务。取得工程切换 token 后，新的编辑 begin 也返回 BUSY。

新建工程采用同一顺序，当前宿主拒绝尚未结束的插件编辑，不隐式丢弃事务。关闭时先取消工程准备，停止插件并取消其编辑，再分离 `EditStore`、释放历史和管理器。取消回调异常后允许对已清空的 store 重试分离；只有分离成功才能释放外部 host。仍无法分离时保留相关对象至进程结束。局部调用方持有的 `HistoryChange` 仍须在场景释放前交还。

## 不依赖循环缓存的姿态记录

`native_history::PoseEditCapture` 与 `OwnedPoseEdit` 已实现 type 1 姿态编辑的独立记录。Begin 保存编辑前数据并预分配持久记录容量，`MaximumRetainedBytes` 返回该记录的保留字节上界。Finish 保存前后发生变化的骨骼姿态与缩放差异。记录不依赖原有 30 槽撤销环，后续环覆盖或关键帧池扩容不会破坏已有记录。

Prepare 每次解析当前模型，形成短期 `ModelEdit` 候选。发布保留当前播放头与原有环游标；缩放按变更骨骼合并，不覆盖其他骨骼之后求值得到的缩放。宿主仍须持有原生模型，并在访问前验证稳定身份。

当前仅接受位置、旋转、未注册姿态标记和姿态缩放。其他操作类型与物理开关变化明确拒绝。Finish 分配失败后，捕获对象仍可在同一受控编辑范围内无分配回滚；若物理开关或模型结构已变，回滚完整拒绝。捕获对象不恢复旧环、控件或共同日志元数据，析构也不自动回滚。

`NativePoseScope` 把捕获、预留、采用和失败回滚接在一起。它持有规范的 `RetainedSceneObject`，在访问模型前核对稳定 ID、活动槽位及存在状态。提交失败先回滚，再解除历史锁；若模型身份、结构或物理状态已变化，不能安全回滚时冻结历史并返回 FAILED。模型驻留资源由调用方单独计量，姿态节点只计自身记录及包装开销。

以下生产入口已接入受控路径，由内部 `NativePoseTestBinding` 显式绑定应用和历史。普通宿主未启用此绑定，仍走原路径。

| 入口 | 已接入行为 |
| --- | --- |
| 位置、旋转、缩放数字输入 | 只有 EDIT 修改标志为真才提交，避免重复失焦把显示舍入值记回姿态。无效模型槽、骨骼和非有限数值拒绝修改。 |
| 骨骼重置 `495` | 保存原有根骨骼 X/Z 保留和无父骨骼换算规则，同时记录姿态缩放。 |
| 粘贴 `497`、镜像粘贴 `498` | 按名称匹配，预先计算镜像目标与缩放矩阵；提交成功后才更新骨骼选择与物理重置请求。 |
| 主窗口及浮动窗口的位置、旋转轴复位 | 复用相同事务范围，保留各入口的旋转换算精度。 |
| 缩放轴复位 | 在捕获前计算目标矩阵，覆盖全局、局部和视图坐标；提交时只写姿态数据。 |
| 撤销 `400`、重做 `401`、`Ctrl+Z`、`Ctrl+X` | 按共同历史顺序执行，不依赖当前模型选择或相机模式。文本输入框保留自己的快捷键处理。 |

这些路径不写旧 30 槽环。成功提交后，`PublishBoundPoseEdit` 更新 dirty、历史按钮和读数，不跳帧、不改变全局轨道或附件选择。无匹配、无实际变化及失败都保留重做分支。撤销入口在空历史、BUSY 或准备失败时也不回落旧环，播放和录制期间拒绝执行。

其他姿态写入、其余关键帧操作和全局编辑尚未迁入，不能凭 `NativeHistory(app)` 非空就整体切换旧撤销入口。`mms.edit` 尚未开放。

## 骨骼关键帧迁移顺序

选中骨骼在当前帧的登记已拆出独立计划 `PlanBoneRegistration`，生产按钮 `500` 在显式 `NativePoseTestBinding` 下使用它。范围包含插入、覆写、自动插值、姿态修复、缩放键和三类键选中标记清理。普通宿主尚未启用绑定。物理开关变化、播放、录制及场景变更中明确拒绝；绑定后的相机模式、失败和无变化不回落旧环。

内部接口及职责如下，均不属于已公开的插件 C ABI：

| 组件 | 接口与行为 |
| --- | --- |
| 稳定键池身份 | `BoneKeyPoolIdentity`：扩容保持身份；销毁重建取得新身份；借用池为 0。独立登记当前仅接受自有池。 |
| 可取消扩容 | `BoneKeyPoolGrowth::Prepare/Publish/Rollback/Accept`：Prepare 保持当前分配；Publish 保留旧块；Rollback 恢复指针、容量、访问标记及身份；Accept 才释放旧自有块。候选新块只读，无扩容时的作者数据回滚由调用方负责。 |
| 缩放作者快照 | `bone_scale::AuthoringState`：`Capture/Clone/Equals/RegisterKey`，只保存缩放键及插值曲线；新槽清理残留曲线，覆写保留原曲线。`AuthoringRestore::Prepare` 接收目标容量，准备可取消存储并提供 `IsCurrent/Publish`。不替换姿态或旧环。 |
| 自由曲线作者快照 | `bone_curve::AuthoringState`：`Capture/Clone/Equals/Invalidate`，保存九轨道、切线及原有 `nativeHash`；捕获不触发惰性失效。`AuthoringRestore::Prepare/IsCurrent/Publish` 只交换作者数据，保留旧环。 |
| 登记计划 | `PlanBoneRegistration(app, slot, options, out)`：接受帧号、物理求值模式、自动插值和物理复选框状态。成功且无变化时输出为空；有变化时返回持有模型资源的 `HistoryChange`。 |

计划在私有稀疏视图中计算，记录实际写入的键槽及自动插值邻居、姿态字段差异、选中标记、`maxFrame`、`searchCursor` 和应用的最大登记帧。缩放与自由曲线保存前后作者快照，不依赖 30 槽环。记录按实际保留容量计费，模型驻留资源仍由调用方另行计量。

调用方须在同一串行编辑范围内连续执行计划和首次 `PrepareNative`，期间不得修改作者数据或派发窗口消息。短期候选校验本次指针、容量和源数据；长期记录保存池身份和槽号，后续正常扩容后可重新定位。计划不支持作为可任意延迟提交的编辑任务使用。

完整候选校验成功后，发布依次执行池切换、原生键与姿态写入、缩放交换、自由曲线交换、接受扩容。发布不分配、不调用窗口或物理回调；dirty、按钮、读数与曲线编辑器通知在共同历史提交并解锁后更新。准备失败保持原分配；成功登记之后再撤销只恢复作者数据，保留已扩大的容量。

接下来仍需迁移：

1. 物理开关变化及对应求解器候选，不能在发布中直接调用可能失败的 `NotifyBonePhysicsMode`。
2. 相机、光照、阴影及附件等全局轨道的范围缩放；模型三族范围缩放已合并为一个候选和一个历史节点。
3. 其余登记、插帧、删帧、关键帧复制粘贴及图形曲线编辑入口。模型三族删除、混合范围缩放和插值粘贴／重置按钮已受控接入。表情及显示登记的本批进展见下一节。

## 表情及显示登记

内部绑定下，表情登记按钮 `525`、`524`、`527`、`526` 分别读取第 0、1、2、3 行表情选择，调用 `PlanMorphRegistration`。显示／IK／外亲登记按钮 `438` 调用 `PlanDisplayRegistration`。两个计划均先准备私有键数据、选中标记和帧数元数据，再提交一条共同历史。原生专项 2,118 项及 PMX 原名、PMD 中文改名的真实控件与插件往返已通过；普通宿主尚未切换。

首次登记保存当前状态，不跳帧、不重新求值，也不重置物理。新键按旧登记函数的槽位扫描和链表插入规则生成；已有帧只覆写该帧。成功修改时清除三族原有键选中标记，并选中新登记的键。只有选中标记不同、实际键数据相同的重复登记视为无变化，保持当前标记及 redo。

撤销与重做恢复该记录范围内完整的三族选择状态，包括原先未选中、在撤销后被用户选中的槽位；后续独立扩容增加的尾部槽位不属于该记录。插件事务从 begin 到提交或取消期间，`SharedHistory::PrepareNative`、`CommitNative` 和独立撤销／重做返回 BUSY，保持原历史和 redo。插件自身提交及 `JoinNative` 混合事务仍使用正常的发布协议。被拒绝的 `CommitNative` 消耗传入的原生候选，调用方须在插件事务结束后重新准备。

表情登记保留原始曲线和切线，由目标原生键链参与曲线求值。PMD 的 base 表情不接受登记；PMX 的索引 0 可登记。显示登记直接按 IK 和外亲表的索引保存状态，空名称或重复名称不参与匹配。显示键拥有的 IK 与外亲数组必须随候选完整准备，取消不能释放活动键的数组。

撤销和重做按执行时的播放头重新采样受影响表情，或显示／IK／外亲状态。显示变化只重新求值关联且没有未登记编辑的骨骼，保留其他骨骼、其他表情及播放头。两个登记入口均保持 `searchCursor`；新增键才提升模型 `maxFrame`，提交后按旧规则更新 `lastRegisteredFrame`。

后续仍须迁移关键帧粘贴 `421`、镜像粘贴 `422`、键盘批量登记、VMD 导入、物理烘焙、插帧／删帧、图形曲线编辑及其他直接作者写入。以下全局登记入口也仅在显式绑定下启用，不代表普通宿主已开放编辑服务。

## 相机、灯光、附件及自阴影登记

四个登记按钮通过 `native_global_commands.cpp` 准备并提交一条共同历史。计划成功且输出为空表示无变化；失败和无变化均不回落旧路径，不清选中标记，不截断 redo。

| 入口 | 私有计划及输入 |
| --- | --- |
| 相机 `452` | `PlanCameraRegistration` 保存当前相机位置、旋转、距离、视角、透视与父骨骼。插值复选框决定是否重置已有键的插值字节。 |
| 灯光 `468` | `PlanLightRegistration` 保存当前方向与颜色。 |
| 附件 `487` | `PlanAccessoryRegistration` 接收位置、旋转和缩放七项输入，与目标键同时发布；透明度沿用附件当前值。 |
| 自阴影 `565` | `PlanShadowRegistration` 接收输入框换算后的距离，与当前模式及目标键同时发布。 |

附件和自阴影入口沿用旧控件读取的七字符限制及角度、距离换算，但在任何写入前拒绝非数字和非有限值。输入框解析、键池增长、选择回放及曲线准备失败时，原输入文本和场景数据保持不变。相机、灯光与自阴影在已有后续键时直接覆写第 0 帧根键，避免旧插入路径创建第二个零帧键。

`GlobalKeySelection` 保存四个全局轨道和 255 个附件轨道的键选中标记。成功登记清除捕获容量内的标记并选中目标键，撤销恢复原标记；后来扩容产生的无关尾部由对应操作管理。轨道行选择属于视图状态，仅在首次成功登记后切换。撤销和重做保持用户当前的模式和行选择。

`curve_host::TrackAuthoring` 保留每条记录原始的曲线作者数据。准备方向候选时，从该数据和目标原生键链生成曲线层；发布只交换已分配的节点。正常读取和原生键池扩容不丢失自定义切线，新的曲线编辑或对象身份替换会使不适用的记录失效。

首次登记保存当前姿态，附件七项输入和阴影距离属于本次修改。撤销和重做按当时的播放头局部求值受影响轨道，不跳帧、不重新求值其他模型或附件。无作者曲线时保留旧采样规则，包括附件位置及旋转的阶跃、缩放及透明度的线性变化。父模型和父骨骼引用在准备及发布前校验，记录持有对应对象的稳定身份。

这些记录只计自身数据及曲线存储；驻留模型、附件与渲染资源仍由调用方另行计量。整合后的完整历史 92,245 项检查及 16 组相关 CTest 通过；PMX 原名和 PMD 中文 EXE 的真实控件、真实插件与附件私有导入混合往返均通过。记录见 `build/abi-global-registration-native-final/report.json` 和 `build/abi-global-registration-host-1/report.json`。普通宿主保留旧路径，Win7 与 AMD 真机验收仍未完成。

## 历史发布后的对象列表刷新

`scene_history_ui` 把对象列表刷新与场景求值分开。调用方在一次对象发布前 `CaptureSelection`，发布成功后 `RefreshObjectLists`，并传入共同历史的 undo/redo 可用状态。快照只用于这一次提交，调用方须保持对象存活，不能跨越地址复用。

刷新按原生顺序重建模型、附件、父模型和父骨骼列表；父骨骼项保留真实骨骼编号。选中的模型被删除时回到相机模式，附件被删除时选择剩余列表的第一项。相机模式的注册范围包含四个固定轨道和附件。列表未变时只更新必要的选择，避免重复清空控件。

组件不修改姿态、关键帧、绑定、播放头或场景 dirty，不运行 seek 或模型重新求值。模型模式的注册范围、Morph/IK 子面板、显隐和视口重绘仍由调用方安排。Win32 控件更新可能部分失败；此时返回 `ControlFailure`，调用方须从原生状态重试成功后再允许保存 PMM。受控删除和导入入口均调用该组件，已通过本机验证。

### 受控模型与附件删除

`native_object_commands.cpp` 接入模型删除 `437` 和附件删除 `473`。只有内部绑定启用时才使用共同历史；普通宿主保留原路径。新路径确认后重新核对对象身份、代次和排序，实测资源并准备一个删除节点。取消、预算不足、未知资源容量、对象过期或编辑器占用均不回退旧释放逻辑。

确认框和界面刷新期间保持操作锁，阻止主窗口及浮动窗口的输入、嵌套命令和插件编辑。关闭请求延后到解锁后处理。仅同步历史发布段允许进入同一队列。播放、录制、捕获、保存、关键帧范围及复制窗口、附件绑定、边缘、重力和阴影编辑窗口占用时拒绝操作。

发布成功先用不分配的操作修正内部选择，再刷新列表和读数，防止刷新失败后的绘制访问已删除模型。延迟刷新保存稳定对象 ID，包括相机模式下的附件注册范围；重试不把旧下拉框行号解释成重新排序后的其他附件。刷新完成前，新的历史操作和工程保存返回 BUSY。

`HistoryCommandHost` 将真实插件的 undo/redo 转发至同一受保护入口，其余事务方法转发至原 `SharedHistory`。插件回调内只先修正选择，控件刷新留给回调外的宿主安全点；这不保证整个调用完全没有绘制消息。全程保留当前播放头、全局轨道选择及未受影响对象的作者姿态。

`native_object_command_checks.inc` 覆盖真实确认框、三语言、取消、重入、关闭请求、预算与分配失败，以及控件故障和三附件注册范围保持。`run_edit_history_probe.py` 在 PMX 原名、PMD 中文 EXE 下驱动实际 437／473 和真实插件 undo/redo，验证源文件离线恢复、资源复用、稳定 ID 与新代次及 PMM 往返，见 `build/abi-object-command-host-2/report.json`。本批含插入候选的原生历史累计 36,156 项通过。

## 删除绑定的恢复组件

`src/plugins/scene_history.cpp` 提供原生删除所需的绑定组件，尚未代替完整对象删除命令。

| 函数 | 记录内容 |
| --- | --- |
| `CaptureModelRemovalBindings` | 其他模型的外部亲骨骼当前值和显示键选择值；相机当前绑定和相机键；附件当前绑定、附件键及可见性；模型组合框顺序。 |
| `CaptureAccessoryRemovalOrder` | 删除附件后其他附件显示顺序及附件渲染分界位置的变化。 |
| `CaptureObjectsRemovalBindings` | 一次记录多个模型和附件的删除。只修改本批以外的存活对象，排序按全部被删前项的数量调整。 |

这些组件只记录被修改的字段，恢复时不覆盖位置、缩放等无关数据。历史记录保存对象、字段和关键帧槽位，每次准备时解析当前地址。注册池通过 `KeyPoolIdentity` 保持身份，正常扩容不影响后续撤销，也不覆盖扩容后新增的键。借用数组仍要求原地址和容量不变。

发布前检查对象身份、槽位、池身份、容量、嵌套选择数组和值。对象已释放、池已替换或来源已改写时返回 STALE，并保持历史游标。准备完成后再扩容会使该候选失效；重新准备可以取得新地址。释放后重新分配的池不会沿用旧身份，即使地址相同也不能接受旧记录。

## 模型和附件资源保留

`RetainSceneObject(app, kind, slot)` 为同一个原生对象取得共享的 `RetainedSceneObject`。对象存在时仍由活跃场景管理；对象退出场景后，保留对象持有其资源。模型原生内存、关键帧池、侧表和 COM 资源保持原对象，不根据路径重新加载。附件另保留完整关键帧池、轨道游标和启用状态，并为退出场景后的槽位预先分配空轨道。

| 内部接口 | 行为 |
| --- | --- |
| `PreparePresence(present)` | 准备活动槽位、稳定 ID、运行时代次、物理及附件轨道的存在状态变化。发布前再次验证来源。 |
| `CaptureRemoval()` | 每次准备实测对象及目标物理快照，将资源与删除绑定组件合为一个 `HistoryChange`。 |
| `PrepareInsertion(insertion, staging)` | 实测刚加载对象，准备导入记录和临时移出候选；不会代替加载器的失败回滚。 |
| `PreparePresenceBatch(objects, present)` | 为同一应用内的多个对象准备一个存在状态候选，统一准备物理世界。 |
| `CaptureRemovalBatch(objects)` | 聚合实测对象资源和一份删除绑定记录，一次提交可删除整批对象。 |
| `PrepareInsertionBatch(objects, insertion, staging)` | 为整批加载结果准备一个实测导入记录，使用与单对象相同的临时移出及提交流程。 |
| `ImportAccessory`、`ImportModel` | 接受从未进入活动槽位的私有对象、新增纹理及模型物理候选，形成首次发布与后续往返共用的导入记录，已通过本机验证。 |
| `MeasureResources(report)`、`MeasureResourcesBatch(objects, report)` | 只读统计当前保留的 CPU 数据和可查询 DX9 数据，返回总量及不完整类别。批内按分配地址和 COM 身份去重。 |

`PrepareInsertion` 处理已经加载到场景的对象，要求调用方持有场景修改锁，并且尚未发布 dirty 标记或刷新界面。调用方先发布并销毁 `staging`，使新对象暂时退出场景，再通过 `SharedHistory::PrepareNative` 和 `CommitNative` 提交 `insertion`。历史预留失败时，对象保持退出状态；释放其保留对象会销毁这次加载的资源。既有对象保留探针采用此流程。本批受控导入入口改用 `ImportAccessory` 和 `ImportModel`，私有对象在首次提交前不占用活动槽位。

`model_load_ui::DeferredRefresh(HWND)` 允许加载器暂缓 PMD、PMX 成功尾部的 `PostLoadInit`。范围按窗口及所属线程匹配，支持嵌套；退出或异常不自动刷新。调用方只有提交成功后才显式执行 `PostLoadInit`。普通加载仍立即刷新。这一机制只延后该处界面更新，不取消已有加载通知和资源创建。

`scene_resource_budget` 按实际池容量、嵌套数组、侧表容器及 DX9 查询结果统计。相同地址或 COM 身份在一个批次内按最大已知容量收费，失败不覆盖调用方的报告。报告字段为 `cpuBytes`、`d3d9Bytes`、`totalBytes`、`missing`。

`MMS_OK` 只表示统计完成，`Complete()` 才表示没有已知缺项。未登记文本或旧撤销缓冲、未知物理派生类、任意曲线回调、Alembic 私有缓存或外部 MMV 资源无法完整查询时，报告保留对应 missing 标记。实测准入遇到缺项返回 NOT_READY。全局纹理缓存、分配器元数据和驱动私有开销不属于该对象保留数据预算。

增强构建通过 `owned_text` 记录自有宽文本的实际字节数，保持模型原有 `wchar_t*` 布局。PMX 的长度前缀、固定 40 字节生成名称、英文名称回退和工程名称替换均按真实分配登记；销毁或替换时注销。Collector 按分配及登记节点身份去重，不再由可见字符串长度猜容量，也不扫描未登记指针。加载失败会清理本次文本，原始兼容构建不启用容量登记。

`history_physics::Retained::Transition::MeasureTargetResources` 可以在发布前统计本次候选完成后保留的物理历史数据，包括准备阶段创建的 `Saved`、实际 vector 容量及共享世界顺序快照。它不计临时候选、碰撞缓存及即将被替换的旧快照，也不代替刚体和形状计量。过期或已发布候选返回 false，且不改 Collector；分配失败仍允许取消或重试候选。

增强构建的 `undo_storage` 登记旧撤销缓冲的实际请求容量及分配方式。原有写入和释放入口均经登记器处理，计量不再根据 dirty 数量或读取未知地址上的快照头推断长度。登记失败释放新块；已登记块按原分配方式释放，未知块保持原调用方的释放方式。原始兼容构建使用直通实现。

`bullet275_storage` 针对固定 Bullet 2.75 头文件读取刚体约束引用数组的真实分配身份及容量，包含元素全部移除后仍保留的空间。类型化成员访问不改变 Bullet 布局或库代码，版本断言阻止未经复核的升级；未知派生类型仍标记缺项。

实测路径先准备存在状态与物理候选，再组合对象资源、附件两侧交换池、目标物理快照和记录开销。`PreparedHistoryChange::TargetRetainedBytes` 返回发布后的完整原生费用；返回 false 时使用固定 `RetainedBytes`，忽略输出参数。首次提交、撤销和重做各自重新准入，费用与游标一起发布。撤销/重做超出总预算时拒绝，不能淘汰其他节点替它支付增长；serializer 失败也不改变费用。

短期候选保存资源身份和容量清单；最终验证通过 `Collector::Covers` 重读资源，拒绝准备后新增或增长的分配及不完整查询。验证不插入清单节点，缩小或移除资源仍按原数值保守收费。CPU 验证路径不分配；DX9 查询沿用只读 COM 查询，不能由此断言驱动内部没有临时分配。

带 `resourceBytes` 的旧重载保留用于固定预算调用方和早期夹具，不能把传入 0 当成自动计量。对象跨节点仍可能重复收费；预算约束的是历史保留数据，不是进程峰值。已执行原生修改的采用协议暂不接受动态目标费用，因为反向候选的目标不是已写入的当前状态。

### 私有导入准备与受控入口

以下实现仅在内部绑定下使用。最终原生历史累计 36,842 项检查及 PMX 原名、PMD 中文名隐藏宿主探针均通过，另 15 组相关 CTest 通过。普通宿主和原始兼容构建保留旧加载流程；Win7／AMD 真机仍待验收。

`accessory_import::Prepare` 创建独占附件、网格、材质数组和已登记的私有关键帧池。失败或取消由 `Prepared` 回收。X 路径和纹理名在局部路径变量中解析，不写活动槽位、界面、dirty、工作目录或路径工作区。VAC 保留自身的 `sourcePath`，网格相对 VAC 所在目录解析，纹理相对实际 X 所在目录解析；初始姿态、缩放和阴影值同时写入附件及根关键帧。材料缓冲在加载失败和异常路径中也会释放。

`model_import::Prepare` 复用 PMD、PMX 解析器，将新模型放在独占所有者中，使用路径工作区副本和独立物理世界。解析期间的提示先保存为数据，由 `ShowMessages` 在无消息发布段之外显示；取消模型信息提示会取消导入。私有模型清理不关闭现有 DX12 渲染器。已加载 `MMEffect.dll` 或 `MMHack.dll` 时，两类私有准备均返回 NotReady，因为现有外部加载通知不能随失败撤回。

`import_texture_cache::Preparation` 只准备本次新增纹理，缺失的可选纹理不使整笔导入失败，分配或设备错误则使准备失败。`Finish` 提供保留资源和发布候选；发布前不追加活动缓存，取消释放未发布增量。导入历史另计保留的纹理数据及名称，同一 `Collector` 按分配地址和 COM 身份去重；不同历史节点可以保守重复计入同一纹理，尚无全日志共享账本。已发布的共享缓存项归渲染器管理并跨撤销保留，撤销导入不删除可能被其他对象使用的纹理。EMM、EMD 仍须显式加载。

`TryImportBoundModel` 和 `TryImportBoundAccessory` 在 `LoadModelFile`、`LoadAccessoryFile` 写入活动槽位前接管受控调用。入口先取得操作锁，准备私有对象、纹理与模型物理候选，按实测预算准备一个历史节点。只有全部校验通过才发布槽位、身份和资源，再更新 dirty、选择与对象列表。准备失败、预算拒绝和取消不回退旧加载器；撤销和重做复用保留对象，不重新打开源文件。

文件选择入口 `435`、`472` 在受控模式下传入绝对初始目录，并设置 `OFN_NOCHANGEDIR`。入口另保存当前目录，在对话框成功或取消返回后立即恢复；保存或恢复失败则停止导入。取消和加载失败不写记忆目录、路径工作区，也不调用 `RefreshRequest` 改变当前姿态。`AccessoryImportChecks` 和 `import_picker_host_checks::Run` 均通过，后者让对话框替身主动切换目录并驱动实际菜单。

`run_private_import_probe.py` 在真实 DX9 宿主中验证 PMX／PMD／VAC 导入、原生与插件交错撤销、离线重做和失败后保留 redo；主顶点、轮廓顶点及索引缓冲各自 Lock／Unlock 六类故障均完整回收私有对象，既有场景不变。最终记录见 `build/abi-private-import-native-3/report.json`、`build/abi-private-import-host-2/report.json`。本批新增的四处解析索引检查只有静态复核，未宣称完整畸形文件覆盖。

准备好的对象、绑定、物理和附件曲线候选各自保有内部记录。调用方释放原包装对象或历史记录后，候选仍可验证及取消；这不会延长 `MMDApp` 和物理世界的寿命。同一槽位先删除旧对象、再导入新对象时，两个对象分别保留原生指针、关键帧池及作者状态，并按共同历史顺序恢复。

`curve_host::AccessoryAuthoring` 单独保留附件的自由曲线、切线及原生基准。发布通过提取或插入已有 `std::map` 节点完成，不分配内存，也不覆盖相机等其他轨道。曲线编辑器的关闭和刷新不属于该发布阶段，须在宿主接入时安排。

保留对象只能在遵守共同历史所有权约定的受控入口中长期存在。绕过组件直接释放原生对象会破坏该约定，其他原生写入仍须逐项迁移。工程重置和关闭时，未完成候选及所有保留对象必须先于 `MMDApp` 和物理世界释放。对象仍存在时，保留对象析构不销毁活跃对象；对象已退出场景时，最后一个所有者负责释放资源。

## Bullet 移出和恢复

增强构建的 `history_physics::Broadphase` 保持原有 `bt32BitAxisSweep3` 算法，并允许预先准备、交换碰撞对缓存。`history_physics::Retained` 记录要保留的刚体和约束，原始兼容构建保持旧路径。

封装在创建碰撞代理时初始化其包围盒，支持导入后尚未执行第一次物理更新就准备历史。状态校验只比较三维坐标和变换矩阵的有效分量，不读取 Bullet 向量未使用的第四分量。

移出时，刚体退出物理世界的碰撞对象和非静态刚体数组，约束退出约束数组。组件保留原有代理句柄，将碰撞及射线过滤掩码设为零，并禁用刚体模拟。恢复时重新加入原指针，恢复数组顺序、过滤掩码和激活状态。对象保留期间的速度、姿势和资源不通过重新构造获得。

准备阶段分配目标数组和碰撞对缓存。恢复会显式检查重叠，因此静止物体无需先移动才能重新参与碰撞。未受删除影响的碰撞算法及接触数据继续保留。`Publish` 不分配 C++ 或 Bullet 内存，也不销毁资源；旧接触在候选析构时清理。`CommitNative` 和编辑事务提交在释放编辑锁前销毁已发布候选。任何物理推进或物理世界销毁前，都必须先销毁这些候选。

候选校验物理推进序号、物理数组、碰撞对、代理包围盒、过滤参数及刚体状态。准备后发生物理推进、碰撞检测或相关状态变化会使候选失效。停车期间的刚体必须保持不变，恢复前也会检查。当前不支持物理 action、碰撞过滤回调、ghost 回调、碰撞对用户回调、约束过滤引用，以及关联保留刚体但不在本次保留集合内的约束。保留约束的两个端点必须都在保留集合内；不满足时拒绝准备。

`Retained::PrepareBatch(objects, present)` 为同一物理世界中的多个保留对象准备一组物理数组和碰撞对缓存，随后统一发布。单对象接口也使用这一实现。整批删除后可分别恢复，分别删除后也可整批恢复；组件合并保存的顺序约束，冲突时拒绝准备。跨保留对象的关节仍不支持，即使两个端点都在批次内也会拒绝。

对象批量接口要求列表非空、所有对象属于同一应用，且同种对象的槽位不重复。模型和附件可以使用相同数字槽位。重复所有者、失效成员、替换 broadphase 或冲突顺序都会拒绝整批操作，不发布部分对象。公共场景多对象写入服务仍待接入。

## 模型删键与混合范围缩放的受控接入

`PlanBoneKeyDeletion` 和 `PlanBoneRangeScale` 生成独立历史记录。删键保留旧实现的链接修改和自动插值邻居写入；范围缩放按原槽位顺序重插，压缩到同帧时保留旧覆盖顺序。记录包含缩放及自由曲线作者数据，不依赖旧 30 槽环。准备、取消和无变化操作均保留当前选择及 redo。

内部绑定下，按钮 423 和删除快捷键调用 `PlanModelKeyDeletion`。骨骼、表情和显示／IK／外亲键可以混选，一次删除只追加一条记录；一次撤销恢复全部参与轨道。三族都没有显式标记时，快捷键才在私有计划中补选当前非零帧的所选骨骼键。失败不改变标记、当前值或 redo。普通宿主仍走原路径。

范围缩放对话框通过 `PlanModelRangeScale` 支持三族的 7 种非空勾选组合。各族在私有键链上按旧槽序删除和重插，保留压缩碰撞的覆盖顺序及骨骼自动插值。显示键继续按旧名称规则匹配 IK 和外亲。尚未支持的导入目标映射及不合法名称返回 NOT_READY，不执行部分缩放。

聚合层最后一次性写入共享的 `maxFrame`、`searchCursor`、应用最大登记帧和三族选中标记。最终标记属于旧处理顺序中最后一个实际有键的勾选族；空族不会清除前族结果。只要任一族的帧号变化，其余有键的勾选族也按旧顺序处理；全部帧号因整数截断保持不变时，操作不追加历史、不改变标记或 redo。表情按目标键链重新求值，显示键产生的目标外亲窗口也供骨骼采样。

`PrepareBoneEvaluation` 在每次提交、撤销和重做准备时，用该方向的目标键及作者快照重新采样当前帧。只更新受影响且没有未登记编辑的骨骼，保留其他骨骼、Morph、显示/IK 状态及播放头。切换模型或帧号后撤销仍按当前帧求值。物理开关变化及物理模式 3 的 IK 启动暂返回 NOT_READY，不能在发布时调用旧全模型 `SeekModelFrame`。

`PlanDisplayKeyDeletion` 保存显示键标量、IK 字节及外亲引用，按槽位恢复到当前池。每次准备按目标键链重新计算当前可见性、IK 启用状态、外亲对象及连续相同外亲关系的起止帧。正常扩容后重新定位，替换池身份、嵌套缓冲区别名或目标模型失效会拒绝操作。发布保留现有缓冲区所有权。

外亲窗口会影响骨骼采样。例如骨骼最后一键在第 0 帧，外亲在第 10 帧变化，旧求值可能在第 15 帧将该骨骼局部位移归零。删除第 10 帧的外亲键后，骨骼必须按新窗口重新采样。混合删除让骨骼参与者同时读取目标骨骼键和目标外亲窗口；没有删键但受外亲影响的骨骼也参与求值，未登记姿态仍保留。

`PlanMorphKeyDeletion` 按旧槽位顺序删除表情键。它保留原始曲线及切线，使用只读作者快照和目标原生键链派生当前权重；撤销恢复原键后，原曲线仍可生效。表情没有独立的未登记标志，因此受影响表情遵循旧删键后的 Seek 行为，重新求值并覆盖当前未登记权重；其他表情保持原值。

聚合记录先准备全部参与者，统一检查键池、当前值、作者数据、模型身份及内存区间。提交阶段不分配内存、不进入消息循环，按骨骼、表情、显示的顺序发布。骨骼用目标外亲窗口求值，但其提交前校验仍检查旧窗口；因此显示状态最后发布。任一准备失败均丢弃整笔候选，不能拆为部分成功。

`tests/native_bone_transform_checks.inc` 直接调用旧 `DeleteMarkedModelKeys`，并复现旧范围缩放的低层写入次序作为对照。第一批原生历史共 20,794 项通过，构建及测试记录为 `build/plugin-abi-key-transform-build-1.log` 和 `build/plugin-abi-key-transform-native-1.log`。

`tests/native_model_range_checks.inc` 验证 7 种勾选组合与旧注册器的 42 组对照，并覆盖无骨骼模型、后序空族、当前帧与外亲窗口、逐分配失败和实际 `ApplyFrameRangeScale` 路由。原生历史累计 28,066 项通过，见 `build/plugin-abi-model-range-native-final.log`。真实 PMX/PMD 宿主另调用受控缩放入口，验证三族只追加一条记录、真实插件跨帧撤销与原生重做，见 `build/abi-model-range-host-1/report.json`。

## 骨骼插值按钮的受控接入

模型模式的插值粘贴 `431` 和重置 `432` 已接入 `PlanBoneInterpolationEdit`。它们修改选中的现有骨骼键，包括选中的第 0 帧根键；下拉框支持 X、Y、Z、旋转、缩放及全部通道。一次操作产生一条共同历史，普通宿主仍使用旧路径。

## 相机插值按钮的受控接入

相机模式的插值粘贴 `431`、重置 `432` 通过 `PlanCameraInterpolationEdit` 进入共同历史。范围是选中的现有相机键，包括第 0 帧；支持 X、Y、Z、旋转、距离、视角及全部通道。一次按钮操作产生一条记录，可与插件编辑交错撤销。普通宿主仍使用原路径。

内部参数 `CameraInterpolationOptions.channels` 的位 0–5 对应上述六个通道；`values[6][4]` 按通道存放 `x1/y1/x2/y2`，各值为 0–127。重置使用 `20/20/107/107`。粘贴单通道时读取插值复制缓存的对应通道，全部模式读取六组值。零掩码、没有选择或字节未变均不追加历史、不清除 redo。

记录只写实际变化通道的插值字节，并保存自由曲线作者状态。提交、撤销及重做不跳帧、不求值，不覆盖当前未登记的相机姿态、父骨绑定、其他轨道、游标或最大登记帧。用户后来改变的键选中标记保持原样。取消、失败及无变化不产生界面发布通知。

计划先验证键链与选中槽，再准备目标曲线。发布前重新校验键池、源数据、作者状态和短期候选；失败不写入部分结果。普通扩容保留键池身份，已提交记录可在新地址撤销；替换键池或准备后扩容会拒绝。`TrackAuthoring` 在稳定键池身份下识别同一作者来源，最终发布时更新其地址，避免自由曲线因扩容误失效。发布及取消不分配内存，历史按实际保留容量计费。

`TryApplyBoundInterpolation` 根据模式分派骨骼或相机计划。相机模式在播放、录制、场景变更、保存、烘焙、鼠标捕获及相关模态编辑期间拒绝；共同历史已有事务时也拒绝。绑定后，非法下拉索引、失败及无变化均不回落旧写入。

验收入口为 `native_edit_history_tests --camera-interpolation-only` 和 `tests/plugins/run_camera_interpolation_probe.py`。后者使用真实按钮、原名 PMX 宿主及中文改名 PMD 宿主、真实插件 DLL。当前执行结果见 [相机插值验证记录](records/abi-camera-interpolation-2026-10-17.md)。这批不开放普通宿主的 `mms.edit`，也不覆盖关键帧复制粘贴、插删帧、图形曲线编辑器和控制点拖动。

## 已实现的事务规则

### Manager 的显式附加与回调边界

`Manager::AttachEditHost` 仅在首次加载插件前调用。Manager 拥有 `EditStore`，外部应用拥有 `SharedHistory`；转发器的 `AttachStore/DetachStore` 连接同一队列。插件持有的函数表上下文属于实例，分离服务后调用返回 NOT_READY，不解引用已释放的 store。

只有顶层命令调用和本插件的 UI 队列执行回调可发起编辑。getState、属性读取、嵌套调用、事件、serializer、participant、取消及停止回调均不能重入编辑。失败命令或异常队列回调仅取消由本插件发起的未完成事务，不取消本插件只是参与者的其他所有者事务。

受控宿主的场景快照 `sceneRevision` 来自同一 `SharedHistory`，插件不必猜测原生命令后的修订号；绑定几何的 `structureRevision` 仍独立。普通宿主的只读快照不因此获得编辑权限。

成功 commit、undo 或 redo 解锁后触发 `SetEditPublished` 通知。应用立即标记工程变化，延后刷新撤销按钮、读数和曲线编辑器；插件自己的消息循环提前消费通知时，通过定时器重试。通知异常不改变已经提交的结果，历史资源只在插件回调外回收。

`run_edit_history_probe.py` 在原创 PMX/PMD、原名及中文 EXE 下验证真实 DLL、菜单分派、原生重置与插件编辑交错撤销、一次命令多次提交、准备失败、新建、PMM 重开及关闭取消。该入口只用于隔离测试，不能作为普通宿主全部写入已经迁移的证据。

begin 校验非零场景修订号，并复制标签。事务创建者负责 prepare、commit、cancel；其他插件可通过自己的上下文 join 该事务，但只能交付本插件的 participant。每个插件在同一事务中最多加入一次，并须已注册 serializer。

prepare 在宿主编辑锁内重新校验修订号和 serializer 注册代次。所有 participant.prepare 成功后，宿主才读取 before/after 不透明字节，深复制并释放借用租约，最后为统一历史预留发布资源。任何一步失败，取消全部已经接受的 participant，消费事务，不追加历史。

commit 只接受已准备事务，在同一编辑锁内再次检查场景修订号及 serializer 注册代次。检查通过后消费各 participant 的 context，最后调用 `EditPublication::Publish()`。发布对象须在 prepare 阶段完成内存分配；Publish 只交换状态和已经准备好的历史节点，不运行插件回调或消息循环。

有效的 commit 尝试不论成功还是失败都会消费事务。重复 commit 返回 STALE；重复 cancel 不产生影响。prepare 后不能 join；未 prepare 的 commit 返回 CONFLICT，仍允许修正或取消该事务。插件停止前，`EditStore::Retire` 取消其创建或参与的未完成事务。

违反无异常 commit 契约时，内核停止接受新编辑。不对已消费 context 再调用 cancel，也不将半提交状态标为成功；退休返回失败，宿主接入时须据此保留实例和 DLL。原生插件在进程内执行，这一保护不能消除违规回调自身造成的状态改动。

`StorageStore::PrepareRestore` 只恢复历史记录包含的插件。缺失 provider 时不调用其他候选；任一 prepareLoad 失败时取消已经准备的数据，不改变当前状态或历史游标。恢复不会覆盖 `readSaved` 所指的磁盘保存基准。

## 原生恢复的准备与发布

增强构建已将 `UndoModelEdit` / `RedoModelEdit` 接到 `native_history::ModelEdit`。内部声明见 `include/mikudancestudio/native_edit_history.hpp`，实现见 `src/model/native_edit_history.inc`。原始兼容构建保留旧路径。这一步改造原生恢复过程，尚未把原生和插件记录排入共同历史。

`Prepare(model, frame, redo)` 复制本次操作涉及的姿势、关键帧及辅助状态，分配 redo 缓冲，准备缩放和曲线侧表。关键帧按被修改的槽位保存，不复制整个骨骼关键帧池。类型 4 的连续操作整体准备，最多检查 30 个环槽；损坏循环直接拒绝。覆盖范围如下。

| 原生记录 | 恢复内容 |
| --- | --- |
| 1、3 | 未注册骨骼位置、旋转、编辑标志；类型 3 另恢复当前帧。 |
| 2、4 | 完整骨骼键记录、姿势及链式操作的中间 redo 状态。 |
| 5 | 烘焙键、最大帧、分配游标、骨骼物理开关及缩放键。 |
| 6 | Morph 全池、曲线及切线、最大帧和分配游标。读取真实散布操作产生的 before/after。 |
| 7 | 删除前的骨骼键、Morph 键、显示键、IK 标志和外部亲骨骼选择值；保留活跃数组的所有权。 |

`IsCurrent(frame)` 检查本次读取的数组身份、容量、环槽、快照内容、原生值及侧表。`Publish(frame)` 再次校验，随后只复制准备好的值和交换容器，不分配内存、不发送窗口消息、不求值、不调用插件。候选只能发布一次；放弃候选不改活跃状态。调用者必须保证模型仍存活，并从准备到发布一直串行化编辑。该内部指针接口不能直接暴露给插件，也不能代替宿主的对象代次检查。

`Refresh(physicsMode)` 在发布之后同步物理标志和界面，按原生类型执行必要的重新求值。它不属于无分配发布阶段。按钮和快捷键改用返回成功状态的 `TryUndoModelEdit` / `TryRedoModelEdit`；准备失败时不继续修改工程 dirty 标记或撤销按钮状态。

MSVC 的某些容器移动构造会分配内存，因此包含 `std::map` 的状态对象不能用整体 `std::swap` 实现发布。缩放、骨骼自由曲线及 Morph 层改用各容器自身的 `swap`。回归测试在发布期间禁止 C++ 分配，验证这条约束。

当前恢复候选要求快照容量不超过仍存活的池。池被替换或缩小会使候选失效。可撤销删除须保留模型及其池，恢复对象后再允许恢复其更早的编辑记录；永久释放才使该对象的历史资源失效。恢复辅助不会为了应用过期记录而改写新对象。各原生编辑入口创建历史的过程尚未全部改成两阶段提交。

## 宿主接入边界

`EditHost` 是本体内部接口，不进入公共 C ABI。

| 方法 | 本体责任 |
| --- | --- |
| `Revision` | 返回统一场景编辑修订号，覆盖关键帧、未注册姿势、参数、绑定与插件工程状态；不能仅返回绑定几何快照的观察修订号。 |
| `Enter` / `Leave` | 串行化原生和插件编辑；在加载、保存、播放求值、烘焙或其他原生修改未完成时拒绝进入。 |
| `Reserve` | 准备一次操作的原生候选及历史节点，保存插件 before/after，验证所有目标代次。失败不修改活跃场景或历史。 |
| `EditPublication::Publish` | 无分配地交换候选、追加一个共同历史节点、废弃对应 redo，并递增统一修订号。业务事件在完整发布后排队。 |
| `History` | 从共同历史选择 undo/redo，先准备全部原生和插件恢复数据，再一起发布。失败保留历史位置。 |

内核不拥有第二个插件专用撤销栈。旧测试中的 `EditHostFixture` 仅验证事务协议；新增测试直接使用 `SharedHistory`，主窗口接入也须使用这一实现。

## 当前原生撤销入口

现有历史主要是每模型 30 槽 undo/redo 环，记录布局见 `include/mikudancestudio/undo_layout.hpp`。以下路径须进入共同历史，不能只修改界面按钮。

| 入口 | 当前内容及接入要求 |
| --- | --- |
| `bone_edit_undo.cpp::PushBoneEditUndo` | 未注册骨骼姿势；分配及捕获须先完成，再登记共同历史。 |
| `model_keyframe_edit.cpp::AdvanceUndo`、注册/删除 | 旧环类型 1–4、7 的恢复已整体准备；骨骼当前帧登记、模型三族删键、混合范围缩放及模型插值按钮已通过独立计划受控接入。其余登记和写入入口待迁移，见[骨骼关键帧迁移顺序](#骨骼关键帧迁移顺序)。 |
| `model_keyframe_edit.cpp` 物理烘焙 | 类型 5，同时含关键帧、姿势、容量及搜索游标。须与骨骼缩放和曲线侧表一起恢复。 |
| `sequence_scatter.cpp` | 类型 6，持有完整 Morph 池及曲线状态的 before/after。不得退化为只恢复当前值。 |
| `vmd_load.cpp` | 动作导入；一次导入及其缩放、曲线数据应形成共同历史节点。 |
| `command_control_400.cpp`、`command_control_450.cpp`、`command_file_menu.cpp` | 存在直接写环的注册、粘贴或清理路径；仅接管 `AdvanceUndo` 无法覆盖。 |
| `frame_line_edit.cpp`、`ui_editor_click.cpp`、`misc_dialogs.cpp` | 时间线和对话框直接写环；须先准备快照与内存。 |
| `playback_state.cpp`、`oni_skeleton_pump.cpp` | 播放和捕获相关姿势/键记录；需明确一次操作边界，避免按帧无限追加。 |
| `bone_scale.cpp`、骨骼/Morph/全局曲线侧表 | 模型环关联的缩放、骨骼曲线和 Morph 散布恢复已准备后交换；全局曲线及独立编辑器历史仍待接入。 |
| `command_control_400.cpp`、`key_ladder.cpp`、`UndoModelEdit/RedoModelEdit` | 已统一调用新的模型恢复过程并识别失败；按钮和快捷键在显式绑定下选择共同历史，普通宿主尚未切换。原始兼容构建保留旧路径。 |

重开工程须丢弃旧历史。删除对象须保留可撤销资源并登记存在状态变化；重用原生环槽时不能覆盖共同历史仍需使用的数据。当前绑定快照的 ID/代次与工程保存机制可复用，但绑定快照本身不能代替完整可撤销编辑状态。

## 开放服务前的验证

需在真实宿主覆盖骨骼姿势、注册键、删除键、VMD 导入、物理烘焙和 Morph 散布，与插件状态改动交错后的 undo/redo；并覆盖跨模型、相机模式、对象删除、环槽回绕、工程重开、缺失插件和 schema 拒绝。prepare 或历史预留失败时，原生状态、插件状态、dirty 标记、修订号和历史游标均须保持不变。

Win7 和 AMD 真机项目暂列待验，不阻塞上述实现与本机验证。接口继续采用 Win7 目标、CPU 基础实现和厂商无关数据，不加入新系统或专有 GPU 的必需依赖。
