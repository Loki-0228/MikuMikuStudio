# 编辑事务内核与原生撤销接入

`src/plugins/edit_store.cpp` 已实现 `edit.h` 对应的两阶段事务内核。`src/plugins/shared_history.cpp` 实现原生与插件共用的历史队列，`src/plugins/scene_object_history.cpp` 提供模型及附件资源的保留与恢复。真实隐藏宿主已验证资源恢复，但主窗口和各原生写入入口尚未接入共同历史。因此 `queryService("mms.edit", ...)` 仍返回 NOT_FOUND，可写 UI 属性仍返回 NOT_READY。

## 共同历史的范围

共同历史按提交顺序记录跨模型编辑、模型及附件导入、对象删除和插件工程编辑。当前选中的模型不参与历史节点选择。删除对象本身是一条可撤销记录，不清空该对象先前的编辑历史。

导入节点须持有完整对象及其资源。撤销导入后，对象退出活跃场景；重做从历史保留的数据恢复，不重新读取源路径。删除节点须保留对象、动作键、未注册姿势、曲线侧表、物理及渲染恢复数据，并保存受影响的相机、附件、其他模型绑定和显示顺序。只有节点被截断、超出历史预算或工程关闭，且没有其他所有者时，才释放保留资源。

对象 ID 在撤销删除后保持不变，运行时代次重新分配。删除前取得的引用不能直接用于恢复后的对象；插件须重新获取场景快照。仍持有的旧快照继续只读。历史实现按稳定 ID 保留资源，不能仅依赖槽位或内存地址。

插件作者通过事务边界决定撤销粒度。多步算法先在私有候选中完成计算，再提交一个事务，用户只需撤销一次。需要逐步撤销时，每一步分别 begin、prepare、commit。多次已完成的提交不会事后合并，也不能跨越其他编辑合并。取消只丢弃当前未提交事务，不隐式撤销前面已经提交的步骤。公共接口规范见 [SDK 编辑事务参考](../sdk/mms/edit.md)。

## 共同历史内核

`SharedHistory` 实现 `EditHost`，原生操作和插件事务写入同一组 undo/redo 节点。每个节点包含标签、插件 before/after 字节及可选的 `HistoryChange`。原生服务可用内部 `EditStore::JoinNative` 将一个聚合候选加入已有插件事务；这个 C++ 指针不进入插件 ABI。

`HistoryChange::Prepare(direction)` 返回 `PreparedHistoryChange`。候选须只分配和验证；`IsCurrent` 在发布前再次核对来源；`Publish` 不得分配、抛异常、运行插件或进入消息循环。一次操作涉及多个原生对象时，由聚合候选统一准备和发布。历史撤销先准备原生候选和所有 serializer，再检查原生来源，全部成功后发布并移动节点。

历史节点在 prepare 时分配，publish 通过链表 splice 追加或移动。重做分支截断、旧节点淘汰只移入待回收队列；`Collect` 在宿主安全空闲点释放资源，避免在原子发布阶段析构模型、纹理或 Bullet 对象。当前默认最多 128 条、256 MiB 保留数据预算，内部构造参数可调整。原生候选须报告实际持有数据的大小；该预算不是进程内存上限，准备和待回收数据也会暂时占用内存。

新提交才截断重做分支。准备失败、取消或陈旧拒绝均保留该分支。Reset 清空历史并递增修订，不重新从 1 开始，使之前准备的事务失效。原生事务由历史登记；Reset 和历史析构会先释放这些事务的候选与资源，调用方遗留的空 token 只能返回 STALE。`EditStore` 必须先于它所引用的历史对象销毁。违规的 void commit 会冻结整个共同历史，包括原生入口，不把半提交状态登记为可撤销结果。

`SceneIdentity::PreparePresence` 已实现可撤销存在状态的身份候选。准备时预留新代次，取消会留下未使用的代次数值；发布只修改该对象的 present 和 generation。多个对象可以一起准备并按任意顺序发布，旧代次不会重新生效。

### 已执行原生修改的采用协议

同步数字编辑不能先改姿态，再尝试分配历史节点。内部 `AppliedTransaction` 把这个流程分为三步：

| 调用 | 调用时机和保证 |
| --- | --- |
| `ReserveAppliedNative(label, maximumNativeBytes, token)` | 修改前调用。预分配节点，检查记录上界，并保持共同历史的排他锁。存在未结束的插件事务时返回 BUSY。 |
| `PrepareAppliedNative(token, change)` | 原生修改完成后调用。检查实际记录大小不超过预留上界，准备反向候选，验证当前确实处于修改后状态。此步可以分配，不执行反向修改。 |
| `CommitAppliedNative(token)` | 再次检查候选和记录大小，只把节点加入历史，不重放修改。不分配内存，成功后才截断重做分支。 |

token 到析构才解除排他锁，因此提交成功后仍可先清理候选。准备或提交失败时，调用方先用捕获数据回滚姿态，再释放 token；token 本身只取消预留，不负责回滚原生数据。空操作直接取消，不截断重做分支。此范围内不得运行插件、进入消息循环或刷新窗口。场景切换和新的编辑操作均被历史锁拒绝。

这套接口是宿主内部的 C++ 协议，不改变插件 `edit.h`。记录大小仍是历史保留数据预算，不等于整个进程或模型资源的内存上限。

## 工程切换与关闭

`integration.cpp` 为当前 `MMDApp` 创建一个 `SharedHistory`，与插件管理器共用 `StorageStore`。内部 `NativeHistory(app)` 返回该队列，公共 `mms.edit` 仍未开放。

`PrepareReset` 在插件准备新工程数据前取得排他 token。此时不清历史，取消加载只释放 token。PMM v1、v2 加载器在 `pmm_settings::Reset` 前调用 `BeginProjectSceneReplacement`，提交历史清理并回收退出场景的对象，随后才清身份、曲线、模型和物理资源。token 保持到插件工程提交或取消完成，避免过程中重新写入历史。

`EditStore` 向历史登记自身。只要存在未完成编辑事务，Reset 和 PrepareReset 就返回 BUSY；宿主须先调用 `CancelPending`。该函数按原取消规则释放插件上下文、混合候选和原生资源。取消回调异常会冻结历史并返回 FAILED，不遗留剩余事务。取得工程切换 token 后，新的编辑 begin 也返回 BUSY。

新建工程采用同一顺序。关闭路径区分正在执行的回调与已准备但尚未提交的数据：前者禁止重入；后者先取消工程准备，再释放历史，最后销毁管理器。局部测试或后续编辑服务自行持有的 `HistoryChange` 仍须在场景释放前交还，不能靠修订失效延长原生世界寿命。

## 不依赖循环缓存的姿态记录

`native_history::PoseEditCapture` 与 `OwnedPoseEdit` 已实现 type 1 姿态编辑的独立记录。Begin 保存编辑前数据并预分配持久记录容量，`MaximumRetainedBytes` 返回该记录的保留字节上界。Finish 保存前后发生变化的骨骼姿态与缩放差异。记录不依赖原有 30 槽撤销环，后续环覆盖或关键帧池扩容不会破坏已有记录。

Prepare 每次解析当前模型，形成短期 `ModelEdit` 候选。发布保留当前播放头与原有环游标；缩放按变更骨骼合并，不覆盖其他骨骼之后求值得到的缩放。宿主仍须持有原生模型，并在访问前验证稳定身份。

当前仅接受位置、旋转、未注册姿态标记和姿态缩放。其他操作类型与物理开关变化明确拒绝。Finish 分配失败后，捕获对象仍可在同一受控编辑范围内无分配回滚；若物理开关或模型结构已变，回滚完整拒绝。捕获对象不恢复旧环、控件或共同日志元数据，析构也不自动回滚。

`NativePoseScope` 把捕获、预留、采用和失败回滚接在一起。它持有规范的 `RetainedSceneObject`，在访问模型前核对稳定 ID、活动槽位及存在状态。提交失败先回滚，再解除历史锁；若模型身份、结构或物理状态已变化，不能安全回滚时冻结历史并返回 FAILED。模型驻留资源由调用方单独计量，姿态节点只计自身记录及包装开销。

以下生产入口已接入受控路径，由内部 `NativePoseTestBinding` 显式绑定应用和历史。普通宿主未启用此绑定，仍走原路径。

| 入口 | 已接入行为 |
| --- | --- |
| 位置、旋转、缩放数字输入 | 只有 EDIT 修改标志为真才提交，避免重复失焦把显示舍入值记回姿态。无效模型槽、骨骼和非有限数值拒绝修改。 |
| 骨骼重置 `495` | 保存原有根骨骼 X/Z 保留和无父骨骼换算规则，同时记录姿态缩放。 |
| 粘贴 `497`、镜像粘贴 `498` | 按名称匹配，预先计算镜像目标与缩放矩阵；提交成功后才更新骨骼选择与物理重置请求。 |
| 主窗口及浮动窗口的位置、旋转轴复位 | 复用相同事务范围，保留各入口的旋转换算精度。 |
| 缩放轴复位 | 在捕获前计算目标矩阵，覆盖全局、局部和视图坐标；提交时只写姿态数据。 |
| 撤销 `400`、重做 `401`、`Ctrl+Z`、`Ctrl+X` | 按共同历史顺序执行，不依赖当前模型选择或相机模式。文本输入框保留自己的快捷键处理。 |

这些路径不写旧 30 槽环。成功提交后，`PublishBoundPoseEdit` 更新 dirty、历史按钮和读数，不跳帧、不改变全局轨道或附件选择。无匹配、无实际变化及失败都保留重做分支。撤销入口在空历史、BUSY 或准备失败时也不回落旧环，播放和录制期间拒绝执行。

其他姿态写入、type 2–7 独立记录和全局编辑尚未迁入，不能凭 `NativeHistory(app)` 非空就整体切换旧撤销入口。`mms.edit` 尚未开放。

## 骨骼关键帧迁移顺序

本节描述 type 2、type 4 独立记录的待实现方案。目前只完成 `BoneKeyPoolIdentity`。
注册池正常扩容保留身份，销毁后重新分配取得新身份，借用数组返回 0。身份耗尽时拒绝新建，模型二进制布局不变。
关键帧捕获、独立记录、侧表快照接口和纯数据修改函数均未实现，注册及范围缩放入口尚未迁入共同历史。

首个接入范围限定为选中骨骼在当前帧的注册，包含插入、覆写、自动插值和缩放键，但不切换骨骼物理开关。
现有 `RegisterSelectedBoneKeys` 会写旧环、提前更新按钮，并清除骨骼、Morph、显示键的选中标记，不能直接套用姿态捕获。

后续实现按以下顺序拆分：

1. 在修改前形成注册计划，确定骨骼、目标帧、复选框参数、新槽位及全部受影响的键。
   变更集合须闭合于实际写入的邻居：插入与覆写涉及当前槽、`previous`、`next`，自动插值还会改邻居的插值值。
   删除后重建邻居插值时须继续加入该邻居的前后键，不能固定按每个删除键三个槽估算。
2. 拟定 `BoneKeyEditCapture` 与 `OwnedBoneKeyEdit`，保存各槽完整 `BoneKey` 的 before、after，以及姿态差异、`maxFrame` 和 `searchCursor`。
   捕获接口提供 `Begin`、`MaximumRetainedBytes`、`Finish` 和 `Rollback`，记录通过 `Prepare` 生成恢复候选。
   长期记录保存池身份和槽号，正常扩容后重新解析地址。短期候选绑定本次指针与容量，准备后再扩容须重新准备。
   借用池仍要求原地址和容量不变，借用池转为自有池不能视为同一身份。
3. 为缩放与自由曲线增加独立的作者数据快照，不复制或交换原有 30 槽撤销环。
   缩放键与曲线可基于 `bone_scale::CurveTableState`，另补不存在侧表时的预建存储和无分配交换。
   自由曲线须保存每个骨骼的九条轨道、切线及 `nativeHash`，新增只读捕获、校验和交换接口。
   原生注册使旧自由曲线失效时，在此次修改中明确记录失效结果，不能等后续 `Evaluate` 才删除旧曲线。
4. 在修改前计算记录上界并预留共同历史，提交时按实际保留容量计费。
   预算包含槽位差异数组、姿态差异、缩放及曲线映射节点、各轨道键数组，所有乘加检查 `uint64_t` 溢出。
   完整键池可作为临时捕获手段，但持久记录应保存变更槽，不能为每次注册永久保留两份完整池。
5. 明确扩容失败回滚的边界，再接入无分配回滚。
   当前 `BoneKeyPoolEnsure` 成功后已释放旧自有分配。若要求恢复原指针和容量，须新增保留新旧分配的扩容候选。
   若允许取消后保留新增容量，契约须写明只恢复作者数据并清空新增键，不能声称恢复原分配。
6. 从原注册函数分离纯数据修改，移除其中的 `AdvanceUndo`、窗口消息和失败弹窗。
   `NotifyBonePhysicsMode` 须与原子发布隔离。首个范围在修改前拒绝物理开关变化，后续再准备独立的物理状态候选。
   三类键选中标记清理也须纳入捕获或延后处理。dirty、按钮、曲线编辑器通知只在提交成功后更新。
7. 将 type 4 的删除与重新插入作为一次组事务迁移。
   `ScaleBoneKeys` 当前经过 `DeleteMarkedKeyframes`、`BeginRangeScaleBoneUndo` 和多次 `RegisterBoneKey`，任一步失败都须回滚整组。
   组事务只产生一个共同历史节点，不能依次提交删除与插入来代替原子操作。混合 Morph、显示键删除仍需各自的准备组件。

## 历史发布后的对象列表刷新

`scene_history_ui` 把对象列表刷新与场景求值分开。调用方在一次对象发布前 `CaptureSelection`，发布成功后 `RefreshObjectLists`，并传入共同历史的 undo/redo 可用状态。快照只用于这一次提交，调用方须保持对象存活，不能跨越地址复用。

刷新按原生顺序重建模型、附件、父模型和父骨骼列表；父骨骼项保留真实骨骼编号。选中的模型被删除时回到相机模式，附件被删除时选择剩余列表的第一项。相机模式的注册范围包含四个固定轨道和附件。列表未变时只更新必要的选择，避免重复清空控件。

组件不修改姿态、关键帧、绑定、播放头或场景 dirty，不运行 seek 或模型重新求值。模型模式的注册范围、Morph/IK 子面板、显隐和视口重绘仍由调用方安排。Win32 控件更新可能部分失败；此时返回 `ControlFailure`，调用方须从原生状态重试成功后再允许保存 PMM。当前组件尚未接管实际导入、删除菜单。

## 删除绑定的恢复组件

`src/plugins/scene_history.cpp` 提供原生删除所需的绑定组件，尚未代替完整对象删除命令。

| 函数 | 记录内容 |
| --- | --- |
| `CaptureModelRemovalBindings` | 其他模型的外部亲骨骼当前值和显示键选择值；相机当前绑定和相机键；附件当前绑定、附件键及可见性；模型组合框顺序。 |
| `CaptureAccessoryRemovalOrder` | 删除附件后其他附件显示顺序及附件渲染分界位置的变化。 |
| `CaptureObjectsRemovalBindings` | 一次记录多个模型和附件的删除。只修改本批以外的存活对象，排序按全部被删前项的数量调整。 |

这些组件只记录被修改的字段，恢复时不覆盖位置、缩放等无关数据。历史记录保存对象、字段和关键帧槽位，每次准备时解析当前地址。注册池通过 `KeyPoolIdentity` 保持身份，正常扩容不影响后续撤销，也不覆盖扩容后新增的键。借用数组仍要求原地址和容量不变。

发布前检查对象身份、槽位、池身份、容量、嵌套选择数组和值。对象已释放、池已替换或来源已改写时返回 STALE，并保持历史游标。准备完成后再扩容会使该候选失效；重新准备可以取得新地址。释放后重新分配的池不会沿用旧身份，即使地址相同也不能接受旧记录。

## 模型和附件资源保留

`RetainSceneObject(app, kind, slot)` 为同一个原生对象取得共享的 `RetainedSceneObject`。对象存在时仍由活跃场景管理；对象退出场景后，保留对象持有其资源。模型原生内存、关键帧池、侧表和 COM 资源保持原对象，不根据路径重新加载。附件另保留完整关键帧池、轨道游标和启用状态，并为退出场景后的槽位预先分配空轨道。

| 内部接口 | 行为 |
| --- | --- |
| `PreparePresence(present)` | 准备活动槽位、稳定 ID、运行时代次、物理及附件轨道的存在状态变化。发布前再次验证来源。 |
| `CaptureRemoval(resourceBytes)` | 将对象资源与删除绑定组件合为一个 `HistoryChange`，交给共同历史准备和提交。 |
| `PrepareInsertion(resourceBytes, insertion, staging)` | 从刚加载的对象准备导入记录和临时移出候选。重做保留的导入记录不读取源文件。 |
| `PreparePresenceBatch(objects, present)` | 为同一应用内的多个对象准备一个存在状态候选，统一准备物理世界。 |
| `CaptureRemovalBatch(objects, resourceBytes)` | 聚合全部对象资源和一份删除绑定记录，一次提交可删除整批对象。 |
| `PrepareInsertionBatch(objects, resourceBytes, insertion, staging)` | 为整批加载结果准备一个导入记录，使用与单对象相同的临时移出及提交流程。 |
| `MeasureResources(report)`、`MeasureResourcesBatch(objects, report)` | 只读统计当前保留的 CPU 数据和可查询 DX9 数据，返回总量及不完整类别。批内按分配地址和 COM 身份去重。 |

导入接入要求加载器持有场景修改锁，并且尚未发布 dirty 标记或刷新界面。加载器先发布并销毁 `staging`，使新对象暂时退出场景，再通过 `SharedHistory::PrepareNative` 和 `CommitNative` 提交 `insertion`。历史预留失败时，对象保持退出状态；释放其保留对象会销毁这次加载的资源。当前真实宿主探针按此流程调用内部组件，实际加载菜单尚未采用该流程。

`model_load_ui::DeferredRefresh(HWND)` 允许加载器暂缓 PMD、PMX 成功尾部的 `PostLoadInit`。范围按窗口及所属线程匹配，支持嵌套；退出或异常不自动刷新。调用方只有提交成功后才显式执行 `PostLoadInit`。普通加载仍立即刷新。这一机制只延后该处界面更新，不取消已有加载通知和资源创建。

`scene_resource_budget` 按实际池容量、嵌套数组、侧表容器及 DX9 查询结果统计。相同地址或 COM 身份在一个批次内按最大已知容量收费，失败不覆盖调用方的报告。报告字段为 `cpuBytes`、`d3d9Bytes`、`totalBytes`、`missing`。

`MMS_OK` 只表示统计完成，`Complete()` 才表示没有已知缺项。原始文本容量、旧撤销预留容量、Bullet 私有数组、任意曲线回调、Alembic 私有缓存或外部 MMV 资源无法完整查询时，报告保留对应 missing 标记。全局纹理缓存、分配器元数据和驱动私有开销不属于该对象保留数据预算。

`resourceBytes` 仍须由调用方提供完整预算，组件另计历史包装及绑定记录开销。单次报告不能覆盖后续池增长或新生成的物理快照；同对象跨节点也仍可能重复收费。自动预算接入尚未完成，探针中的固定预留值不代表实际测量，也不能忽略 missing 后直接启用导入和删除菜单。

准备好的对象、绑定、物理和附件曲线候选各自保有内部记录。调用方释放原包装对象或历史记录后，候选仍可验证及取消；这不会延长 `MMDApp` 和物理世界的寿命。同一槽位先删除旧对象、再导入新对象时，两个对象分别保留原生指针、关键帧池及作者状态，并按共同历史顺序恢复。

`curve_host::AccessoryAuthoring` 单独保留附件的自由曲线、切线及原生基准。发布通过提取或插入已有 `std::map` 节点完成，不分配内存，也不覆盖相机等其他轨道。曲线编辑器的关闭和刷新不属于该发布阶段，须在宿主接入时安排。

所有导入及删除入口接入后，才能让保留对象长期存在。绕过组件直接释放原生对象会破坏其所有权约定。工程重置和关闭时，未完成候选及所有保留对象必须先于 `MMDApp` 和物理世界释放。对象仍存在时，保留对象析构不销毁活跃对象；对象已退出场景时，最后一个所有者负责释放资源。

## Bullet 移出和恢复

增强构建的 `history_physics::Broadphase` 保持原有 `bt32BitAxisSweep3` 算法，并允许预先准备、交换碰撞对缓存。`history_physics::Retained` 记录要保留的刚体和约束，原始兼容构建保持旧路径。

封装在创建碰撞代理时初始化其包围盒，支持导入后尚未执行第一次物理更新就准备历史。状态校验只比较三维坐标和变换矩阵的有效分量，不读取 Bullet 向量未使用的第四分量。

移出时，刚体退出物理世界的碰撞对象和非静态刚体数组，约束退出约束数组。组件保留原有代理句柄，将碰撞及射线过滤掩码设为零，并禁用刚体模拟。恢复时重新加入原指针，恢复数组顺序、过滤掩码和激活状态。对象保留期间的速度、姿势和资源不通过重新构造获得。

准备阶段分配目标数组和碰撞对缓存。恢复会显式检查重叠，因此静止物体无需先移动才能重新参与碰撞。未受删除影响的碰撞算法及接触数据继续保留。`Publish` 不分配 C++ 或 Bullet 内存，也不销毁资源；旧接触在候选析构时清理。`CommitNative` 和编辑事务提交在释放编辑锁前销毁已发布候选。任何物理推进或物理世界销毁前，都必须先销毁这些候选。

候选校验物理推进序号、物理数组、碰撞对、代理包围盒、过滤参数及刚体状态。准备后发生物理推进、碰撞检测或相关状态变化会使候选失效。停车期间的刚体必须保持不变，恢复前也会检查。当前不支持物理 action、碰撞过滤回调、ghost 回调、碰撞对用户回调、约束过滤引用，以及关联保留刚体但不在本次保留集合内的约束。保留约束的两个端点必须都在保留集合内；不满足时拒绝准备。

`Retained::PrepareBatch(objects, present)` 为同一物理世界中的多个保留对象准备一组物理数组和碰撞对缓存，随后统一发布。单对象接口也使用这一实现。整批删除后可分别恢复，分别删除后也可整批恢复；组件合并保存的顺序约束，冲突时拒绝准备。跨保留对象的关节仍不支持，即使两个端点都在批次内也会拒绝。

对象批量接口要求列表非空、所有对象属于同一应用，且同种对象的槽位不重复。模型和附件可以使用相同数字槽位。重复所有者、失效成员、替换 broadphase 或冲突顺序都会拒绝整批操作，不发布部分对象。公共场景多对象写入服务仍待接入。

## 已实现的事务规则

begin 校验非零场景修订号，并复制标签。事务创建者负责 prepare、commit、cancel；其他插件可通过自己的上下文 join 该事务，但只能交付本插件的 participant。每个插件在同一事务中最多加入一次，并须已注册 serializer。

prepare 在宿主编辑锁内重新校验修订号和 serializer 注册代次。所有 participant.prepare 成功后，宿主才读取 before/after 不透明字节，深复制并释放借用租约，最后为统一历史预留发布资源。任何一步失败，取消全部已经接受的 participant，消费事务，不追加历史。

commit 只接受已准备事务，在同一编辑锁内再次检查场景修订号及 serializer 注册代次。检查通过后消费各 participant 的 context，最后调用 `EditPublication::Publish()`。发布对象须在 prepare 阶段完成内存分配；Publish 只交换状态和已经准备好的历史节点，不运行插件回调或消息循环。

有效的 commit 尝试不论成功还是失败都会消费事务。重复 commit 返回 STALE；重复 cancel 不产生影响。prepare 后不能 join；未 prepare 的 commit 返回 CONFLICT，仍允许修正或取消该事务。插件停止前，`EditStore::Retire` 取消其创建或参与的未完成事务。

违反无异常 commit 契约时，内核停止接受新编辑。不对已消费 context 再调用 cancel，也不将半提交状态标为成功；退休返回失败，宿主接入时须据此保留实例和 DLL。原生插件在进程内执行，这一保护不能消除违规回调自身造成的状态改动。

`StorageStore::PrepareRestore` 只恢复历史记录包含的插件。缺失 provider 时不调用其他候选；任一 prepareLoad 失败时取消已经准备的数据，不改变当前状态或历史游标。恢复不会覆盖 `readSaved` 所指的磁盘保存基准。

## 原生恢复的准备与发布

增强构建已将 `UndoModelEdit` / `RedoModelEdit` 接到 `native_history::ModelEdit`。内部声明见 `include/mikudancestudio/native_edit_history.hpp`，实现见 `src/model/native_edit_history.inc`。原始兼容构建保留旧路径。这一步改造原生恢复过程，尚未把原生和插件记录排入共同历史。

`Prepare(model, frame, redo)` 复制本次操作涉及的姿势、关键帧及辅助状态，分配 redo 缓冲，准备缩放和曲线侧表。关键帧按被修改的槽位保存，不复制整个骨骼关键帧池。类型 4 的连续操作整体准备，最多检查 30 个环槽；损坏循环直接拒绝。覆盖范围如下。

| 原生记录 | 恢复内容 |
| --- | --- |
| 1、3 | 未注册骨骼位置、旋转、编辑标志；类型 3 另恢复当前帧。 |
| 2、4 | 完整骨骼键记录、姿势及链式操作的中间 redo 状态。 |
| 5 | 烘焙键、最大帧、分配游标、骨骼物理开关及缩放键。 |
| 6 | Morph 全池、曲线及切线、最大帧和分配游标。读取真实散布操作产生的 before/after。 |
| 7 | 删除前的骨骼键、Morph 键、显示键、IK 标志和外部亲骨骼选择值；保留活跃数组的所有权。 |

`IsCurrent(frame)` 检查本次读取的数组身份、容量、环槽、快照内容、原生值及侧表。`Publish(frame)` 再次校验，随后只复制准备好的值和交换容器，不分配内存、不发送窗口消息、不求值、不调用插件。候选只能发布一次；放弃候选不改活跃状态。调用者必须保证模型仍存活，并从准备到发布一直串行化编辑。该内部指针接口不能直接暴露给插件，也不能代替宿主的对象代次检查。

`Refresh(physicsMode)` 在发布之后同步物理标志和界面，按原生类型执行必要的重新求值。它不属于无分配发布阶段。按钮和快捷键改用返回成功状态的 `TryUndoModelEdit` / `TryRedoModelEdit`；准备失败时不继续修改工程 dirty 标记或撤销按钮状态。

MSVC 的某些容器移动构造会分配内存，因此包含 `std::map` 的状态对象不能用整体 `std::swap` 实现发布。缩放、骨骼自由曲线及 Morph 层改用各容器自身的 `swap`。回归测试在发布期间禁止 C++ 分配，验证这条约束。

当前恢复候选要求快照容量不超过仍存活的池。池被替换或缩小会使候选失效。可撤销删除须保留模型及其池，恢复对象后再允许恢复其更早的编辑记录；永久释放才使该对象的历史资源失效。恢复辅助不会为了应用过期记录而改写新对象。各原生编辑入口创建历史的过程尚未全部改成两阶段提交。

## 宿主接入边界

`EditHost` 是本体内部接口，不进入公共 C ABI。

| 方法 | 本体责任 |
| --- | --- |
| `Revision` | 返回统一场景编辑修订号，覆盖关键帧、未注册姿势、参数、绑定与插件工程状态；不能仅返回绑定几何快照的观察修订号。 |
| `Enter` / `Leave` | 串行化原生和插件编辑；在加载、保存、播放求值、烘焙或其他原生修改未完成时拒绝进入。 |
| `Reserve` | 准备一次操作的原生候选及历史节点，保存插件 before/after，验证所有目标代次。失败不修改活跃场景或历史。 |
| `EditPublication::Publish` | 无分配地交换候选、追加一个共同历史节点、废弃对应 redo，并递增统一修订号。业务事件在完整发布后排队。 |
| `History` | 从共同历史选择 undo/redo，先准备全部原生和插件恢复数据，再一起发布。失败保留历史位置。 |

内核不拥有第二个插件专用撤销栈。旧测试中的 `EditHostFixture` 仅验证事务协议；新增测试直接使用 `SharedHistory`，主窗口接入也须使用这一实现。

| `vmd_load.cpp` | 动作导入；一次导入及其缩放、曲线数据应形成共同历史节点。 |

## 开放服务前的验证

需在真实宿主覆盖骨骼姿势、注册键、删除键、VMD 导入、物理烘焙和 Morph 散布，与插件状态改动交错后的 undo/redo；并覆盖跨模型、相机模式、对象删除、环槽回绕、工程重开、缺失插件和 schema 拒绝。prepare 或历史预留失败时，原生状态、插件状态、dirty 标记、修订号和历史游标均须保持不变。

Win7 和 AMD 真机项目暂列待验，不阻塞上述实现与本机验证。接口继续采用 Win7 目标、CPU 基础实现和厂商无关数据，不加入新系统或专有 GPU 的必需依赖。
