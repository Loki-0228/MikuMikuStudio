# 文档组织规则

文档以 main 分支实际实现为依据，按读者要完成的工作组织。同一功能发生变化时直接更新原章节，合并重复说明，移除已替代的行为和方案。

## 文档位置

| 位置 | 内容 |
| --- | --- |
| `guides/` | 功能入口、操作步骤、默认行为和常见问题 |
| `reference/` | 文件格式、字段、兼容边界及构建档范围 |
| `records/` | 按功能组织的实现机制与技术限制；目录名保留以兼容已有链接 |
| `development/` | 构建、测试、测量、接口和维护方法 |
| `records/*/data/` | 原始样本数据，保留其来源和测量条件 |
| `images/`、`ui/` | 文档图片和界面资源 |

## 编写当前功能

- 标题、文件名和正文不用日期组织内容，不累积「本轮」「随后」「某版本新增」等开发流水账。
- 先说明功能、入口、默认值和保存位置，再说明限制。完整包、最小包和可选插件分别标明范围。
- 冲突描述以 main 的实际代码为准。设计、候选实现和其他分支的能力不能列为已支持。
- 同一事实在主要页面完整说明，其他页面链接引用。已修复问题改写为当前行为；仍未确认的问题保留明确边界。
- 不把旧测试次数、过往截图或固定设备的性能数字写成当前版本保证。测量必须能追溯到程序身份、设备、素材和采样条件。

时间代码、文件格式版本、ABI 版本和有意义的兼容标记属于功能定义，可按需要保留。原始数据中的采样时间不应为排版而改写。

## 发布说明

[包说明](../records/releases.md)按功能维护安装、构建档差异及使用限制，历史版本说明在 GitHub Releases 和 Git 历史中查阅。打包需要的版本注释属于机器读取标记，不作为可见标题或导航。发布流程见[整理发布包](prerelease.md)。

## 引用与验证

移动或合并页面时同步修正文档内链，已有显式锚点保留为兼容入口；新链接使用无日期的功能锚点。检查相对路径、页内锚点、图片和数据文件，并执行 `git diff --check`。

纯文档调整检查结构与引用即可，不要求重建程序。改动实际构建输入或测试逻辑时再运行对应检查。
