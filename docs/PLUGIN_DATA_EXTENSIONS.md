# 插件数据格式与编辑工具接口方案

本文定义格式读取、查看、编辑、转换和导出的建议协议。新增服务与结构均为提案，尚未加入 SDK。
本页遵循[统一扩展架构](PLUGIN_EXTENSION_ARCHITECTURE.md)。简单格式插件和完整编辑器使用同一套 C ABI、对象身份、UI、资源和共同历史。

## 当前实现与新增范围

`scene.h` 已提供绑定阶段的对象、网格、骨骼、蒙皮、Morph、材质、纹理路径及原始物理记录。该接口只读，尚无拓扑编辑、任意格式提供者、纹理内容租约或约束图编辑服务。
`storage.h` 已提供 `mms.serializer`，可以保存插件专用字节。序列化不自动把这些字节变成可查询、可渲染、可编辑的公共对象。
`edit.h` 已定义共同事务，受控宿主已有原生与插件状态的混合历史验证。普通宿主仍不发布 `mms.edit`。内部导入、删除和键帧计划器不是供插件使用的公共 ABI。

新增格式能力覆盖模型、网格、骨骼、蒙皮、UV、表情、材质、纹理、动画、物理、约束、几何缓存和工程结构。
格式扩展不等于给文件选择器增加后缀。提供者必须分别声明自己能读取、查看、修改、转换和导出的内容。

## 格式能力与流程

建议 `mms.format` 管理格式提供者和作业；实际解析与编码由 `mms.format.provider` 提供者完成。

| 声明 | 内容 |
| --- | --- |
| 格式身份 | 提供者 ID、格式 ID、格式版本集合、扩展名、MIME、探测规则和 schema 版本。扩展名仅用于候选筛选。 |
| 读取 | 可映射的公共 schema、可保留的专有块、外部资源规则、流式或随机访问要求。 |
| 查看 | 可产生绑定几何、求值结果、缩略图或只读专用面板的范围。 |
| 编辑 | 支持的属性及操作，例如修改顶点位置、重建拓扑、修改权重、增加节点。可读不代表可写。 |
| 导出 | 每个目标版本可表达的 schema、限制、外部文件及纹理能力。能导入某版本不代表能导出。 |
| 转换 | 可提供的单位转换、拓扑转换、动作重定向、烘焙及降级策略。每种策略声明代价与损失。 |

建议 `MmsFormatCapabilityV1` 包含 `formatId`、`formatVersion`、`schemaId`、操作位集和可查询的约束描述。操作位至少区分 `READ`、`INSPECT`、`EDIT`、`EXPORT`、`CONVERT`。
静态能力用于界面筛选，实际对象还需 `assess`。例如格式可导出蒙皮，但当前对象的影响骨骼数超过格式限制时仍须诊断。
格式探测只读取有预算的前缀或受限随机区段，不修改工程。多个提供者匹配时由用户选择，宿主不按最后注册者覆盖。

导入分为文件读取、私有候选验证、只读预览、编辑事务发布。预览可以包含专用数据查看器，关闭预览只释放候选。
转换可以作用于候选文档，也可以准备当前工程的编辑候选。前者不产生工程历史；后者必须明确提交到共同历史。
导出读取冻结的工程修订。导出任务不能为了满足格式限制临时修改原工程，再尝试恢复。

## 公共数据与插件专用数据

建议 `mms.data.schema` 注册版本化 schema，`mms.data.read` 提供不可变文档快照，`mms.data.edit` 创建和提交私有变更候选。现有 `mms.scene` 继续作为已发布的绑定及求值读取视图，不改写其 V1 布局。
公共 schema 由宿主定义，字段单位、坐标系、引用、默认值和验证规则统一。扩展字段放在插件命名空间，不能篡改公共字段语义。
公共文档是编辑源数据，求值帧是计算结果。把计算后的顶点写回源数据属于显式烘焙，不能由刷新或渲染自动执行。

| 公共数据族 | 建议基本记录及约束 |
| --- | --- |
| 文档与对象 | 文档 ID、对象 ID、层级、实例引用、单位、坐标系及资源根；项目间引用显式声明。 |
| 网格与 UV | 稳定顶点、边、面及面角 ID，拓扑、每域属性、UV 集和法线；UV 缝可按面角存储，不能只用现有逐顶点 UV 表达。 |
| 骨骼与蒙皮 | 稳定骨骼 ID、层级、绑定矩阵、权重及变形算法；算法限制由目标能力报告。 |
| 表情与动画 | 目标 ID、通道、曲线、插值、时间基准、分层及混合规则；支持范围逐项查询。 |
| 材质与纹理 | 公共材质参数、具类型的节点及连接、纹理内容引用与色彩元数据；未知节点保留为专有结构。 |
| 物理与约束 | 刚体、形状、关节、约束类型、求值依赖及参数单位；宿主不能求值的类型保留并标记未支持。 |
| 几何缓存 | 拓扑版本、时间索引、块化点或变形数据、插值及缺帧规则。 |

首版优先表达现有加载器能恢复的记录，再逐项开放面角属性、节点、约束和缓存。公共 schema 能描述某字段不代表当前求值器、原生保存器或导出器能够处理。
每个文档可同时包含公共记录、插件专用块、资源引用及来源映射。专用块拥有稳定 ID、owner、schema、依赖集合和不可变字节资源，不以任意内存指针作为持久化格式。
插件可为专用块提供只读查询、预览几何、属性面板、编辑命令和求值提供者。其他工具只通过公开 schema 或服务操作该块；不能猜测字节布局。

### 未知数据的保留与写回

导入候选保存来源格式及版本、原始字段或块、原索引与稳定 ID 的映射、外部引用清单，以及影响原始编码的依赖修订。
原始块状态建议分为 `PRISTINE`、`REWRITABLE`、`OPAQUE`、`INVALIDATED`。原字节保留与可直接写回是不同能力。

| 修改情况 | 写回规则 |
| --- | --- |
| 依赖未变化，格式与版本相同 | 提供者确认块边界及引用有效后，可保留原始编码。 |
| 已知字段改变，提供者理解该结构 | 重新编码已知字段，并验证未知字段的长度、偏移、索引与校验依赖。 |
| 顶点、骨骼、材质索引或资源关系改变 | 必须按稳定 ID 映射修正所有相关引用；不理解的相关块转为 `INVALIDATED`。 |
| 目标格式或版本不同 | 原块仅在目标支持的扩展容器中保留；否则导出计划列出保留失败。 |
| 插件缺失或 schema 无法识别 | 原块和资源继续保存，可查看公共部分；相关编辑和导出明确禁用或报告损失。 |

不得把含旧索引和偏移的未知字节盲目拼回修改后的文件。`OPAQUE` 表示内容可保留但未保证能独立重写；依赖变化必须重新评估。
缺失插件时允许保存 MMS 工程的完整 opaque 包，不能因为没有查看器就丢弃数据。不能安全维护依赖的公共编辑须拒绝，或让用户明确接受将相关块标记失效；失效标记、旧数据和诊断一并进入事务。
已知数据与专有块发生冲突时，由格式提供者的写回规则决定权威来源。导出计划必须说明采用哪份值，不能无提示覆盖用户修改。

## 身份与拓扑变化

现有 `MmsTriangleV1.vertex[]` 是快照内索引，不可作为跨编辑持久身份。新编辑 schema 为顶点、边、面、面角、材质、骨骼及动画通道分配稳定 ID。
移动顶点或调整权重保留 ID。分裂生成新 ID，并记录来源关系；合并记录多对一映射。删除保留历史墓碑，正常创建不复用已删除 ID。
建议 `MmsTopologyRemapV1` 描述 `oldId` 到零个、一个或多个 `newId` 的映射、关系类型及可选权重。映射仅说明关系，不自动决定所有工具的语义。
选择集合、Morph、权重、约束和专有块分别声明如何处理 remap。删除被引用骨骼或材质时，候选必须同时给出重绑定、级联删除或拒绝策略，不能留下悬空引用。
撤销恢复原稳定 ID 和原数据。重建的运行对象获得新 generation，旧引用不能写入恢复后的对象。未受影响对象的 ID 不因容器重排而改变。
历史中的同一对象可以恢复旧结构修订，但宿主发布的运行修订保持单调增加。缓存依据发布修订失效，不能把旧内容编号当作新运行状态。

## 资源租约与大数据

建议 `mms.resources` 提供 `createStaging`、`writeChunk`、`seal`、`describe`、`mapRead`、`unmap`、`retain`、`release`。输入格式、尺寸、哈希、资源版本和字节数显式声明。
`seal` 成功后资源不可变，按块或内容哈希共享；已发布快照不会指向后台仍在写入的缓冲。
纹理、几何缓存、导入源块和历史恢复数据使用内容租约。文件路径仅是来源说明，不能替代重做所需的内容。
外部资源明确选择嵌入、复制到宿主管理的内容仓库，或保持外链。保持外链时记录内容指纹及缺失策略；要求可撤销恢复的内容必须额外保留，不能在重做时重新读取外链。

候选、快照、资源缓存、任务和历史分别计量，共享字节只计一次，引用开销另计。数量与字节乘法检查溢出，单对象、单事务和总量上限可查询。
大数据可分块准备和写入宿主临时仓库。准备取消、校验失败或进程重启时，未发布块由事务清单回收；已被工程或历史引用的块不能一起删除。
磁盘支持的历史必须有校验、原子清单和恢复协议。缺少资源时整次撤销或重做失败，游标不移动，不能只恢复剩余对象。
当前 `edit.h` 插件 before/after 每块上限为 64 MiB。大网格不能靠扩大字节数组绕过预算；公共数据变更由宿主原生参与者保留块资源，插件专有大数据另需版本化的资源引用恢复协议。
在该协议实现前，超过现有限制的私有历史明确拒绝。`mms.storage` 的旧字节协议保持原语义，不暗中把路径字符串当作恢复内容。

## 建议 C 协议

以下为接口形状和调用契约，不是已发布头文件。省略的能力位和具体 schema 在各能力实现时冻结。字段沿用统一 ABI 规则。

```c
typedef struct MmsDataRefV1 {
	MmsHeader h;
	MmsId documentId;
	MmsObjectRef object;
	MmsId elementId;
	uint64_t structureRevision;
} MmsDataRefV1;

typedef struct MmsDataChangeSetV1 {
	MmsHeader h;
	MmsId documentId;
	uint64_t expectedRevision;
	MmsHandle candidate;
	MmsSpan affectedObjects;
	MmsSpan resourceLeases;
	uint32_t flags, reserved;
} MmsDataChangeSetV1;

typedef struct MmsFormatDiagnosticV1 {
	MmsHeader h;
	MmsId diagnosticId;
	MmsDataRefV1 target;
	MmsString fieldPath, message;
	uint32_t severity, lossKind;
	MmsSpan availableActions;
} MmsFormatDiagnosticV1;

typedef struct MmsDataEditApiV1 {
	MmsHeader h;
	void* context;
	MmsResult (MMS_CALL *createCandidate)(void*, MmsHandle snapshot, MmsHandle* candidate);
	MmsResult (MMS_CALL *stage)(void*, MmsHandle candidate, MmsSpan operations);
	MmsResult (MMS_CALL *validate)(void*, MmsHandle candidate, MmsHandle* report);
	MmsResult (MMS_CALL *freeze)(void*, MmsHandle candidate);
	MmsResult (MMS_CALL *attach)(void*, MmsHandle transaction, const MmsDataChangeSetV1*);
	MmsResult (MMS_CALL *discard)(void*, MmsHandle candidate);
} MmsDataEditApiV1;
```

`elementId` 为零表示整个对象。`structureRevision` 用于拓扑和字段路径的校验，不替代对象 generation。`candidate` 是宿主所有的候选句柄，不能填插件指针。
诊断的 `lossKind` 区分不支持、精度降低、引用丢失、时间采样、物理烘焙和原始块失效。`availableActions` 记录稳定动作 ID、参数 schema、默认是否安全、预期损失和处理范围。
`operations` 是带记录版本的操作数组，每项包含操作种类、目标引用、schema 字段、期望修订及具类型的值或资源引用。创建、设置、插入、删除、重绑定、拓扑 remap 分别校验，不接受一段任意宿主内存补丁。
`snapshot=0` 表示新建空的私有导入文档；宿主预留新 ID，只有发布后才出现在工程中。从已有快照修改则保留基线身份和修订。
`validate` 成功表示诊断完成，report 中另有 `valid` 和诊断项。数据不合法时仍可成功返回 `valid=false` 的报告；分配或调用本身失败才返回错误且不写输出。报告使用只读租约并须释放。
`affectedObjects` 和 `resourceLeases` 是待验证的声明，宿主从实际候选再次计算依赖和变更范围。不能用漏报对象绕过冲突检查或历史保留。

| 建议函数表 | 核心函数及契约 |
| --- | --- |
| `MmsDataSchemaApiV1` | `enumerate`、`describe`、`queryOperations`；查询公共与扩展 schema 的读写范围，不授予修改权。 |
| `MmsDataReadApiV1` | `acquire(document, query, outSnapshot)`、`read(snapshot, refs, fields, outSpan)`、`release`；全部读取同一冻结修订。 |
| `MmsDataEditApiV1` | `createCandidate(snapshot, outCandidate)`、`stage(candidate, operations)`、`validate(candidate, outReport)`、`freeze(candidate)`、`attach(transaction, changeSet)`、`discard(candidate)`；准备期间不改正式文档。 |
| `MmsFormatApiV1` | `enumerate`、`probe`、`read`、`assessExport`、`createExportPlan`、`write`、`queryJob`、`cancelJob`；耗时入口返回作业句柄。 |
| `MmsFormatProviderV1` | `describe`、`probe`、`read`、`assess`、`write`；接收输入资源、候选构建器或冻结快照，不接收 `MMDApp*`。 |
| `MmsToolsApiV1` | `registerTool`、`activate`、`deactivate`；注册输入、命中、操纵器与面板关联，不创建第二套 UI。 |
| `MmsSelectionApiV1` | `acquire`、`createSet`、`replace`、`subscribe`、`release`；具文档身份、类型、稳定子元素 ID 和选择修订。 |

数据读取、查询字段和资源映射允许在持有租约的工作线程进行。`createCandidate` 将候选绑定到创建线程，stage、validate 和 freeze 在该线程执行，不允许多个写者。
`freeze` 成功后结束全部写入，候选可跨线程只读并交给 UI。stage 冻结候选返回 `CONFLICT`；需要继续修改时从冻结内容创建另一个候选。`attach`、共同事务及 UI 注册只在 UI 安全点执行，attach 拒绝尚未冻结的候选。
候选校验返回结构化诊断，不显示对话框。跨对象依赖全部声明；缺字段、坏引用、环依赖、不支持变形或无法准备物理结构时拒绝候选。
`attach` 成功后事务取得候选所有权，调用者不能继续 stage。失败时冻结候选仍归调用者，可按新基线创建另一个候选，或 discard。后续调用遵循现有 edit 的事务状态规则：进入准备或提交后失败，取消并消费事务，释放候选；进入操作前的 `BUSY` 等拒绝，以及未 prepare 就 commit 的状态错误，不消费事务。调用者依据返回值和事务状态决定重试或 cancel，不能把所有失败都视为句柄已失效。
格式提供者的读取和写入回调在其声明的工作执行器调用，不在 UI 上同步等待。回调通过作业上下文读取取消标记和报告进度；回调不得调用 UI 或开始工程事务。
`probe` 和 `read` 的输入是宿主内容流，不把当前工作目录作为资源根。提供者通过资源解析回调处理相对引用；越界路径和缺失资源返回具体诊断。

## 共同历史与原子发布

所有公共数据和插件专用状态加入现有共同历史。作者通过事务数量决定撤销粒度，一个事务一次撤销，多次提交多次撤销。
一个编辑事务只发布到同一活动工程。另一个工程可作为冻结输入；跨工程复制须映射新 ID 和资源，不承诺两个独立工程的原子撤销。
拖动笔刷可在私有候选中持续预览，松手提交一次；分步向导也可在每一步完成后提交。事务未提交期间禁止其他写入绕过其基线。

发布顺序如下。

1. 后台读取冻结输入，生成候选、资源和变更诊断，完成后冻结候选。
2. UI 安全点校验工程身份、来源修订、对象代次及依赖，调用 `edit.begin`。
3. `data.edit.attach` 接入公共候选，插件专用状态通过现有 participant 或后续资源恢复协议 join。
4. `edit.prepare` 准备全部原生运行结构、反向数据、资源保留和插件恢复状态。失败取消整批。
5. `edit.commit` 只交换已准备状态并发布一次修订；不解析文件、不分配、不执行 UI 回调、不推进场景。
6. 提交后排队通知依赖变化，刷新受影响界面，按明确需求安排求值或渲染。

网格拓扑、骨骼结构或物理配置会影响原生运行对象时，准备阶段必须构造可替换结构。不能在 commit 中调用可失败的加载器。
若现有结构无法安全替换，该编辑能力保持关闭，不能先改公共文档再让原生视口继续读取旧指针。预览使用隔离候选，不能拿正式模型做临时预览容器。
撤销和重做先准备节点中的全部对象、资源和插件状态，再一起发布。删去源文件、卸载提供者或资源缺失的情况分别验证；缺失必须参与恢复的插件时整次拒绝，历史游标不变。
空操作不增加历史、不清空 redo、不设置 dirty。失败和取消不移动播放头，不改变当前编辑姿态、选择或已经发布的工程数据。
选择通常是工作区状态，不单独写工程历史。某编辑操作需要恢复选中子元素时，在该节点中明确记录关联选择，不能用旧全局快照覆盖其他窗口的新选择。

## 格式 SDK 与完整编辑器

简单格式 SDK 的 `FormatSpec` 声明格式 ID、版本、能力、`read` 和 `write` 回调。`read` 填同一底层候选构建器，`write` 消费同一冻结文档和导出计划。
SDK 提供常见记录验证、单位转换、错误定位、资源引用和取消检查。宿主负责文件界面、作业进度、候选预览、能力禁用及事务提交。
只提供 `read` 的插件注册为读取提供者，导出入口不显示为可用。提供 `write` 也不能省略能力评估；SDK 可从声明约束生成基本诊断，特殊限制由回调补充。

复杂插件可以保留格式注册和候选对象，增加同一 `mms.ui` 命令、面板和专用视口。工具输入与数据事务分开，不要求重写格式加载路径。

| 工具示例 | 共同接口如何组合 |
| --- | --- |
| 类似 PE 的模型工作区 | 公共网格、骨骼和材质对象，子元素选择模式，视口操纵器，属性面板和同一编辑事务。 |
| UV 编辑器 | 面角或顶点 UV schema，二维画布、框选和捕获，候选预览与一次拖动事务。 |
| 权重工具 | 骨骼与影响权重读取，视口笔刷命中，归一化规则及权重候选；不直接写顶点数组。 |
| 材质节点编辑器 | 公共或插件节点 schema、连接检查、同一画布输入；渲染器不支持的节点显示诊断。 |
| 动作重定向 | 源与目标稳定骨骼映射，多时间冻结输入，后台候选计算，预览后一次或分步提交。 |

操纵器声明目标类别、命中方式、坐标空间、捕获、开始/更新/完成/取消回调和事务标签。
输入回调只更新预览或排队业务请求；工程写入按允许的顶层编辑上下文执行。取消、失焦、目标删除及插件关闭均丢弃未提交候选并释放捕获。
每个编辑器拥有选择集合，也可显式绑定宿主选择。工具不能因为在另一个视口悬停就自动改主工程选择。

## 导出诊断、计划与外部文件

`assessExport` 对冻结输入和目标版本生成逐对象、逐字段诊断。例如多于四个权重影响、不能表示的约束、缺失纹理、未知材质节点、不同拓扑的缓存帧，都必须定位到实际数据。
插件提供 `convert`、`bake`、`skip` 或 `abort` 动作。不能转换的项目不提供虚假的选项；跳过必须说明丢弃哪些对象、字段或资源。
`createExportPlan` 记录输入修订、提供者版本、目标版本、用户选择、转换参数和预计输出清单。执行时按该计划转换私有副本，不能重新选择默认降级策略。
工程在导出期间变化时，任务继续输出冻结版本并说明版本，或由调用者取消重建计划。不能混用新旧修订完成同一文件。

外部文件写入不属于工程撤销。撤销导入或转换不会删除已导出的文件，重做也不会再次导出。
编码先写宿主管理的临时输出，校验后替换目标。单文件使用可用的原子替换；多个文件使用清单、完整性校验和恢复方案，不能承诺任意目录树原子更新。
插件只能写任务授予的输出流和资源输出项。取消未发布任务删除其临时文件；已经发布的外部文件保留，任务报告完成或部分发布后的恢复状态。
需要将烘焙结果保存在工程时，另发明确的工程编辑事务；导出计划本身不设置 dirty，也不增加撤销节点。

## 落地顺序与验收

先实现公共 schema、内容资源及不可变文档读取，再提供私有候选验证和共同历史适配。模型拓扑、物理及插件资源恢复分别完成后才开放对应编辑能力。
格式读取与只读专用查看器可以提前接入。格式写入、损失计划和多文件输出需要独立验收，不能用成功导入代替导出测试。
工具注册基于已有 UI 和后续输入、选择服务；PE 工作区、UV、权重及节点工具作为逐项验证样例，不承诺全部由 MMS 本体内置。

验收必须包含以下场景。

- 同一格式插件先只用声明式读写，随后增加编辑器；格式、文档、资源和元素句柄仍来自同一套接口。
- 混合导入对象、修改拓扑、删除材质、重定向动作和插件专用块，一次撤销全部恢复；拆成事务后逐步撤销。
- 准备阶段任一对象失败、资源超预算、任务取消、引用过期或私有 schema 拒绝时，工程和历史游标保持不变。
- 导入后删除或修改源文件，撤销和重做仍恢复一致内容；资源仓库损坏时整次拒绝，不部分恢复。
- UV 缝、顶点分裂和材质重排保持已知引用正确；无法修正的未知块给出失效诊断，不能静默写回。
- 缺失插件的工程打开并保存后，原始专有块和资源引用仍保留；相关编辑不伪装可用。
- 冻结导出期间继续编辑工程，输出只包含固定修订；取消或失败不留下伪装成功的目标文件。
- 简单 UI 刷新、候选查看和预览不修改主播放头、当前编辑姿态、工程修订或历史。

Win7 SP1 x64 和 CPU 数据路径是基础实现；AMD 不能因厂商检查被拒绝。GPU 求值、特殊渲染及新系统能力按查询结果启用。编译、契约测试、真实宿主与硬件验收分别记录。
