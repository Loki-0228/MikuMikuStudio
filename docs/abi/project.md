### 期望行为

例如原模型为 `{OLD_ASSET_ROOT}\Models\A\A.pmx`，用户选中 `{NEW_ASSET_ROOT}\Models\A\A.pmx`，可推断 `{OLD_ASSET_ROOT}` 到 `{NEW_ASSET_ROOT}` 的根映射。尚未配对的 `{OLD_ASSET_ROOT}\Models\B\B.pmx` 与 `{OLD_ASSET_ROOT}\Effects\Light\main.fx` 分别探测对应的新路径；成功时直接继续加载，缺失或冲突时才保留手动选择。只按文件名搜索并不足以满足这项需求。

1. 保留文件内的原始引用与用户实际选择的路径。用户确认且加载成功的配对才能成为映射依据；选择后文件仍不存在、格式错误、加载失败或取消，不发布映射。
2. 按 Windows 路径组件分析目录，不做字符串片段替换。从已确认配对的末端向上识别保持不变的目录段，并对未配对引用求共同父目录。选择能解释这些相对层级的最高共同父目录作为旧根，推算对应的新根；不能越过不一致的目录段扩大范围。
3. 对每个未配对引用保留从旧根开始的相对路径，探测新根下的候选。多个已确认映射并存时优先采用更具体的目录映射；同等依据指向不同实际文件时保留未配对状态，不以目录扫描顺序决定。
4. 原文件仍可用或已经成功配对的对象不被改写。不同旧盘符、UNC 共享根或互不相关的目录分别归组。显式选择“跳过”的对象保留用户决定；其余待处理引用继续参与自动配对。
5. PMM 当前按流逐项读取。映射必须覆盖本次已登记的待处理引用，并在尚未读到的模型进入解析器时自动应用，不能只修正紧接着的一个模型。若某种格式不能提前完整枚举引用，应渐进登记，不能复制不完整的解析逻辑或丢掉已有动画数据。
6. 模型和效果共享本次工程的根映射；自动候选仍经过各自真实加载器及现有格式、编码和容量检查。效果包括 EMM 内的绝对引用和已锚定的相对引用；不得因为找到了文件就宣称效果编译或绑定成功。
7. 映射属于工程加载/显式效果恢复上下文，不是进程级永久替换规则。新建、打开其他工程、取消或失败时按所有权清理；普通单文件导入不能污染下一工程。加载不改写原 PMM/EMM，正常保存才持久化已接受的新路径。

开启「记住上次文件夹」时，已找回的模型或配件目录可供本次打开中的后续选择使用。整个工程成功打开后才更新应用记住的目录。若后续资源缺失而取消，重新打开时仍从上一次成功操作的目录开始。 取消与重开回归（本地证据，未随本文发布）
