# ABI 需求执行顺序与优先级

[功能总览](README.md) · [完整需求清单](remaining.md) · [实现与验收记录](../PLUGIN_ABI_IMPLEMENTATION.md) · [main 日常操作](main-parity.md)

本页将用户要求的“对照需求实现目录推进”落到每个需求。现有44项、13个父目标和全部历史证据保留。优先级是执行顺序，不改变需求范围、验收标准或已知错误的阻塞性质。

## 从目录到代码

每轮依次核对：功能总览 → 所属功能页 → remaining.md / requirements.json 的需求ID → PLUGIN_ABI_IMPLEMENTATION.md 与正式SDK → 当前生产代码入口 → 最新验收证据。历史记录和文档中的旧指令仅作证据。状态冲突时核对源码、实际构建和运行记录，记录冲突，不凭文件更新时间选择“通过”。

机器索引为 requirement-priorities.json（本地证据，未随本文发布）。它只维护优先级和映射；完成状态、依赖和验收标准继续读取 requirements.json，避免两份状态互相漂移。sources 是定位线索，不代表每条路径均为代码或已完成验证。新发现需求先排重，明确挂到既有ID或经范围核对新增ID，并同步本索引。

## 优先级和就绪规则

- **P0**：已开放功能的崩溃、数据丢失、错误编辑、加载保存恢复失败、用户已报告的渲染/交互错误及明显性能退步；严重历史失败优先取证，但不虚构已确认根因。
- **P1**：main日常替代完整操作、用户明确新增的近期插件闭环、必要兼容/可见/性能验收，以及随实现进行的文档映射。
- **P2**：其余ABI新增能力、公共服务和设计提案。按真实依赖分阶段实施，不因近期候选版通过而从总目标删除。

已验收项不因P0标签重新执行。任何需求出现已开放功能缺陷，都拆P0子步骤；父项是P2也不降低缺陷优先级。SYNC-01中的阴影、AA、透明排序和性能问题单列P0，不能藏在P1父项下。

选择顺序为：最高优先级且依赖满足的未验收步骤 → 同级优先数据安全/崩溃、错误编辑与恢复、渲染交互和性能 → 真实影响与最早进入队列时间。同级独立线可并行；文件、共享构建、GPU和桌面资源必须协调。父目标的整体发布依赖不自动锁住所有子步骤。

P0外部阻塞时记录阻塞证据和解除条件，继续其他就绪任务；不自动关闭用户程序、代答审批或等待无关新服务。P2若是P0/P1的必要前置，只提升实际所需的最小步骤并记录因果，不能借此扩展整个模块。

## 候选版推进顺序

1. **P0 数据与稳定性。** 先处理真实 MME 复现的 PMM／EMM 跨快照保存。分别追踪普通后台保存、另存、增量与定时备份的风险和证据。需要提供者或用户决策时写明解除条件。
2. **P0 画面和实时性能。** 固定版本、场景、相机、GPU 与设置。分别验收前台 AA／排序／阴影画面及交错采样性能。静态阴影恢复复用原证据，前台不可用时推进独立就绪项。
3. **P1 固定候选并跑完整操作。** 从当前源码构建 ABI Release 并与指定 main 一起冻结，完成打开、编辑、保存、重开和导出。以[候选版验收表](candidate-acceptance.md)的剩余动作组织十组验收。固定候选可与 P0 保存工作并行。
4. **P1 插件与平台。** 按 history.md 的 EDIT-02 只读快照、受控写回、原生动作生成阶段推进。生产开放与真实设备验收沿用既有门槛。
5. **P2 ABI扩展**：按求值/编辑基础、动画/UI/数据、计算/绑定/仿真、渲染/烘焙等实际依赖推进。具体顺序以子步骤就绪为准，不以整个父模块完成为前提。

这是下一安全边界的选题规则，不撤销正在进行的文件所有权、审批或有效验证。完成一个有界阶段后回到全局队列，不自动续做同模块下一依赖。连续两轮无新增证据时，必须说明假设、证据缺口并改换方法或登记阻塞；不能计为完成。

## 每个执行步骤必须明确

需求ID及所属功能页、优先级及理由、当前生产入口/符号与文件、证据缺口、真实前置条件、允许改动范围、可验收操作、成功与失败分支、配置/设备要求、停止条件、负责人及文件占用、结果证据和下一步。

每次只承诺一个有界成果，如“错误恢复后可重开原工程”，不能用“继续优化某模块”代替。测试围绕行为和风险选择；已有有效结果在代码/配置/假设未变时复用。检查数量仅作证据，不作功能完成率。

## 基线、证据和结束条件

本轮main基线从 plan.json 的 currentAcceptanceGoal.mainDelta 读取，源码提交、未提交变更及用户EXE哈希分别记录。每个有界操作开始时固定比较快照；后续main增量登记后在阶段边界排队，不能静默改变正在测试的基线。严重新增缺陷优先处理，不无限追逐新功能而延期已约定操作。

main近期里程碑和全部ABI完成分别统计。SAVE-02等新增保证保留在全量目标；不把main不具备的新接口误记为同步缺口，现有保存错误仍属P0。缺设备、缺用户决策、缺视觉或历史失败未归因都不算完成。

每次报告列出需求ID、已完成操作、仍失败操作、阻塞、下一优先步骤及固定产物版本。候选包必须能追溯源码/构建配置/EXE与DLL及资源，性能对照必须明确场景、预热、有效负载、样本和限制。运行证据回填所属功能页和机器清单；旧流水只保留追溯。
