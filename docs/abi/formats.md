## 当前推进范围

### 同名表情与贝塞尔曲线

同名表情导出 VMD 后，在表情定义一致的模型上重开会恢复各自的关键帧及贝塞尔曲线。表情定义变化时，保留目标有歧义的关键帧，只导入可唯一匹配的名称。完整包扩展格式与旧版读取边界见[名称扩展说明](../reference/pmm-extensions.md)。 实际 VMD 往返验收（本地证据，未随本文发布）

### 大型 VMD 导入

完整配置和原始兼容配置的默认准备、强制串行均可导入各 16,385 条骨骼和表情记录。每条轨道得到 16,384 个按帧排序的关键帧。同帧重复时采用文件中最后一条。提交骨骼值已变、表情段截断的同规模文件时，MMS 拒绝导入并保留现有动作与撤销状态。旧工具和实际桌面对照仍待验。 完整配置回归（本地证据，未随本文发布） · 双配置回归（本地证据，未随本文发布）

### 标准 VMD 交换

从菜单载入 VMD 时，文件选择器和模型名确认返回后会复核工程、目标模型和起始帧。目标变化会取消旧请求。取消或读取失败保留动作、未保存标记和记住的目录，菜单导入也保留物理重置状态。完整和原始兼容配置已验证切换工程、模型、帧，拒绝无效文件及重新导入到当前模型。拖入无效 VMD 的回归也通过。 VMD 导入回归（本地证据，未随本文发布）

完整配置与原始兼容配置分别导入同一份标准 VMD 并导出，再各自读取对方的文件并重新导出。センター骨骼第 0 和 18 帧的位置、旋转及四通道贝塞尔控制值一致，まばたき表情第 0 和 23 帧的权重一致。 原版 MMD 9.32 在隔离桌面于文件命令前退出，旧版双向互导仍待验。 标准 VMD 往返与原版启动记录（本地证据，未随本文发布）

从「文件 → 保存动作数据」导出 VMD 时，文件选择器返回后会复核工程、编辑模式和目标模型。取消、切换目标、目标目录消失或已有 VMD 被占用时，旧文件和记住的动作目录保持原状。修正后可重新导出并从菜单载入到另一模型。两种 Release 配置均通过 Unicode 目录和占用失败后重试。原始兼容配置另验证骨骼名超过 CP932 字段容量时给出提示并保留原文件。 VMD 保存失败与重试验收（本地证据，未随本文发布）

## 旧MMV配置迁移

目标 CFG-01 来源于内部设计参考（未随本文发布）的硬性要求和“工程与配置”能力行。VMM、VEM、EMM、EMD 由对应导入器负责显式迁移，不自动覆盖原文件，也不自动加载效果分配文件。

现有旧 MMV 桥仍调用 `MMV4MMSGetPluginApi`，将工程打开和保存事件交给旧 runtime。这条路径不证明旧配置已转换成新 ABI 对象。另一方面，[mms.serializer](../../sdk/mms/storage.md) 已能往返保留未知插件 schema 和原始字节；这是可复用基础，不应重复登记为未实现。迁移仍须建立旧对象引用与新稳定身份、绑定、层顺序、参数轨道的对应关系。

实现前先确定各格式实际支持版本和损失报告，再准备完整候选；依赖 FMT-01 导入协议、CMP-02 绑定与参数轨道和 EDIT-02 生产事务。发布失败、取消、缺插件或未知版本均保留原文件和当前工程。验收须有真实格式样本、成功保存重开和拒绝前后内容对照，不能只验证序列化字节或旧 DLL 的通知。
