## 执行与汇报

1. 按风险选下一项。优先处理数据一致性与崩溃，再处理用户已报告的画面、性能及其他候选阻塞。固定候选与保存方案可并行，构建、GPU 和桌面操作串行协调。
2. 验收前写明操作、预期结果、失败分支和证据。执行时引用候选包标识。每个新问题记录实际候选、配置、复现和证据；修改后只重跑受影响操作及必要相邻回归。
3. 外部阻塞写明解除条件，继续独立就绪项。若前台不可用，先做包与输入冻结、保存代码和可运行回归。隔离测试完成后继续保留必需的前台或真机验收。
4. 每轮只汇报三件事：**哪个用户操作通过了、什么还挡着候选版、下一轮关闭哪一项**。最新记录以此表和链接证据为准，整体完成率只在需求清单维护。
