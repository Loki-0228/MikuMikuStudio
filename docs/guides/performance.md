# 性能与设备

先区分模型计算、像素绘制与等待开销，再调整设备或预览比例。帧率数字只能用于同一工程、姿态、特效和测量条件的比较。

## 选择运算器

打开「帮助 → 运算器」，分别设置主渲染设备和顶点计算设备。主渲染决定最终绘制设备，顶点计算决定模型顶点由 CPU 或可用 GPU 处理。修改保存在程序旁的 `data/processor.ini`，跨工程使用，下次启动生效，不写入工程。

顶点计算的自动模式会比较完整顶点阶段的耗时，并检查结果。它的排名不是整帧性能排名。D3D9 没有提供的设备显示为不可选信息项；DXGI 能检测到显卡不等于该显卡能作为当前 D3D9 主渲染设备。

遇到兼容问题时选择 CPU 顶点计算并重新启动，再比较同一场景。DX12 不可用时保留 DX9 与 CPU 路径。设备选择和回退的具体依据见[运算器记录](../records/performance/devices.md)。

## 判断缩小预览是否有效

用相同的工程和镜头依次比较 100%、较低比例、较低比例、100%。比较期间保持动作、物理和特效配置相同，关闭其他渲染任务并等待编译、压缩结束。

- 像素或阴影绘制占主要时间时，缩小预览通常能减少这部分耗时。
- 模型更新、物理或 CPU 等待占主要时间时，降低分辨率的收益有限。
- MME 自建目标遵循 FX 声明，固定尺寸不随主视口缩小。预览比例只主动调整默认渲染的阴影贴图，不再单独适配某些 MME 阴影。
- TAA 与 SMAA T2x 需要运动历史，仍有不随像素数等比例下降的工作。

当前完整包和最小包会缓存未变化的模型结果。CPU 蒙皮下，如果只有镜头或描边参数变化，只更新必要的描边数据；动作、表情、物理或源几何变化仍正常计算。完整包还对适用的大模型减少 GPU 读回字节数，该路径仍经过 CPU 和 D3D9 上传。

缓存范围和预览开销见[预览与缓存专题](../records/performance/preview.md)。固定姿态吞吐率不能代替动作与物理播放帧率。
