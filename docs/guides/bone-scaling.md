# 原生骨骼缩放

骨骼缩放是 MikuMikuStudio 新增的动画功能，不属于原版 MMD 9.32 的功能对齐范围。PMD、PMX 的所有骨骼都可以缩放，不依据骨骼类型、可移动标记、IK 或物理状态禁用。

## 操作

在模型模式选择骨骼。视口右下角的移动按钮下方新增一排四个按钮：整体、X、Y、Z。箭头采用与原按钮一致的风格，指向四个对角方向。两根交叉箭头先合并轮廓，再对整体描边；XYZ 字母保持直立。

按住按钮向上拖动放大，向下拖动缩小。Ctrl 精调，Shift 加速。缩放使用乘法，默认每向上拖动 100 像素约放大到原来的 2.718 倍；不穿过零，也不产生负缩放或翻面。达到数值安全范围后，该次增量不应用。

| 按钮或模式 | 缩放方向 |
| --- | --- |
| 整体 | XYZ 等比缩放，不受坐标系选择影响。 |
| 局部 XYZ | 选中骨骼当前自身的轴，沿用原有局部轴定义。 |
| 全局 XYZ | 世界坐标的 X、Y、Z。 |
| 视图 XYZ | 相机视图的水平、垂直、深度方向。 |

每个受操作骨骼以自己的原点为中心。子骨骼的连接位置跟随父骨骼缩放，继承的形状随子骨骼旋转，长宽比例不会因旋转角度改变。此规则适用于多级骨骼，也适用于物理回写。多选包含祖先和后代时，只对选中的根骨骼施加增量，避免后代被重复缩放。多个互不从属的选中骨骼分别以自己的原点缩放。

切换局部、全局、视图只改变后续操作方向，不修改当前姿态。在不同方向上反复缩放仍可能产生斜切，因此运行时和存储都保留完整 3×3 变换，不把结果强制压成三个独立数值。单纯旋转子骨骼不会因父级非等比缩放而新增斜切。

Issue #16 修正了父级非等比缩放后的子骨骼旋转行为。PMM 和 VMD 的缩放存储格式不变；旧动作中依赖原有旋转拉伸效果的姿态会按修正后的规则显示。

相机、配件、灯光及无有效骨骼选择时，四个按钮显示禁用遮罩且不响应拖动。遮罩以图标透明度裁切，周围没有矩形底色。播放期间不能编辑。

### 面板缩放模式与视口手柄

模型面板的骨骼操作区是三列四行的按钮阵列。第一行第一格把原来的「選択」与「BOX選択」合成一个按钮：每次点击在非选择、选择、框选三种状态之间循环，按钮文案随状态在「選択」和「BOX選択」之间切换，按下态表示某个选择类模式正在生效。第一行另外两格是「全て選択」和「未登録選」。第二行是「移動」「回転」和新增的「拡大縮小」（英文 `scale`，中文「缩放」）。第三行仍是「コピー」「ペースト」「反転」，第四行仍是「登録」「初期化」「物理演算」。网格坐标集中在 `include/mikumikustudio/panel_controls.hpp` 的 `kBoneModeGrid`，由 `HandleWindowSize` 逐个应用，面板回归测试读同一张表，因此按钮位置只有一处定义。按钮的勾选态与合并按钮文案由 `RefreshBoneModePanel` 从 `MMDApp::EditMode()` 统一写出。

进入缩放模式后，视口在选中骨骼处绘制缩放手柄，替代原来的移动箭头：

| 手柄 | 外观 | 拖动效果 |
| --- | --- | --- |
| 视图平面方框 | 位于视图平面、一角对齐骨骼原点的白色半透明正方形，四边有白色描边 | 沿视图平面两个方向同时施加同一个缩放增量 |
| 单轴手柄 | 沿用坐标系选择器的 X、Y、Z 三根杆，杆端是轴色实心方块（X 红、Y 绿、Z 蓝） | 只缩放该轴 |

手柄的拖动量按本帧几何计算，不沿用右下角按钮的纵向像素差。单轴手柄取「轴端方块投影中心减原点」的屏幕方向，与鼠标位移做点积，因此 X 杆朝右时向右拖动放大、Y 杆朝上时向上拖动放大、相机转向后沿该杆在画面里的倾斜方向拖动才有效；光标沿垂直于手柄的方向移动时该次增量为零。白色方框是二维拖动：取「原点指向对角的屏幕方向」（方框位于视图平面，其屏幕投影恒为轴对齐正方形，对角线恒为 45 度）与鼠标位移做点积，得到一个增量同时施加到视图平面的两个方向，因此水平、竖直和斜向拖动都能改变缩放，远离原点放大、靠近原点缩小；这里不是按 dx、dy 分别给两个方向独立的倍率。Ctrl 精调与 Shift 加速与右下角按钮一致，公式仍是 `exp(增量 × 速度)` 并在 ±2 处截断。视口右下角 HUD 排保持原有语义：只看纵向像素差，向上拖动放大。原有的移动轴与旋转环拖动不经过这条路径，行为不变：屏幕平面骨骼移动本来就同时使用两个指针轴的位移。

命中测试优先判定轴色方块，其次是白色方框范围之外的杆，最后才是方框内部；方框覆盖的像素不触发单轴缩放。某一轴的投影长度不足以把手柄方块与原点和方框区分开时（该轴指向镜头，包括视图模式下收缩到原点的深度轴），渲染帧把该轴标记为不可用：既不绘制杆与方块，也不参与命中，这些像素全部归白色方框；该轴的 `DragScreen` 增量为零。判定阈值取「两块手柄方块的边长」与 8 像素中的较大者，因此近退化的轴在刚收缩时就会让位，不会与方框抢中心。

相机/配件/灯光面板、播放期间以及没有有效骨骼选择时，手柄不绘制也不响应点击：绘制与命中测试共用 `bone_scale::Enabled` 和本帧发布的几何两个条件，手柄所在渲染帧若未绘制就会把几何标记为不可用。

## 关键帧与撤销

缩放与骨骼的位置、旋转一起登记到现有骨骼关键帧。未登记的缩放属于当前姿态，切换帧时按已有姿态编辑流程处理。原有骨骼记录和关键帧结构的字节布局不变，缩放状态在独立表中维护。

两个关键帧之间对伸缩部分做线性插值，对分解出的旋转部分做最短路径四元数插值，避免直接插值矩阵导致中间帧塌缩。没有缩放数据的关键帧默认为单位变换；最后一个关键帧之后保持其数值。

支持撤销、重做、骨骼姿态复制与粘贴、关键帧复制与粘贴、镜像粘贴、帧移动和删除。镜像粘贴同时反射斜切分量。「初始化」恢复选中骨骼的单位缩放。「删除无用帧」会比较缩放，不能把只有缩放变化的帧当成重复帧删除。

关键帧烧录从原动作曲线采样缩放。物理烧录在独立 Bullet 世界中逐子步应用缩放，记录求解后与位置、旋转配套的缩放值，避免回放时重复缩放。新帧的缩放参与同一次撤销和重做。离线计算和取消不改变当前模型姿态、刚体或 joint。

### 缩放插值曲线

模型面板左下的插值面板（通道选择框 433）在模型模式下多出一项「拡大縮小 / scale / 缩放」，排在「回　転」之后、「すべて」之前，所以模型模式的通道索引是 0..3 原有四通道、4 缩放、5 すべて；相机模式的六通道与「すべて」保持原索引不变。缩放通道只有一条曲线，对完整的 3×3 缩放矩阵先用与骨骼四通道相同的 0..127 贝塞尔时间映射（12 步二分，与 `BoneEase` 同一取值域、同一 x1/x2/y1/y2 顺序）求出 eased 时间，再调用既有的 `bone_scale::Interpolate`。默认线性（20/20/107/107，与原骨骼四通道、相机六通道的线性默认一致）；区间属于它的终点键，与骨骼通道把 `BoneEase` 作用在正在应用的那把键上一致。

面板的左下控制点手柄、线性按钮 432、曲线复制 430、粘贴 431 与「すべて」都覆盖这条曲线：430 取第一个被标记关键帧的曲线，431 与 432 作用于所有被标记关键帧。曲线按关键帧槽位存放，随撤销/重做、关键帧复制以及姿态与关键帧剪贴板（含镜像粘贴；时间曲线与镜像无关）一起搬运；登记既有关键帧时保留曲线，槽位被池重新分配给新键时先清曲线，删除关键帧时矩阵与曲线一起清，因此复用的槽不会把上一把键的曲线带给新键。

持久化编解码已实现。PMM 在同一扩展容器里写 `org.mikudancestudio.model.<slot>.boneScale.v2`：先写 v1 的完整布局（两个 uint32 计数、60 字节的姿态项、64 字节的关键帧项），再按关键帧项的顺序为每个关键帧追加 4 字节曲线，依次是 x1、y1、x2、y2，取值 0..127。只有当这次导出至少有一条关键帧带非线性的曲线时才写 v2；一条非线性曲线都没有时仍写 `...boneScale.v1`，输出与改动前逐字节相同。

VMD 尾扩展同样如此：有非线性曲线时写 version 2，每条 entry 由 55 字节变为 59 字节，末尾追加同样的 4 字节曲线；没有曲线时仍写 version 1，payload 与改动前逐字节相同。footer、`prefixBytes`、`prefixCrc32` 以及 CRC32 的覆盖范围在两个版本里都一样，读取时的拒绝规则也不变。

PMM 按记录键的 `.v1` / `.v2` 后缀选择布局并严格核对负载长度，VMD 按 version 字段核对每项长度。截断的 v2 不能当作 v1 读取。v1 记录读回后每个键的曲线都是线性默认；线性曲线在内存里等同于没有条目，所以「没有曲线的键」与「显式线性曲线的键」写出的字节相同。曲线字节超出 0..127、长度与版本不符、CRC 不符以及未知版本都整块拒绝；未知版本后缀的记录原样保留在工程里。曲线按关键帧槽位存放，读取时先用骨骼下标与名称匹配到槽位，再把曲线写到同一个槽位。

单位缩放关键帧也可以带非线性曲线。例如从 2 倍回到 1 倍，末端 1 倍关键帧的曲线仍会保存；不能因为矩阵是单位阵而省略它。

## 保存与原版兼容

| 文件 | 缩放数据处理 |
| --- | --- |
| PMM 工程 | 当前姿态和缩放关键帧写入 [PMM v2 扩展容器](../reference/pmm-extensions.md)，优先保留旧版文件头，超出旧格式能力时按自动扩容规则保存。 |
| VMD 动作 | 标准 VMD 内容保持不变，缩放写入同一个文件末尾的版本化扩展。 |
| 普通 VMD | 没有缩放尾部扩展时，导入的骨骼关键帧使用单位缩放。 |
| VPD 姿态 | 标准段保存普通姿态，MMS 的[缩放扩展](../reference/vpd-scale.md)保存缩放；没有扩展时恢复单位缩放。 |

传递含缩放的动作只需一个 `.vmd` 文件。扩展以长度和校验值绑定标准前缀，未知版本或校验失败时不应用缩放，标准动作仍按原有流程读取。原版 MMD 9.32 可读取标准位置、旋转等动作，但不会显示骨骼缩放。

PMM 和 VMD 扩展长度按字段表示范围、地址空间和可用内存检查，缩放条目还受各自计数校验约束。无法保存时提示并保留已有文件。VMD 先写入同目录临时文件，完整写入并刷新后才替换目标文件。

通过原版 MMD 重新保存 PMM 或 VMD，会丢弃本程序的缩放扩展。原版可读取标准部分，不具备编辑或保存骨骼缩放的能力。

PMM 工程里的编辑模式字段是 4 字节整数，原版取值 0 到 4：0 选择、1 框选、2 无、3 旋转、4 移动。缩放模式写入 6，字段宽度、字节位置和前后字段顺序都不变；原版读到 6 时不匹配任何已知模式，行为等同「无模式」。本程序读回 6 会恢复到缩放模式。合并按钮的循环状态由 `EditMode()` 决定，不额外占用存档字段。

原版读取兼容性依据本地 MMD 9.32 x64 的静态核查：最后一个显示/IK 帧循环在文件 VA `0x14006E786` 结束，`0x14006E7B3` 随即关闭文件，没有检查 EOF 或拒绝尾部数据。参考 EXE 的 SHA-256 为 `07516fd3bf1e6b1339836b6773a156f61bdd6f848eeb621fdda012375df313a1`。这是代码路径核查，未启动原版界面作导入验证；不把结论推广到其他第三方读取器。标准骨骼帧只有位置和旋转等字段，可参阅 [babylon-mmd 的格式说明](https://noname0310.github.io/babylon-mmd/docs/reference/understanding-mmd-behaviour/introduction-to-vmd-and-vpd/#bone-keyframes)。

## 刚体与 joint

所有绑定骨骼的刚体都继承骨骼缩放，包括「骨骼追随」「物理演算」和「物理＋骨骼位置对齐」三种模式。缩放改变实际碰撞形状、相对骨骼的偏移和继承的骨骼间距。未绑定骨骼的刚体保持原状。

球、盒、胶囊保留完整仿射碰撞边界，支持非均匀缩放和斜切。Bullet 刚体仍保存正交旋转，形状包装器保存伸缩部分。动态刚体仅在缩放改变时应用增量，平常继续物理运动。模式 2 保留原有骨骼位置对齐行为。

joint 的 A、B 两端连接点分别继承对应刚体的形变，连接轴随之旋转。平移上下限按 A 端原连接轴的伸缩倍率更新，零距离锁定保持为零。角度上下限、弹簧刚度、质量和阻尼保持原值。防过度拉伸的距离也会更新，不再使用缩放前的长度。

任意斜切下，Bullet 六自由度约束仍要求三条正交轴，因此连接轴取极分解的旋转部分，平移限位按各轴长度近似。碰撞边界保留完整形变；惯性张量采用形变后包围盒的对角惯量近似，不代表精确的质量分布。

恢复单位缩放时恢复原碰撞形状和 joint 参数。缩放不改写模型的原始刚体尺寸、偏移或 joint 限位记录，保存 PMM/VMD 后由骨骼缩放重新求值。物理调试线框显示实际缩放形状。

## 求值边界

物理同步先更新碰撞形状和 joint，再求解刚体姿态。回写时分离父级形变、骨骼伸缩和刚体旋转，最终骨骼矩阵只应用一次缩放。渲染和烧录共用该求值逻辑。IK 仍按原有链长求解，不根据缩放重新计算 IK 链长。

位置使用完整仿射变换；非均匀缩放下的法线需要逆转置变换。SDEF 使用分解后的伸缩与旋转，不能直接把缩放矩阵当作纯旋转四元数。单位缩放继续使用原有蒙皮计算路径。

实现细节、历史构建与性能对照见[骨骼缩放验收记录](../records/animation/physics.md#骨骼缩放开发与验收)。
