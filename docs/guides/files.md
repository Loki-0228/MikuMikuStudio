# 文件与兼容性

| 文件 | 保存内容 | 用途 |
| --- | --- | --- |
| PMM | 模型与媒体引用、场景设置、关键帧和支持的工程扩展 | 保存和继续编辑整个工程 |
| VMD | 骨骼、表情及支持的场景动作轨道 | 交换动作，不代替 PMM |
| VPD | 骨骼姿态及支持的缩放扩展 | 保存或应用一组姿态 |
| EMM | MME 效果分配 | 与 PMM 和 FX 素材一起保留 |

## 优先保存旧格式

完整包保存 PMM 时先检查实际使用的内容。旧格式能容纳时使用 `0002`；预留空槽不会触发新格式，高位稀疏关键帧会在输出文件中压紧。

实际非负关键帧、显示计数或正帧号超出旧格式能力时，使用 MMS `0003`。原版 MMD 和最小包不能打开该文件头。名称扩展、引用路径的编码差异和负数关键帧本身不强制切换 `0003`。路径使用 CP932、系统代码页或其他可还原编码，必要时使用带标记的 UTF-8。字段内的字节在其他程序中可能显示为乱码；这不保证原版 MMD 能解析同一文件路径。MMS 按编码标记和实际路径解析还原。超出固定字段大小的路径仍拒绝保存。名称的完整文本保留在扩展中，标准部分保留模型加载器的绑定名称。

名称、剩余关键帧、显示分组、表情显示项和可用帧范围按内容计算并扩展，不要求用户手动设置容量。无法安全扩展或当前操作超出可支持范围时，程序拒绝该操作。

## 保存负数关键帧

在完整包中用 PMM 保存负帧编辑。负数关键帧与带符号的当前位置、播放范围保存在 `MMSXPMM2` 尾部扩展中，标准部分保持非负帧号，文件扩展名仍为 `.pmm`。当前读写不使用设计稿中的新分节布局。

要继续编辑负帧，保留完整 PMM。原版 MMD 读取 `0002` 时只恢复标准部分，重新保存会丢弃负帧扩展。含负数数据时不生成会丢失该数据的标准部分 PMM 副本。标准 VMD 导出只包含非负关键帧。

## 处理无法无损保存的名称

完整包在扩展中保留完整名称，并提示旧字段的差异。能够生成可用旧格式副本时，自动写入 `.compat.pmm` 或 `.compat.vmd`；同名副本添加序号。

短名称冲突、容量超限或路径不兼容时，程序说明不能生成兼容副本，不通过删除关键帧或错误匹配骨骼来生成文件。保存目的地的 Unicode 路径与文件内部引用的编码限制是两件事。

## 与原版或最小包交换文件

原版 MMD 重新保存 `0002` 工程时可能丢弃 MMS 扩展。最小包仅保存标准内容，忽略完整包的缩放、曲线和网格缓存扩展。交换前另存副本，并检查目标程序中的实际结果。

当前源码的最小包可以导入结构可解析、但名称或引用超出旧格式限制的 PMD、PMX，并保留数据、显示警告。保存时按所选格式检查 CP932 编码、字段长度和关键帧绑定。出现导入警告后，交换文件前仍需验证保存结果。具体边界见[旧版 MMD 限制实测](../reference/legacy-mmd-limits.md)；当前测试不能保证任意工程在 MMD 9.32 中无损往返。

详细数据定义见 [PMM 扩展](../reference/pmm-extensions.md)、[VPD 缩放](../reference/vpd-scale.md)和[最小构建档](../reference/minimal-build.md)。载入、保存、编码与容量的证据见[工程格式记录](../records/formats/projects.md)和[模型载入记录](../records/formats/models.md)。

## 自定义备份与增量命名

在「帮助 → 自动备份设置」中，分别点击「备份命名」或「增量命名」设置文件名规则。输入框下方用灰色只读框显示预览，快捷按钮在光标位置插入代码。`.pmm` 扩展名自动补齐。

| 代码 | 含义 | 示例 |
| --- | --- | --- |
| `[/NAME]` | 原工程名，不含扩展名 | Stage |
| `[/N]` | 序号，至少三位 | 001 |
| `[/YY]` | 两位年份 | 26 |
| `[/YYYY]` | 四位年份 | 2026 |
| `[/MM]` | 月 | 10 |
| `[/DD]` | 日 | 23 |
| `[/hh]` | 小时，24 小时制 | 15 |
| `[/mm]` | 分钟 | 09 |
| `[/ss]` | 秒 | 05 |

默认备份名称精确到秒；重名仍自动追加序号。已有自定义规则中的 `[/fff]` 仍可读取，但界面不再提供毫秒插入按钮。

代码区分大小写。日期、时间使用本机时间。除序号外，预览显示当前展开值。未知代码和非法文件名会阻止确认。

「增量保存」默认关闭，独立于定时备份。开启后，每次手动保存按规则创建新的 `.pmm`，成功后将新文件作为当前工程。已有文件不改名、不后移、不覆盖。重新打开增量文件后，`[/NAME]` 仍使用该系列的原工程名；另存为不同名称会开始新系列。

备份与增量规则分别保存。规则没有序号时，重名文件追加序号；已有同名 `.emm` 也会占用该名称。序号不限制为三位，文件路径仍受宿主长度限制。新 `.emm` 是否生成继续由 MME 的随 PMM 保存选项决定。自动备份仅清理带有匹配文件名归属标记的备份，不按自定义名称猜测文件归属。

「同时保存 .pmm1」仍用于普通覆盖保存时保留旧文件。增量保存已创建独立文件，因此不再额外移动 `.pmm1` 历史。
