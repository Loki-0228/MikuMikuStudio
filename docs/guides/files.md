# 文件与兼容性

| 文件 | 保存内容 | 用途 |
| --- | --- | --- |
| PMM | 模型与媒体引用、场景设置、关键帧和支持的工程扩展 | 保存和继续编辑整个工程 |
| VMD | 骨骼、表情及支持的场景动作轨道 | 交换动作，不代替 PMM |
| VPD | 骨骼姿态及支持的缩放扩展 | 保存或应用一组姿态 |
| EMM | MME 效果分配 | 与 PMM 和 FX 素材一起保留 |

## 优先保存旧格式

完整包保存 PMM 时先检查实际使用的内容。旧格式能容纳时使用 `0002`；预留空槽不会触发新格式，高位稀疏关键帧会在输出文件中压紧。

实际关键帧、显示计数、帧号或引用路径超出旧格式能力时，使用 MMS `0003`。原版 MMD 和最小包不能打开该文件头。名称扩展本身不强制切换 `0003`。

名称、剩余关键帧、显示分组、表情显示项和可用帧范围按内容计算并扩展，不要求用户手动设置容量。无法安全扩展或当前操作超出可支持范围时，程序拒绝该操作。

## 处理无法无损保存的名称

完整包在扩展中保留完整名称，并提示旧字段的差异。能够生成可用旧格式副本时，自动写入 `.compat.pmm` 或 `.compat.vmd`；同名副本添加序号。

短名称冲突、容量超限或路径不兼容时，程序说明不能生成兼容副本，不通过删除关键帧或错误匹配骨骼来生成文件。保存目的地的 Unicode 路径与文件内部引用的编码限制是两件事。

## 与原版或最小包交换文件

原版 MMD 重新保存 `0002` 工程时可能丢弃 MMS 扩展。最小包仅保存标准内容，忽略完整包的缩放、曲线和网格缓存扩展。交换前另存副本，并检查目标程序中的实际结果。

最小包要求名称和文件内引用能够用 CP932 完整表示，字段长度也必须符合旧格式。当前测试不能保证任意工程在真实 MMD 9.32 中无损往返。

详细数据定义见 [PMM 扩展](../reference/pmm-extensions.md)、[VPD 缩放](../reference/vpd-scale.md)和[最小构建档](../reference/minimal-build.md)。载入、保存、编码与容量的证据见[工程格式记录](../records/formats/projects.md)和[模型载入记录](../records/formats/models.md)。


## 自定义备份与增量命名

在「帮助 → 自动备份设置」中，分别点击「备份命名」或「增量命名」设置文件名规则。输入框下方用灰色只读框显示预览，快捷按钮在光标位置插入代码。`.pmm` 扩展名自动补齐。

| 代码 | 含义 | 示例 |
| --- | --- | --- |
| `[/NAME]` | 原工程名，不含扩展名 | Stage |
| `[/N]` | 序号，至少三位 | 001 |
| `[/YY]` | 两位年份 | 26 |
| `[/YYYY]` | 四位年份 | 2026 |
| `[/MM]` | 月 | 10 |
| `[/DD]` | 日 | 23 |
| `[/hh]` | 小时，24 小时制 | 15 |
| `[/mm]` | 分钟 | 09 |
| `[/ss]` | 秒 | 05 |

默认备份名称精确到秒；重名仍自动追加序号。已有自定义规则中的 `[/fff]` 仍可读取，但界面不再提供毫秒插入按钮。代码区分大小写，日期时间使用本机时间；未知代码和非法文件名会阻止确认。

「增量保存」默认关闭，独立于定时备份。开启后每次手动保存按规则创建新的 `.pmm`，成功后把新文件作为当前工程；已有文件不改名、不后移、不覆盖。规则没有序号时，重名文件追加序号；已有同名 `.emm` 也占用该名称。成功发布后新文件成为当前工程，同一会话内继续保留该系列的原工程名；另存为不同名称开始新系列。

备份与增量规则分别保存在中央设置的 `autosave` 段。自动备份只清理带有匹配文件名归属标记的备份，不按自定义名称猜测文件归属。

完整构建重新打开增量文件时会从 PMM 扩展记录恢复系列原工程名。原始兼容配置有意忽略工程扩展记录，因此该配置下重新打开的文件按当前文件名开始新系列，不沿用扩展中的原工程名；同一会话内的连续增量保存仍使用内存中的系列名。
