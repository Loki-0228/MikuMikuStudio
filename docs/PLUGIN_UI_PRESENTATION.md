# 插件界面样式、绘制与动画接口方案

本文固定界面需求和建议接口。基础 C++17 包装、声明式 INPUT、工具栏命令溢出、SELF／注册 SUBTREE 刷新、按钮及 INPUT STATE、绑定 DATA 与显示租约、INPUT 默认属性 DATA，以及保留布局 LAYOUT 已接入，实际接口以 SDK 为准。INPUT 编辑仅在受控共同历史宿主启用，普通启动只读。原状态内容服务提供文案、说明和禁用原因，并允许收紧 INPUT 的启用、只读和可见状态；通用菜单及面板内容的完整 STATE、自动依赖、绘制层和动画函数仍为提案。
本方案不改变普通宿主的 `mms.edit` 开放状态，也不把界面动画记入场景撤销历史。
跨 UI、视口和数据工具的分层封装以[统一扩展架构](PLUGIN_EXTENSION_ARCHITECTURE.md)为准；本页重点规定 UI 对象、刷新和交互。

## 目标与边界

MMS 本体默认不播放过渡动画。面板拖拽应实时跟随输入，旧位置及时重绘，不留下拖影。
插件可以实现复杂动画，自行计算时间线、缓动、弹簧、串联和并行动作。
触发源可以是场景事件、后台任务完成、快捷键、插件消息或界面操作，不要求来自控件。
动画目标可以是另一个控件、多个区域或独立绘制层，不要求与触发源相同或相邻。
宿主提供受控事件、目标定位、坐标转换、绘制资源、临时呈现和按需帧回调，不内置通用动画引擎。

首期覆盖插件绘制区域，以及宿主逐项声明支持的装饰区域。现有原生控件保留输入、焦点、输入法和辅助功能行为。
全界面换肤需要各原生区域接入样式绘制；全界面任意缩放、旋转、透明过渡还需要统一合成，不能仅增加 ABI 就宣称完成。
Win7 SP1 x64、CPU 绘制和 AMD 兼容是基础约束；不以 CUDA、NVAPI、AVX2、DirectComposition 或新系统 API 为必需依赖。

复杂行为由插件实现。宿主既不内置桌宠行为引擎，也不要求简单菜单插件理解绘制或动画服务。
底层只有一套稳定 C ABI，完整表达简单和复杂交互。可选的 C/C++ 便利 SDK 只包装这套接口。
简单插件使用声明和默认行为；复杂插件可以拆除默认行为，继续操作同一对象，不需要迁移到另一套 UI 系统。
注册表、状态、身份、权限、资源、绘制和生命周期只有一套实现；不同 `queryService` 表只是按能力划分入口。

## 当前实现

基础类型化和声明式注册已有 [C++17 SDK](../sdk/mms/cpp-ui.md)：`CommandUi` 用 `RegistrationBundle` 组合现有命令、菜单、按钮、分组和默认布局。原始 C 表、handle、权限及生命周期规则继续生效。失败回收受阻时保留引用，插件在 `stop` 中显式关闭并重试。数据刷新另由同层的 `data_refresh.hpp` 包装原来源、绑定和显示租约。

工具栏 BUTTON、GROUP 和 SEPARATOR 可在原布局提示中选择 `MMS_UI_OVERFLOW_MENU=3`。空间不足时，宿主将后序命令呈现为「更多」菜单；空间恢复后使用原按钮 HWND 和 handle。分组可继承该策略，`MMS_HINT_KEEP_TOGETHER` 保持整组折叠。菜单使用原命令的状态和调用入口，STATE 更新已有项，注销或失效时移除对应项。该范围仅限 `mms.toolbar.main.extensions` 及其 GROUP，完整语义见 [SDK 工具栏命令溢出](../sdk/mms/cpp-ui.md#工具栏命令溢出)。INPUT 已支持工具栏及 GROUP 挂载，但不支持溢出菜单；DOCK、侧栏、属性区、时间线和状态栏挂载仍未开放。状态：**本机已验证**；完整配置 21／21、原始兼容配置 18／18、ABI 契约重复 6／6。实现与验收证据见 [UI 框架记录](records/abi-ui-framework-2026-10-19.md)。

[重绘 SDK](../sdk/mms/cpp-refresh.md)用 `RefreshServices` 和 `RefreshTicket` 包装同一刷新 C 表，提供局部矩形便利方法、跨线程所有权移交及显式清理。原始票据可继续用于 C 接口，没有额外宿主实现。

[界面刷新接口](../sdk/mms/refresh.md)直接使用这些原始元素句柄，当前覆盖同插件已有按钮、INPUT 和原生 surface 面板的重绘、按钮及 INPUT STATE、有效绑定目标的 DATA 及保留布局的 SELF LAYOUT。完成不表示像素已显示。纯重绘不查询命令状态；按钮 STATE 只读查询目标命令和可选[内容提供者](../sdk/mms/state-content.md)，INPUT STATE 只读属性元数据和编辑可用性，不读取属性值。DATA 先准备完整显示候选再交换模型。只有显式请求 LAYOUT 才重新排版，纯 LAYOUT 使用缓存状态和已发布文案，不回调提供者。这些阶段不触发整个场景求值。

## ABI 共通约定

新增服务分别通过 `queryService` 查询，不改变现有 V1 函数表前缀。建议首版均为独立的 1.0 服务。
沿用 `MmsHeader`、`MmsResult`、`MmsHandle`、`MmsString`、`MmsSpan`、`MMS_CALL` 和 8 字节对齐。
跨 DLL 不传 STL、异常、分配器、长期有效的 HDC 或图形设备指针。描述、字符串和绘制指令由宿主校验后复制。
除已有 `enqueueUi`、下文明确允许跨线程的刷新入队和不可变租约读取外，UI 对象修改接口均限定 UI 线程。后台任务先排队，再发布事件或更新呈现。
所有成功注册返回归属调用插件的句柄；停止插件时统一撤销。失败不修改输出参数；DATA 候选准备失败保留旧模型。组合请求不承诺撤回已成功的阶段，应读取 completedKinds。

已实现的 `MmsUiTargetRefV1` 为 `{ h, element, instanceGeneration, projectEpoch }`，其中 `element` 是原 `mms.ui` 注册句柄。
`mms.ui.refresh.getTarget(element)` 返回本插件按钮或面板的运行时引用。注销、视图重建和目标失效会改变实例代次，正常移动只改变实际几何修订。工程替换或重置使旧 `projectEpoch` 失效。
现有 `MmsUiElementV1.generation` 会随布局提交改变，不能直接充当长期动画的实例身份；旧布局校验规则保持不变。
刷新目标还返回能力位、ready、逻辑可见性、客户区 DIP 尺寸及几何修订。后续 geometry 服务可增加稳定字符串解析、坐标变换、呈现修订和裁剪区域，不另建元素身份。
跨目标定位允许读取已公开目标。修改仍受目标能力和归属限制；宿主区域必须显式开放样式或装饰层权限。
其他插件未开放的视图不能被换肤、截取内容、移动或覆盖；不会因知道 ID 就取得写权限。

`acquireTargets` 一次声明目标集合和属性集合，全部校验后生效。首版同一目标同一属性只允许一个呈现会话持有。
多个插件争用同一属性返回 `CONFLICT`；不同目标或不同属性可独立运行。禁止用不确定的「最后调用覆盖」解决冲突。
`submit` 的整批目标、资源和数值须先验证，再替换宿主保留的呈现状态；失败保留上一批，不部分更新。
这仅保证内部呈现状态整批替换，不承诺多个原生 HWND 的窗口系统操作或屏幕扫描原子化。

## 简单插件的便利 SDK

当前可编译接口为 `mms::sdk::CommandUiSpec` 与 `CommandUi::Register`，完整示例见 [hello_menu](../sdk/mms/examples/hello_menu/plugin.cpp)。以下涉及默认刷新订阅、工具 SDK 和尚未开放能力的示例属于后续扩展，不表示现有便利层已实现全部行为。

建议提供 `CommandSpec` 和 `PlacementSpec`，声明命令 ID、标签、分组、顺序、位置候选、快捷键和状态函数。
属性控件再声明 `propertyId`、类型、范围和显示格式。没有编辑服务时保留只读显示，不绕过事务写入工程。
后续位置候选封装由宿主根据可用宽度选择菜单、工具栏、面板或溢出入口，统一处理文字测量、隐藏禁用、键盘导航及辅助功能。当前工具栏溢出只改变原按钮的呈现，不自动改换挂载点。
插件只提供业务回调；简单插件无需手动创建 HWND、计算像素坐标、编写重排或动画代码。

以下是便利 SDK 的声明伪代码，不是当前可编译 API：

```cpp
CommandSpec item;
item.id = "sample.analyze";
item.label = "分析动作";
item.placement = {"mms.toolbar.main.extensions", "mms.menu.plugins"};
item.group = "sample.tools";
item.order = 10;
item.overflow = Overflow::Menu;
item.state = QueryAvailableState;
item.invoke = StartAnalysis;
auto registration = sdk.RegisterCommand(item);
```

便利层内部调用真实的 `registerCommand`、`registerElement`、布局、样式和事件接口，不维护平行控件树或私有注册表。
C 包装返回同一底层句柄的带类型引用，C++ 包装增加可移动 RAII 所有权；组合结果保留命令、元素和订阅的各自引用。
插件可获取这些引用继续底层调用，也可拆除包装创建的默认订阅和布局行为，同时保留控件及业务状态。
移交所有权必须显式完成，借用引用不能再次销毁；原生 `MmsHandle` 兼容保留，由宿主校验对象类型和 owner。
局部注册失败时按逆序撤回本组已注册项目；这只是统一对象的批量清理，不建立第二套生命周期。
插件停止时宿主仍负责最终回收，不能仅依赖 C++ 析构。便利层不得偷偷创建后台线程或替插件运行重任务。
当前注册、布局、INPUT、显式选择的工具栏溢出及受支持的刷新 ABI 可用；INPUT 不进入命令溢出菜单。DOCK、侧栏、属性区、时间线和状态栏挂载仍未开放，见 [SDK 当前服务](../sdk/mms/README.md#当前服务)。
新增功能先检查服务及目标能力。溢出没有独立能力查询，旧宿主即使提供布局 1.0 也可能拒绝 `overflow=3`；须检查设置提示的结果，再由插件明确选择受支持菜单或报告不支持。
上下文菜单依据目标身份和只读状态生成；异步结果到达后更新注册描述，不在菜单绘制或状态查询中等待计算。

便利接口的声明与底层调用关系如下。

| 声明 | 底层对象和处理 |
| --- | --- |
| 标签、业务回调、启用条件 | 一个命令及状态绑定；菜单和按钮引用同一命令，不各存一份启用状态。 |
| 位置候选、分组、顺序 | 元素注册和宿主布局提示；先检查挂载能力，再按稳定顺序选择位置。 |
| 最小宽度、伸缩、换行、折叠 | 同一布局服务处理，用户保存的覆盖优先于插件默认值。工具栏的 `overflow=3` 和 `MMS_HINT_KEEP_TOGETHER` 已实现，其他位置的折叠仍待开放。 |
| 快捷键、焦点及辅助信息 | 命令快捷键与原生或开放的输入能力；冲突返回诊断，不能私自安装全局钩子。 |
| 属性类型、范围、面板 | 属性注册、读值绑定、面板 surface 和同一 UI 元素；写入须接共同事务。 |
| 依赖及刷新偏好 | `mms.ui.refresh.bind` 已实现来源到单目标显示模型的绑定，显式组合 DATA、STATE、LAYOUT 和 REPAINT；自动依赖传播仍待实现。 |

宿主为选择菜单溢出的工具栏命令提供「更多」入口。父区域没有可用宽度或高度时，该入口随父区域隐藏。未选择溢出的元素保留原裁剪或滚动规则，宿主不越过父区域显示菜单按钮。旧宿主拒绝该提示时，插件须明确选择已声明的菜单位置或返回不支持；便利 SDK 不静默改变挂载点。

## 统一刷新请求

当前 `mms.ui.refresh` 1.0 支持 SELF 和同插件注册 SUBTREE 的 REPAINT、按钮及 INPUT STATE、有效绑定目标 DATA、未绑定 INPUT 的属性 DATA，以及保留布局 LAYOUT；GROUP 仅支持 SUBTREE。绑定见[数据刷新 SDK](../sdk/mms/data-refresh.md)，子树及局部矩形见[刷新范围](../sdk/mms/refresh.md#子树范围)。DEPENDENTS 和来源自动订阅尚未实现。宿主逐目标及成员检查组合能力；执行时 completedKinds 记录已完成阶段，字段、配额及错误码以 SDK 为准。

| 请求位 | 当前状态与语义 | 不隐含的动作 |
| --- | --- | --- |
| `REPAINT` | 已实现：标记目标客户区的损伤区域，由窗口正常绘制。 | 不重新取数据、不求值场景、不推进时间。 |
| `DATA` | 已实现 SELF：捕获来源精确版本，准备完整候选后交换不可变显示模型；失败保留旧结果。 | 不写工程，不同步读取大文件，不自动计算整个场景。 |
| `STATE` | 已实现按钮启用、选中、受支持的显隐及文案、说明、禁用原因；INPUT 复用内容服务并可收紧启用、只读和可见状态。溢出菜单的已有项复用原按钮标签和命令状态。通用菜单、面板内容与自动依赖待接入。 | 不调用命令、不读取 INPUT 属性值，不在查询中提交编辑，不单独重排控件。 |
| `LAYOUT` | 已实现 SELF：使用保留树、缓存状态和已发布文案重新量测，排列已有按钮及已挂载 surface，发布完成的几何。 | 不保存一次新的用户布局，不自动增加历史。 |

### 已实现的重绘与票据

`getCapabilities`、`getTarget` 限定 UI 线程，允许在命令回调内纯读。`request`、`query`、`cancel`、`release` 可从工作线程调用。后台调用只复制输入并访问队列，不读取 HWND 或注册表。服务使用独立的刷新消息和 UI 安全点，不调用旧 `Refresh`、`HandleWindowSize` 或 `FrameDriver`。

局部矩形使用目标客户区 DIP，并带取得矩形时的非零 `expectedGeometryRevision`。矩形经裁剪后向外取整为像素区域。无矩形表示整个目标客户区，此时允许零几何修订，但仍要求目标已就绪、实例和工程代次匹配。DATA 必须填写有效 `binding` 及非零 `sourceRevision`；其他请求两者为 0。`flags`、`reserved` 为 0。

布局移动前暂停目标，失败后保持未就绪。暂停不改变修订；重新发布时只有实际位置、尺寸、窗口 DPI 或逻辑可见性变化才改变几何修订。隐藏但已有窗口的目标可以合法重绘，请求不会显示它或创建新视图。

相同 owner、目标引用、kinds、binding、sourceRevision、coalesceKey 和几何约束策略的待执行贡献可合并，同组 STATE 只查询一次。不同 kinds 独立执行，避免状态失败吞掉纯重绘。每个 ticket 独立完成、取消或失败。COMPLETED 表示请求的状态或区域失效操作完成，不保证已收到 WM_PAINT。release 不取消贡献。

STATE 回调和原生状态应用保持只读保护，不继承命令编辑来源。在同插件的只读因果链中重新提交 DATA/STATE 返回 BUSY，包括由该链安排的 UI run、cancel 及后代任务；其他插件的独立后台任务不继承该限制。回调后及每组执行前重新校验目标；同值不重复修改原生状态。单独 STATE 的显隐要求有效 PRESERVE_HIDDEN_SLOT 槽位；无槽位时须组合 LAYOUT，重新排列受影响区域。纯 STATE 不移动相邻控件，也不修改用户布局偏好。溢出隐藏与命令显隐分开，更新隐藏按钮的状态不会把按钮移出溢出菜单。新目标及布局快照发布实际几何，旧租约保持原值；布局尚未重新发布时返回 NOT_READY。

当前按插件限制 256 个保留票据、256 KiB 队列字节，每请求最多 32 个矩形，每次安全点最多处理 64 个贡献。运行期值由能力查询提供。未释放终态仍占用记录配额，立即释放待执行票据也不能绕过上限。停止会拒绝新请求并取消待执行贡献，已有引用仍需释放，未排空时宿主保留 DLL。

### 后续数据绑定与依赖刷新

SELF DATA 已实现来源复制、版本捕获、显示交换及租约；不自动订阅或传播。SELF LAYOUT 也已实现保留布局重排。以下规则约束尚未实现的完整 STATE、更广范围的 LAYOUT 和依赖扩展。数据绑定需要声明来源身份、可观察 revision、目标与依赖。布局依赖由宿主建立；插件添加的依赖须在注册时检查循环。
完整更新按 DATA、STATE、测量与 LAYOUT、损伤合并与 REPAINT 的顺序执行。只有值或度量实际变化才向后传播。需要新场景结果时，插件先发显式求值任务，完成后再请求显示该结果。
SUBTREE 和 DEPENDENTS 只能覆盖目标公开的范围。请求扩展到祖先布局容器时，仅测量必需容器，不能直接扩大到全窗口。DATA 需要非零 binding，其 sourceRevision 属于真实来源，不是布局修订或任意插件计数。

队列键包含 owner、目标实例、binding、来源身份及合并键。同一来源 revision 可合并请求位和矩形；后续依赖调度可考虑较新版本取代旧数据需求，但须保留旧请求额外区域。当前实现按精确版本分组，不以较新版本替换已接受的旧快照。
互不兼容的来源或空间分开排队。重复请求仅合并范围，不创建重复数据读取。矩形过多时折叠成目标裁剪内的包围矩形，不扩大到整场景。
安全点取出当前批次，再执行依赖图。回调期间的新请求进入下一批，禁止同步 flush 或递归派发。绘制只回放保留内容，不执行业务回调。
同一 binding 已消费的 revision 再次请求 `DATA` 不重复读取。控件结果相等时不发送状态变化，不再触发布局。持续动画须通过帧服务按需安排下一次重绘，不能靠自发刷新维持无限循环。
宿主为每次处理建立不可伪造的因果批次。状态、数据和布局回调产生的请求继承该批次，不能自己新建根批次。
若同一因果批次再次访问已经处理的相同 binding 和 revision，丢弃重复贡献并记录诊断。检测到跨 binding 循环或持续自触发时停止该批次，相关 ticket 失败；不会一直推迟到后续安全点循环执行。
来源确实变化时可以安排新更新，但每插件的待处理票据、目标数、矩形数、字节数及每次安全点的工作量均有上限。达到队列限额返回 `BUSY`，不得用无限延后隐藏积压。
工作量预算只能限制宿主接收及调用数量，不能中断已经挂起的原生插件回调。耗时数据读取应先走任务服务，刷新回调只取得已准备结果。

取消未执行 ticket 只撤回该贡献，其余合并请求继续。批次已经开始时 cancel 返回 `BUSY`，不回滚已应用的只读 UI 更新。所有 ticket 必须落入明确终态。
目标重建、工程切换或 binding 注销后，旧贡献以 `STALE` 或 `CANCELLED` 结束。停止插件时拒绝新请求，撤销待执行贡献，等待正在执行的回调退出再释放 DLL。
只读 UI 结果准备失败时保留上一份完整显示，并给出陈旧或失败状态。不能保留一半新属性和一半旧布局，伪装为完成。
刷新服务不得设置工程 dirty、写入项目、移动播放头、覆盖当前编辑姿态或增加撤销记录。真实数据变更必须先通过共同事务发布，再由提交事件触发刷新。

### 后续绘制层与场景渲染

绘制层提交内容后，将新旧边界和裁剪变化交给 `mms.ui.refresh`。旧的 `paint.invalidate` 便利写法若保留，只包装 `REPAINT`，不再维护第二条失效队列。
宿主恢复损伤区背景并重画相交层；目标外像素保持不变。纯面板重绘不能调用完整 `FrameDriver` 或重新加载效果。
布局改变视口像素尺寸时，视口依赖可以明确请求新尺寸渲染；相机与输入帧未变时不得重新推进物理。主场景求值、视口渲染和 UI 回放分别计量。
系统窗口暴露及本体拖拽产生的损伤也进入同一调度，保留原生必要绘制。刷新合并不能吞掉捕获丢失、取消或退出等交互事件。

## 事件与目标分离

建议事件包包含 `topic`、`sequence`、单调时间、可空的 `sourceObject`、可空的 `sourceUi`、`payloadVersion` 和借用 payload。
订阅过滤器可以只指定主题，不强制填写 UI 元素。插件主题必须位于自己的命名空间，不能伪造宿主事件。
宿主事件覆盖工程和对象生命周期、已提交属性变化、布局应用完成、目标销毁、主题及 DPI 变化、交互开始和结束。
已有 `onEvent` 继续兼容；新订阅服务可桥接同一事件源，但序号和交付约定必须明确，避免插件双重响应。
事件按序排队交付，不在绘制、布局发布或场景提交中同步回调插件；尺寸和悬停等高频通知可按主题合并。
回调期间 payload 只读，长期保存需自行复制。事件、绘制和帧回调不继承编辑命令权限，不允许递归派发消息。
需要修改场景时，插件另行通过已开放的编辑入口排队；当前未开放的服务继续按原状态拒绝。

例如，插件收到计算完成事件后查询状态栏装饰目标，再让工具栏提示和插件画布中的图形同时移动。
宿主只检查目标权限和样本值，不要求动画回到触发源，也不解释插件内部的动画编排。

## 复杂交互用例

| 用例 | 插件行为与最小宿主能力 |
| --- | --- |
| 任务完成后跨区域提示或桌宠回应 | 后台任务排队发布结果事件；插件定位另一个面板及透明视口，分别提交绘制和动作。 |
| 文件拖放后多个目标响应 | 受控 drop 输入返回处理结果；文件读取在工作线程完成，多个目标根据同一结果更新，导入工程另走编辑事务。 |
| 桌宠玩法状态机和组合动画 | 插件维护行为状态、动作队列和组合时序；宿主只提供输入区域、帧请求、音画资源及独立视图能力。 |
| 跟随播放或分析结果 | 订阅时间或结果通知；插件可跟随工程时间，也可用自己的时钟，不通过修改工程播放头实现动画。 |
| 角色拨动控件并打乱布局 | 纯视觉拨动走 presentation；真实控件位移走可撤回 layout session，用户操作优先，一键还原。 |
| 上下文菜单与异步建议 | 菜单取当前目标和只读状态，异步计算返回后验证任务代次及目标身份，再更新菜单或显示提示。 |

后台结果至少携带任务 ID、任务代次、目标实例代次；依赖工程内容时还带工程身份和来源修订。
UI 安全点先校验，再更新界面。已取消、对象已重建或结果对应旧工程时丢弃结果，不能把旧结果应用到同名新目标。
复杂计算可放工作线程或独立进程，UI 回调只处理短任务。进程内 ABI 无法强制中断挂起插件，也不提供崩溃隔离保证。
编辑分组只包含工程数据修改。呈现、桌宠动作和临时布局不设置场景 dirty，不占撤销节点，不进入工程视频或图片录出。

## 坐标与真实布局

几何快照包含每个目标的 `layoutRect`、`clipRect`、所属坐标空间、有效 DPI、局部到宿主变换及当前呈现变换。
布局声明继续使用 DIP。`mapPoints` 明确区分元素局部 DIP、宿主客户区 DIP 和窗口系统像素；首版无需公开屏幕空间。
启用独立透明宿主的桌面范围时，另提供受能力控制的显示器工作区坐标空间及其代次；跨窗口映射仍由宿主完成。
所有转换来自同一份快照。混用几何修订、失效目标或不可逆变换返回 `STALE` 或 `ARGUMENT`，不猜测坐标。
当前宿主存在 DPI 虚拟化，不能再乘一次显示器缩放；依据是 `src/plugins/native_ui.cpp` 的 `WindowDpi` 和 SDK README 的面板约定。

真实布局决定占位、原生 HWND 位置、裁剪和可访问性边界，继续由布局事务或宿主拖拽处理。
临时呈现保存偏移、缩放、透明度和裁剪等视觉值，不改布局文件、对象数据、命令语义或窗口的真实位置。
`submit` 不得借机修改真实布局。插件需要永久移动元素时，先完成布局事务，再用新几何修订计算视觉过渡。
布局或 DPI 改变后，旧样本失效；宿主通知插件重新取快照。首版不隐式把旧坐标动画套到新布局。
呈现会话结束后清除临时值，回到真实布局。插件如需保持最终静态装饰，应显式提交普通绘制内容或样式。

可撤回布局会话单独记录自己修改的字段及其起始值，操作仍要满足目标尺寸、父节点和顺序约束。
默认不写入用户布局文件；只有显式 `commit` 才转换为普通持久布局覆盖，不能自动提交一次恶作剧效果。
回退仅恢复仍由本会话持有且未被用户改写的字段；目标销毁时跳过，不能用整个旧快照覆盖用户后续操作。
用户开始拖拽目标时，宿主撤回冲突的临时布局，再从恢复后的真实位置开始直接操作。
插件卸载或调用「还原插件布局」时取消会话并撤回覆盖；已有持久布局另保留宿主「恢复默认布局」入口。

## 样式与绘制

样式首版建议覆盖背景、前景、边框色、边框宽度、圆角、字体资源和状态色；每个目标逐项报告支持的属性。
禁用、焦点、输入法和高对比度的可用性优先于插件装饰。移除覆盖后重新使用宿主默认样式。
会改变字形测量或控件尺寸的字体修改必须触发布局测量，不能冒充纯绘制变化；间距和尺寸仍走布局提示。
宿主样式覆盖按「系统可用性约束、用户选择的主题、插件声明、宿主默认值」确定优先级，不允许插件改写全局系统设置。

绘制层声明目标、裁剪区域、层级、资源预算和输入模式。基础绘制层默认穿透，只有独立注册的输入区域可以接收交互。
基础指令包括填充矩形、线段、圆角矩形、路径、文字、位图、裁剪栈及二维变换；超出能力的指令直接拒绝。
颜色使用明确的 sRGB 和预乘 alpha 约定；位图提交规定格式、行距、尺寸和字节数，先校验乘法溢出再复制。
字体、图片和路径用不透明资源句柄引用；保留的显示列表持有资源引用，调用者释放后不会使已提交列表悬空。
显示列表必须完整闭合状态栈；提交失败保留上一份列表。`WM_PAINT` 只回放已经验证的列表，不进入插件代码。
宿主合并新旧视觉边界、裁剪变化和笔画扩展形成损伤区域，先恢复背景，再重画受影响层，防止残影。

CPU 后端以局部 32 位 DIB 和 GDI 为基础，必要的 alpha 在宿主缓冲内合成，最后复制到目标窗口。
首版不依赖 Win7 不具备的子窗口透明合成能力，也不把任意 HWND 截图当作可交互控件替身。
插件已有的 `surface` 原生子窗口仍可自行绘制，但其内部原生子控件不会自动变成宿主可合成的图层。
跨目标动画可以在宿主开放的同一画布内画装饰；跨原生父窗口只能映射坐标并分别提交各层，不能保证覆盖所有兄弟 HWND。
透明覆盖窗口及 3D 视口按下一节独立建设；模糊、透视和原生控件截图过渡不属于基础绘制层能力。

## 透明视口与桌宠模式

`overlay.createHost` 建议区分 `CLIENT_OVERLAY` 和 `DETACHED_WINDOW`，默认限制在 MMS 自己的窗口及控件。
客户区覆盖层跟随主窗口移动、裁剪和可见性。脱离主窗口的透明宿主有独立位置，但生命周期仍归 MMS 和插件管理。
Win7 可用宿主拥有的透明顶层窗口与预乘 ARGB 位图作为 CPU 二维实现候选，不能依赖透明子窗口合成。
宿主负责跟随遮挡、最小化、Z 序和销毁；不默认置顶、不激活主窗口，不覆盖其他应用的交互区域。
可选桌面范围必须单独配置并报告能力，以所选显示器工作区为边界；不默认包含控制其他应用、系统输入钩子或修改桌面设置。
独立透明窗口的像素提交、输入区域和资源预算均走宿主服务，插件不取得任意窗口管理权限。

内部透明桌宠可先用二维图像或序列帧实现。三维角色通过 `mms.scene.evaluate` 隔离模型姿态和物理状态，再由 `mms.render.view` 管理渲染目标。
相机、播放时钟和求值实例分别创建并绑定，不借用主工程的可变对象，也不在主工程帧之间来回 seek。
不可变网格和纹理可在有明确寿命及计量规则后共享；实时姿态和物理世界不能只因为模型路径相同就共享。
后台行为运算只提交动作意图；场景更新及图形资源操作按宿主指定线程和安全点执行。
三维视图的透明输出、设备丢失恢复、效果支持范围、颜色和 alpha 约定需要独立渲染服务明确，不能从二维 ABI 推导。
当前 `scene.h:147–154` 只提供快照读取；`src/app/frame_driver.cpp:463–525` 仍围绕当前 `MMDApp` 呈现，没有上述隔离视图 API。
多开视口和不同渲染器的详细方案见[插件视口与渲染服务](PLUGIN_VIEWPORT_RENDERING.md)；上表的渲染函数仅概述本节依赖。
UI paint 层与三维视口、渲染提供者使用不同资源服务，但共用底层对象身份、owner 和生命周期；便利 SDK 仍只包装这些底层接口。
多视口不能等同于共享一份可变相机、设备上下文或渲染状态，跨渲染器资源交换须按渲染服务明确的格式和寿命处理。

「整个 MMS 桌宠模式」可由宿主隐藏常规编辑区并显示独立透明宿主实现，必须保留退出模式和恢复编辑界面的操作。
模式切换保存并恢复 MMS 自己的窗口可见性和布局，不修改工程、录出参数或其他应用状态。
CPU 兼容承诺覆盖二维界面、调度和输入，不承诺三维模型的完整 CPU 光栅化。三维后端不可用时回退为二维形象或静态提示。

## 输入路由

事件订阅是事后观察，不能取消已经完成的动作；输入处理则同步返回 `PASS`、`HANDLED` 或 `REQUEST_CAPTURE` 等明确结果。
输入包包含目标引用、指针 ID、按键、修饰键、时间、快照修订及局部坐标；drop 数据以只读租约交付。
宿主先按注册区域命中，再派发输入；透明空白默认穿透。可交互区域必须与显示内容同步更新，不能缓存过期坐标。
捕获只能由当前合法交互取得，目标隐藏、销毁、取消或插件停止时释放；键盘焦点必须来自用户操作，不由动画自动抢占。
原生编辑框继续处理输入法。自绘文字编辑需另行提供输入法、选区、Tab 和辅助功能契约，首期可直接嵌入原生编辑框。
命中和焦点变更在回调退出后应用，禁止在输入回调中递归消息循环。未声明的输入保持原 MMS 行为。

## 帧请求、取消与直接交互

`requestFrame` 为单次请求，同一会话最多保留一个待执行请求；需要继续动画时，插件在本次回调后再次请求。
建议帧数据包含单调时间、有效时间差、序号、几何修订、可见状态和恢复标志；不使用场景帧号作为 UI 动画时钟。
宿主按显示需求合并请求，并允许限帧或跳帧；不保证固定 60 fps。插件根据时间求值，不根据回调次数累计位移。
隐藏、最小化和模态占用时暂停交付；恢复首帧时间差为零并标记恢复，插件决定暂停时间线或跳到当前进度。
UI 帧工作项独立于场景求值，不调用 `Seek`、物理步进、效果重载或完整 `FrameDriver`。无请求时不新增动画唤醒。
实现可复用更新协调器的单调时钟和安全点，但必须新增 UI 专用队列，不能把现有视口渲染请求当作动画请求。

用户开始拖拽时，宿主先取消目标及受影响后代上冲突的临时几何呈现，再把控制权交给真实布局。
拖拽期间拒绝重新占用这些属性，防止插件把元素拉回旧位置。颜色等不冲突属性可继续，具体能力由目标声明。
命中测试、焦点和输入法始终跟随真实控件；首版装饰动画不改变输入命中位置，不能用移动的绘制副本承接点击。
可交互画布还须使用输入服务的反向坐标映射、捕获、键盘导航和辅助功能约定，不能只增一个命中回调。

会话终止原因包括完成、插件取消、用户交互抢占、目标销毁、几何失效、宿主关闭和资源失败。
取消待执行帧保证不再开始其回调；取消正在执行的回调返回 `BUSY`，退出回调后完成清理。
结束通知在安全点至多交付一次，停止中不启动新回调。宿主须先取消帧、解除层和订阅，再允许插件 DLL 卸载。
仍有正在执行的回调或未释放的租约时停止返回 `BUSY` 并保留 DLL，不能强制终止线程或卸载正在执行的代码。
绘制资源由宿主保留到最后一次回放结束；GPU 加速资源丢失时可重建 CPU 副本或退出加速，不留下 DLL 回调引用。

## 本体实时拖拽的实现顺序

1. 记录拖拽起始尺寸和最新指针位置，捕获鼠标；每次安全更新只采用最新输入，不排队重放所有鼠标移动。
2. 根据最小尺寸和可用空间计算真实布局，按父窗口批量应用 HWND 位置，核对结果后发布几何修订。
3. 合并新旧区域的损伤并局部缓冲重绘；尺寸变化时重新初始化缓冲，不保留旧边缘像素。
4. 视口尺寸确实改变时另发视口重绘请求；纯控件重绘不触发场景求值、物理推进或效果重载。
5. 松手后保存最终布局。Esc 恢复起始布局；捕获丢失或窗口关闭立即结束拖拽，不留下挂起状态。

此路径不插值、不缓动、不延迟跟随，不调用插件动画计算来决定本体布局。
批量窗口操作失败时保留最后确认的几何，尝试恢复并安排重绘；不能继续公布未经核实的目标矩形。
是否存在残影须用真实桌面拖拽验收，隐藏窗口和消息测试不能替代视觉验收。

## 能力、错误与回退

`getCapabilities` 应报告支持属性、指令和层级，以及每层尺寸、总像素、资源字节、指令数、待处理事件数和帧频上限。
预算以实际保留资源计量，检查整数溢出；同一资源句柄在本服务内只计一次，不用无限增长的重绘队列隐藏成本。
目标只支持颜色时，不接受缩放或透明度。原生 HWND 只支持真实移动时，不能把临时矩阵返回为成功。

| 结果 | 约定 |
| --- | --- |
| `NOT_FOUND` | 服务、主题或目标未注册；插件保持静态原生界面。 |
| `UNSUPPORTED` | 能力、属性、指令或层级不支持；回退到基础样式或即时切换。 |
| `NOT_READY` | 首次布局尚未应用、目标尚未挂载或插件正在停止。 |
| `STALE` | 实例代次或几何修订失效；重新解析和取快照后再提交。 |
| `BUSY` / `CONFLICT` | 回调重入、用户交互占用或其他呈现会话冲突；不抢占用户操作。 |
| `ARGUMENT` / `VERSION` / `THREAD` | 非法数值、格式、未知标志、版本或线程错误；不更新可见状态。 |
| `MEMORY` / `FAILED` | 分配、资源上限或绘制失败；保留上一份有效内容，必要时恢复宿主基础绘制。 |

二维 UI 的 CPU 路径必须完整可用。硬件加速只能按运行时能力选择，失败回到 CPU，不依据显卡品牌拒绝加载。
系统关闭动画或用户选择减少动态效果时，帧数据报告策略变化；插件结束视觉过渡，功能结果立即呈现。
实时拖拽是直接操作，不受「关闭过渡动画」影响。宿主资源不足时仍须响应输入，并及时恢复基础绘制。
Win7 SP1、AMD 真机、输入法、键盘导航、多 DPI 和桌面遮挡恢复均需要验收；当前文档不提供这些新能力已通过的结论。

## 分批落地与验收

首阶段已有插件目标身份与 REPAINT 队列。后续继续本体实时拖拽、几何转换及事件订阅，再接入样式、CPU 绘制层和按需帧请求。
便利 SDK 随相应底层能力分批提供；透明宿主、输入区域、可撤回布局会话及隔离三维视图分别验收，不捆绑成一次重写。
首个示例用非 UI 事件同时驱动两个独立目标，展示插件自行编排时间线；移除插件后保留可操作的静态界面。
当前重绘的验收范围为跨线程请求、局部矩形过期、实例与工程代次、隐藏目标、取消单个贡献、队列限额及停止释放。来源修订合并、绑定循环和回调自触发属于后续依赖刷新验收。每例须核对播放头、工程 dirty、历史数量和场景求值计数不变。
声明 SDK 的验收先注册普通按钮，再关闭默认刷新并向同一元素添加绘制层；核对命令、元素及目标身份没有被替换。
契约测试覆盖错代次、几何变化、批量提交失败、资源租约、取消重入、停止和卸载、隐藏恢复以及预算耗尽。
交互测试覆盖动画中开始拖拽、拖拽中布局变化、Esc、捕获丢失、快速缩放窗口和不同父窗口目标。
纯装饰动画必须验证场景修订、物理步进和效果重载均无变化；拖拽改变视口尺寸产生的重绘单独计量。
界面范围按已迁移的目标能力逐项扩大；未迁移的本体区域继续原生绘制，不以「已开放 UI ABI」代替全界面支持声明。
