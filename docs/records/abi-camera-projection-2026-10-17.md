# 相机透视切换共同历史验证（2026-10-17）

本批基于 `codex/plugin-abi` 的 `f4b0d76`，仅修改 `D:/MMD-Next/MMS-abi-dev`。相机透视按钮 `446` 接入受控共同历史，普通 `mms.edit` 仍关闭。

## 行为与接口

`CmdControl400::446` 在显式绑定下由 `TryToggleBoundCameraPerspective` 接管。原模式字节为零时表示透视，非零时表示正交，按钮勾选表示透视。切换依据作者字节，零变 1，非零变 0，不依赖按钮当前勾选外观。拒绝或无操作后恢复复选框，避免原生控件提前切换外观造成不一致。

内部 `ApplyBoundCameraProjection(MMDApp&, orthographic, changed)` 接收明确的正交布尔值，目标写 0 或 1。记录保留原模式字节，撤销可精确恢复旧数据中的 7 等非标准非零值；显式要求正交会将 7 规范为 1，这属于实际字节变更。该入口是 C++ 内部接口，不是公共 C ABI。

每次实际切换形成一条共同历史，成功后按原规则激活相机轨道；原轨道已选中时保留多行选择。无操作、播放、逐帧播放、待录制、事务忙碌或准备失败不追加历史，不改变作者值、dirty、选择或 redo，不回落旧 GPU 写入。普通按钮点击每次都切换，无独立取消对话框；取消未结束的插件事务后可重试，已提交模式通过共同撤销恢复。

## 投影记录与复核

将原内部 `CameraFovChange` 扩展为 `CameraProjectionChange`，视角和模式共用同一记录类型。记录分别保存 FOV 和模式的 before/after，每条只发布被编辑的字段。撤销模式保留后来改变的视角、距离和姿态；撤销视角保留后来改变的模式。短期候选校验键池身份、记录代次、当前帧、视角、模式及距离。正常键池扩容保留身份，替换池拒绝旧记录。

发布只写作者参数和既有 `cameraProjectionRefreshPending`，不分配、不调用窗口、GPU、插件或文件，不保存旧矩阵或 GPU 资源。安全刷新按当前模式、当前视角和当前距离调用既有 `ApplyFrameCameraProjection`，而不是恢复旧设备矩阵。透视方向使用统一帧投影构建器的现有角度换算；旧 `446` 的单独矩阵写入不在受控路径中执行，避免下一帧覆盖。两个方向均在提交后的刷新边界更新设备，不推动场景求值或播放头。

没有设备时保留刷新请求；零、非有限或极小正交距离不能表示为有限 float 矩阵时，沿用前批安全刷新保护，保留原设备矩阵。此保护只覆盖受控延后刷新，不表示全部旧投影入口已经修复。模式开关、FOV 文本和插件撤销共用既有安全刷新，按钮从当前作者模式同步。
