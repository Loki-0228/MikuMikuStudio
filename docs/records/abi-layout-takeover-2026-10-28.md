# 原生拖拽接管临时布局

后续进度：公共 C 服务与 C++17 SDK 已接入并通过验证，见[公共服务记录](abi-layout-session-public-2026-10-28.md)。下文保留原生接管批次的证据及当时状态。

本批继续实现内部临时布局会话，接入真实侧栏和底部面板的鼠标入口。公共 `mms.ui.layout.session` C 服务及 SDK 尚未开放，完整需求仍为部分实现。目标范围未修改，main 已提交 HEAD 为 `d551f1f`，阴影同步继续暂缓；本批没有修改 main 或覆盖稳定版程序。

## 接管规则

注册表用进程内唯一的交互令牌占有工具栏、属性扩展行、左侧栏和右侧栏区域。侧栏拖拽占有四个区域；底部面板拖拽占有属性扩展行。其他区域仍允许插件预览。

按下分隔线时，宿主先占有区域并撤回其中的临时字段，再通过实际 NativeUi 刷新控件、预留空间和视口。只有布局有效且仍持有原令牌时，才记录拖拽起点。被撤回的预览不会因拖拽取消而恢复；它已经让出用户控制权。拖动期间同区域的新预览返回 `BUSY`，已撤回的会话仍按其终态返回 `NOT_READY`。

松键保留最终位置；取消、Esc 和捕获丢失恢复手势开始时的本体布局。结束操作只释放自己的令牌，旧手势不能解除新手势的占有。准备过程中收到取消或松键时，不继续建立旧拖拽。

这些接口是宿主内部 C++ 接线，不构成已经发布的插件 ABI。现阶段支持的插件目标与[临时布局内部接线](abi-layout-preview-2026-10-28.md)相同，不包含 DOCK、跨父节点或任意本体控件。

## 审查修复

- 侧栏和底部入口同时检查两个方向的手势序号，避免一种拖拽的旧续体覆盖另一种新拖拽。
- 取消恢复期间，嵌套按下可能因布局未就绪而失败。没有新活动手势且请求几何未改变时，外层仍完成排版批次、恢复就绪状态并释放捕获。
- 确认当前窗口仍持有捕获时，忽略过期的捕获丢失通知。既有测试改为实际释放捕获，再保留原恢复断言。
- 同步布局开始前同时使旧几何和刷新目标失效，防止第二次排版失败后误用刷新内部先前发布的快照。线程、回调及忙碌状态检查拒绝的调用未开始新布局，保留已有有效快照。

## 已有证据

注册表专项在完整配置与原始兼容配置各通过 9,719 项。完整 ABI 契约分别通过 45,105 项和 45,081 项。证据为 `本地验收记录（未随本文发布）`。这些契约测试没有链接本批最后修改的原生鼠标处理代码，原生路径由独立宿主专项验证。

真实宿主使用实际 Manager、NativeUi、注册表和窗口消息处理。测试 DLL 只提供已有客户端的可信测试入口，没有虚构公共预览服务。每次运行复制测试程序和原创探针到独立目录；主窗口保持隐藏，进程内输入隔离避免移动用户鼠标和抢占焦点。

最终证据为 `本地验收记录（未随本文发布）`，普通启动与共同历史绑定模式均通过，覆盖：

- 四个实际插件挂载区域的控件矩形、可见性、保留空间和视口同步恢复。
- 侧栏及底部拖拽的松键、取消、捕获丢失和 Esc 路径。
- 冲突拒绝、其他区域继续使用，以及旧令牌不能解除新拖拽。
- 实际定位调用返回点注入取消／松键、取消恢复期间的失败嵌套按下，以及旧底部松键清理期间启动新侧栏拖拽。
- 实际刷新先发布有效几何，随后显式布局遇到一次真实 C++ 分配失败。验证旧快照失效、调用方仍持有令牌、释放后重新刷新成功，以及回调／错误线程被拒绝时不使已有快照失效。
- 测试手势期间共同历史数量、修订及保留字节不变；播放头、工程脏标记、插件布局偏好和设置文件字节不变。快照在初始化及测试控件注册完成后建立，不据此判断启动、退出或注册阶段是否写设置。

故障测试最初从 `GetClientRect` 钩子直接抛出 C++ 异常，测试程序在断言前以 `0xC0000409` 终止。该错误注入保留在 `本地验收记录（未随本文发布）`，不计通过。修正后钩子只在真实调用成功后设置一次性标志并正常返回，后续实际 C++ 分配抛出异常；断言要求标志消耗且仅失败一次，没有修改生产接口或添加生产测试开关。

最终测试程序 SHA-256 为 `69c31ecea8c9f562523dacf845617bb10cc3b44d566dd454747b8b10393e7ab1`。相同程序还通过既有完整侧栏、底部及视口鼠标回归，证据为 `本地验收记录（未随本文发布）`。完整配置及原始兼容配置核心库构建均退出 0；这些构建仅用于测试，没有部署产品 EXE。
