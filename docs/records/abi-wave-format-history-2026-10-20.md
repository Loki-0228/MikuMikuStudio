# 扩展 WAV 播放与共同历史

日期：2026-10-20。分支为 `codex/plugin-abi`。本批补齐[首批音频历史](abi-physics-audio-history-2026-10-20.md)中的 WAV 位深覆盖，并修正普通媒体入口的缓存来源管理。新增格式仅进入完整配置，原始兼容配置保持既有范围。

## 格式及数据规则

| 输入 | 播放表示 |
| --- | --- |
| 普通 PCM8／16 | 保留采样字节。经过验证、适合旧读取器的格式继续直接读取源文件，包括带 LIST 元数据和 `fmt18/cbSize=0` 的布局。其他合法布局写成规范 RIFF 缓存。 |
| PCM24／32 | 有符号小端整数，确定性取容器高 16 位，不加入随机抖动。 |
| IEEE float32／64 | 有限值截幅至 `[-1,1]`，内部区间按 `trunc(x*32768)` 转换；正端点为 32767，负端点为 -32768。NaN／Inf 拒绝整次准备。 |
| EXTENSIBLE PCM／float | 校验完整子格式 GUID、扩展长度、有效位数和声道掩码。PCM 有效位左对齐，低填充位必须为零。PCM8／16 可保留原字节，其余按上述规则生成 PCM16。 |

以上范围为单／双声道。EXTENSIBLE 只接受未指定布局或标准单声道中央、双声道左右布局，不自动降混其他布局。采样率、声道顺序和帧数保持。RIFF／chunk 边界、奇数字节填充、重复格式或数据块、整帧对齐及字节率均在读取前校验。

高位深规范化服务于播放、波形和历史恢复，不代表无损高位深音频编辑或导出。原始低位精度不在 PCM16 播放缓存中保留。PMM 继续保存用户原始音频路径，不写入内部缓存路径，也不内嵌音频；跨进程重开仍需要外部源文件。源文件缺失后，在同一会话中撤销与重做使用保留的私有播放内容。

## 实际入口与资源

`Asset::DecodeWave` 直接解析 RIFF，不调用 Media Foundation。`Asset::Decode` 对 WAV 直接进入此路径，对压缩格式沿用系统解码。`media::PrepareAudio` 复用同一 WAV 解码器并持有缓存租约，因而普通菜单、拖放、PMM 打开和受控共同历史都有相同格式覆盖，不互相递归。

旧 PCM24／32 context 的捕获使用独立读取句柄，核对原文件身份、格式、数据范围并保留原游标。播放转换为 PCM16，但已存在的波形字节原样保留。PCM8／16 的原严格字节、波形及历史检查继续有效。

转换前以 64 位计算输出长度，用按完整帧对齐的固定 64 KiB 缓冲逐块读取，不分配完整输入副本。PCM、波形、私有磁盘缓存和后续 DirectSound 候选继续计入现有保留预算。该预算不是进程瞬时内存峰值的硬上限。缓存及解码临时文件均在实际 EXE 的 `data/audio-cache`，准备失败销毁未发布缓存。

普通 PCM 直通还须匹配旧读取器的消费式 `data` 搜索规则。元数据中的完整 `data`，或紧邻真实标记之前的末尾 `d`，均会改走规范化缓存，避免旧读取器误认数据位置或在 EOF 循环。规范化 WAV 切回普通 PCM 时清理旧缓存及来源记录，避免 PMM 保存上一段音频路径。

## 验证与审查

证据目录为 `build/verification/abi-wave-formats-20261020/`。

| 检查 | 结果 |
| --- | --- |
| WAV 格式及共同历史 | `test-formats-final-source.log`，1,216 项通过。覆盖两种历史模式、已知样本逐字节预期、非零低位、整数与浮点边界、EXTENSIBLE、原生波形对照、实际播放、源文件移走、旧 PCM24／32 捕获、失败预算及分配反例。 |
| 真实 PMM | `test-pmm-final-source.log`，八种普通／EXTENSIBLE PCM24、PCM32、float32、float64 完成实际拖放、PMM 保存重开和播放。关闭时句柄及缓冲释放检查通过。 |
| 原 PCM 历史 | `test-audio-regression.log`，362 项通过。包含原样波形、原始源文件移走、混合插件事务、取消、无变化、内存和 DS 失败。分配扫掠计数随实现分配次数变化，未删原断言。 |
| 系统压缩音频 | `test-compressed-regression.log`，217 项通过，真实 MP3／AAC／M4A／WMA 保留播放及撤销／重做。 |
| 媒体回归 | `test-media-verified.log`，普通含 LIST 的 PCM 直通、四种音频解码、视频定位、缩放及 WIC／MOV 编码检查通过。 |
| 构建及产品 | `build-source-replacement.log` 完整 x64 Release 成功，`build-original-final.log` 原始兼容配置成功。最终原名、中文改名产品的隐藏启动、插件菜单及实时布局通过 `test-product-source-final.log`。 |

独立审查发现滚动字串搜索不等价旧消费式扫描，已改为消费状态机并加入 `JUNK{0,'d'} → data` 反例。初次媒体回归也暴露普通含 LIST 的 PCM 不再直通，随后保留经验证的旧布局并重新验收。初次构建的 `DWORD` 与 `uint32_t` 模板类型不一致已修复，失败日志保留。

[表情输入夹具修复](abi-morph-input-fixture-2026-10-20.md)使完整原生历史套件越过旧 ANSI 断言。完整套件随后停在系统拒绝真实鼠标定位的 HUD 断言，故本批仍未登记为全套通过。未弱化或跳过该断言。

Win7 SP1 x64、CPU 基础路径及 AMD 仍为要求，本批 WAV 解码未新增系统编解码器或显卡依赖。本机结果不代表 Win7 或 AMD 真机验收。普通 `mms.edit` 继续关闭，可写 INPUT、其他媒体及模型资源写入仍需迁移。
