# CPU 几何缓存与附件历史协调

基线为 `e71a624`。几何缓存参考 main 已提交的 `3782e0c`，仅移植相关机制，保留 ABI 加载器已有的私有导入、文件唯一所有权、资源失败处理及 MME 输出槽。本批完成有界几何缓存、附件历史协调和私有菜单快照的本机定点验收。DSH 承担菜单快照及 HUD 回滚的原子代码修改，Codex 负责设计、整合、文档和实际验收。整体 ABI 仍未完成。

## 几何缓存边界

缓存仅在进程内保存 PMD／PMX 已解析的 CPU 几何字段。默认总预算为 256 MiB、单项 128 MiB、32 项，待发布数据和仍有使用者的退役快照继续计费。`Clear` 推进代次，清理前准备的数据不能随后重新发布。缓存不保存可变模型、GPU 对象或物理指针，不创建磁盘文件或独立设置文件。

PMD 顶点保留完整工作记录；CPU 索引保持每项四字节、低位十六位有效的原有布局。PMX 仅复制解析器实际初始化的字段，保留追加 UV 的分量排列、SDEF 的偏移结果和现有权重分支。此迁移不增加 PMX 2.1／QDEF 支持，也不改变现有无效追加 UV 的处理。

命中时先在私有临时区准备完整顶点和索引副本，两者均成功后才改变解析位置。任一复制、分配或跳转失败时丢弃整套候选，继续原始几何解析。GPU 缓冲仍为当前模型独立创建。未命中数据在几何解析后捕获，只有模型加载器完整成功后才发布；该加载器后续材料、文本或资源阶段失败不发布。工程导入事务在加载成功后仍可取消，此时允许保留纯文件几何缓存；它不保留候选场景对象，也不替代工程事务的发布。

源文件校验使用 Win7 可用的文件身份、只读共享限制及 SHA-256 内容采样。未命中前后比较完整文件，命中及发布复核几何内容，防止仅凭大小、时间或路径复用旧数据。源文件大于单项预算与 128 MiB 中的较大值时，指纹读取前直接绕过缓存，避免扫描原解析器忽略的巨大尾部。指纹与共享限制不提供对恶意并发、映射写入 ABA 的事务快照。哈希增加的读取与计算成本尚未测量，不据此宣称提速。

原始兼容产品不启用进程缓存；独立测试可显式构造缓存验证后端。`SequentialFileReader` 增加绝对跳转；失败保留逻辑位置和未消费窗口，文件关闭仍由原 reader 负责。

## 附件历史协调

全操作模式改为显式提交后，未记录的父绑定调整曾使旧父绑定／HUD 节点失效；登记重放按轨道重新采样，也可能与前一个父绑定节点的期望不同。私有协调记录现区分历史逻辑绑定与实际呈现绑定。原生求值在写入前捕获来源，写入后只确认已计算的那一对值；不对事后读取的任意外部写入补发可信凭据。

父绑定、HUD、登记和附件粘贴共用同一协调记录。首次准备显式传递本次是否保留历史，包含显式提交模式下插件要求的共同事务。取消、准备失败和预算拒绝不安装记录；最终发布不分配。来源身份、键池代次、父模型及骨表、历史代次和槽发布序号均继续校验。旧对象槽位复用只观察旧元数据；新对象的求值不能改写旧对象记录。首条记录安装前取得的旧句柄在该槽发布后失效，重新准备不能绕过来源校验。

模型及附件删除现与同一记录协调。删除快照分别保存逻辑绑定和本次实际清除的绑定。模型删除会检查全部现存附件，即使附件尚无协调记录，也先准备私有候选；准备失败不安装记录。撤销恢复本次真正清除的实际字段，未清除的字段保留合法的重新采样结果。重做重新检查当前实际绑定，避免把首次删除时的状态永久套用到后续重做。

专项覆盖逻辑父模型 A、实际采样父模型 B、删除 A、再次求值、撤销删除、遍历更早 HUD／父绑定节点及再次重做。附件删除后，另一附件复用槽位并修改绑定，再撤销新附件、恢复旧附件，也可继续遍历旧历史。对象身份、骨表、资源保活及准确的待移除模型集合共同证明尚未恢复的来源；不会把尚未恢复的模型当作当前已存在。

方向快照和外层删除事务共同准备，最终发布不分配、不调用插件。取消、内存不足、预算拒绝及历史重置不留下部分修改。固定部分与后续加入的协调记录分别计费，反复删除和恢复仍受原历史预算限制。该路径使用明确绑定的共同历史；没有绑定历史的旧 CPU 路径保持原行为，不根据应用地址猜测 journal。绑定宿主下尚未纳入规范来源的自定义曲线采样回调保守拒绝，不将其记为已全部支持。

最终父绑定及删除专项通过 6,266 项，HUD 核心通过 5,711 项。相邻登记、稀疏登记、历史模式、场景资源、VMD、粘贴和删键合计十组通过 95,042 项。

用户恢复 DSH 后，正式 CLI 确认宿主可用，子任务 `720bb8e7-769a-4954-a861-cdaadf407e47` 的实际工作目录为 `D:/MMD-Next/MMS-abi-dev`。DSH 只编写私有 `native_menu_snapshot.hpp/.cpp`；Codex 负责接口设计、独立测试、复审和文档。已读取两轮正式结果并跟踪至终态，未执行回收或重启。

`Capture` 在窗口所属 UI 线程读取已经物化的真实菜单树，保留父行索引、重复命令位置、UTF-16 标签及勾选／禁用状态。普通标签按精确长度读取并复核；自绘、分隔符和旧位图项不解引用应用指针。失败不替换旧输出，条数、深度和文字均有预算。它不填充动态菜单、不执行命令、不创建稳定 ABI 身份，也不提供控件几何或完整宿主目录。

首次实际测试复现文字缩短一单位、增长后被旧缓冲截断以及空子菜单深度误判，合计五项断言失败。DSH 按相同子任务修正后，真实隐藏窗口专项通过 66 项，包含长文本分配失败、线程拒绝及查询导入恢复。完成状态不作为验收依据，结果采用 Codex 的实际运行报告。

第二项任务 `851560d8-167b-4d65-8629-6a37796fd165` 的实际工作目录同上，只允许修改 `native_accessory_hud_history.cpp`。附件协调新增后，历史 `Reset` 会使提交凭据过期，首轮最终回归因此发现旧 HUD 拖拽不能回滚仍由自身持有的预览。修复将预览取消的所有权证明与提交凭据分开，继续检查同一场景、对象身份、键池、帧、绑定代次、父模型及骨表，再按字段比较并回滚；提交、撤销及重做的校验没有放宽。

该任务曾因查找错误的 include 路径出现 `CodeRunFailedError/CODE_RUN_FAILED`，正式结果保留 `sawError=true`。Codex 提供准确路径后任务完成，未重启宿主或绕过权限。最终验收依据是修复后的实际运行。新增场景代次变化反例确认取消不会回滚其他场景的姿态，HUD 核心 5,711 项及全部十组历史检查通过。两项任务均已读取正式结果并核对源码，未执行回收操作。

## 保留的失败证据

`red-build-01` 构建成功，实际 `--accessory-parent-only` 在「重做未记录父绑定草稿之前的骨节点」失败。修复后初步专项通过 5,796 项，再补齐删除方向快照至最终 6,266 项。`menu-red-checks-01` 保留 59 项中的五项失败，修复后的最终两配置各通过 66 项。

首轮映射夹具错误地要求已有可写映射时必须命中，本机实际以共享冲突安全绕过，因此失败。现夹具分别验证操作系统允许共享时的复制拒绝，及拒绝共享时的普通解析和无发布；本机走后者，不把它当成 SHA 独立覆盖。大尾夹具也已修正先关闭写句柄，避免把已有写句柄拒绝误判为源大小限制生效。

完整配置构建先后发现 HUD 缺少预算模块头文件、测试错误声明文件局部函数，均已修正；后一次构建最后误请求仅存在于原始配置的 `original_profile_io_tests`，该批此前产品及实际测试目标已成功，不能将整条构建记为通过。首轮历史运行的 `0xC0000005` 由新测试缺少三个全局键池导致，补齐自有池后再运行通过，保留失败日志。

相邻 HUD 测试的微小预算反例曾误用外部 journal，而夹具绑定另一 journal；修正为在该作用域绑定准确 journal，仍保留原 MEMORY 断言。`final-full-history-01` 随后发现真实的 `Reset` 预览回滚回归，由第二项 DSH 任务修复，最终 `final-full-history-02` 全部通过。两类失败均未通过放宽原生产来源校验处理。

曲线编辑器全量曾在 provider 复制退休组合断言失败。该二进制 SHA-256 `3bbfa890…` 与既有 `abi-curve-insertion-geometry-20261021/curve-final-full-06` 的 36,281 项通过产物相同。该目标不链接本批缓存或历史库，不能据此归因于本批，也不能据旧通过掩盖新的失败。随后增加失败上下文，未修改生产曲线实现。

## 已核实但未在本批实现

- 完整原生 UI 只读目录。现有六个扩展根和快照没有覆盖所有真实菜单、控件或其几何。后续应增加独立只读服务，共用注册身份，不改变旧 V1 结构或跨 owner 写权限；菜单读取不能触发动态填充、命令或场景求值。
- 背景图片菜单 232／233、图片拖放和位置／缩放拖动的共同历史。现有加载器在新图片解码前释放旧纹理，失败可能丢失当前资源；需要独立资源候选和离线撤销重做，不能只包装菜单后宣布完成。
- PMX 并行准备、磁盘缓存管理、效果／纹理准备缓存、负帧、多视口、独立求值及洋葱皮等仍按剩余需求推进。

普通生产 `mms.edit` 保持关闭，公共 SDK 和集成入口未改动。本批所列功能已通过本机定点验收，整体 ABI 按剩余需求继续推进。保留 Win7 SP1 x64、CPU 基础路径及 AMD 要求；Win7、AMD 和人工视觉验收没有新增结论。
