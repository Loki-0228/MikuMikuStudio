# 本体 UI 只读目录接入方案

方案核对基线为 `f9faf69`。首批生产服务及分层 SDK 已按本页接入，结果见[实现与验收记录](abi-ui-catalog-2026-10-22.md)。以下保留实施前差距及设计约束；完整本体目录、全部业务命令和跨目标写入仍待完成。

## 实施前覆盖

`UiRegistry::Snapshot` 枚举原注册表中的命令、属性和元素，初始只有六个 MMS 扩展根。`NativeUi` 创建插件呈现，`RefreshMenus` 只同步插件菜单。上一批 `native_menu_snapshot::Capture` 只编入独立测试，未接入生产目录。

`ui_init.cpp::CreateUIControls` 的初始表实际有 175 项，生成头仍保留早期「168」的注释，不能据该注释计数。实际创建还受构建配置影响。曲线宿主、编辑器、浮动窗口、对话框和画布热点另行创建。将初始表或 `EnumChildWindows` 的结果称为完整 UI 目录，会遗漏这些对象及业务语义。

当前有效门禁是 owner、UI 线程、实例、工程代次、停止状态和回调限制。清单中的能力名称尚未构成通用的 `ui.read`／`ui.write` 授权。现有刷新队列还会拒绝非当前 owner 的目标，目录开放读取不改变该限制。

## 同一对象身份

目录继续使用 `UiRegistry` 的元素、命令和属性句柄。内部记录增加来源及宿主关联，区分插件注册、宿主语义登记和当前菜单观察。`HWND`、`HMENU`、命令数字及菜单位置不作为公共身份，也不新增一套可独立操作的控件句柄。

宿主明确登记的控件提供稳定语义 ID，例如相机视角、照明 R 和主时间轴。创建和重建分别产生呈现实例代次，稳定 ID 不因重建改变。原插件控件和菜单必须对应原 `registerElement` 返回的句柄，不能因目录观察重复登记。

尚无语义登记的菜单项只能具有当前运行期的观察身份。重复命令数字、插入、重排和原生句柄复用均不能证明身份延续。结构变化无法可靠匹配时退役原观察实例，旧引用返回 `STALE`；已取得的不可变快照仍可读。跨重排的稳定语义最终须在菜单构建点登记。

观察对象不参与 NativeUi 的控件创建、布局偏好写回或可写布局操作，避免把旧窗口再次创建为插件按钮。查询权限不授予刷新、移动、覆盖、聚焦、读取输入值或调用命令的权限。

## 独立版本服务

新增 `mms.ui.catalog` 1.0 服务和独立头文件，保持现有 `MmsUiApiV1`、V1 结构及大小断言。首版提供能力查询、快照获取、元素解析和快照释放，沿用 `MmsHeader`、`MmsSpan`、UTF-8、八字节对齐及客户端租约规则。C++ 便利包装只调用这张底层表。

快照条目至少描述原元素句柄、稳定 ID、owner、父元素、关联命令和属性、来源、角色、已知字段位及实际支持能力。描述修订、呈现实例、工程代次分别表达；布局提交时变化的 `MmsUiElementV1.generation` 不能替代实例身份。

覆盖范围明确列为注册树、主窗口已物化菜单、主窗口已登记控件及其他已接入窗口域，并分别说明未物化内容及未知字段。首批服务不能返回笼统的「完整本体 UI」状态。未知自绘标签、敏感输入值和未登记命令能力应如实保留为未知或不支持。

快照有每插件及全局租约数量和字节预算，独立持有文字和数组，不借用菜单、插件 DLL 或栈内存。超预算、内存不足、观察变化或发布失败保留完整旧版本，失败不改输出。停止时拒绝新租约，卸载沿用既有 outstanding lease 规则。

## 宿主发布

`integration.cpp::InitializeRuntime` 当前先创建 `NativeUi`，再加载插件。首份目录应在发出 UI_READY 前准备。后续在 UI 安全点读取当前菜单、验证窗口线程和结构，再发布完整候选。菜单循环中的结构发布继续延后。

服务查询只租用已经发布的数据，不为补齐目录调用 `WM_INITMENUPOPUP`、业务命令、旧 Refresh、布局处理、状态提供者或场景求值。原生菜单未展开而尚未创建的内容标为未物化。内容未变时不增加修订，不发送重复 Changed，避免观察和刷新递归。

主窗口初始控件从现成创建表及实际创建结果登记，失败创建不发布。其他窗口从各自创建及销毁点登记和退役，包含 `animation_curve_host_ui.cpp`、`animation_curve_editor.cpp`、浮动视口、录制窗口、对话框及时间轴和 HUD 自绘热点。查询不使用可能发送本进程消息的 `GetWindowText` 读取输入值，标签来自登记描述或已缓存翻译。

Win32 `commandId` 只是私有来源信息。原生命令须分别完成状态、参数、共同历史、安全点、失败和取消审查后，才能注册为原 `CommandRecord` 并供控件引用。不能提供通用 `WM_COMMAND` 调用器，也不能用空回调将未迁移业务标为可调用。普通生产 `mms.edit` 继续关闭。

## 验收证据

生产接入至少通过真实 MMS 隐藏宿主加载测试 DLL，由 `queryService` 取得目录。同时确认真实本体菜单、已登记控件和插件元素的身份及内容，插件项与原注册句柄相同。原始兼容产品当前跳过 ABI 初始化，其独立后端检查不能代替生产服务可用性。

菜单检查包含父位置、重复数字、Unicode、禁用、选中、分隔符、自绘未知标签、空子菜单及未物化范围。增删、重排、替换、窗口重建和工程重置后检查旧实例失效及冻结快照寿命。

查询前后对照播放头、姿态、dirty、历史数、焦点、捕获、菜单初始化及命令回调计数。工作线程获取返回 `THREAD`；已租用纯数据可跨线程读取，不触碰原生窗口。另验预算、OOM、错误 header、停止、跨 owner 释放及小容量输出的失败原子性。

完整目录、全部业务命令及跨目标操作授权仍是独立待完成要求。Win7 SP1 x64、CPU 和 AMD 要求保持，导入检查及本机测试不代替真机验收。
