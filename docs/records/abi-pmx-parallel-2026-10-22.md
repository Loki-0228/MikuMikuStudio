基线为 `f9faf69`。参考 main 已提交的 `3782e0c`，将顶点 CPU 准备接入 ABI 加载器，并修正参考实现的末批取消边界。没有使用 main 工作目录的未提交源码。整体 ABI、磁盘缓存和完整 UI 目录仍未完成。

## 生产行为

完整配置在 PMX 几何缓存未命中、顶点数至少 131,072 且未显式禁用时，最多启动两个 CPU 工作线程。三个批次各容纳 8,192 个顶点。packed 数据及偏移表共 3,760,128 字节，另有固定的批次、线程和队列元数据；该数字不是整个模型或缓存的内存上限。

调用线程独占文件读取，先准备完整批次，再交给工作线程。工作线程只读取该批次拥有的字节并写入独立顶点区间，不使用 D3D、UI、COM、工程数据或诊断输出。主顶点、描边和索引 GPU 缓冲仍在原加载线程创建，仍属于当前模型。

默认小模型、原始兼容产品及进程环境 `MMS_PARALLEL_PREPARE_DISABLE=1` 保留原逐字段串行解析。几何缓存命中仍先复制完整顶点与索引，再跳转到原位置，整个命中不启动工作线程。未提供字段、追加 UV 排列、SDEF 算术、未知权重的单骨回退、UTF16／PMX 2.0 限制及无效 UV 处理保持，不增加 QDEF 或 PMX 2.1 支持。

首次读取前准备全部批次存储。准备分配失败返回 `unavailable`，输入和目标保持不变，加载器继续原解析。工作线程启动失败时保留已经启动的线程；全部未启动则由调用线程处理相同批次。已开始读取后的短读和取消不能返回 `unavailable`，调用方丢弃候选，不能从当前流位置错误重跑串行。

每条记录前、完整批次提交前和最终 join 后检查可选取消位。当前半批不提交，退出时先结束全部已启动线程。Reader 异常同样在 join 后传播。统计中的顶点及批次数量表示完整读取并提交的工作，只有成功返回时才证明这些工作全部完成。系统互斥、条件变量或 join 本身的原生异常没有通用恢复保证。

内部 helper 接受取消位；现有同步生产加载入口没有新增外部取消接口，不能将内部检查记为已完成整个导入交互的后台取消方案。工作线程继承调用线程 MXCSR，保留舍入和支持的 FTZ／DAZ 控制，不汇总工作线程浮点状态旗标到调用线程。

该模块不创建设置文件或磁盘缓存。真实分支见证使用已有的 `runtime_log::Trace`，仅在显式指定诊断路径时输出；默认不创建文件。没有新增基础图形后端、特定厂商依赖或 AVX 要求，也没有依据本批检查宣称加载提速。
