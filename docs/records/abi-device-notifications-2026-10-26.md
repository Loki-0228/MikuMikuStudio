# 设备状态通知可靠投递

日期：2026-10-26。工作区 `D:/MMD-Next/MMS-abi-dev`，分支 `codex/plugin-abi`。

## 实现与契约

设备通知不再进入分配内存的通用业务事件队列。Manager 保存最新失效代次、当前设备状态和修订号，每个插件实例保存已尝试投递的失效与恢复游标。记录和正常派发只使用标量及栈上消息，不分配事件节点。

安全入口先完成资源释放，再向有效插件投递最新 LOST，最后投递当前 RESTORED。快速连续的中间状态可以合并。LOST 表示该代资源失效，投递时设备可能已经恢复；RESTORED 必须在回调开始前仍对应当前可用代次。回调改变设备状态时立即终止旧批次，保留新状态，不再向后续插件投递过期恢复。

插件游标在调用前提交。回调抛异常按已尝试处理，不无限重试该插件，也不阻止其他插件收到通知。错误日志的分配失败被隔离。停止的实例不再接收通知，新 Manager 没有旧状态。

通知唤醒失败不清除待投递状态。PostMessage 失败时通过定时器重试；两者均失败时，后续帧安全入口仍可投递。插件回调、准备中的工程加载和待释放资源会阻止派发并保留状态。

帧入口现在可以投递普通设备事件。`FrameDriver` 在该入口返回后立即检查待恢复状态；若回调产生新的延期 Reset，本帧在后续求值和绘制前退出。公共 C ABI 表布局、VMD 格式与阴影逻辑未改变。

## 剩余范围

本机制保证宿主保留和重试最新状态，不保证插件自身的资源重建成功；抛异常的插件不会被无限重试。操作系统同时拒绝消息与定时器且没有后续安全帧时，通知仍保持待投递，不能声称立即送达。通用非设备业务事件队列不属于本批修改范围。

post、租约分类、完整多视图渲染、DX12 原生与 BakePreview 独立呈现仍待统一。原始兼容配置只运行管理器和 DLL 专项，不表示产品启用了插件运行时。真实驱动掉线、Win7、AMD、多显示器和长时间运行未验收。

main 开始与结束核对均为 `d551f1f`。本批没有同步阴影修改，按用户要求继续暂缓。整个 ABI 目标仍未完成。
