# 原生相机曲线导入、导出与烘焙

记录日期：2026-10-19。对应 [main 审查对照表第 9、10 项](abi-main-review-comparison-2026-10-18.md)，修复起点为 `codex/plugin-abi` 的 `de9ae12`。

当前状态：完整配置 11 组整合、原始兼容配置 7 组回归及真实 PMX 原名／PMD 中文改名宿主均通过。正式 ABI 程序已重新构建；目标硬件验收仍单独保留。

## 三类曲线的含义

| 类型 | 实际求值依据 | 导出规则 |
| --- | --- | --- |
| 原生相机曲线 | 标准相机记录的原始控制字节和原生时间反算。标量控制柄仅供画布编辑。 | 完整、同步且未改变原生含义的通道保留稀疏标准相机记录，不改成逐帧代理。 |
| 标量作者曲线 | `animation_curve::Track` 的 Free、Linear 或 Step 曲线。 | 沿用原有逐帧标准代理和既有作者曲线尾段，保留作者数据。原生与标量混合时，原生部分也按其实际采样器生成代理。 |
| 精确保形片段 | `NativeCameraInterval` 保存原区间、原时间域、控制字节及有效画布几何。 | 沿用现有精确片段策略，在导出准备阶段按原采样器生成整帧代理。工程内继续保留片段元数据。 |

触碰端点或交叉的合法 X 控制柄不能直接交给标量核心后忽略失败。原生曲线需要同时保留原始控制字节、画布代理和实际采样器。否则画布仍能显示一条曲线，导入后的运动却已经改变。

本次不改变既有 `CameraSample`、`CameraCurveTime` 或已保存精确片段的数值含义，也不引入新的 PMM 片段版本。

## 原生输入和稀疏导出

[`animation_curve_motion.cpp`](../../src/animation/animation_curve_motion.cpp) 在内存中用 `NativeCameraData` 保留标准相机记录、来源版本和对应轨道基线。导入恢复通道时，原始控制字节与几何一并恢复，再安装宿主现有的相机采样器。未改动的原生记录可以直接按原版本重新编码。

从 MMS 原生时间轴导出时，`CanCaptureNativeCamera` 核对标准相机通道、帧拓扑、有效原始控制、旋转共享时间曲线，以及可写入标准字段的 FOV 和透视值。宿主还核对采样器身份，避免把自定义回调误当成原生曲线。条件不满足时，按标量、混合或精确片段规则处理。

第 0 帧的控制字节虽然不参与区间求值，仍属于标准记录。普通读取、原生镜像、私有重定时视图与作者重新协调统一保留这些字节。未使用的根控制允许原始整数 0–255；活动区间仍要求合法 0–127。零帧删除提升后继键时，作者元数据使用实际新根的字节，不继承旧根。旋转继续保存原始欧拉角及绕圈数，不通过四元数归一化改变运动。

`parentModel` 和 `parentBone` 不属于标准相机记录。它们继续按已有作者尾段策略保存，不影响标准相机九通道的原生导出资格。此次没有新增 VMD 尾段标记或数据布局。普通原生导出没有增加固定的帧跨度上限，精确片段准备仍保留原有内存预算。

VMD 版本存在两个不同边界。

- 同一个未改动的原生 `Motion` 经 `Decode` 后直接 `Encode`，保留来源 VMD1 或 VMD2 的标准记录和版本。
- 曲线窗口先恢复工程通道，再按现有界面惯例导出新的 VMD2。该流程不承诺保留来源文件的 VMD1 版本身份。VMD1 没有的 FOV、透视等字段按其既定默认含义映射。

因此，编码器的 VMD1 往返与界面新建 VMD2 导出需要分别验收，不能互相替代。

## 局部烘焙保留范围外的曲线

[`channel_bake.cpp`](../../src/animation/channel_bake.cpp) 原先只把 `Channel::track` 交给 `Resample`，将画布代理当成相机真实运动。仅替换内部采样语句仍不足够，原有边界恢复还会把范围端点改回代理的数值。

现在先在私有副本中准备两个范围边界。原生边界保留原区间及时间域，画布代理采用有效的可编辑控制柄，范围外继续用现有精确片段求值。范围内按请求间隔从 `Channel::sample` 取值，生成烘焙后的 Linear 键。未选择的相机通道也保留原生区间，避免标准镜像共用新增帧时改变其运动。

纯标量曲线仍使用原有边界细分。烘焙完成后按新拓扑重排控制元数据，只保留仍与几何一致的精确片段。准备失败不发布私有副本。既有原生写入和受控共同历史入口继续负责提交，不在采样器内登记历史或移动播放头。

这里的精确保留指现有宿主相机采样器的函数。没有作者层时，`ReloadModels` 的旧原生求值与宿主采样器存在浮点运算次序差异，包括 Y 控制值乘除顺序和欧拉角的角度转换。不能据一个样例零误差便推断所有输入逐位相等，回归仍需记录最大绝对误差和 ULP，并沿用已有容差。

## 两层内部 C++ 接口

动作数据层在 [`animation_curve_motion.hpp`](../../include/mikudancestudio/animation_curve_motion.hpp) 提供 `CaptureChannels`、`RestoreChannels`、`CanCaptureNativeCamera` 和 `Evaluate`，负责原生记录、作者轨道及编码之间的转换。

宿主层在 [`animation_curve_host.hpp`](../../include/mikudancestudio/animation_curve_host.hpp) 提供 `InstallImportedCameraTiming`、`PrepareMotionChannels`、`PrepareCameraBakeSources` 和 `FinishCameraBakeChannel`。这些接口安装现有采样器或准备私有通道副本。

这两层都是宿主内部 C++ 接口，没有新增插件公共 C ABI、服务版本、对象句柄或权限。现有 VMD 标准字段、原生采样器和持久化格式继续适用。Win7 SP1 x64、CPU 基础路径及 AMD 兼容约束保持不变。
