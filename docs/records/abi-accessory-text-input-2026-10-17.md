# 附件文本共同历史验证（2026-10-17）

本批基于 `codex/plugin-abi` 的 `5a2e263`，仅修改 `D:/MMD-Next/MMS-abi-dev`。附件位置、旋转、缩放和透明度文本 `478..485` 接入受控共同历史，普通 `mms.edit` 仍关闭。

## 行为与接口

`CommitBoundAccessoryNumber` 在旧写入前消费修改标志。完整文本必须是有限数值，不接受过长输入和尾随非空白内容；目标值仍按旧七字符窗口读取。例如 `12.345678` 按 `12.3456` 处理。旋转使用旧 double 运算顺序 `/ 180.0 * 3.141592025756836`，缩放允许零和负数，透明度限制为 `[0,1]` 并按两位小数显示。位置、旋转及缩放使用原四位小数读数。这些字段没有配对滑杆。

内部入口 `ApplyBoundAccessoryField(MMDApp&, slot, field, value, changed)` 接收位置 `0..2`、弧度旋转 `3..5`、缩放 `6` 和透明度 `7`。它检查绑定、编辑锁、运行状态、槽位、字段、键池及有限值；一次实际修改形成一个共同历史节点。该入口不是新增公共 C ABI。未修改、同值、非法输入、忙碌或准备失败不创建历史，不改变 dirty 或 redo，不回落旧写入。失焦或 Enter 不会把舍入读数反写。

成功后按原规则激活附件行。已经选中的附件保留多行选择；新激活附件按原规则独占选择。选择是界面状态，不作为标量撤销内容。提交后的可选通知失败不把已完成编辑报告成失败。撤销只恢复目标字段，保留当前帧、当前选择、其他字段、绑定、模型姿态、旧模型环及全部关键帧。

## 身份、寿命与发布

`AccessoryPoseChange` 保存八字段 before/after 和单字段编号。长期记录按槽位、对象指针、稳定 ID 和键池身份检查来源。每次短期候选另存对象代次、帧号、八字段及父模型／骨骼编号，提交前再次核对。确认对象在场后才解引用。发布只写目标字段并推进记录状态，不分配、不调用窗口、GPU、插件或文件读取。

标量节点不保留额外网格或大容量备用键池，计量只包含自身记录。受控导入／删除节点已持有对象资源；共同历史先恢复删除，再撤销更早的标量修改。FIFO 淘汰更早记录时，标量节点先于后续删除节点退出。活动对象仍由场景持有。因此长期记录允许受控恢复更新对象代次，但仍要求同一稳定 ID、同一对象和池身份。正常池扩容保持身份；槽替换、池替换和同址新对象均拒绝旧撤销。这不覆盖未迁移代码任意释放或破坏资源的行为。
