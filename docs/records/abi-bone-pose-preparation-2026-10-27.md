# 独立骨架姿态准备

## 本批实现

内部 `BonePreparePosePrivate` 从自有骨骼表选择动画姿态或调用方提供的物理备份，再按原生顺序合成骨骼表情。它与原 `SetPhysicsMode` 共用准备循环，原入口保留后续层级调度；新入口只准备输入，不执行层级、IK、尺度或物理模拟。

共享实现位于 `src/model/bone_pose_prepare.hpp`。私有入口使用 `BoneTransformContext` 持有的 CPU 数学函数，没有访问全局数学表、尺度注册表或诊断，不分配内存。原入口继续调用原 `QuatMultiply`，保留每次刷新导入函数及既有 fallback 的行为。

## 调用约定

```cpp
BonePreparePosePrivate(ownedModel, 0, *context);
// 执行这个阶段的全部层级。
// 进入下一物理前后阶段前，再从原始输入准备一次。
```

调用方独立拥有并验证模型、骨骼和表情记录，物理备份如被选择也必须已经有效。上下文租约覆盖调用期。不同线程使用不同可变工作区，可共享只读上下文；不能直接把正在编辑的原生模型交给后台任务。

两个模式值有不同含义：

| 条件 | 姿态来源或表情行为 |
| --- | --- |
| 形参 `physicsMode == 0`，或负数 | 所有骨骼读取 `trans/rotQuat`。 |
| 形参 `physicsMode == 1` | 有刚体标记的骨骼读取 `ikBackup`，不检查 `physicsDisabled`。 |
| 形参 `physicsMode >= 2` | 有刚体标记且 `physicsDisabled == 0` 才读取 `ikBackup`。 |
| 模型字段 `model.physicsMode == 2` | 对所选姿态应用骨骼表情，与上述来源选择独立。 |

因此无物理的 mode 0 仍会应用 PMX 骨骼表情。形参 mode 1 不能用来表示“忽略物理”。

每次先覆盖所有骨骼的 `physicsOffset/physicsQuat`，然后按记录顺序加平移、乘旋转。非法表情骨骼索引沿用原生跳过规则；不会跳过零值或单位旋转，也不归一化。D3DX 调用 `Multiply(pose, morph)` 的结果为 `morph * pose`，不可颠倒。

求解阶段会修改上述工作字段，因此物理前、后两轮各准备一次，再执行该轮全部层级。不能跨阶段沿用，也不能每个层级都重置。现有 `MorphEvaluationFrame` 产生的是累加偏移；后续装配须放入自有偏移表，不可直接当作最终骨骼旋转或再次乘权重。

原生表情回归实际执行 `InitializeBoneMorphOffsets → ModelApplyMorphs → SetPhysicsMode`，检查高索引骨骼、重复直接／组表情、重复求值及归零。物理烘焙回归另覆盖共享场景与自由曲线复制；该夹具没有骨骼表情，不用于替代前项证据。

独立审查确认旧 `QuatMultiply` 函数、层级循环和共享准备逻辑保持原语义。旧 fallback 的 Hamilton `pose * morph` 与真实 D3DX 顺序不同，本批保留该差异；未运行 `Load()==false` 分支，也不宣称二者等价。私有上下文仍要求完整 CPU 数学后端。
