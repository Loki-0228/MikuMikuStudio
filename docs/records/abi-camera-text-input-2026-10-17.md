# 相机面板文本共同历史验证（2026-10-17）

本批基于 `codex/plugin-abi` 的 `2fb4ea5`，仅修改 `D:/MMD-Next/MMS-abi-dev`。接入相机位置、旋转及距离的七个面板文本字段 `544..550`，普通 `mms.edit` 保持关闭。

## 实现和交互

`CommitBoundCameraNumber` 只处理当前主／浮动面板的七个相机字段。仅在 EDIT 修改标志为真时解析，先消费标志，再校验并提交。失焦回调不再提前清除这组字段的标志，避免漏记；重复失焦或 Enter 不会把已经格式化的两位小数再次写回原始姿态。

解析保留原 double 中间值。位置转 float，俯仰取负，其他旋转保持正号，角度使用原 `3.141592025756836 / 180.0`；距离取负。菜单数值对话框的 float 换算没有替代面板规则。完整文本必须为有限数值，可含末尾空白，超长和尾随非空白内容被拒绝。被拒绝或同值输入只恢复读数，不写历史或 dirty，不截断 redo。

相机归零和文本共用 `ApplyBoundCameraField`，继续使用七字段 `CameraPoseChange`。编辑准入、记录分配、历史预留和源校验均在写入前完成，发布只改一个字段。成功后激活相机轨道并刷新；相机轨道已选中时保留多行选择。未修改、同值、忙碌和失败不改变选择。其他姿态、相机键、曲线、父绑定及播放头不由文本操作改变。

普通文本框没有独立取消对话框；未提交输入不创建工程历史。工程变更仍只在合法提交时记录，输入框自身的文本编辑行为保持。

## 代码复核

修改标志在状态写入前消费，原生通知即使重入也不会再次提交同一文本。模型模式仍走既有骨骼处理；其他文本字段不因句柄查询而被接管。未绑定和原始兼容 profile 保留旧路径，后者本批未单独重建。

`ApplyBoundCameraField` 只在成功发布后报告 changed。可选的界面通知位于提交之后，不能把已经发布的编辑重新报告成失败并诱导重复提交。这个边界不承诺对提交后窗口状态进行事务回滚。视角 `448`、滑杆、拖动和滚轮均未纳入本批。
