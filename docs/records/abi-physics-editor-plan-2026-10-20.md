# 物理模型编辑的事务迁移

本记录是菜单 262 的源码审计与实施依赖，实际编辑窗口尚未接入共同历史。菜单的旧注释称其为 frame-edit，实际 `PhysicsModelDlgProc` 编辑模型刚体、关节及其名称，确认后重建表和 Bullet 对象，属于模型工程编辑。

## 现有写入与所有权

`physics_model_dialog.cpp::InitPhysicsModelDialog` 建立两组暂存表，借用模型名称指针。暂存中的 `keyData`、`constraint` 是列表索引，碰撞掩码使用编辑表示，不能直接复制为持久记录。初始化还会清零真实骨骼平移和旋转；取消后的重新求值可能覆盖未登记姿态。

`CommitPhysicsEdits` 先释放旧物理对象、名称和表，再建立新对象。后续分配失败无法回滚到原状态。`physics_scale::Forget` 还会修改形状、质量、关节和碰撞缓存，并释放缩放形状，不能放入要求不失败的正式发布阶段。

`RetainedSceneObject` 首次保留模型时固定物理表、数量及 Bullet 对象。它的 `MembershipCurrent` 要求这些身份保持。直接替换会使已有导入、删除等历史节点失效，也可能使保留的关节指针悬空。保留前后字段副本不足以解决这些资源问题。

## 实施顺序

1. 为已保留的物理对象提供一个候选内的混合加入、移除操作。该步已按[混合交换记录](abi-physics-exchange-2026-10-21.md)实现并通过原成员、导入及新增交换共 4,255 项。它准备完整的世界成员顺序、碰撞缓存、掩码和目标容量，正式发布不分配内存，但不等于支持首次导入的资源替换。
2. 增加从私有 `ImportScene` 首次接入并替换旧资源的候选。旧资源停放与新资源接入必须属于同一世界发布，不能顺序执行两个独立发布。
3. 将模型物理表、完整名称分配、刚体、形状、motion state、关节和缩放派生状态组成可保留的资源版本。模型持有当前版本，历史持有旧版本；导入、删除及模型析构共用该所有权，避免重复释放。
4. 将窗口改为私有编辑会话。打开时固定模型和场景身份，编辑及预览不改正式骨骼或物理世界。确认后验证来源、转换编辑索引、准备资源和历史预算，再一次提交；取消不求值当前场景。
5. 接入实际菜单、窗口及共同历史。两种记录模式均一次确认形成一次显式提交，无变化保留 redo，撤销和重做使用保留版本，不重新读取模型文件。

前后资源、完整名称容量、停放状态及历史账本均计入保留预算。物理表或标量字段的大小不能代表整个节点的成本。

## 验收范围

验收须进入真实菜单 262 和窗口，覆盖增删与重编号、Unicode 名称、缩放物理、取消、无变化、分配和预算拒绝、过期来源、跨模型与插件交错、对象删除恢复及原文件移走后的撤销重做。播放头、未登记姿态及其他模型当前物理状态须保持。

CPU 世界及现有物理编辑夹具可用于本机回归；Win7 SP1 x64、AMD 和其他硬件验收仍需对应设备。后续每一步必须有实际代码及运行证据，不能将本方案或混合成员交换单独登记为菜单迁移完成。
