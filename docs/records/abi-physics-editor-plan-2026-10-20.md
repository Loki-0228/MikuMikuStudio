# 物理模型编辑的事务迁移

本记录保留菜单 262 迁移前的源码审计和实施依赖。完整配置的资源版本、私有编辑窗口及共同历史已随后接入，当前实现和验收边界见[模型物理编辑记录](abi-model-physics-history-2026-10-21.md)。下文「迁移前写入与所有权」描述旧路径，不代表新完整配置仍按该方式写入。原始兼容配置保留旧入口。

菜单的旧注释称其为 frame-edit，实际 `PhysicsModelDlgProc` 编辑模型刚体、关节及其名称，属于模型工程编辑。

## 迁移前写入与所有权

`physics_model_dialog.cpp::InitPhysicsModelDialog` 建立两组暂存表，借用模型名称指针。暂存中的 `keyData`、`constraint` 是列表索引，碰撞掩码使用编辑表示，不能直接复制为持久记录。初始化还会清零真实骨骼平移和旋转；取消后的重新求值可能覆盖未登记姿态。

`CommitPhysicsEdits` 先释放旧物理对象、名称和表，再建立新对象。后续分配失败无法回滚到原状态。`physics_scale::Forget` 还会修改形状、质量、关节和碰撞缓存，并释放缩放形状，不能放入要求不失败的正式发布阶段。

`RetainedSceneObject` 首次保留模型时固定物理表、数量及 Bullet 对象。它的 `MembershipCurrent` 要求这些身份保持。直接替换会使已有导入、删除等历史节点失效，也可能使保留的关节指针悬空。保留前后字段副本不足以解决这些资源问题。

## 实施顺序

1. 为已保留的物理对象提供一个候选内的混合加入、移除操作。该步已按[混合交换记录](abi-physics-exchange-2026-10-21.md)实现并通过原成员、导入及新增交换共 4,255 项。它准备完整的世界成员顺序、碰撞缓存、掩码和目标容量，正式发布不分配内存，但不等于支持首次导入的资源替换。
2. 增加从私有 `ImportScene` 首次接入并替换旧资源的候选。该步已通过 `PrepareReplacing` 实现，旧资源停放与新资源接入属于同一次世界发布，准备和取消不改变两侧数组或容量。首次替换专项 1,850 项及包含旧入口的成员专项 6,118 项通过，见[首次替换记录](abi-physics-first-replacement-2026-10-21.md)。
3. 已实现完整配置的物理资源版本。`ModelPhysicsResources` 保留完整物理表、名称容量、native 对象和 scale 派生状态；当前模型、旧历史、导入、删除及模型析构使用同一所有权。资源专项 276 项通过。
4. 已实现完整配置的私有编辑会话。固定来源身份，草稿及骨骼预览不改正式姿态或世界，确认后转换索引并准备完整资源和预算；取消不求值场景。准备专项 7,481 项覆盖 Begin、Set、Take 的 C++ 分配失败及同 plan 重试。
5. 已接入实际菜单 262、Unicode 控件和共同历史，两种记录模式一次确认形成一次显式提交，无变化保留 redo，撤销与重做不重新读取模型文件。真实控件专项 4,534 项通过；这是同桌面隐藏窗口的本机验证，真实 PMX／PMD 编码整合、原始兼容运行及硬件验收不据此标为完成。

前后资源、完整名称容量、停放状态及历史账本均计入保留预算。物理表或标量字段的大小不能代表整个节点的成本。

## 验收范围

下列为迁移时定义的验收目标，不表示全部已经逐项通过：真实菜单 262、增删与重编号、Unicode 名称、缩放物理、取消、无变化、分配和预算拒绝、过期来源、跨模型与插件交错、对象删除恢复及离线撤销重做。已执行的 CPU 世界、实际控件及故障检查以[本批记录](abi-model-physics-history-2026-10-21.md)为准，真实文件编码整合仍待最终报告。播放头、未登记姿态及其他模型当前物理状态须保持。

CPU 世界及现有物理编辑夹具可用于本机回归；Win7 SP1 x64、AMD 和其他硬件验收仍需对应设备。后续每一步必须有实际代码及运行证据，不能将本方案或混合成员交换单独登记为菜单迁移完成。
