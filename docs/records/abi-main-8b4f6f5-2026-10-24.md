# 自定义保存命名同步

日期：2026-10-24。工作区 `D:/MMD-Next/MMS-abi-dev`，分支 `codex/plugin-abi`，起始提交 `99e8382`。本批同步 main 已提交的 `8b4f6f5` 与 `d4def67`，main 核对 HEAD 为 `66bdaa2`。

## 来源行为

- `8b4f6f5` 为定时备份与手动保存增加自定义命名。新增 `save_naming.hpp`（`[/NAME]`、`[/N]`、`[/YY]`、`[/YYYY]`、`[/MM]`、`[/DD]`、`[/hh]`、`[/mm]`、`[/ss]` 与旧 `[/fff]`），备份与增量各一条规则。备份默认精确到秒，重名追加序号；增量默认 `[/NAME]_[/N]`，每次手动保存创建新文件并把新文件作为当前工程，不再把旧历史顺延为 `.pmm1`、`.pmm2`。设置窗口增加「备份命名」「增量命名」按钮，命名窗口含规则输入框、十个插入按钮、灰色只读预览；「增量保存」移到第二行。保存时把系列原名与本次文件名写入工程扩展记录，重开增量文件继续同一系列，另存为不同名称开始新系列。
- `d4def67` 修正命名对话框与视口渲染比例窗口共用 `RT_DIALOG 9140` 的冲突：命名对话框改用 9162，9140 保留给视口窗口。

## 实现

ABI 在保持自身设置与插件分层的前提下重新实现：

- [save_naming.hpp](../../include/mikumikustudio/save_naming.hpp)：采用 main 的纯函数实现，负责展开、校验、系列名计算与下一个可用文件名（PMM 与 EMM 都占名）。
- [autosave.cpp](../../src/app/autosave.cpp)：设置增加 `backupPattern`、`incrementPattern`。ABI 的偏好仍存中央 `data/settings.json` 的 `autosave` 段；旧 INI 辅助函数同步读写两项，供迁移和测试使用。旧毫秒规则在读取时迁移为新的秒级默认值。备份文件名改用 `save_naming::Next`，仍由归属标记与文件名共同确认清理范围。
- [pmm_save.cpp](../../src/io/pmm_save.cpp)：增量保存先生成新的唯一目标名，把系列原名与文件名写入扩展记录；发布时拒绝已存在的同名 EMM，新建文件不做替换，也不移动 `.pmm1` 历史。ABI 的插件工程对发布（`PublishProjectPair`）在增量保存时按「仅新建」发布并要求不存在同名 sidecar。
- [pmm_save_versions.hpp](../../src/io/pmm_save_versions.hpp)：保留覆盖保存的 `.pmm1` 链与回滚，删除已不存在的编号后移分支；原配置的单文件发布同步简化。
- 命名窗口：[autosave_dialog.cpp](../../src/window/autosave_dialog.cpp)、[autosave_dialog.hpp](../../src/window/autosave_dialog.hpp) 增加 9162 命名对话框与三语文字；备份设置对话框改为 main 的 300×183 布局，工具提示只保留文件夹与 `.pmm1` 两项。[dialogs.rc](../../res/templates/dialog/dialogs.rc) 合并 main 的两个对话框资源，同时保留 ABI 的 9140 视口渲染比例对话框，资源 ID 无重复。
- 测试：[autosave_tests.cpp](../../tests/autosave_tests.cpp)、[backup_dialog_checks.hpp](../../tests/backup_dialog_checks.hpp) 覆盖规则展开与非法输入、命名窗口三语、灰色只读预览、自定义备份命名与归属清理、增量设置独立；[pmm_versions_checks.hpp](../../tests/pmm_versions_checks.hpp) 改为增量保存语义（新文件、旧文件不变、EMM 不被覆盖、另存为开新系列）。测试仅在全构建可用的断言用 `#if !MMD_ORIGINAL_PROFILE` 标注，原配置保留同会话系列名检查。

与 main 的剩余差异：

- 原始兼容配置在载入时有意忽略工程扩展记录（原有行为），因此重开增量文件不会恢复系列原名，同会话内仍用内存记录继续同一系列；完整构建按扩展记录恢复。
- ABI 的偏好保存在中央 `settings.json`，main 该提交仍是 INI；ABI 保留 INI 辅助函数作为迁移和测试入口。
- 插件工程对发布沿用 ABI 自身的事务与 sidecar 规则，未改 main 的单文件发布路径。
