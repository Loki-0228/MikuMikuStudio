# 同模型重名轨道粘贴同步

来源为 main 已提交的 `6facf91330530c917dba70e20ea1c30268829bd2`。原问题是复制重名骨骼或表情后，在同一模型中粘贴仍按名称找轨道，可能拒绝合法粘贴或写入第一个同名轨道。

## 对应实现

复制记录增加进程内来源旁表，保存源模型、骨骼及表情表身份、轨道索引和名称。有效同模型复制按原索引登记，跨模型仍执行名称解析。实际模型释放、初始化及应用关闭清理来源身份；共同历史暂时移除仍保留的模型不等同于资源释放。

ABI 的 `TryPasteBoundKeys` 在旧粘贴路径之前接管操作，因此本批同时适配共同历史入口。普通模型粘贴先捕获私有 `ModelPasteSource`，为有效同模型记录补充索引，再交给原规划与事务接口。镜像粘贴仍按左右名称映射，VMD 原有显式目标和 Unicode 解析路径不变。

独立审查发现来源提交会先更新剪贴板计数，再分配身份数组。分配失败时可能保留较短的旧缓冲。本批增加模型复制失败清理，释放模型剪贴板缓冲及实际已分配的显示记录子数组，清零计数和身份，禁用粘贴。成功发布完整来源记录后才启用粘贴。

旁表不写入 PMM、VMD 或其他文件，不改变名称长度、磁盘结构及 MMS 标记规则。Win7、CPU 和 AMD 基础依赖不变。

## 验证证据

两配置的 `bone_registration_tests` 及核心库构建成功。最终骨骼完整回归通过，包含真实复制、普通粘贴、整批撤销重做、负帧同源映射、过期身份及坐标编辑。证据为 `本地验收记录（未随本文发布）`。

完整配置的共同历史回归结果如下，证据位于 `本地验收记录（未随本文发布）`。

| 入口 | 结果 |
| --- | --- |
| `--key-paste-only` | 965 项通过，包含真实复制后的镜像映射及目标歧义拒绝。 |
| `--mixed-model-paste-only` | 2,525 项通过，包含两种历史模式下的重名骨骼、表情和混合粘贴，以及复制分配失败扫描和重试。 |
| `--model-paste-only` | 1,988 项通过，覆盖原表情和显示帧粘贴。 |
| `--vmd-import-only` | 285 项通过，验证原导入入口。 |

共同历史测试实际执行 420、421、400、401 命令。更换为另一模型的剪贴板后仍可撤销，释放剪贴板后仍可重做；混合粘贴保留一次历史记录，旧撤销环不写入。镜像测试实际执行 422，不用原索引替代左右映射。

首次完整配置骨骼回归在原坐标输入夹具失败：夹具仅设置文字，未设置真实编辑状态，而既有提交 `47eba21a` 已禁止未修改字段在失焦时回写。独立 `--movement-only` 重现同点失败，排除了新复制用例的顺序影响。本批改用 EDIT 的选择及替换消息模拟输入，并检查修改标记，保留生产门禁。较早的失败汇总不视为最终通过证据。

分配失败扫描覆盖 C++ 身份数组、字符串及旁表分配；模型 `malloc` 返回空时已有检查，但未注入每一个 C 分配点。原始兼容配置不因此开放产品 ABI。没有执行 Win7、AMD 真机验收，未发布或覆盖稳定版程序。

## 边界

负帧路径本次只同步有效同模型的原轨道映射。负帧跨模型重名歧义及共同历史接入仍有既有缺口，不属于已完成的验证范围。模型删除后撤销恢复的复制身份依据实际存活对象保留规则实现，仍需专项覆盖该完整操作序列。

本批未同步暂缓的阴影修改，未修改 main，也未覆盖稳定版 EXE。目标范围未修改。
