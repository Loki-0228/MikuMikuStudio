# PMM 输入与临时映射的异常清理

本批接续[工程打开身份保护](abi-project-open-identity-2026-10-19.md)，处理读取结束后仍可能抛出异常的清理路径。真实 V1/V2 主体的关闭后故障验证已通过，工程身份测试的模拟主体另行保留。

## 文件描述符

V1、V2 在完成原生读取后关闭 PMM，随后继续更新窗口、通知扩展、提交插件工程并更新最近工程。后续操作可能抛出内存或运行时异常。旧 shell 捕获异常时再次关闭之前的整数描述符；如果该数字已被新文件复用，会误关新文件。

内部 `pmm_io::Input` 统一接管 PMM 描述符。读取函数仅借用数字；各正常关闭和中止位置消费同一所有者，析构兜底处理仍持有的流。关闭先清空所有权、结束该流的 `CheckedReads`，再调用 CRT。重复关闭不查询或操作已消费的数字。

读取检查与文件同时结束。否则，复用同一数字的新文件还会被线程局部检查误判为旧 PMM，正常 EOF 也可能被报为短读。

公共 `void LoadSceneFile()`、`void LoadSceneV1(MMDApp*, int)`、`void LoadSceneV2(MMDApp*, int)` 保留。内部状态返回函数改接收所有者引用。V1 可选尾段继续允许 EOF；直接调用旧 V2 包装时不额外开启严格短读检查。所有关闭位置和正常业务通知顺序保留，PMM/VMD 格式及原生采样不变。

## V2 临时映射

V2 模型中止分支原来先释放临时映射和工作数组，再重置场景。如果重置抛出异常，外层读取捕获还会释放同一数组。成功尾链在原释放位置前抛出异常时，也缺少兜底释放。

局部 `ModelWorkspaceOwner` 接管工作数组及其四类映射。模型中止和成功尾链仍在原位置释放，先消费指针再释放内容；其余异常由析构清理。窗口、模型解析和重置的调用顺序保留。它不保存场景快照，也不扩大替换后失败的场景回滚承诺。

## 验证边界

独立 CPU 回归使用真实 CRT 文件、确定的描述符数字复用及真实读写哨兵，检查关闭、异常展开、无分配清理、短读诊断和嵌套读取上下文。完整配置与原始兼容配置均已通过 125 项检查，各观察到 11 次真实所有者关闭。

真实宿主由实际保存器生成 V2，并独立构造 V1 的无物体必读字段，保留首个可选尾段的合法 EOF。两版均先正常读取，再覆盖 `bad_alloc`／`runtime_error` 与有／无描述符复用的八种尾链组合。另以实际 V2 缺失模型分支触发中止，并在第一次重置时抛出异常，验证工作数组不会重复释放。错误后再正常打开两版工程。

测试不替换读取主体。完整配置在实际 `native_mesh::ProjectOpened` 注入异常；原始配置在成功尾链中真实的 `PostViewRefresh` 返回后注入。原始配置的 mesh 和最近工程回调是可被链接器合并的空函数，不能通过拦截共享空函数地址辨认通知。CRT 观察器只记录并转发真实 open/close，不屏蔽无效关闭。

错误后检查保存目标与工程目录清空、场景门禁释放、复用哨兵仍可真实读写。通过独占打开及重命名验证 PMM 读锁已释放，通过独占打开配对锁验证插件事务未遗留锁。成功和失败打开均不改写来源文件。
