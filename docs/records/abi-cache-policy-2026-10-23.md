# 缓存策略与中央设置

本批实现缓存配置后端，供后续磁盘存储和管理窗口使用。它尚未接入效果编译、纹理准备、统计或清理入口，因此不代表 main 的完整缓存功能已经同步。

`cache_manager::Store` 使用中央设置文件的 `sections.cacheManager`。生产包装固定读取实际 EXE 目录下的 `data/settings.json`，缓存根为 `data/cache`。不读取旧 `cache.ini`，不使用工作目录、系统用户目录或环境变量重定向。原始兼容配置的生产包装返回 `Disabled`，不创建数据目录；显式构造的通用 Store 保留测试能力。

| 字段 | 默认值 | 有效范围 |
| --- | --- | --- |
| `enabled` | `true` | JSON 布尔值 |
| `automaticCleanup` | `true` | JSON 布尔值 |
| `limitMiB` | `4096` | 十进制整数，64 至 102400 MiB |
| `recentProjects` | `10` | 十进制整数，1 至 100 |

字节换算使用 64 位整数。只有文件、节或字段缺失时使用对应默认值。已存在字段的空值、错误类型、负数、小数、指数或越界数值均返回 `Invalid`。设置忙碌或读取失败分别返回 `Busy` 或 `Io`，生产 `Enabled()` 在这些情况下返回 `false`。

读取返回不透明快照，保存时比较该快照的原设置节。其他设置节的更新可以共存，同节变化返回 `Conflict`，由调用方重新读取并处理，不自动覆盖。保存保留未知字段的 JSON 值，包括嵌套对象、数组及 Unicode 字符串；不承诺保留原始空白或转义写法。

完整候选快照在写盘前构造，保存成功后只交换已准备好的对象。读取或保存失败保持调用方输出；输入快照与输出可以是同一个对象。设置后端沿用真实文件锁及临时文件替换，失败可能留下正常锁文件或已创建的父目录，不等同于文件系统完全无副作用。

独立审查修复了两项分配失败路径：`Decode` 的字符串查找不能位于 `noexcept` 内，`UIntValue` 仅捕获格式错误，其他异常交给入口转换为 `Io`。实现与测试均不依赖渲染器或显卡。

验收证据位于 `build/verification/abi-cache-policy-20261023`。最终结果如下：

| 范围 | 结果与证据 |
| --- | --- |
| 增强配置后端 | `full-final` 5,710 项通过；反例恢复后 `full-restored` 5,689 项通过。分配扫描覆盖有效读取、坏整数读取及别名保存，逐分配点失败后验证原快照仍可提交。检查次数受实际路径长度和分配次数影响。 |
| 原始兼容后端 | `original-final` 5,680 项通过。通用 Store 的验收不代表该配置启用了生产缓存。 |
| 安装路径及 EXE 改名 | 两套独立安装分别运行 `MMS.exe` 和 `renamed-host.exe`。增强配置各 145 项、原始兼容各 61 项通过，均设置 Win32 环境变量及工作目录诱饵。增强配置另覆盖生产包装的真实忙碌、损坏设置及恢复；原始兼容检查 `Disabled` 且不创建 `data`。 |
| 跨进程写入 | 两配置各运行三个自有进程，两路分别提交 20 次同节增量，另一路更新无关节 40 次。最终值、未知字段及全部进程退出码正确。 |
| 中央设置回归 | 两配置各 70 项通过。 |
| 受控反例 | 错误根目录、读取失败默认启用、跳过 CAS 的覆盖写入均以明确断言失败。源码按原字节恢复，重建后再次通过完整增强配置专项。 |
| 构建与兼容性 | 两种产品构建通过；x64、子系统 6.1、导入表和效果资源 117/118 与本批基线一致。正式 `build/release` 程序散列未变。 |

这些检查使用真实配置后端和文件操作，不执行 UI、GPU 或真实插件验收。分配注入仅覆盖当前线程的普通 `new`，不代表系统内存、磁盘断电和硬中断全部故障已经验证。

专项目标为 `cache_manager_policy_tests`，分别用 `--store 新绝对目录` 和 `--installation 新绝对目录` 运行。安装专项必须复制到独立目录，EXE 同级的 `cache-policy-test-installation.txt` 内容为 `MMS cache policy test installation v1` 加一个 LF 换行，运行前该安装没有 `data` 和插件载荷。证据目录也必须全新，避免覆盖用户设置。具体构建参数、复制路径和运行命令记录在构建日志及各次 `report.json` 中。

main 在本批开始及最终产物核对时均为 `fed9768f9fe726c4b5e068849808803f1713ad42`。DSH 在已确认工作区内完成单一实现文件，Codex 补充构建、测试与文档，并完成独立审查及实际验收。审查记录、正式 DSH 结果、构建日志、反例和产物检查分别保留在上述证据目录。

后续仍需实现受管文件存储、读租约、跨进程容量限制、索引及发布恢复、工程关联、固定保留、清理、管理窗口和实际消费者。当前 `enabled` 只表达配置，不是写入额度或删除许可。Win7 与 AMD 真机验收仍待完成。
