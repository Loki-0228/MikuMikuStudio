# 视角文本共同历史验证（2026-10-17）

本批基于 `codex/plugin-abi` 的 `24e8f27`，仅修改 `D:/MMD-Next/MMS-abi-dev`。视角文本 `448` 接入受控共同历史，普通 `mms.edit` 仍关闭。

## 行为和记录

`CommitBoundFovNumber` 在旧写入前接管已绑定的文本，先消费 EDIT 修改标志，再验证完整输入。转换保留原七字符窗口和整数读取，例如 `67.875` 写入 67。未修改、同值和非法输入不产生历史或 dirty，不截断 redo。成功后按原交互激活相机轨道并同步读数和滑杆；滑杆范围不会改写已保存的原始视角值，超范围作者值继续保留。

`CameraFovChange` 保存原始浮点视角与目标值，绑定相机键池身份。发布只写 FOV 和临时投影刷新标志，不分配、不调用窗口或 GPU。撤销可恢复非整数原值，保持当前播放头、距离、透视模式、位置和旋转。正常池扩容后可继续往返，替换池使旧记录过期；短期候选检查帧号、视角和记录代次。

投影请求是增强版 `MMDApp` 尾部的临时布尔标志，位于原 PMM／兼容状态之外，不改变已有成员偏移，不进入工程数据。它不保存旧矩阵或资源，多个请求合为当前状态的一次更新。没有设备时保留请求；安全刷新读取当前相机状态，再使用原 `ApplyFrameCameraProjection` 更新设备。插件历史回调中的通知仍延后到既有安全刷新，不能把 GPU 调用放进原子发布。

## 代码复核

正交距离为零、非有限或极小时，刷新不会安装含无穷值的矩阵。验证使用 double 检查投影系数能否表示为有限 float，避免检查本身先发生 float 溢出。无效距离不阻止视角作者值提交，设备保留原矩阵，后续正常帧仍按既有流程更新。此保护仅覆盖本批延后刷新，不表示全部旧投影入口已经修复。

原始兼容 profile 和未绑定的路径保留旧实现；本批未单独重建原始 profile。没有新增 C ABI、图形后端或厂商依赖。普通文本没有独立取消对话框；未提交文本不创建工程历史，已提交操作通过共同撤销取消。
