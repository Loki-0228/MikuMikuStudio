# main 工程版本保留功能同步

日期：2026-10-20。接续 `49a9c40`，本次同步截止 main 的 `9500a262099526e79db8fbb4118db99661cc817f`。仅同步已提交功能，按 ABI 的存储事务和集中设置适配。

## 功能及用法

在自动备份设置中启用“保留上一版 PMM / EMM”后，手动保存会保留磁盘上原来的工程。该开关默认关闭，与定时备份开关独立，写入 `data/settings.json` 的 `autosave.keepPrevious`。显式指定的测试 INI 及单次旧配置迁移继续有效。

版本名称沿用 main：`scene.pmm` 的上一版为 `scene.pmm1`，更早版本逐次增加 `1`；其效果文件分别为 `scene.emm1`、`scene.emm11`。ABI 还保留每一版的 `scene.pmm1.mms-plugins.json`，保存原插件字节、工程 ID、保存 ID 和对应 PMM 哈希。首次保存不虚构上一版，定时备份副本不额外创建这条版本链。

打开对话框、启动参数、拖放和最近工程支持 `.pmm1`、`.pmm11` 等后缀。后缀只负责文件路由，实际内容仍由 PMM 加载器验证。打开 `.pmm1` 后继续保存，会把其旧状态保存为 `.pmm11`。

MME 通过进程内虚拟通知名称访问与版本相符的 `.emm1`，不生成临时别名文件。只有明确注册的映射允许重定向读写；显式选择的 EMM 后缀保留。映射有容量、名称冲突、分配失败和序号耗尽保护，通知失败不会把已经完成的 PMM 发布改报为保存失败。

## ABI 存储适配

UI 线程捕获版本保留开关，后台仅操作快照和文件。旧版本三件套的准备发生在当前工程的排他保存锁内；轮转前还获取旧版本的锁，避免移动另一个 MMS 正在保存的工程。旧版本存在未完成的恢复日志时拒绝轮转，留给该版本自身恢复。

普通准备失败、文件占用或首次发布失败且原文件均未改变时，恢复旧版本链。当前工程已有部分发布或保留恢复日志时，保留归档供后续恢复，继续使用 ABI 原有的 PMM／插件数据配对恢复。

## 边界

旧版本轮转沿用 main 的文件移动和失败回滚方式。其准备过程没有独立的持久化轮转日志：不能据普通错误或完整准备后的中断测试，宣称轮转任意中间时刻的真实掉电都具备跨文件原子性。当前 PMM 与插件数据的既有配对恢复日志继续有效。

EMM 保存仍受第三方后续渲染回调及自动保存设置控制。归档保留的是保存开始时磁盘上的 EMM，不保证其已反映尚未写盘的效果编辑。版本链受路径长度及磁盘空间限制，不作无限保留保证。

本批不改变标准 VMD 数据格式，不接受 MDS 标记，不恢复曲线修复工具。Win7 SP1 x64、CPU 基础路径及 AMD 兼容要求保持；没有新增真机 Win7／AMD 验收结论。main 工作区与稳定程序未修改，测试使用的第三方 DLL 不进入发布目录。
