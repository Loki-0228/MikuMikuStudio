# 历史记录模式与统一系统设置

本批在独立 `codex/plugin-abi` 工作目录实现「帮助 → 系统设置」。界面名称为「历史记录模式」，另有最大保留步数、历史内存预算和本机建议值。默认仅记录显式提交，保留 32 步，预算 64 MiB。用户可以手动设为 1～100000 步、16～16384 MiB。

## 两种模式

| 模式 | 已接入入口的行为 |
| --- | --- |
| 记录全部编辑操作 | 姿态、滑杆、数值及参数调整，每次有效变化都记录历史。重复位置和无操作不追加。 |
| 仅记录显式提交 | 调整仍实时生效，但不追加历史或清除 redo；登记关键帧、导入、删除、关键帧编辑及插件显式事务继续记录。 |

现有骨骼姿态作用域、全局数值／开关及 Morph 权重均按调整意图进入共同历史。关键帧登记、导入、删除等仍使用显式意图。预览继续经过原子准备、来源校验及安全发布，并更新场景 revision，旧候选不能在预览变化后继续发布。预览临时准备和回滚所需分配仍可能失败，但不受历史保留预算限制。

切换模式不重建历史，也不单独产生工程 dirty 或撤销节点。未结束的原生候选、插件事务或其他历史忙碌状态拒绝切换。配置先保存成功，再修改模式和容量；保存失败不裁剪已有记录。

**当前边界：普通运行仍未绑定完整共同历史，`mms.edit` 仍未开放。模式和容量已在受控迁移入口及真实测试宿主验证，不能据此宣称普通运行的全部原生操作已经支持。** 界面说明该选项针对已支持的编辑操作。帧线插删、粘贴、VMD 导入与视口拖动等仍需迁移。本批没有为使开关看似立即覆盖所有操作而混用两套历史。

## 步数和内存

步数与预算同时约束共同历史。降低上限时先回收最旧的 undo，仍超限时裁掉最远端 redo，保留紧邻当前状态的记录。记录回收不改当前姿态或播放头。显式提交超过预算时在发布前拒绝，不能先改工程再丢弃撤销数据。

「按本机计算建议值」取当前可用物理内存的 1/16，限制在 16～256 MiB。存在记录时，建议步数按当前平均保留字节估算；没有记录时按每步 2 MiB 估算。建议仅填写输入框，点击保存才应用，用户可以继续修改。每次提交仍执行实际计量和分配检查，平均值不是后续操作大小的保证。

预算约束历史计量的保留数据，不是整个 MMS 的内存上限。当前场景、渲染器、GPU、插件私有数据、临时准备和回收前资源都可能有额外占用；步数与内存预算也不限制 CPU 使用率。配置不能保证系统绝不发生内存不足。

## 单一配置文件

宿主配置统一写入程序旁 `data/settings.json`，不依赖 EXE 名称或工作目录。根结构为 `schemaVersion=1`、`sections` 对象。

| 分区 | 内容与旧来源 |
| --- | --- |
| `history` | 模式、步数和内存预算。 |
| `window` | 原 `mmconfig.ini` 的窗口、界面语言、显示尺寸、侧栏与目录记忆。 |
| `language` | 原 `model_info_language.ini` 的模型名称语言及翻译偏好。 |
| `antialias` | 原 `antialias.ini` 的抗锯齿设置。 |
| `processor` | 原 `processor.ini` 的生产处理器选择；不从旧蒙皮测试配置推断全局策略。 |
| `shadow` | 原 `adaptive_shadow.ini` 的自适应阴影及增强过滤。 |
| `autosave` | 原 `autosave.ini` 的自动备份选项；默认目录继续相对当前安装解析为 `data/backups`。 |
| `viewport` | 原 `viewport.ini` 的操作柄角落。 |
| `curveEditor` | 原 `curve_editor.ini` 的曲线编辑偏好。 |
| `recentProjects` | 原 `recent-pmm.txt` 的最近工程列表。 |
| `pluginUi` | 原 `data/plugins/ui-layout.json` 的插件布局。 |

仅在相应分区缺失时读取旧文件并迁移，之后以中央文件为准。旧文件保留，不自动删除，生产写入不再重建这些分散配置。显式测试路径及环境变量 override 继续独立，避免测试污染生产设置。

保存使用锁内读改写、临时文件和原子替换。同值不写盘，不同分区互相保留；未知字段尽量保留，损坏文件及未知 schema 不被默认值覆盖。插件布局使用分区 CAS，同一布局的过期写入返回冲突，其他分区变化不冲突。`settings.json.lock` 是协调文件，不是第二份配置。

工程及插件专用工程数据、备份、日志、插件自己的文件不混入系统设置。`PLUGINS/config.json` 继续控制插件扫描层数，插件清单及第三方配置不改写。仅供显式测试使用的旧蒙皮文件 API 保持，生产处理器策略归 `processor`。
