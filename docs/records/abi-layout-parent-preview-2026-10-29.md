# 同区域临时重新分组

本批继续临时布局需求，目标范围不变。正式 `MMS_LAYOUT_MOVE` 原来已经支持持久父节点移动；新增工作是临时会话的父节点覆盖。当前为内部接线阶段，公共 `mms.ui.layout.session` 仍为 1.0／1.1，不能据此声明插件已经能调用新的父节点字段。

后续进展：同日已通过 [1.2 公共 C／SDK 及真实 DLL 验证](abi-layout-parent-public-2026-10-29.md)。下文保留本内部批次的实现和证据，公开接口状态以该后续记录为准；跨根、DOCK 等剩余范围未变。

## 实现与约束

内部 `LayoutPreviewValue` 增加 `PreviewParent` 和目标父元素 handle。Begin 声明目标及依赖，Apply 整批验证并发布；有效父节点通过 `UiRegistry::EffectiveParent` 读取，沿用现有注册对象、身份、布局和生命周期，不创建另一套控件树。

本阶段允许本插件的 BUTTON、INPUT、SEPARATOR 和 GROUP 在同一工具栏／属性区／侧栏挂载根下移动到本插件 GROUP 或该根。要求 MOVE 权限；目标 GROUP 必须是容器。跨根、跨插件、菜单、工作区 PANEL、DOCK 继续拒绝。跨区域功能仍是未完成需求，不以本阶段支持范围替代。

整批最终图和其他活动会话一并校验。自身、后代、批量及跨会话循环都拒绝；失败不部分发布。撤回某个会话可能暴露旧父链，因此继续核对其他会话并撤销不再有效的父节点字段。父依赖保存注册身份和字符串 arena，避免同 ID 重注册或内存复用冒充原目标。

正式提交复用现有 MOVE、偏好文档和布局历史，内部批量在最终图校验，允许“先把子组移出，再让原父组成为它的子组”这类最终无环的操作，不受输入数组顺序影响。公共持久 MOVE 保持原有逐项验证。仅父节点提交不重排控件，也不夺走独立的尺寸／顺序会话；失败保留可继续操作的预览。本批没有增加或重新验收磁盘偏好保存故障路径。

## 原生控件与刷新

NativeUi 的子节点枚举、实际挂载查找和祖先可见性读取统一有效父节点。同挂载根内移动不会改变 HWND 的实际父窗口，因此可以保留 INPUT 的窗口、未提交文字及选择区。

临时移入原本隐藏的目标组时，只暂停并隐藏 INPUT；排队的失焦和 Enter 不得误提交。自身或共同祖先的持久隐藏仍优先，不能被一个父节点预览改成临时隐藏。正式提交到隐藏组后，继续采用原来的持久隐藏销毁／重建规则。

`UiRefreshQueue::SyncTopology` 同样读取有效父节点，使 SUBTREE 刷新和界面分组一致。旧拓扑上的待处理请求应失效，新请求按当前组的成员执行；回滚和整组移动也须保持该规则。

## 验证状态

交互回归记录（本地证据，未随本文发布）中，完整／原始兼容两种配置分别通过 INPUT 755、溢出 675、surface 265、工作区面板 660、公共 C 316、C++ SDK 239、真实 NativeUi 858 和 ABI 契约 45,157 项。SDK 为假宿主检查；NativeUi 与 INPUT 使用真实隐藏窗口，SUBTREE 用例通过实际刷新队列及命令状态回调核对成员和旧请求失效。原始兼容产品不因此开放 ABI。

上述首次汇总的两个内部预览专项失败，不能把该汇总称为全部通过。原因是新分配故障夹具把发布成功后派生拓扑同步失败也误判为事务必须回滚。修正后严格区分：发布前失败保持父关系、修订、通知、会话和输出不变；发布后失败维持已成功的操作与唯一历史，只重试拓扑同步，不重复 Apply／Commit。测试中的私有消息窗口只观察刷新请求准入，不替代真实 NativeUi 验证。

最终内部预览补验（本地证据，未随本文发布）两配置各 **25,237 项，0 失败**。Begin／Apply／Commit 父节点故障扫描分别覆盖 7／23／286 个分配点，包含同步恢复后再次同步不重复编辑。最终仅修改测试，生产代码与先前通过的交互二进制一致，因此保留原 16 组通过证据并补验这两组。失败日志未覆盖。

独立只读复审未发现本批新增阻塞问题。两配置相关目标构建通过；完整开发程序构建见 构建记录（本地证据，未随本文发布），可选启动导入检查为 `[]`。这些结果不等于真实输入法、可见动画、物理鼠标或硬件兼容验收。
