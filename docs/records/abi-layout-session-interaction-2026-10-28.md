# 临时布局交互与面板失败恢复

本批在 `codex/plugin-abi` 修复临时布局会话与真实输入控件、溢出菜单的交互，并修复已有 surface 面板的失败处理。工作区 PANEL 的临时布局会话仍未开放。

## 实现

- `ControlVisibility` 统一判断控件及祖先的有效显隐，并区分持久隐藏与临时覆盖。临时隐藏保留已挂载 INPUT；持久隐藏仍卸载。临时显示可覆盖隐藏基线。
- INPUT 在实际提交前检查有效显隐。会话已经隐藏但原生窗口尚未刷新的间隙中，排队失焦和 Enter 不再提交或清空草稿。尺寸、顺序和恢复显示不主动抢焦点。
- 同步 IMM 取消使用固定 HWND 快照及身份检查。INPUT 消息处理期间，NativeUi 延后可能卸载输入框的刷新；布局测量遇到重入修改时放弃旧结果。
- 溢出菜单记录布局修订和宿主排版参数版本，打开后发生布局变化则丢弃旧选择。
- 已挂载 surface 先隐藏，再执行隐藏页原有的尺寸及 DPI 通知。隐藏、显示或尺寸回调失败时不重新发布有效几何。首次创建失败仍显示原错误占位，不改变既有约定。

交互及回归证据分别位于 `本地验收记录（未随本文发布）` 和 `本地验收记录（未随本文发布）`。这两次汇总中的 surface 结果仍为失败，最终面板复验由 `本地验收记录（未随本文发布）` 替代。INPUT 最终证据为 `本地验收记录（未随本文发布）`，追加了直接从布局入口进入同步 IMM 注销的检查。测试先修复了祖先恢复时沿用旧零高度区域而清空草稿的问题。面板断言则按既有刷新契约修正：已发布目标暂停后仍可查询身份，但 `ready=0`；从未发布的目标返回 `NOT_READY`。首次失败日志保留。

真实 MMS 宿主的普通模式及共同历史绑定模式均通过，目录为 `本地验收记录（未随本文发布）`。两个模式都经过已加载 DLL 的 C 表及 SDK 调用。测试没有覆盖稳定版 EXE。

INPUT 测试用真实 EDIT、Manager、插件 DLL 和共同历史，仅替换本进程的焦点查询及指定 IMM 调用来注入同步重入。溢出测试使用真实菜单与命令分发，但模拟弹出菜单的返回值。这些不是物理输入或像素验收。

用户反馈 `user32_smoke.exe` 输出 `user32 main hwnd=000000000001000C`，确认其桌面能够创建窗口。该结果不是绘制、输入法、多 DPI 或真实鼠标验收。

## 保留范围

PANEL 临时显隐与顺序还需要选中页恢复、用户切页接管和 surface 生命周期协议。DOCK、跨父节点与跨插件目标仍未实现。真实微软拼音、候选窗、像素显示、跨屏 DPI、Win7 及 AMD 硬件验收不由隐藏窗口测试替代。

布局验证期间 main 核对至 `d551f1f`；随后发现的 `6facf91` 已另行完成[粘贴行为同步](abi-main-6facf91-2026-10-28.md)。阴影相关提交按用户要求继续暂缓。本批不修改 main、不覆盖稳定版 EXE、不修改目标范围。
