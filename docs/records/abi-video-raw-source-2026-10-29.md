## 已实现的内部接口

实现在 `include/mikumikustudio/cache_files.hpp` 和 `src/io/cache_files.cpp`，沿用受保护的缓存目录和文件身份检查，不新增公共插件 ABI。

| 接口 | 行为与调用责任 |
| --- | --- |
| `Directory::PrepareRawSource(path, maximumBytes, write, cleanup)` | 打开并保留源文件读句柄，检查单文件上限，创建唯一空文件。成功返回 `RawSourceWrite`；其 `Plan()` 包含创建身份和预期长度，供上层在开始复制前登记。`maximumBytes` 不是磁盘总预算。 |
| `RawSourceWrite::Complete(lease, cancelled)` | 使用固定 64 KiB 缓冲分块复制、计算摘要、刷新文件；转为只读租约后重新检查身份、长度和全文件摘要。失败保持原输出和待处理计划；重试从头复制。取消通过原子标志采样，不调用用户回调。 |
| `RawSourceLease::Path()` | 返回固定的卷 GUID 绝对路径，文件内容是原编码数据，没有缓存头。调用者必须让租约覆盖解码器打开、读取及后续重开的整个寿命。 |
| `AcquireRawSource(info, lease)` | 检查确切文件身份、长度和摘要后取得独立租约；不根据文件名推断所有权。 |
| `RemoveRawSource(info)` | 仅在独占打开并复核身份、长度、摘要后，通过同一文件句柄请求删除。活跃读者导致拒绝；`DeletePending` 不表示磁盘空间已经回收。 |
| `RawSourceWrite::Abort()` | 显式放弃候选；关闭过的写句柄须按原身份重新打开，不能按同名路径盲删。 |
| `RawSourceCleanup::Abort()` | 处理创建后身份查询与即时清理同时失败的情况。回执保留原始独占句柄，无须再次查询身份或按名称定位；清理再次失败时仍保留回执。 |

`CleanupRequired` 只在需要接管清理回执时返回；调用者传入的非空回执会使后续准备返回 Busy，防止覆盖待清理责任。所有对象的析构及移动覆盖只关闭句柄，不擅自按路径删除文件；上层必须先保留计划并核算未完成及待删除文件。接口本身不提供跨进程额度、崩溃恢复或未知文件清理权限。

源文件允许正常硬链接，捕获期间禁止通过链接改写内容。Windows 允许移除未打开的硬链接别名；复制依赖已经持有的句柄，不依赖该别名继续存在。自有缓存文件则严格拒绝多硬链接、重解析点和身份不匹配。

## 审查与实际验证

审查修复了一条失败路径：创建文件后，如果身份查询和同句柄删除同时失败，旧方案可能关闭句柄并遗失清理责任。现在在创建前准备回执所需内存，失败时交出原句柄；测试覆盖反复删除失败、外部写入／重命名拒绝及最终重试成功。

两种配置的最终原始来源专项均 **324 项通过、1 项跳过**。覆盖分块复制、取消、读写及刷新故障、重开失败重试、内存分配失败、并发租约、清理回执、硬链接及真实目录联接拒绝。跳过项是文件符号链接创建（系统返回 1314，缺少所需权限）；不能将其记为通过。

真实 VfW 专项在两种配置各 **1,799 项通过**：生成两帧 AVI，捕获后删除原文件，使用租约提供的原样卷 GUID 路径打开，逐像素核对 0→1→0 帧、双读者、关闭后重开，以及读者释放前拒绝删除。没有退回普通盘符路径。此结果只证明 VfW；Media Foundation 和 FFmpeg 尚未获得对应证据。
