## 布局历史失败原子性

文档核对发现，旧实现先发布布局再分配历史记录；撤销／重做还会在发出变化通知后修改历史栈。因此内存不足可能让界面已经改变但调用返回失败，通知重入也可能操作外层尚未更新的栈。

现在提交先准备历史，撤销／重做在同一发布步骤更新布局和两侧历史栈，最后发送通知。新增测试逐个注入提交、撤销、重做及偏好导入的内存分配失败，检查布局、历史、修订号、对象代次和通知数不变；另覆盖通知内再次撤销、重做或提交，以及 32 步上限和无变化提交保留重做记录。此修改不增加公共 ABI。

## 实现

`sdk/mms/include/mms/cpp/storage.hpp` 增加 `StorageServices` 和 `SavedBytesLease`。查询、读取、释放使用原 `mms.storage` 1.0 C 表。租约保存原上下文和句柄，服务包装对象重查或销毁不改变已有租约；移动、显式转移和释放共用原租约身份。已有输出不被覆盖，错误线程不调用宿主，回调期间禁止对同一租约重入读取、转移或释放。析构不代替 UI 线程上的显式释放。该封装不包含序列化提供者或格式服务。

场景关闭保护修正了上一版重放时提前清除请求的问题。主窗口和浮动窗口收到私有重放消息后，在原窗口过程内处理 `WM_CLOSE`，不再次发送 `WM_CLOSE`。录制、烘焙、场景修改、插件回调和原生对象操作仍在进行时保留请求，等待安全点。消息投递失败也保留请求。`SC_CLOSE` 同样在本次分发内归一化；主窗口和浮动窗口关闭期间互相保护，避免拆除子窗口时重入退出。窗口销毁清除自身待处理状态，重投前检查当前窗口身份与有效性。

本机制处理正常关闭请求，不承诺拦截直接 `DestroyWindow`、进程终止或跨线程释放。原始兼容配置保持原关闭分发顺序。

修正文档中布局撤销的过时描述：现有布局 1.1 已提供进程内偏好历史和 C++ 封装。临时布局会话、用户接管优先和插件关闭后恢复仍未实现。
