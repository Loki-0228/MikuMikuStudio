# 图片来源预算设置与多节原子保存

本批补齐上一批仅能修改配置文件的预算入口。目标范围不变；背景摆放共同历史仍未开放。存储实现、真实界面夹具及独立审查。main 已提交最新仍为 `6facf91`，阴影同步暂缓；未改 main、未覆盖稳定版。

## 用户行为

完整配置的“帮助 → 系统设置”新增“图片源数据预算（MiB）”，默认 128，允许 16～4096 的整数。保留原历史记录模式、步数、历史内存预算和建议值功能。建议值按钮只计算原历史设置，不偷偷改变图片资源预算。

点击保存同时更新历史设置和图片资源设置，并立即应用来源限额。降低限额保留已有图片来源；下一次捕获仍按新旧来源同时占用的峰值检查。取消不改文件或当前预算；非法值保留对话框供修正；保存失败也保留原设置并允许重试。

若原资源字段无法读取，输入框显示为空，必须明确输入合法数值后才能保存；不会以默认值掩盖读取失败。损坏或不支持的整份设置文件仍由存储层拒绝覆盖。

原始兼容配置保留原对话框尺寸、历史控件及 history 单节写入，不展示或修改图片预算。两配置均增加 Windows 对话框回调异常边界，控件创建失败退出，不保存残缺控件内容。

## 接口和失败规则

内部 `system_settings::Store::WriteSections(std::string_view sectionsObject)` 及全局同名包装接受非空的“节名 → JSON 对象”映射。所有名称和内容先验证，然后在同一文件锁下读取、递归合并，经过整体大小、节点数及深度校验，最后只替换一次文件。未知根字段、其他节和已存在的未知成员保留；任意一节非法或保存失败都不部分提交。原单节和 CAS 行为保留。

UI 保存前准备全部字符串、回调和可能首次分配的全局预算状态。绑定历史时，把一次 `WriteSections` 放入现有 `SharedHistory::Configure` 的持久化回调；写入成功后调用无分配的预算 `Configure`。该回调成功之后，历史配置仅更新标量及转移列表节点，没有后续分配或用户回调。两类运行时设置都更新后才回收旧历史资源，失败时两类运行时设置均不修改。

新字段仍为程序目录 `data/settings.json` 内的 `sections.resources.backgroundPictureSourcesMiB`，没有增加配置文件。这是编码来源预算，不是解码器、纹理、历史或程序总内存上限。
