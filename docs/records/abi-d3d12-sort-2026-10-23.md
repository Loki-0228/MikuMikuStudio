# 可选 D3D12 预览的透明排序策略

本批从 `3f37a38` 继续，main 核对至 `fed9768`。修改仅属于 ABI 工作区，不覆盖正式稳定版程序。源码及专项已完成独立静态审查，本机真实硬件、帧回退及两套工程设置回归通过。未据此完成全部透明排序、ABI 或平台验收。

## 行为

可选 D3D12 预览原先对每个透明材质执行精确深度排序，即使用户选择关闭排序也会改变面顺序。该算法也不等同于已接入 D3D9 的桶排序、对象范围或 Maximum 策略。

`RenderD3D12Native` 现在只接受 Off。其他档位及未知值在任何 native 初始化前返回 false，让现有 `RenderFrameScene` 继续执行 D3D9。已经存在的 native 实例在回退时释放，其子窗口随之销毁。用户的预览启用请求保留，切回 Off 可以重新建立预览。排序精度、跨对象范围、工程修订和播放头不由该门禁修改。

Off 帧直接复制作者索引并转换为 INDEX_BUFFER 状态，不再为透明排序创建 keys、编译排序着色器或执行排序 Dispatch。模型蒙皮和正常绘制保留。`ValidateD3D12Native` 检查已提交帧的作者索引，不依据之后修改的 UI 设置推断旧帧；回退销毁实例后拒绝导出旧帧。

策略回退状态由内部标志及固定字符串返回。第一次候选给 `std::string` 赋长文本，独立审查发现其分配失败可能穿出门禁，已改为无分配表示。该修正不代表其他旧异常处理中的所有字符串分配均已消除。

## 验收范围

`d3d12_sort_policy_tests` 分别提供无需图形设备的真实入口检查及显式请求的硬件检查。前者包括首次回退期间的线程局部分配拒绝、四档与未知档位、两种范围、初始化查询、请求保留和禁用状态。分配拒绝先通过实际 `operator new` 调用校准，离开受控区间后才执行断言和清理。

硬件模式使用同一个实际适配器的 D3D9 和 D3D12、隐藏父窗口以及合成 PMD。同一材质的一面、近面在先和远面在先三种情况形成独立像素对照，同时执行真实 GPU 索引读回校验。测试覆盖修改设置但尚未渲染时的旧帧校验、实际回退后的子窗口销毁、旧帧拒绝，以及切回 Off 后恢复。缺少对应硬件、运行时或调试组件时明确跳过，不算硬件通过。

`transparent_sort_settings_tests --d3d12-fallback` 使用真实隐藏宿主，观察 `RenderFrameScene` 到 native 门禁再到 D3D9 的执行。四档与两种范围均要求真实 BeginScene、EndScene 成功，以及原地面网格 VB、IB 和参数的 before-DIP 提交。这项证据不等于读取单次 DIP 返回值、模型像素或 FPS 只记一次。

常规完整配置和原始兼容配置继续关闭 D3D12。可选运行验收使用单独启用 D3D12 的构建目录；测试目标显式获取与核心一致的 `MMD_ENABLE_DX12`，避免用关闭分支的结果冒充 native 验收。

## 仍未覆盖

- D3D12 本身尚未实现 D3D9 的新排序算法，当前提供能力回退。
- `RenderFrameScene` 因 MMV、捕获或其他外层条件跳过 native 入口时的通用窗口生命周期，需要单独核对。
- 冷启动分配拒绝不覆盖已有 native 实例析构中的全部 COM 或系统分配。原有 fence 等待和设备移除处理也未重写。
- 多窗口、多视口、真实 MME、Win7 和 AMD 真机验收仍未完成。
