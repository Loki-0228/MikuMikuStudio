# 增强模型来源路径的共同历史

日期：2026-10-22。分支 `codex/plugin-abi`，基于 `4d9c24a`。本批把菜单 263 的成功来源切换接入现有共同历史，保留原 PMD 文件输出及增强数据随 PMM 重开的行为。普通生产 `mms.edit` 仍未开放。

## 路径与文件分别发布

`NativeModelSourcePlan` 在文件对话框前固定模型对象、稳定 ID、owner、槽位、绑定及场景代次、初始工程与历史修订。候选保留完整的新旧 256 个 UTF-16 字符，包括第一个 NUL 后的原始尾部。私有 writer 始终接收该对象，不在对话框结束后重新读取选择目标。

文件输出成功后，绑定宿主按 `ExplicitCommit` 提交一个来源节点。两种记录模式都记录这次确认。普通未绑定菜单沿用实际 Manager 的编辑权限检查及安全发布，但不伪造共同历史绑定，也不开放插件编辑服务。原始兼容配置保留原菜单路径。

| 情况 | 外部文件 | 工程来源及历史 |
| --- | --- | --- |
| 取消或准备失败 | 不开始输出。 | 不改来源，不增加节点，保留 redo。 |
| 写入、flush、close 或替换失败 | 保留已有目标，删除本次临时文件。 | 不发布候选。 |
| 对话框后选择、绑定或来源过期 | 输出前拒绝。 | 不改向另一模型，也不覆盖外部修改。 |
| flush、close 后来源过期 | 在 `MoveFileExW` 前拒绝。 | 不发布候选，保留旧文件与历史。 |
| 文件成功，最终历史提交拒绝 | 保留已经写出的文件。 | 保留旧来源及历史，单独报告来源未切换。 |
| 同一来源路径 | 仍写出文件。 | 保留完整旧缓冲，不新增节点或清除 redo。 |

文件发布与工程事务不是联合原子操作。失败提示在候选、历史 token 及操作保护全部释放后显示；已写出的外部文件不因提交拒绝而删除或重新导出。

## 撤销与影响范围

撤销、重做只复制保留的路径，不读取、改写或删除 PMD。模型删除后恢复可以使用新的对象代次继续回放，模型排序和当前选择不会改向另一对象。每次准备重新核算保活 owner 的实际记账成本，预算不足在文件输出前拒绝。

影响为 `ProjectData`，不重置物理、求值场景、移动播放头或刷新姿态读数。成功切换及回放设置原工程修改标记，因此 `SceneRevision` 按 `ModifiedFlag` 的既有语义递增一次；该计数不是求值次数。相同路径和拒绝不递增。模型目录、增强标记、顶点与 CPU 缓存保持原样。

轻量 `Operation` 在对话框及文件写入期间保留输入门，不创建完整场景 mutation 或启停顶层窗口。`Publication` 只包围内部准备、紧邻文件替换的只读复验及最终提交。后台文件调用、对话框和第三方 hook 不获得持续的发布授权。最终路径 `Publish()` 正常分支只检查标量不变量、复制 512 字节并更新内部标量。

## 本机证据

证据目录为 `build/verification/abi-model-source-history-20261022/`。完整与原始配置的产品、PMD、ABI 测试构建通过。路径参与者 `--model-source-path-only` 通过 6,150 项，覆盖两种历史模式、完整尾部、取消、OOM、预算、权限、过期、删除恢复及混合插件事务。既有 `native_model_source_checks.inc` 是粘贴来源测试，已保持不变；新路径测试使用独立文件和入口。

真实 `InitMainWindowAndD3D` 宿主通过全部操作、显式提交及普通启动三组：修改 Toon 表，另存增强 PMD，保存 PMM，替换活动数据后重开工程，确认重新加载新 PMD 的 Toon 修改。绑定两组还验证来源撤销、PMD 临时离线时重做，以及 same-path 保留 redo。三组原始输入文件的 SHA256 均未变化。该结果不包含刚体或关节增强编辑的工程重开验收。

实际菜单 `--model-source-save-only` 通过 3,900 项。它从自有 STATIC 窗口进入真实 `MainWndProc`、分派及 writer，和上述完整初始化宿主分开计证。真实 `_close` 转发成功后修改来源尾部，改变及同路径两组均在 Move 前拒绝；真实 Move 成功后再令实际 journal gate 拒绝，检查文件保留、来源及历史不变，并在操作保护释放后确认来源仍有效。该反例没有替换 writer、文件替换或提交结果。最终源码与二进制冻结在 `candidate-04/manifest.json`。

最终选取 39 组成功结果，逐组核对可执行文件与冻结哈希，包括上述 2 组专项、3 组完整宿主、两套既有 21 组 ABI 回归及 13 组相邻检查。原始兼容 PMD 两组分别通过 43 项与 44 项，完整 PMD 通过 105 项。历史通知采用新增菜单夹具后重编译版本的 209 项结果，替换早期二进制的同组记录，其余未变二进制沿用本批已取得的运行结果。

初轮测试把工程修订误当作求值次数，错误要求成功后不递增，已依据 `ModifiedFlag` 的正式定义修正。随后实际错误提示框先后因激活观察及过早关闭消息未结束，触发一次 240 秒和两次 45 秒超时。失败报告保留，不计为通过。初始化返回后的线程内检查已确认真实提示文案及释放顺序；最终改为检查自有提示框初始化返回后调用真实 `EndDialog`，全组通过，不依赖前台焦点或全局输入。

DSH 会话 `a93d99bf-718b-4488-9764-3ad136e26a26` 的实际工作目录为本 ABI checkout，只修改 `native_model_source.hpp/.cpp`。首次会话中保留 `CODE_RUN_FAILED` 的读取失败及恢复记录；后续收紧发布函数的轮次正式完成、`sawError=false`，终态游标 178。Codex 负责跨模块整合、测试与独立复核，不把 DSH 的完成状态当成验收。

## 兼容与剩余范围

两套产品仍为 x64、子系统 6.1。完整配置新增的直接导入仅为 `comdlg32!CommDlgExtendedError`，用于区分取消与保存对话框失败；原始配置导入未变。微软列出的最低客户端为 Windows 2000，当前产品未导入 Windows 10 的 API-set 转发项。见[接口要求](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/nf-commdlg-commdlgextendederror)。

Win7 SP1 x64、CPU 基础路径、AMD 及程序旁 `data` 的要求保持。运行继承 Default 桌面，只操作夹具窗口和文件；不代表真机系统、显卡、输入法或多屏 DPI 验收。其余原生写入、模型增强、外部资源与完整 ABI 仍需继续实现，不能据此开放普通插件编辑服务。正式 release 的 SHA256 仍为 `180db2580c99a3578f30b2539451ff82605aebdec337daebce8b77edf86cf65a`。
