# 独立骨架求解上下文

## 本批实现

内部 `BoneTransformContext` 持有独立的 CPU 数学后端，`BoneFrameTransformPrivate` 在调用方自有的模型工作区上执行原生五阶段骨骼求解。私有入口和原入口共用同一套局部变换、层级、CCD IK、继承及世界变换代码，没有复制第二套求解器。

这是单个层级、单个物理前后通道的内部执行入口。它尚未装配冻结动作、骨架定义、表情和外部依赖，也没有新增公共 C ABI 或完整场景帧。调用者仍须安排层级顺序、输入姿态和外部目标的求值顺序。

## 接口与生命周期

定义见 `include/mikumikustudio/bone_transform_context.hpp`。

```cpp
auto context = BoneTransformContext::Create();
// context 为空：所需 CPU 数学后端不可用；分配失败仍抛 bad_alloc。
if (context) {
    BoneFrameTransformPrivate(ownedModel, afterPhysics, layer,
                              ownedModelSlots, physicsMode, *context);
} else {
    // 向调用方报告后端不可用，不生成求值帧。
}
```

使用前必须检查创建结果。上下文在宿主安全点创建，发布后只读；任务持有 `shared_ptr<const BoneTransformContext>`，覆盖整个调用期。各线程分别拥有可变骨骼、IK 和选择表；可以共享只读外部矩阵，但不能读取另一个线程正在修改的目标模型。

调用前还须保证所有索引、链链接、选择器和目标有效，选择器 0 存在，全部输入在调用期存活。这些是内部入口的前置条件，不是允许插件直接传入原生指针；后续公开服务仍须通过快照、身份及额度检查构造工作区。

上下文用独立的 DLL 引用解析八个数学导出：三轴旋转、矩阵乘法、矩阵转四元数、向量归一化、四元数乘法及四元数转矩阵。平移矩阵继续由原本地代码构造。x64 使用 `d3dx9_43.dll` 的 CPU 数学函数，不创建设备，也不要求特定显卡厂商。缺少 DLL 或任一必要导出时创建失败，不静默混用不完整后端。

模块引用由内部对象管理；导出缺失、对象分配失败及共享指针控制块分配失败均沿同一析构路径释放。最后一个上下文租约释放后销毁内部对象。

## 与原入口的隔离

| 行为 | 原入口 | 私有入口 |
| --- | --- | --- |
| 数学函数 | 每次数学调用仍刷新全局 D3DX 表，保留宿主 IAT 钩子行为 | 只读自己的已解析函数表，不调用全局 `Get()/Load()` |
| 尺度缓存 | 仍在五阶段之前执行 `RestoreTransforms` | 不读写尺度注册表，也不执行恢复 |
| 诊断探针 | 诊断构建中保持原记录行为 | 在两个探针调用前阻断，不读取计数或写文件 |
| 求解顺序 | 原五阶段及原计算顺序 | 同一五阶段及同一计算顺序 |

私有入口绕过宿主 IAT 钩子，不继承插件对宿主数学入口的改写；这不保证绕过 DLL 内联或导出表修改。原入口的手写 fallback 保持原样。其四元数矩阵公式的已知差异仍待单独处理，本批不宣称 fallback 与 D3DX 等价，私有上下文也未开放 fallback 后端。

逐位比较按每个层级和物理通道执行，包含四组矩阵、物理位移／四元数和 IK 累计四元数。夹具实际运行双链接 CCD，覆盖 PMX 三类限制、PMD 左右膝盖、重复链接、零／一次迭代、继承和协同旋转、根骨、外部父级及物理门控。另有禁用 IK 的对照，并检查限制确实改变结果，避免空路径通过。

并发检查让四个工作区共享同一上下文及只读外部目标，结果与原入口一致；生命周期检查先释放宿主持有者，再由四个线程继续求值。全局 API 哨兵检查覆盖已有上下文和新创建上下文，确认它们不调用或改写全局函数表。尺度检查先实际应用尺度，再证明私有入口不恢复缓存，而原入口仍恢复。

诊断目标直接编译同一生产文件并启用 `MIKUMIKUSTUDIO_DIAG`。私有 IK 实际改变骨骼，但不生成 trace 或 precheck；随后原入口以第一条记录覆盖测试哨兵，证明私有调用未消耗记录计数。

重构前对照从 Git 提取 `327694f` 的原文件，重命名旧函数后与当前 core 链接。同一测试程序实际引用旧 `BoneFrameTransformReference` 和新 `BoneFrameTransformPrivate`；独立审查核对了源码、编译参数和对象符号。旧源码副本仅在本地验证目录，不进入产品源码。

分配失败测试验证异常传播、其他租约继续有效及成功对象正常销毁。DLL 引用释放路径经过 RAII 审查；测试没有强制卸载进程中的共享 D3DX 模块，也不把弱引用过期当作系统 DLL 引用计数的测量结果。缺失 DLL／导出的分支未通过移除系统文件进行运行验证。
