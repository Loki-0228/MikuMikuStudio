# 公开网格场景 1.5（2026-10-27）

`mms.scene.evaluate` 1.5 在完整配置中提供独立网格来源、同源绑定顶点、索引和材质分段，以及独立帧的 CPU 变形顶点。来源和帧沿用原骨架求值的对象身份、句柄、后台求值、额度及停止保护；1.4 的骨架来源保持独立行为。C++17 `EvaluationMeshServices`、`EvaluationMeshSource` 和 `EvaluationMeshFrame` 包装相同 C 句柄。调用契约见 [求值 SDK](../../sdk/mms/evaluation.md#15-同源网格)。

拓扑只能从来源读取；帧可以在来源释放后独立读取变形顶点，但不保留拓扑。批量读取上限为 4096 项，先校验并暂存，失败保持调用方全部输出。后台读取计入工作空间并保留在途引用；停止后拒绝新调用。模型和目标的来源数据在同一安全点冻结，不采纳当前未登记的编辑值。QDEF 等不支持类型返回 `MMS_E_UNSUPPORTED`；测试中的 QDEF 为运行时注入，不是 PMX 2.1 文件验收。

实现期间修复三项集成问题：插件必需服务检查缓冲区原先不足以容纳 1.5 表；畸形骨架帧可能伪造网格回调而缺失 UV 数组；最后句柄释放与在途回调交错时，宿主闭包可能在内部锁内析构并重入。来源、帧及原有采样路径现在保留活跃计数和额度至锁外销毁结束。1.4 表前缀和功能行为保留；扩展内部数据结构使字节计费有所变化，不承诺旧版精确字节数不变。

## 验证

证据在 `build/verification/abi-public-mesh-20261027/`，源码在最终构建前冻结，测试后复核哈希一致。完整及原始兼容配置产品均构建通过；原始兼容配置不在生产中开放场景求值服务，双配置 mock 与 DLL 测试不改变这一点。

- 网格及场景契约：两配置各 740 项；包括越界、失败输出保持、异常回调、未启用 UV、配额、在途释放和析构重入。
- C++ SDK：两配置各 507 项，包括版本、句柄、批量读取及失败保持；这些测试不证明 SDK 能识别所有伪造的成功响应。
- 真实 DLL 生命周期：两配置各 648 项，包括来源与帧读取进行中的停止和释放。
- 完整 ABI 套件：完整配置 44,818 项，原始兼容配置 44,830 项通过。
- 真实三模型宿主和插件：1.5 实际协商、C 与 C++ 两层调用、同源拓扑、目标动作变化和生产 CPU 蒙皮逐顶点对照、删除及 PMM 重载后的帧寿命通过。测试对两个依赖模型各一个顶点在运行时指定受外亲影响的骨骼，详见前批[夹具记录](abi-mesh-scene-topology-2026-10-27.md)。
