# 图片拖动共同历史及鼠标定位失败保护

本批只推进 ABI 工作区，main 最新已提交版本仍为 `6facf91`；没有复制 main 未提交文件、同步暂缓的阴影修改或覆盖稳定版程序。目标范围未修改。

## 用户反馈及实际修复

用户在自己的桌面运行 `native_edit_history_tests --camera-hud-only`，仍得到 `positioned=0`：期望客户坐标 `(100,107)`、屏幕坐标 `(108,138)`，实际屏幕坐标 `(467,243)`。因此撤回“仅自动执行环境导致”的推断。

独立于 MMS 的窗口诊断也得到 `SetCursorPos` 返回 FALSE、立即读取的 LastError 为 0；获取鼠标和坐标转换成功，线程桌面和输入桌面都是 Default。系统调用失败的最终原因尚未确定，不能把本批测试通过表述成真实鼠标 warp 验收。

生产代码 `frame_modes.cpp` 原来在未确认定位成功时就把当前／上次鼠标坐标写成中心。现在只有定位成功才写入中心；失败时保留真实采样，并在开始拖动时同步上次坐标，避免无移动时的虚假增量。边界回中同样按成功结果更新相应轴。图片会话在同步回调后复核序号，防止已取消会话的旧调用继续改写坐标或隐藏光标。

## 图片手势行为

- Ctrl 加顶部图片平移／缩放入口使用同一共同历史。AllOperations 将连续预览合成一条记录；ExplicitOnly 更新草稿，保留既有撤销／重做分支。按下但不移动、往返至原位均不产生记录。
- 准备事务先于首个字段写入。预览只修改摆放字段，不改变播放头、重置物理或提前标记工程已修改；成功结束后才发布工程和视口变化。
- 历史只保存固定摆放元数据及稳定图片 ID，不增加来源／纹理所有权。撤销重做重新取得当前激活票据，因此导入、拖动、替换、删除交错后，删除磁盘源文件仍能按图片导入历史保留的来源重放。
- Esc、捕获丢失、关闭、绑定切换和场景重置取消手势。取消只恢复仍等于本次预览的字段，保留外部修改。图片／AVI 替换及 PMM v1/v2 加载在媒体身份失效前先取消，包括失败的替换尝试。
- 窗口鼠标释放和帧轮询释放共用最终实时坐标采样，忽略过期消息坐标。最后一次坐标读取失败时只提交此前已接受的预览；重复释放不再追加记录。
- 刷新失败保留图片待刷新票据；重试不重复提交历史。可见视频仍优先占有背景目标，当前绑定历史的视频拖动继续拒绝，不误改下面的图片或相机。

实现位于 `src/plugins/native_picture_gesture.hpp/.cpp`，接线涉及 `frame_modes.cpp`、`native_viewport_history.cpp`、图片加载／清理、关闭和 PMM 加载入口。结束过程先摘下活动会话，保持清理屏障直至事务、工具、捕获及刷新完成；关闭延后只覆盖单次同步操作，不跨整个鼠标手势持有。

## 验证

背景最终汇总（本地证据，未随本文发布）共 20 组全部通过，包含两配置来源／资产／身份／注册表／策略／PMM，手势内核、实际 BMP／AVI 与像素、激活、光标、重置、图片历史及本批图片拖动。汇总保存程序 SHA-256 和每组退出码；原始配置不开放新图片历史。

本批图片专项使用真实隐藏宿主、D3D 图片和共同历史。输入层仅替代系统鼠标／按键边界，调用实际顶部命中、帧处理及窗口消息路由。覆盖两种模式、平移／缩放、两种释放路径、最终采样、定位失败、取消、预算拒绝、刷新重试和媒体／场景／绑定切换。不是可见画面或真实手动拖动验收，也不是实际设备丢失测试。

初次测试发现三个夹具前提错误，均修正而没有放宽生产约束：ExplicitOnly 不会为网格调整生成测试所需的 redo 节点；8×8 小图自动适配后的缩放高于既有 100 上限；还原测试渲染比例后必须重新请求顶点刷新。常规最终采样测试改从缩放 1 开始，既有缩放上限不变。

相机专项（本地证据，未随本文发布）通过 8,666 项，完整原生历史（本地证据，未随本文发布）通过 713,350 项，使用相同 SHA-256：`9c9f6437e61b733a0aeb0fed3dd746c512de6b785d6d1e3476695cba9a1c5e12`。全集汇总最初用了错误的结束标记 `PASS checks=`；已按原日志的 `PASS native history: 713350 checks` 更正匹配，并保留修正说明，原退出码为 0。

相机夹具在定位失败时，仅允许移动同进程、同线程、隐藏且未修改窗口过程的系统 STATIC 窗口，让未移动的真实鼠标对应指定客户坐标。严格复核窗口尺寸、焦点、捕获、鼠标屏幕位置和最终坐标；按实际 Unicode 模式比较实例／类窗口过程，避免 ANSI 适配地址不同造成误拒绝。重入用例先准备坐标再安装产品窗口过程，不能移动已安装产品过程的窗口来绕过测试。日志持续标记 `SetCursorPos remains FAILED (not a warp acceptance)`。

ABI 开发程序构建成功，日志为 最终构建（本地证据，未随本文发布）；可选启动导入检查为 `optional startup imports=[]`。不表示真机 Win7、AMD 或所有图形功能已经验收。

原始兼容配置专用 UI 回归（本地证据，未随本文发布）通过 677 项、0 失败，未显示测试窗口、改变焦点或调用文件对话框。此前误构建该目录残留的 `sidebar_resize_tests.vcxproj`，得到 full-only 头依赖和 IME 链接错误；当前 CMake 明确不为 mmd932 生成这个目标。已撤回为残留工程所尝试的头／链接修改，改用正式 `original_profile_ui_tests` 目标构建验收。这不是原始兼容产品的运行故障，也不能把旧残留工程当作当前受支持目标。

## 剩余边界

### 同步重入补验

补充图片手势专项（本地证据，未随本文发布）通过，测试二进制 SHA-256 为 `9ec39872910a024e10b15c2426cc6daa9b94a986ab819e856e1d07f8358d7e72`。两种历史模式下，在实际视口刷新调用中同步发送 WM_CANCELMODE，验证整次预览撤回、旧调用不继续回中；捕获释放时发送 WM_CAPTURECHANGED 并尝试重新开始，清理屏障内拒绝、结束后允许。还验证刷新内 WM_CLOSE 延后、资源仍有效及外层返回后排队重放。
