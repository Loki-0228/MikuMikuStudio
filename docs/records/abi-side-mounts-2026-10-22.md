# 左右侧栏挂载与布局失败恢复

本批在 `codex/plugin-abi` 增加两个真实原生控件区域。`mms.sidebar.left.extensions` 位于本体时间线右侧、主视口左侧；`mms.sidebar.right.extensions` 位于主视口右侧。两处承载原 BUTTON、GROUP、SEPARATOR、INPUT，不接收 surface 或 DOCK。开发方式见[侧栏 SDK](../../sdk/mms/side-mounts.md)。

## 原对象和布局

两个根加入原 `UiRegistry`，由现有 `acquireAnchors` 枚举。C++ 声明继续调用同一 C 表。属性记录、编辑草稿、刷新目标、DATA binding、依赖及订阅没有第二份实现。

`NativeUi` 的四个原生控件区域共用内部 `ControlMount` 管理窗口、缓冲、边界和滚动。左右列默认纵向，先按原布局树测量内容宽度，再给中央工具栏、工作区、属性行和视口分配剩余区域。空组没有有效控件时宽度为零。内部容量约束保留中央空间；两列以实际客户区计算水平和垂直滚动页，最多四轮收敛，失败不发布就绪几何。

宿主保留原时间线的 `SidebarWidth` 和 `SidebarRatio`。共享视口计算新增左右预留参数，继续用原整数居中和渲染比例。两参数为零时原黄金坐标不变。浮动和全屏模式忽略两列预留，录制尺寸规则未修改。中央视口、Present、覆盖层及命中使用同一扣宽区域；本批没有创建新渲染器。

纯 resize 和分隔线几何更新保留 HWND、元素 handle 和实例，不因重排重建输入控件。输入草稿、选区和焦点沿用原规则，用户主动转移焦点仍按 INPUT 的既有行为处理。跨根移动或显式布局隐藏仍遵守原视图重建语义，注册 handle 和属性记录保留，旧实例及依赖失效；不能把注册身份与原生视图身份混为一谈。

## 失败后可以直接修复布局

审查发现，布局先改变内部保留宽高，随后宿主同步失败时，下一次同值请求可能跳过同步。现在内部单独保存最后成功发布的 `LayoutReservations`，并保留失败发布标记。宿主回调返回失败、NOT_READY 或抛异常后，相同 LAYOUT 必须再次同步，成功后才恢复 ready。普通同步 Layout 仍由调用方读取实际保留区域。

内部滚动、切页和 Refresh 不代表应用已读取新保留宽高。它们遇到尚未同步的尺寸时保持暂停，并通过原异步消息请求宿主处理；只有公开同步 Layout 或成功的队列回调确认发布。ReadyFor 的恢复选项默认关闭，仅 SELF 的接收、票据验证及执行显式开启，不能使 SUBTREE 或 DEPENDENTS 放行单独暂停的子控件。

原刷新队列允许仍挂载、实例未变、支持 LAYOUT 的暂停目标接收 SELF 纯 LAYOUT 或 `LAYOUT | REPAINT` 修复。暂停时 STATE、DATA、纯 REPAINT 及含 STATE 或 DATA 的组合仍拒绝，输出参数保持不变。SUBTREE、DEPENDENTS、停止、工程代次及失效实例的原门禁不变。该变化不开放公共 `mms.edit`，不写共同历史。

## 剩余范围

时间线内部、状态栏、surface 侧栏和 DOCK 尚未开放。原属性自动监听、依赖图自动传播、完整本体命令登记、布局历史及多视口继续列为未完成。普通生产 INPUT 仍只读，生产 `mms.edit` 仍关闭。

几何测试的 DPI 用例只验证输入坐标不重复缩放。控件 IME 检查使用合成消息，不能代替微软拼音真机验收。本批不据此确认连续桌面无闪烁、Win7 真机、AMD GPU、多屏 DPI 或录制编码。旧曲线堆损坏和一次全集超时仍按[既有记录](abi-curve-heap-observation-2026-10-21.md)保留，不因侧栏测试通过而关闭。
