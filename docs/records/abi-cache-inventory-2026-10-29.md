本批继续 ABI 内部资源预算前置工作。main 已提交 HEAD 仍为 `6facf91`，阴影同步暂缓、目标没有改变；没有修改 main、覆盖稳定版或增加公共插件 ABI。

## 实现内容

`cache_files.hpp/.cpp` 新增有界 `Directory::Inventory` 和四类已有文件对象的 `Observe`。盘点包括未知文件、子目录、锁文件及 NTFS 额外数据流，不读取正文，不根据名称认领或删除任何文件。

| 接口／数据 | 含义 |
| --- | --- |
| `FileObservation` | 文件身份、默认数据流逻辑长度／分配长度、全部报告数据流的逻辑／分配总额、属性、链接数、类型及删除待完成状态。 |
| `ObservationLimits` | 单条目的流数量和查询缓冲区限制，默认 128 条、256 KiB；允许范围分别为 1～4096 和 32 字节～4 MiB。 |
| `InventoryLimits` | 默认最多 4096 条目、深度 16、相对路径总计 1 Mi UTF-16 code units、1024 个目录保护句柄，并包含流查询限制。 |
| `InventorySnapshot` | 可移动对象，保存根目录身份及按相对路径排序的条目。根条目路径为空、深度为 0，也计入条目／目录限制。 |
| `Directory::Inventory` | 观测整棵受限目录树，接受取消标志；失败、超限、取消均保留旧输出和旧目录保护。 |
| `PreparedWrite / RawSourceWrite / RawSourceCleanup / FileLock::Observe` | 直接查询已有句柄，不读正文、不移动写指针、不按路径重新打开。RawSourceWrite 尚保留计划但已关闭写句柄时返回 Busy。 |

普通文件采用只请求属性的元数据打开，可与自己的独占写句柄和已锁定的控制文件并存。结果保存原根及遍历子目录的保护句柄，但不保留普通文件的数据读取租约。硬链接按各自名称报告并保留相同身份及链接数，不在盘点层自动相加或去重。

每项观测核对前后身份、基本信息和默认流信息，并取得两次完整流列表比较名称、长度和分配长度。流解析检查记录偏移、对齐、长度、重复名称、负数及总额溢出。遍历后重新核对每个目录的名称集合和目录观测；检测到变化返回 Conflict。重解析点、访问失败、未知查询失败和超限不能变成零占用。

## 数据流及一致性边界

额外数据流可附着在普通文件、根目录或子目录，均参与观测。只有同句柄卷能力明确不支持 named streams 时，才按默认流返回；支持流但查询失败则整体失败。成功返回有效列表时不会因遗留的 ERROR_HANDLE_EOF 丢掉列表，成功空列表的文档特例也有处理。

这里报告的是文件系统提供的流长度／分配量，不含 MFT 等卷内部开销，不是分区物理占用或已释放空间的证明。稀疏文件的逻辑长度和分配长度保留为不同字段。后续计费应明确采用哪一种，并按确切文件身份合并“已写部分与完整预留”，不能把每个名字各算一份后又增加整份预留。

快照**不是全树原子快照**。普通文件在其观测结束后仍可被外部写者改变，末轮目录名称核对不证明文件正文或长度从此不变。统一协调器必须在所有受管写入遵守的共同锁内观测和批准额度；当前结果不能单独授予额度、所有权或清理权限。

新增系统调用保持 Win7 基础要求。微软文档将 [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex)、[GetVolumeInformationByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationbyhandlew) 和 [FILE_STREAM_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_stream_info) 的最低客户端列为 Vista；这项接口核对不替代真机 Win7 验收。
