# 恢复终点事实及其来源额度读取

本批补上“恢复究竟回到哪个真实版本、该版本还有多少来源责任”的基础能力，沿用现有 catalog 恢复协议。没有新增公共插件 ABI、批准恢复入口或视频生产接线；总体目标不变，阴影同步暂缓。

## 已实现

`WritePlan` 新增 `Recovery()`、`RecoveryTarget()`、`RootIdentity()`。真实 `PlanRecovery` 在原 catalog 锁内验证文件和日志后，分别提供：

| 动作 | 可信终点 | 新分配的文件 |
| --- | --- | --- |
| Noop | 当前确切 head | 无 |
| ConfirmPublication | 已完整写入、但尚未完成确认的新 head | 无；仍需真实 flush 和清理日志 |
| Rollback | 排除日志精确指定的候选后，验证得到的旧 head | 没有回滚决定时需新写决定文件；已有决定时不新增 |
| 初始化回滚 | 无已存在 head，终点明确无效 | 按真实计划决定，不能伪造空业务账 |

规划不创建正文、intent 或回滚决定，不因坏链而挑一个较旧版本继续。输出终点带原物理根、owner、revision 和完整 head 身份；执行再次核对根、日志身份和终点，不能使用已过期计划。非恢复或无效计划不会提供恢复动作／终点。

未执行计划持有终点 payload 的实际读租约；`Snapshot` 本身仍为值复制，不拥有文件租约。Confirm 的读租约与原恢复代码所需的独占刷新句柄互斥，因此执行先在 catalog 锁内完成所有前置核对，再消费计划、释放自己的 pin，进入原独占复核／flush。转移后若其他读者导致 Busy，也必须重新规划；尚未发生写入时 `MayHaveWritten` 仍为 false。错误根、过期版本等转移前拒绝不消费计划。消费后的终点值仍可读取，但不再保证其物理 pin。

`ReadRecoverySourceBudget` 与普通额度读取共用目录、页、来源校验和额度推导。它要求调用者持公共管理器锁和已有 control 锁、保活未消费恢复计划；自身不再次取得 control 锁。读取先比对实际 `Video/control/catalog` 身份，再验证真实 pages、项目引用、owner 和 raw 目录绑定。错误根、损坏页面、无终点、非恢复／已消费计划均拒绝并保持原输出。

该结果仅描述恢复终点的未来责任，不代表当前目录已经恢复，也不证明此前获批。完整 Inventory 仍必须计入所有实际候选、日志、未知文件和 ADS；恢复计划本身的成本另行计算。读取不执行恢复、不授予额度、不创建文件。

## 持久批准回执的下一步方案（尚未实现）

恢复事实不是额度许可。若要求重启后在降限／关闭状态下继续兑现已批准的恢复开销，需要明确的持久许可，不能把普通 v1 intent 默认标成“已批准”。

优先扩展现有操作日志为有独立格式版本／Key 的批准 intent，包装原始精确 `intent::Record`，而非维护第二份全局限额。记录应绑定管理根及各实际子目录身份、分配单位、操作和前置版本、固定候选文件计划、各文件角色上限及批准的剩余责任。所有字段必须由管理器实际审批产生并在恢复时重算／核对，不能让记录自报的数值成为授权。

顺序是：同锁下审批完整峰值（包含新日志及最大回滚日志）→ 固定真实零长候选身份 → 在原 `WriteOperation` 持久边界写入并验证批准日志 → 才写正文和提交。半写／未知版本日志不构成许可；未完成批准时的残留只能通过可信原句柄／计划清理，否则保持 unknown 计费，不按名字认领。

回滚 decision 必须携带同一批准信息，避免 intent 删除后丢失证据。完整 commit 只能确认原发布；未完整 commit 按原计划回滚，不能重新 Commit 一个新 generation。未决许可清理未确认前阻止下一来源事务，退额只由重新 Inventory 确认。

上述扩容必须进入共享 footprint 和来源未来责任的计算。Checkpoint 没有相同 intent 流程，必须单独补齐其失败许可与恢复策略，不能顺带宣称覆盖。逻辑额度批准也不保证卷上仍有物理空间；ENOSPC 时应保留许可和残留，不能将零长 PreparedWrite 误称为已实分配完整回滚空间。

可信初始化、统一批准恢复、raw 各阶段调用、生产激活、帧租约和完整视频共同历史继续待实现。
