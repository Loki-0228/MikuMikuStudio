# 缓存写入计划与持久来源额度事实

本批实现内部写入计划及真实持久记录的额度推导，不新增公共插件 ABI。统一预算协调器、视频生产入口和共同历史仍未完成。目标范围不变，main 阴影修改继续暂缓。

## 实现

`cache_catalog::WritePlan` 覆盖初始化、提交、检查点和明确恢复。规划阶段深拷贝输入，绑定真实目录身份、旧 head 和实际恢复记录，返回每个新增文件的完整封套尺寸。执行阶段持 catalog 锁重新核对，不能扩大原计划、改用其他目录或自动重规划。纯预检失败保持输出和未消费计划；实际写入尝试后计划被消费，保留 `MayHaveWritten`，不能据错误返回自动退款。

普通发布包含正文快照、commit、intent 和失败回滚决定的预留；检查点按真实退休列表计费；恢复根据已确认状态决定是否需要新回滚记录。既有 API 复用计划执行路径，故也必须验证旧恢复、故障注入和维护行为。错误目录在打开锁之前拒绝，执行只打开已有锁。

`Directory::LockExisting` 和 `ReadPinnedExistingLocks` 允许只读预算查询使用已有锁。`ReadSourceBudget` 读取真实 catalog、业务页和唯一 Video 原始文件目录绑定，校验工程引用后提供额度事实。只缺少 Video 才返回 Absent；部分目录、缺失锁、损坏记录或页面不能当作空账本，也不自动初始化或恢复。失败保持旧输出。

持久操作预留覆盖“先成功推进，再取消”的最长发布路径：Reserved 为 4 次，Prepared 为 3 次，Captured 为 2 次，Abort 为 1 次。每个文件按实际卷分配单位分别取整；包含名字及真实工程 owner 列表可能带来的根记录增长。维护上界为 `1 + 剩余发布次数` 个最大检查点，允许每次发布前维护并保留结束时的备用检查点。审查纠正了遗漏终端备用、以及仅按提交次数而忽略字节容量更早触顶的边界；不能假定总能等到 63 次提交后再维护。

这是整条路径的空间上界，**不是可以直接逐步消费的额度批准**。协调器仍需结合实际提交槽位、维护已花额度、磁盘盘点和身份匹配，确保操作期间不会重复分配额度。已发布 raw 文件由实际盘点计费；待写承诺还需按身份扣除已观测的对应部分。本批没有实现来源退休／删除的额度策略，也不把忙碌、删除失败或未知文件视为已回收。

## 目录与后续接线

视频新仓库计划调整为 `<exe>/data/cache/Video/{control/catalog,pages,raw}`，进入现有效果／纹理管理器同一盘点根。先前 `data/video-cache` 是规划路径，尚未作为生产视频入口落地；本批没有迁移用户文件。

后续统一锁顺序为管理器跨进程锁、进程状态锁、来源 control 锁、catalog 锁。仍需实现可信初始仓库、实际工程 ID 映射、写入前审批、重启后预留合并、显式恢复及维护额度消费，再接视频菜单／PMM 和可撤销历史。仅共享 settings 限额或读取这些事实不足以完成统一预算。

下一实施切片先约束现有效果／纹理准入：在同一候选盘点内读取来源义务，只有物理账与来源记录都验证成功才整体替换旧账。读取失败保留原占用显示并拒绝新写入，不能先发布新物理值再丢掉预留。Reserved 没有文件身份，计完整承诺；其他阶段只能用准确目录／文件身份抵扣已写默认流，不能拿未知文件或 ADS 占用抵扣未来正文增长，也不能被多个操作重复抵扣。已发布来源不重复加账。该切片仍不启用视频写入、自动恢复或初始化。
