# 模型关键帧混合粘贴

受控共同历史绑定下，模型模式的命令 `421` 已支持骨骼、表情和显示／IK／外亲键的任意组合。一次粘贴的多条源记录合为一个显式事务，两种历史模式都记录一步。骨骼镜像粘贴仍按原规则仅处理骨骼。

普通未绑定运行和既有单类粘贴保留原路径。完整生产绑定与 `mms.edit` 仍未开放。

## 统一准备与发布

`native_model_paste.hpp` 定义内部 `ModelPasteFamilyResult`，包含本族记录、最大帧、游标、匹配状态、实质变化状态及最终目标标记。`PlanBoneKeyPaste`、`PlanMorphKeyPaste` 和 `PlanDisplayKeyPaste` 增加可选聚合结果；不传该参数时，独立粘贴行为不变。这些接口不属于公开 C ABI。

`PlanModelKeyPaste` 复用三族私有计划，先准备显示轨道，再把目标外亲窗口交给骨骼求值，最后准备表情。所有准备都不修改当前键池。

`ModelPasteChange` 先统一校验各族、三个池及显示键的嵌套缓冲区。发布按骨骼、表情、显示、共享元数据的顺序执行，不再在中途重新检查已被前一个参与者改变的共享字段。全部池增长、曲线恢复和求值均已提前准备，发布不分配内存。

共享元数据只发布一次，规则如下。

- 清除捕获范围内的旧标记，再选中各族最终粘贴目标；不只是选中最后一类键。
- 最大帧按旧注册器结果合并，保留其覆盖与追加的差异。
- 最终游标沿用旧普通粘贴最后处理显示池的规则，最后登记帧保持不变。
- 撤销恢复原范围标记，并清除本次粘贴新增尾槽的标记。后来同身份扩容产生、且不属于本记录的范围保留，不能为了清空整池而破坏其他编辑的选择状态。

候选冻结代次、播放头、池身份及存储布局。第一次准备还检查原始选择快照。任意族失败、预算不足、取消、跨池或嵌套缓冲区别名、对象替换及候选过期，均不发布前面的族。

## 求值、无操作与空骨模型

显示键包含可见性、IK 开关和外部亲关系。混合粘贴时，它不再单独重新计算骨骼；骨骼参与者从目标显示轨道统一求值，避免先按旧外亲关系计算，再覆盖关系而留下不一致的姿态。没有匹配骨骼源时，也保留显示轨道所需的骨骼求值。未登记的脏姿态和表情权重保留。

等值源仍可提供参与者和目标标记，供另一族发生实质变化时一并处理。全部族都没有实质变化、源完全无匹配或剪贴板为空时，不创建历史，也不清空已有重做。历史持有键值、缩放、曲线及显示嵌套载荷，撤销重做不读取剪贴板或原文件。

零骨模型按旧 `RegisterBoneKey` 的规则跳过骨骼参与者，继续处理表情和显示键。即使骨骼源不会匹配，也检查计数、源指针及全部目标帧，不能把坏帧号或缺失缓冲区隐藏在无匹配分支中。存在非法 IK 或骨引用的结构仍拒绝。

## 剩余迁移

常规关键帧粘贴的模型组合与五类全局轨道组合已接入受控历史。VMD 批量导入、视口拖动及其他尚未审查的原生写入入口仍需继续迁移。帧线操作尚未统一移动自由曲线作者关键点，完整生产绑定继续关闭。
