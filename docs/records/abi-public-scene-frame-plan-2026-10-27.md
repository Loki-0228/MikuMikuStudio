# 公开骨架场景帧接入方案（2026-10-27）

本文为下一批实现方案，以下新入口尚未加入公开 SDK。当前公开服务为 `mms.scene.evaluate` 1.3，仅提供注册通道采样；内部 `BoneSceneSource` 和 `BoneSceneFrame` 已实现独立骨架求值。接入目标是让插件使用冻结的完整模型集合，在后台获得独立寿命的骨架结果，并与现有服务共用身份、句柄、额度和停止规则。

## 范围和时间

第一批公开帧覆盖模型骨骼的局部动作、骨骼表情、层级、IK、外亲和尺度，采用原生全场两轮调度与确定的加载初值。物理模式为 0，不模拟刚体。附件、相机、灯光、网格蒙皮及历史物理尚不属于这份帧。能力查询须逐项说明，不能标记为完整场景所有通道均可用。

有理数秒必须同时生成连续插值时间和精确离散帧。内部 `EvaluationTime` 负责无溢出转换。位置、旋转、尺度、表情和自由曲线用连续时间；原生键前后选择、物理禁用字节、IK 开关、外亲选择、窗口 snap、终端填零及可见性使用精确离散侧。公开输出保留原请求的规范化有理数时间，不能用近似 double 反推。

求值从新工作区开始。循环外亲读取当前轮目标矩阵，不额外迭代，也不宣称复现连续播放中上一帧残留状态。后续历史物理须由独立实例、缓存或烘焙协议提供，不能复用主工程的活动物理世界。

## 对外接口

在现有函数表尾部追加以下入口，最终 minor 与字节布局在实现时由 C、C++ 和 DLL 契约锁定。旧函数、旧记录和 `createSource` 的骨骼单通道语义不变。

| 拟追加入口 | 责任 | 线程 |
| --- | --- | --- |
| `getSceneCapabilities` | 查询骨架场景支持范围、来源/帧保留量及工作区限额 | 任意 |
| `createSceneSource` | 同次捕获当前全部模型、注册动作及稳定身份 | UI |
| `describeSceneSource` | 返回捕获 ID、历史元数据、模型数和计费量 | 任意 |
| `sceneModelAt` | 按捕获顺序枚举对象身份及骨骼数量 | 任意 |
| `sceneBoneAt` | 枚举指定模型的冻结骨骼 ID | 任意 |
| `evaluateFrame` | 对同一来源同步完成一次独立求值并发布帧句柄 | 任意 |
| `describeFrame` | 返回来源捕获 ID、帧 ID、有理时间及计费量 | 任意 |
| `frameModelAt` | 枚举帧内模型身份、骨骼数及原始可见字节 | 任意 |
| `readBonePose` | 按模型身份和骨骼 ID 复制一份骨架结果 | 任意 |

来源与帧均使用原 `retain`、`release`。首批 `evaluateFrame` 为同步调用，复杂插件可放入已有后台任务；后续异步任务封装仍调用同一求值路径。取消任务只能阻止尚未发布的结果，不能销毁另一个线程正在读取的帧。

骨架结果须逐项命名：刚性变形矩阵、含尺度的变形矩阵、两轮附着矩阵和关节位置。矩阵采用现有行向量约定。`matInit` 是作用于绑定坐标的变形矩阵，不能未经定义就命名为骨骼世界矩阵。首批读取复制到调用方结构，不暴露内部 `ModelFrame()` 借用指针。

## 宿主捕获与身份

宿主在现有 UI 安全点检查场景变更、布局就绪和共同历史状态，然后按原槽位扫描全部非空模型。不可只捕获可见模型、选中模型或当前活动外亲目标，未来关键帧也可能引用其他模型。

模型身份沿用 `scene_host.cpp` 的 `SceneIdentity`，骨骼 ID 沿用 `identities.Element(token, MMS_CHANNEL_BONES, 原骨索引)`。它们与 BIND 快照及现有 `boneAt` 相同，不增加身份注册表。模型指针仅用于这次捕获；成功后只保留冻结数据、对象身份及原索引映射。

`BoneSceneSource::Capture` 校验所有可达键中的目标与骨范围，包括未来引用、传递和自引用。继承与地面保留原类型，无需假对象身份。任一错误拒绝整个来源。完成后还要核对内部场景的模型数、槽位、身份及骨骼数与公开元数据一致。

场景帧独立拥有结果及身份映射，释放来源后仍可读。允许共享不可变身份数据，但来源和帧的保留量均须覆盖各自仍可能持有的元数据；不能依赖来源句柄继续存活来维持帧身份。

## 共用租约与额度

`EvaluationStore::Payload` 区分旧通道来源、场景来源、场景帧三种类型。三者共用现有 `sources_` 表、`Entry.owner`、句柄序列、客户端、总额度和 `Settle`。旧描述、枚举及采样入口先校验类型，再读取通道字段；类型不匹配返回错误并保留输出。

后台求值在锁内验证来源与所有者并登记在途计数，再在锁外运算。发布前重新检查退役、新帧的句柄容量和序号及保留字节额度，不重新要求来源句柄仍在表中。来源已释放不影响获准的计算，来源载荷由在途引用保留；插件已退役则不得发布新帧。所有结束路径均在同一锁内完成计费结算、临时引用释放和在途计数递减。

帧不得持有来源的计费 `Payload`。否则来源最后引用可能在帧析构中绕过原 `Settle`，导致额度无法回收。内部帧本身已经具有独立寿命，应直接持有帧结果和所需身份。

首批沿用单载荷 64 MiB、单插件 128 MiB、服务 256 MiB 的保留额度；来源、帧和旧通道合并计算。内部场景的 256 MiB 默认参数不能直接当作公开来源限额。求值工作区另需服务级和插件级预留计数，限制并行求值的总工作预算。该预留须覆盖未发布结果及其身份索引，直到成功发布并转入保留计费，或失败后释放候选数据。异常、取消和退役都必须归还。嵌套算法未计入的瞬时分配仍须如实说明，额度不是进程精确峰值内存。

## 必需验收

- C、C++ 和真实 DLL 验证表前缀、尺寸、调用约定、能力查询和短缓冲区保护。
- 旧通道句柄与新来源、帧交叉误用全部拒绝，失败输出不变；保留与释放可以跨版本使用。
- 真实宿主逐模型、逐骨对照 BIND 身份；仅修改目标注册动作后，新来源影响消费和传递结果，旧来源不变。
- 精确键前时间同时检查 IK、外亲、地面、窗口及可见性，且骨矩阵能区分错误提前切换；普通分数帧保持连续运动。
- 删除模型、复用槽位、重载 PMM、释放来源后，旧帧的身份和矩阵仍可读，主播放头、编辑姿态和共同历史不变。
- 来源及帧发布逐分配点失败、总保留量边界、并行工作区预留、最后来源释放时的在途求值、退役后拒绝发布及 DLL 停止保护都有实际证据。
- 保留已有通道、原生骨架、PMX/PMD 和两产品构建回归。Win7 与 AMD 真机条件缺失时继续列为待验收。
