# 同步配件列表拖拽排序

ABI 起点为 `26e0a6a`。来源为「排查 MMS 相机崩溃来源」中随后完成的配件列表修改，基于 main `9de615e` 的工作区快照。生产补丁为 `build/abi-accessory-order-source.patch`，SHA256 为 `2EF49EC4A7739E536FD5D55183C9E6B69B902DA7D524F56969C89E0B25445CEE`；源测试 SHA256 为 `2E9A60397F46E2476E5347AC2EDAB1AAFAAF4F29AA4A4E1E9A5731A54CF8CD84`。

## 排序行为

配件列表可以拖拽调整绘制顺序，也可以继续用上移、下移按钮。拖放按行间位置插入，支持移到最后一行之后；拖出列表或取消拖动不修改顺序。拖动和按钮共用移动函数，列表项数据与配件指针一起移动，重复标题不参与身份判断。

移动仅修改对话框的临时列表和顺序数组。「确定」沿用现有提交逻辑，保留当前操纵的配件和登记范围所指的对象；「取消」丢弃临时排序、绘制分界和名称修改。保存、重开继续保留绘制顺序及分界。

ABI 适配增加列表行数与临时数组边界检查。先插入新行，确认位置及项数据后才删除原行；失败时回退新行。动态分配失败不会从 Win32 对话框回调逸出。临时资源初始化失败时取消对话框。

## 共同历史限制

排序、名称和绘制分界的复合操作仍未接入共同历史。审查发现旧入口在绑定共同历史时仍能从普通菜单执行，并直接修改场景。本批在菜单命令、对话框和移动函数处拒绝该绑定状态，并让菜单刷新同步显示禁用状态。

未绑定的普通运行及原版兼容配置保留新拖拽行为。此迁移不表示排序操作已经支持共同历史撤销；以后须准备完整的顺序、名称、分界及对象身份事务，再开放绑定入口。

## 验证

新增测试使用实际导入的 X 配件和生产对话框，覆盖两个方向、行间及末尾插入、同位置拖动、拖出、取消、重复标题、当前操纵对象和独立登记范围。帮助函数测试通过原生列表子类注入插入、项数据和删除失败，核对回退后的文本、身份、临时指针、选择及名称编辑框。

共同历史测试保留一条可实际重做的记录，分别从真实窗口、命令分发和直接菜单入口尝试排序，核对没有打开对话框、分配临时数组或改变配件字节、场景标记、帧与历史。两条菜单刷新路径分别验证绑定时禁用、解绑后恢复。
