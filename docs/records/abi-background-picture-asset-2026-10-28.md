# 稳定图片资产及新建工程后的保留

本批把可恢复图片资产接入完整配置的实际图片替换流程，并修复新建工程保留纹理却丢失来源的问题。它是共同历史的资源前置，**不是已完成图片撤销**。目标不变，main 最新仍为 `6facf91`，阴影同步暂缓，未改 main 或覆盖稳定版。

## 已实现的生产行为

新增内部 `media::BackgroundPictureAsset`，绑定不可变来源字节、复制的路径、原始尺寸、实际解码方式以及稳定 ID。`Primary1024` 记录正常 1024×1024 解码，`Fallback512` 记录回退的 512×512、单层解码。资产不持有设备或 COM 纹理，也不会读取路径；路径是元数据。

ID 由宿主内饱和递增的原子计数器分配，非零、不回绕、不复用；分配失败消耗的 ID 也不会复用。ID 和激活票据属于独立身份域，不能比较数值来推断关系。多个资产可共享同一个来源对象，不重复占用来源预算。资产 `RetainedBytes()` 包括自身开销和来源，可供后续历史计费；固定元数据尚未纳入来源字节预算，不等于完整资源内存上限。

`TryReplaceBackgroundPicture` 在解码和初始摆放准备完成后创建资产，再次核对实例、mutation 及设备，最后随纹理和原生字段一起发布。创建失败保留旧状态。注册表只存一份当前资产；`CurrentPictureSource` 从 `CurrentPictureAsset` 派生，不维护第二份可漂移的来源状态。非空资产路径或尺寸与候选字段不一致时，在写任何字段或废弃票据前拒绝发布。旧资产最后引用在注册表锁外释放。

`ResetAppState` 的既有行为是隐藏背景图片，保留纹理、路径和摆放，以便之后重新显示。现在使用明确的 `RetainForSceneReset` 策略同步保留资产，进入作用域时立即废弃旧激活票据。之后获取新票据才能再次查询同一资产；旧拖拽不会复活。保留策略优先于“发布前保留旧图片”选项，避免组合使用时漏掉票据失效。

保留策略只是不清当前资产，析构不恢复任何快照。嵌套失效、替换或关闭清掉资产后，外层 reset 不能把它重新放回去。关闭始终清理图片和视频两个域，即使调用者只指定一种；关闭也优先于保留策略。普通失效、Forget、重复注册及地址复用仍清资产。

## 内部接口

`CreateBackgroundPictureAsset(source, path, width, height, mode, maxRetainedBytes, out)` 验证非空来源、1～255 字符路径、正尺寸、已知模式及溢出安全的总保留大小。成功输出只读强引用；参数、额度、分配或身份耗尽失败均不改原输出。接口属于宿主内部 C++ 实现，没有新增公开 C ABI 或改变现有表布局。

查询接口仍检查应用实例、所属线程、当前激活票据、关闭状态及媒体变更门禁。返回的强引用可在资产退役后继续读取；它只证明查询时的关联，不能作为后续写入的授权。

## 剩余完整链路

后续进度：下列第 2 项已在 [2026-10-29 PMM 接线批次](abi-background-pmm-assets-2026-10-29.md)完成；PublishPicture 也已支持指定位置与显隐，另有原子 ClearPicture。无分配 Prepared 激活与共同历史仍未实现。下面保留本批结束时的历史状态。

1. **PreparedPictureActivation**：在 Prepare 阶段准备纹理、费用及下一票据，支持任意摆放、隐藏和空图片；Publish 只交换，不能解码、分配或在锁内释放 COM。目前 PublishPicture 仍是普通导入语义。
2. **PMM 来源**：v1/v2 仍走旧加载函数，且处于整场景 mutation 中。需要项目替换授权的内部准备／发布入口，保留文件内摆放、显隐和 clean 状态，不能直接调用菜单导入函数或把无来源旧纹理当空图片。
3. **共同历史**：图片替换、显隐和摆放必须统一接线，再开放绑定历史下背景操作 1／2；撤销不得重读原文件，不能遗留阻塞此前撤销的 STALE 节点。
4. **视频与设备替换**：完整视频 owner、独立非活动解码状态及真正换设备时的资源重建仍待实现。普通同设备 D3D9 Reset 的 managed 图片保留行为没有改成重新读取文件。

本批未修改 VMD／PMM 数据格式、标记或兼容指标。
