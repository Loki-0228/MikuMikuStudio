# 共同历史的影响分类与延迟刷新

本批在 `codex/plugin-abi` 的 `1cf3eab` 上增加内部历史影响类别，为纹理重载等渲染资源操作准备统一的撤销路径。分类已接入真实本地历史和插件转发宿主，纹理重载 278 本身仍是隔离草稿。普通生产 `mms.edit` 保持关闭。

## 分类与发布规则

内部 `HistoryChange::Effects()` 返回以下可组合的位，未覆盖该方法的原生变化默认返回 `All`。这不是新增的公共 C ABI 服务，插件继续通过既有编辑表和序列化器参与共同历史。

| 类别 | 本次成功发布的影响 |
| --- | --- |
| `None` | 更新撤销、重做按钮。仍发布真实历史修订和可信信号。 |
| `ProjectData` | 立即设置 `SceneModified` 和 `RecordedFrameCountByte1`。 |
| `SceneReadout` | 刷新姿态、全局读数、对象列表、音频、表情和曲线等旧完整读数路径。 |
| `Viewport` | 向原更新队列请求 `RenderDirty | PresentDirty`，不请求 `EvaluateDirty`。 |
| `All` | 合并以上三个影响位。未知原生变化和含插件数据的聚合记录保守使用该值。 |

物理重置仍由 `RequiresPhysicsReset()` 独立决定，不能据此推断影响类别。插件记录只要存在参与者条目，即使序列化字节为空，也保守合并 `All`；仅有标签的原生记录不因此变成插件编辑。

准备阶段先复制不可变的 `EditRecord`，再读取原生影响并冻结在历史节点中。这样即使测试原生回调修改调用方保留的可变原记录，也不能改变已捕获的数据。普通提交、未记录的 Adjustment、已应用事务提交及撤销、重做均在可信发布信号之前更新 `LastPublicationEffects()`；发布尾段不再调用 `Effects()` 或分配内存。

`ReserveAppliedNative` 的占位 `All` 在实际变化准备成功后替换为真实类别。失败、取消、预算拒绝和普通配置不改变上次成功发布的类别。`NextPublicationEffects(bool redo)` 只预览下一节点的冻结值，不进入编辑门禁或调用参与者；空历史、错误线程和不可用状态保守返回 `All`，真正授权仍在原 `History` 路径。

## 刷新与输入保护

`PublishBoundHistoryEffects` 在成功提交后按类别设置标量、更新按钮并请求对应刷新。`PublishBoundPoseEdit` 保留旧签名，包装为保守的 `All`。UI 失败只能排队补刷，不能把已成功的提交或撤销报告为失败。

插件转发使用同一历史和同一延迟队列。每次发布立即设置应有的工程、录制及物理标量，再把影响位合并到 `pendingEffects`。消费先移出本批；消费中再次入队的相同位仍属于下一批。失败把本批合回，`None` 通过独立 pending 标志保持按钮刷新。延迟消费不再次标脏，防止成功保存后执行旧 UI 请求又将工程改为未保存。

纯 `Viewport` 和 `None` 路径使用轻量 `Operation`，保留原输入、关闭和重入保护及真正的历史发布授权，只持有 `ScopedUiInputGate` 和原窗口子类化。它们不建立 `ScopedSceneMutation`，不启停顶层窗口，不关闭渲染器，不改变布局就绪状态或待处理输入标记，也不捕获场景草稿、扫描对象或修复选择。

`SceneReadout` 仍保留旧完整保护和读数行为。历史遍历先建立轻量保护并预览冻结类别，仅在需要场景读数时升级为旧完整保护，再于发布前捕获草稿。包含 `Viewport` 的组合独立消费该位，不因已执行完整读数而省略绘制请求。本批未把旧完整路径改造为轻量路径，也不宣称所有旧读数消费都没有间接求值副作用。

原命令分发在插件菜单返回时不再无条件通知曲线变化。真实插件编辑由共同历史发布及延迟消费发出相应通知，插件 UI 命令本身不等同于曲线数据修改。内置命令保留原通知行为。

## 反例与修正

证据目录为 `build/verification/abi-history-effects-20261022/`，失败候选和日志均保留。

- `host-full-03` 通过真实 DLL 菜单撤销纯视口节点后，记录到额外一次曲线通知并失败。来源是命令分发的无条件退出通知，现已按上述规则修正。
- `red-guard-full-04` 在纯视口首次提交记录到 `whole_invalidation=1` 并失败。原 publisher 无条件重绘主窗口，现已仅在 `SceneReadout` 路径保留。
- 独立审查发现原完整 `Operation` 会建立 `ScopedSceneMutation`。该保护在进入时关闭渲染器缓存，退出时设置 `MessageSeen=1` 并同步重绘整窗，使后续安全点不能保持纯重绘前置。完整 UI 锁还会启停顶层窗口并排出额外视口请求。轻量保护修正了两条纯 UI、渲染路径；没有以返回时清零输入标记掩盖这些副作用。
- 早期无分配信号测试的新增断言错误地要求已有三次通知后的计数为零。修正的是测试前置计数，后续同一真实发布专项通过，未将该夹具错误认定为生产缺陷。

## 未完成与验收边界

模型排序专项在首次 `CommitBoundModelOrder` 后的行身份与选择断言失败。当前候选、上一批冻结基线以及本批早候选均在相同断言失败，均发生在此次修改的历史遍历之前。证据为 `native-full-05`、`order-baseline-05`、`order-early-05`。原因尚未确定，既不能认定为本批引入，也不能将该专项登记为通过。

所有运行继承 Default 桌面，只操作夹具自有窗口，不生成全局输入。新宿主不运行可见安全点，因此不证明实际 GPU 呈现、真实 Win7、AMD、微软拼音、多屏 DPI 或肉眼视觉结果。`ShutdownD3D12Native` 调用次数为零也不等同于 DX12 硬件验收。

纹理重载 278、默认 D3DX 入口的真实资源测试、其余原生写入、通用事件、多视口、独立求值及格式编辑继续按[剩余工作](abi-remaining-work-2026-10-17.md)推进。Win7 SP1 x64、CPU 基础路径、AMD 和程序旁 `data` 约束保持，原始兼容产品仍不开放 ABI 运行时。既有曲线堆故障、未解释超时及菜单间歇问题没有因此关闭。
