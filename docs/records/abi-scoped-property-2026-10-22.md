# 原属性与共同历史的范围自动刷新

本批在 `codex/plugin-abi` 的原刷新队列中扩展 `mms.ui.refresh.property` 1.1，使独立属性通知或明确选择的共同历史发布驱动注册子树及显式依赖图。[SDK 参考](../../sdk/mms/scoped-property-refresh.md)描述插件可用的接口。本批不开放普通生产 `mms.edit`，不改 main 或正式 release。

## 接口与数据语义

服务表为 88 字节，保留原 64 字节前缀并追加范围能力、登记及查询。能力、描述、状态分别为 40、96、176 字节，旧结构和全局 ABI minor 0 保持。新旧查询及注销操作同一订阅句柄，共用原 128／2,048 个订阅额度。

触发属性与范围种子分别声明。属性无需 INPUT，GROUP 无需额外 binding。每个成员优先使用自身显式 DATA binding，其余适用的原 INPUT 在 UI 消费时读取自身当前属性。通知序号不保存属性值；显式 DATA 则在接受整张复合票据时原子捕获来源版本集合，后续发布不能覆盖旧集合。

每个范围使用一张原票据，顺序为全部 DATA、STATE、一次保留布局 LAYOUT、REPAINT。工作代次区分相同通知序号下的图、绑定及恢复变化。只有相关真实事件可以恢复失败消费者，不因重复 Drain 或无关票据完成重跑。

可信共同历史发布仍只记录原子通知并安排现有宿主消息，后续 UI 安全点才展开范围。显式开启历史跟随的订阅响应真实提交、撤销、重做和不新增步骤的 Adjustment；准备、失败及取消不发布成功变化。

C++17 `ScopedPropertyRefreshServices` 与可移动订阅所有者包装同一服务及句柄，不组合多个 SELF 伪造范围能力。基础能力、基础查询和通知仍使用原表槽。

## 审查与反例

证据位于 `build/verification/abi-scoped-property-20261022/`。失败候选、构建日志和运行日志均保留。

- 初次真实 DLL 测试在第 3,865 项失败，测试草稿属性未声明 `UNDOABLE`，与原属性登记规则不符。修正夹具的声明，未放宽生产门禁。
- `candidate-02` 在第 2,596 项复现观察分配失败误触发消费者重试。旧实现先提交成员，再观察来源；后者失败写入 GRAPH 等待位，恢复观察又被当作真实图恢复。修复改为完成全部临时分配后，同锁提交完整成员与来源。反例进一步核对序号、工作代次、等待原因、结果及 pending 在失败后和后续无关 Drain 中保持原值。
- `candidate-03` 通过上述反例后，在第 4,233 项遇到生命周期夹具错误。删除独立种子使订阅失效，但仍登记的触发属性允许通知；只有属性更换、工程代次变化或 owner 停止才使旧引用失效。修正测试的精确预期。
- 新绑定观察故障测试最初因同一 `auto` 声明的两项类型不同而编译失败。拆为两个声明，保留该次构建日志。
- `candidate-05` 在第 2,671 项复现新增冷 binding 后漏装来源监听：绑定成功，但观察分配失败导致首次发布没有唤醒订阅。该问题需要记录准确的真实绑定事件，不能通过观察失败时无条件重试来绕过。
- 静态审查要求真实绑定事件先于完整观察提交，避免已知冷来源被误唤醒；DEPENDENTS 的事件匹配排除种子。新增回归覆盖普通及故障观察、发布前后两种 UI 消费时序、来源移除，以及无关成员和种子绑定不得重试失败消费者。
- SDK 审查发现句柄便利重载错误依赖目标当前的非空图能力。改为查询属性服务的范围能力，允许空图先登记；假宿主同时覆盖能力不足、查询失败及畸形输出。
