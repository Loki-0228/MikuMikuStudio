# 纹理重载的资源版本与共同历史

本批基于 `codex/plugin-abi` 的 `720d25f`，将完整配置的实际菜单 278「重新读取纹理」改为私有准备、一次发布。绑定共同历史时，两种记录模式都把这次显式操作记为一个节点；未绑定时仍使用同一原子资源方案，但不记录历史。普通公共 `mms.edit` 继续关闭。

## 资源与发布

`NativeTextureReloadPlan` 捕获共享 Toon 的 11 个槽、完整 30 项边缘颜色，以及纹理缓存首个空名称之前的原槽。每槽保留名称身份、原位置、实际 COM 资源和完整 32 位 `tag`。前后版本各自保活，撤销、重做不重新读取文件，也不删除后来导入追加的缓存尾项。

开始准备前，先经过实际绑定历史或普通原生历史的编辑权限检查。准备同时固定场景代次、绑定代次、历史修订、渲染器、设备、工作目录及 ExeDir；加载回调后重新核对来源。预算不完整、设备不符、来源变化或关键资源失败时不发布任何一槽。内存不足、设备丢失等基础错误拒绝整批；可选缓存图片缺失保留原有空纹理及颜色策略，共享 Toon 缺失仍使用原嵌入资源回退。

发布候选提前持有目标引用。最终发布仅交换宿主持有的指针、颜色及 tag，并使纹理查询缓存失效，不分配、不调用 AddRef／Release 或驱动。被换下的引用在候选后续析构时释放。取消和拒绝不退回先释放旧资源的旧重载路径。

资源预算检查验证实际 D3D9 纹理及其设备身份；COM 接口指针不同时，以规范 IUnknown 身份核对，不能把伪造的 `GetDevice(E_NOTIMPL)` 当作有效设备。

## 默认加载与刷新

共享文件路径在首个 D3DX 调用前固定，按捕获的 ExeDir 解析为绝对路径，不修改进程工作目录。能够无损表示时保留 A 入口，否则使用 W；嵌入 PNG 仍走原共享内存入口。每次文件、内存及回退调用前重新读取实际导入槽。

审查同时发现缓存默认加载器在 1×1 纹理与 usage 重试间复用旧函数指针。本批在每次实际重试前重新执行原加载器的 `api.Load()`，保留既有 `1024 → 0 → 0` 顺序及清理规则。失败回调写出非空 COM、或合法 C++ loader 写出非空后抛异常，均释放其转移引用且保持调用者原输出。

该 participant 冻结的历史影响为 `Viewport`，不请求物理重置。绑定提交释放事务后调用原 `PublishBoundHistoryEffects`；纯重载只更新历史按钮并提交不含 Evaluate 的绘制请求。撤销、重做沿用同一分类。

实际主窗口有两个额外入口需要处理：外层命令分发不再对 278 无条件通知曲线变化；`ObserveMessage` 仅将无控件 HWND、通知 0／1 的原生 278 菜单／加速键识别为资源刷新。它不清除已有 `MessageSeen=1`，其他控件及命令分类保持。

原始兼容配置继续调用原 `InitToonTextures` 和 `ReloadTextureCache`。本批核对原 `InitToonTextures` 函数内容与基线一致，未开放该配置的 ABI 运行时。

## 尚未证明的范围

278 的入口专项在夹具自有 STATIC HWND 上调用实际主窗口过程，不是完整 `InitMainWindow` 启动；加载钩子提供受控资源，默认真实 D3DX 另有上述 IAT 专项。隐藏窗口不运行可见 SafePoint，不证明 GPU 最终呈现。权限专项使用真实 SharedHistory 的受控 gate，不等同于实际 Manager 回调授权的动态验收。

宿主持有的资源原子恢复不代表第三方 MMV／MMHack 的私有登记表也能回滚；绝对路径与外部 hook 的相对键等价性仍需单独验证。261 缺失旧缓存的保守拒绝、其他渲染器的资源版本及菜单 263 的导出副作用仍未完成。

运行继承 Default 桌面，仅操作测试自己的窗口，不产生全局输入。Win7 SP1 x64、CPU 基础路径、AMD 及程序旁 `data` 约束保持；本批不是 Win7、AMD、真实微软拼音或多屏 DPI 验收。既有曲线堆故障和间歇超时仍未关闭，完整需求继续见[剩余工作](abi-remaining-work-2026-10-17.md)。
