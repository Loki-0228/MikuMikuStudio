# ABI 剩余目标：实施与验收摘要

本文件区分源码实现、专项测试与产品验收。通过可移植测试、模拟接口或单一配置，不代表原生 Windows 产品、另一配置或发布包已经通过。发布判断以能复现的提交、配置和测试结果为准。

## 1. 审查基线与最新证据

- [实施与验证记录](../PLUGIN_ABI_IMPLEMENTATION.md#逐项状态)按阶段记录 ABI 契约、宿主接线、测试与仍受限的能力。与主线的功能对照另见[主线同步](../abi/main-parity.md)。
- 求值 C++ SDK 已仅向调用者报告已验证的 Material/Mesh 记录前缀，不改变公开 C ABI。还应使用 Windows x64 的实际宿主和插件 DLL 验证生命周期以及旧版表的读写边界。参见[求值接口](../../sdk/mms/evaluation.md)。
- PMM、EMM 和插件 JSON 的内部同快照发布有恢复日志、保存锁和完成回执；专项故障注入通过并不证明普通保存、另存、定时备份和真实 MME 都走新入口。保存后继续编辑、硬中断恢复、历史轮转、旁车不匹配需要分别验收。参见[工程与保存](../abi/project.md)与[存储 SDK](../../sdk/mms/storage.md)。
- 模型和纹理准备、效果编译及缓存管理已有部分真实调用路径。普通加载、同进程重开和新进程持久命中不能合并为一次结论；真实 MME 效果链、长时多进程维护、低速盘、配额和恢复另测。参见[缓存能力](../abi/cache.md)和[载入缓存对照](../../tools/main_load_cache_regression.md)。
- 原生动画、物理、布局和媒体的局部通过不能代替同一候选版本的双配置端到端检查。未运行实际原生导出时，不将合成 PNG 验证器或规划顺序当作产品导出通过。参见[候选验收](../abi/candidate-acceptance.md)和[测试指南](../development/testing.md)。

## 2. 发布前保留的验证门槛

1. 绑定提交、二进制、精确配置和输入，覆盖完整与原始兼容配置的工程打开、场景重开、物理切换、撤销/重做、保存/恢复和实际图片导出。
2. 在适用的原生 Windows 环境验证真实设备丢失、资源回收、多 DPI、IME、取消、插件卸载及外部 MME 渲染。仅被遮挡、模拟通知或隐藏窗口检查不算可见交互验收。
3. 使用同一次 Windows x64 构建生成并校验发布闭包；在干净目录测试配套模块、配置、移动和改名，核对第三方文件和许可。参见 [Win7 构建与包范围](../development/win7-build.md)及[受管旧 MME 包](../LEGACY_MME_PACKAGES.md)。
4. 性能对比使用相同资产、设备、窗口与呈现设置；分开统计首开、应用缓存、系统页缓存、实际成功呈现和输出正确性。没有相同输入、版本及运行条件的结果不能当作提速或回退证明。

源级、专项、双配置、实际第三方集成和正式发布包的状态分别记录，未验证的场景不计入通过。
