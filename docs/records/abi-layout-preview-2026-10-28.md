# 临时布局内部接线

后续进度：公共 C 服务与 C++17 SDK 已接入并通过验证，见[公共服务记录](abi-layout-session-public-2026-10-28.md)。下文保留内部接线批次的证据及当时状态。

本批在 `codex/plugin-abi` 工作树实现临时布局的内部会话和原生控件读取路径。公共 `mms.ui.layout.session` 服务尚未开放，完整需求仍为部分实现。目标未修改；main 已提交 HEAD 仍为 `d551f1f`，未复制其未提交内容，阴影同步继续暂缓，未覆盖稳定程序。

## 实现范围

`UiRegistry` 保留原有 `elements` 作为持久基线，新增会话按原元素 handle 保存临时字段。`EffectiveLayout` 合并基线与覆盖，NativeUi 的排序、尺寸、显隐、祖先判断、溢出、状态、快捷键和几何发布使用同一个有效布局入口。没有增加第二套控件身份或排版实现。

内部会话支持本插件在工具栏、属性扩展行、左右侧栏下的 BUTTON、GROUP、SEPARATOR、INPUT；字段为显隐、宽高和同父节点排序。一次最多声明 64 个目标，每个客户端最多保留 32 个会话、全局最多 256 个，终态会话也计入上限，直到释放。原生本体控件、其他插件目标、DOCK、跨父节点移动和样式动画不在这批实现内，仍保留在完整需求中。

内部入口为 `BeginLayoutPreview`、`ApplyLayoutPreview`、`QueryLayoutPreview`、`EndLayoutPreview` 和 `ReleaseLayoutPreview`：

- Begin 只占有字段，不改变界面。不同会话可占有同一目标的不同字段；相交字段拒绝。
- Apply 校验目标、字段、修订、尺寸与全部候选后一次发布。失败不改变有效布局、会话修订或历史。临时应用只使几何失效并请求现有原生布局更新，不写偏好、工程状态或播放头。
- 回退移除会话仍持有的字段，显露当前持久基线，不恢复整份旧快照。
- 正式提交复用普通布局事务校验及历史；准备失败保留预览，成功在通知前同时发布布局、历史和会话终态。实际偏好变化记为一次布局历史；无变化不新增历史。
- 成功的持久写入按操作意图接管对应字段，即使写入值与基线相同也会撤回临时覆盖。准备失败不撤回。完整偏好导入及布局撤销／重做接管全部临时布局；普通快捷键修改不接管布局字段。
- 停止入口在插件返回 BUSY、停止失败或资源租约未排空之前撤回预览；最终退休清理终态记录。停止中的客户端不能新建或应用预览，但可以回退、查询和释放。

临时隐藏已有 GROUP 或控件保留原 HWND。永久用户隐藏仍沿用原有卸载与提供者失效约定；从未显示的隐藏区域不会因此提前创建全部控件。控件的命令／属性可见状态与临时布局显隐分别保存，避免撤回后被旧缓存继续隐藏。
