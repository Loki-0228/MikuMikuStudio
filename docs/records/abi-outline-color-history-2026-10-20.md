# 轮廓颜色共同历史

菜单 286 的全局 PMD 轮廓颜色已接入受控共同历史。两种记录模式都在一次确认后产生一个显式节点；取消和同值保留原历史。普通产品的旧路径保持，公共 `mms.edit` 不因此开放。原生写入口范围见[迁移核对](abi-native-writer-audit-2026-10-20.md)。

## 数据与资源

`NativeModelOutlineColorPlan` 在打开选色窗口前固定共同历史绑定、工程修订、模型成员及稳定身份。它保留实际 PMD 轮廓顶点缓冲的前后资源，颜色记录不依赖原模型文件。

准备阶段只读取已完成的、可读的 main VB，严格检查大小、FVF、stride、资源池及 WRITEONLY 标志。它按现有 `ModelOutlineDistance` 和相同扩边公式重建当前几何，保存 PMD 的逐顶点颜色。WRITEONLY 轮廓缓冲不被读取。重做与撤销只准备非活动目标资源的位置字段，保留相应资源的 diffuse，然后在发布时交换已准备好的 COM 资源引用和 RGB。

最后的来源校验包含当前顶点字节、扩边参数、原始 edgeDisabled、对象及绑定身份。计划不可复制，Take 转移其状态，防止候选准备后通过另一个包装修改 RGB 而保留旧缓冲。同一 change 再次准备前递增准备批次，后次准备即使部分写入非活动缓冲后失败，也会使旧候选失效；发布序号仍独立保留。正式发布不锁缓冲、不分配资源、不释放驱动对象、不求值场景，也不移动播放头。PMX 保持原菜单不改其材质和顶点颜色的行为。设备失败、来源变化、预算拒绝和分配失败均在发布前返回。

选色窗口使用独立的 16 项 COLORREF 数组，分别复制原 12 项数组及注释明确的尾部 4 项存储。确认后分别写回，取消不改颜色表，结构布局保持。原普通和原始兼容分支同样保留全部 16 项，不再跨数组边界向窗口传指针。

## 验证

完整配置及原始兼容配置均构建通过。实际菜单及资源测试在独立隐藏桌面执行，最终证据位于 `build/verification/abi-property-data-20261020/native-03/`；两套普通菜单专项日志位于同根的 `legacy-01/`。

| 检查 | 结果 |
| --- | --- |
| 轮廓颜色、实际菜单 286、两种模式、D3D9 像素、CPU 蒙皮、失败和来源保护 | 3,915 项通过 |
| 原轮廓粗细 | 1,649 项通过 |
| 原轮廓窗口 | 4,844 项通过 |
| 普通完整配置菜单及 16 项颜色表 | 独立 `native_model_outline_color_legacy_tests`，80 项通过 |
| 原始兼容配置相同菜单 | 同目标，80 项通过 |

颜色专项另覆盖实际删除并恢复对象、最后一个模型槽、插件序列化共同节点、取消、无变化、内存预算、分配故障、main VB 读取失败、第二个模型缓冲创建失败、Unlock 失败、非法 FVF 和关闭重入。新增测试首轮的枚举赋值及缺少声明编译错误已修正，失败日志保留。

本机未找到可用的 GPU 蒙皮计算适配器，测试明确输出 `SKIP outline GPU skinning`。实际 D3D9 绘制像素和 CPU 路径通过，不代替 GPU 蒙皮、AMD 或 Win7 真机验收。模型增强、Toon、英文名称及物理模型资源入口仍需迁移。
