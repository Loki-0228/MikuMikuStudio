# 普通旋转重置与原撤销环

日期：2026-10-23。ABI 基线为 `fb11682`，本轮 main 核对为 `fed9768f9fe726c4b5e068849808803f1713ad42`。本批接续[物理接管](abi-physics-takeover-2026-10-23.md)，迁移增强版普通启动中的主窗口、分离窗口旋转轴和菜单 302。main 与稳定版工作区、产物未修改。

## 入口与编辑行为

`TryResetUnboundBoneRotationAxis` 与 `TryResetUnboundBoneRotation` 是私有 C++ 路由，不增加公共 ABI。三个入口先尝试已有绑定路由，再尝试普通旋转路由。普通骨骼命令的失败与合法无变化均由新路径处理，不能回落旧写入；相机和原始兼容配置保持原路径。302 延续绑定路由的结构，普通新路径也不写旧分支中的 Z 键兼容镜像 `dialogFlags[1]`。该字段不是模型数据或模态窗口锁。

轴重置使用原 `RotationTarget`，保留主窗口的 double 中间值、分离窗口的 float 中间值、各自常量与 `Rz * Rx * Ry` 顺序。数学准备先在局部变量中完成，不再暂时把界面角缓存改成弧度。菜单 302 的单位旋转不依赖 D3DX 数学加载。

没有物理接管时，目标显示轴已经为零的命令保留其他轴精度和 redo，仅取消目标草稿；菜单单位旋转无变化时取消三个旋转草稿。mode 3 刚体且 dirty=0 时，零作者值仍可接管，规则与绑定入口一致。位置、缩放和无关旋转草稿不受影响。

旧 `PushBoneEditUndo` 按选中集合保存，但旋转按钮实际修改当前显示骨骼。新路径直接保存这个骨骼的位移、四元数和 dirty，无需它位于选中集合。空选择和显示骨骼未选中时，一次撤销仍能恢复实际修改。

## 准备、发布与生命周期

普通运行继续使用原 30 槽撤销环。先分配单骨快照，准备缩放与自由曲线的配套快照，再检查对象身份、骨表、显示骨骼、位置、旋转、物理来源、选择状态、角缓存、帧、旧环、缩放版本及窗口。还检查目标槽的两个缓冲是否独立拥有，避免重复释放或覆盖其他槽的缓冲。

检查完成后，连续发布配套快照、释放旧双缓冲、安装新记录、写作者旋转与 dirty，最后更新两个游标。此阶段不分配、不发送窗口消息。准备失败保留作者数据、旧环、草稿和 redo；成功只产生一个原撤销步骤，不建立临时共同历史绑定或第二套历史栈。

随后设置工程脏标志、请求视口绘制并更新主窗口的撤销按钮，最后更新当前读数窗口。每次原生消息后重新检查上下文；按钮回调修改位置或角缓存时，后续按钮和草稿发布停止。编辑框消息切换模型、窗口、帧、绑定、身份、显示骨骼或仅改变角缓存时，也停止后续旧上下文写入。已完成的作者事务不会因文本写入失败被撤回，失焦也不会重新提交已取消草稿。

没有完整 `PostViewRefresh`、场景求值或强制安装缩放变换。真实修改过的输入仍沿现有失焦路径提交一次。首次对象身份登记可能消耗内部代次或保留注册容量，本批不声称注册表完全回滚。现有绑定代次在未绑定时为零，临时绑定又立即解绑的 ABA 仍不能仅靠该代次检测；本批不声称覆盖所有外部回调组合。

保留了两项初期失败：`build-full-01.log` 是缺少 `SideState` 完整类型头文件，补充 `native_edit_history.hpp` 后构建通过；`unbound-01/report.json` 是夹具误要求底层撤销同时更新外层 UI 的 `redoDirty`。修正后检查完整环和原标志不变，并实际执行重做。六种重入最初同时修改角缓存，会掩盖目标校验缺失；现已拆为六个上下文条件及单独角缓存条件，独立审查确认不再互相掩盖。

## 剩余范围

普通原撤销环仍不是全部本体编辑向共同历史迁移的完成证明，公共 `mms.edit` 继续关闭。未覆盖选择指针为空、全部窗口句柄复用和所有回调排列，也未运行 Win7、AMD、混合 DPI、真实 GPU 与物理引擎验收。手动编号保存、磁盘缓存管理和其他 ABI 缺项继续按剩余清单推进。
