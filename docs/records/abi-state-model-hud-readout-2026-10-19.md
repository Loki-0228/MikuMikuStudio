日期：2026-10-19。工作区 `D:/MMD-Next/MMS-abi-dev`，分支 `codex/plugin-abi`。本批延续[保留布局与附件 HUD](abi-layout-follow-slider-2026-10-19.md)，不开放普通宿主的 `mms.edit`。

## 按钮状态内容

新增 `mms.ui.refresh.state` 1.0，C 表为 56 字节。原刷新表、请求及状态结构保持 64、112、40 字节。提供者绑定原按钮目标引用，在原 STATE 阶段准备文案、说明及禁用原因；不创建第二个 UI 对象或队列。

每次回调使用短命 builder，`writePrepared` 单次复制 UTF-8 字符串。未设置字段回退到元素标签、命令描述和 getState 禁用原因；显式空字符串可以清空内容。每字段上限 4,096 字节，每插件最多 128 个提供者，保留内容每插件 1 MiB、全局 8 MiB。仍用于原生显示的旧快照继续计费。

STATE 与 LAYOUT 组合先发布有效文案，再用同一文案量测；纯 LAYOUT 不调用内容提供者。替换或注销提供者仅使旧 STATE 贡献过期，独立 DATA 和 REPAINT 保持有效。只读限制沿原 UI 任务因果链传播，不能借内容刷新编辑工程或递归提交状态。

真实原生提示框同时注册子按钮和父区域工具，使禁用按钮仍能查询说明。V5 公共控件实测不接受 72 字节的完整 TOOLINFO；生产改用只包含实际使用字段的 56 字节 V1 前缀，保留 Unicode。未通过强制 v6 清单绕过兼容问题。

审查修复了两个边界：启用时更新的禁用原因必须保留到后续禁用；文案部分写入失败后，直接宿主布局必须先协调实际文案与缓存量测，完整成功才能重新公布几何。UI 应用不承诺原子回滚，准备失败仍保留上一份有效内容。

开发规则、C 表及同对象 C++17 SDK 示例见[状态内容文档](../../sdk/mms/state-content.md)。当前只覆盖宿主按钮，不代表属性、菜单和面板的完整 STATE 已完成。

## 模型与骨骼 HUD

受控路径接入以下 20 个原生操作，普通未绑定及原始兼容 profile 保留原路径。

| 操作号 | 行为 |
| --- | --- |
| 3–5 | 按视图方向旋转骨骼。 |
| 6–8 | 按屏幕水平、垂直或平面移动。 |
| 9–11 | 按当前坐标轴旋转。 |
| 12–14 | 按当前坐标轴平移。 |
| 22–25 | 等比缩放及 X、Y、Z 轴缩放。 |
| 26–29 | 投影视口缩放手柄及平面缩放。 |

按下前预留一次共同历史操作。每个预览样本在独立骨骼、物理标记、选择和缩放运行期副本上执行原数学，成功后只发布改变的姿态字段。缩放的关键帧、自由曲线及旧撤销环不属于这次姿态写入。安全检查按实际数学分支验证尾骨引用，保留不会访问尾骨的合法终端骨操作。

全部操作模式下，完整拖动记录一次调整；仅显式提交模式下，HUD 仍更新当前姿态，但不新增调整记录。结束及重放不重新读文件，不依赖当前选中模型或播放头。取消只恢复仍属于本次操作的字段，保留外部写入；净零拖动也清除自己留下的物理标记和刷新提示，保留已有重做。

释放采样使用最终系统光标。捕获转移、失焦、关闭、Esc 和同步回调取消均结束旧手势，旧鼠标释放消息不能覆盖替代手势。取消使用预分配的 map 与节点，避免 MSVC 空 map 哨兵分配导致 noexcept 终止。首次创建的缩放存储、内部租约及节点上限计入保留预算。

CPU 专项通过 31,357 项，包含原数学对照、三个坐标模式、四种修饰键、两种历史模式、无缩放表、真实窗口消息、预算和分配失败。证据：`build/abi-state-model-hud/model-hud-second/`。

实际文件载入及完整宿主也已通过：PMX 使用原名，PMD 使用中文 EXE 名，主窗口和浮动窗口均验证移动 X 与缩放 X、两种历史模式、插件交错撤销重做、外部未登记字段、取消及捕获移交。夹具在文件内声明可移动骨骼，保留既有网格、Morph 及物理数据，不在导入后替换对象。运行器为 `tests/plugins/run_model_hud_host.py`，结果在 `build/abi-state-model-hud/real-host-movable-first/report.json`。

## 参数回显开销

附件骨骼列表新增每窗口的有界来源缓存。每次仍比较实际骨骼名称、宽字符内容、过滤、语言与翻译设置；原生列表修改会使缓存失效。来源改变时继续按权威名称生成逻辑核对，模型替换、原地改名和外部修改列表仍会正确更新。

列表准备和读回缓冲均在发布前分配。无容量参数的 CB_GETLBTEXT 读取期间，拒绝同步消息链中的嵌套列表增长，避免旧缓冲接收新长字符串；窗口销毁和来源变化使当前准备失败。观察器安装失败时保留列表并继续其他参数回显，下次重试；超过缓存配额的来源使用原比较逻辑。

本机新旧程序按旧、新、新、旧交替运行，各测 4,000 骨骼、100 次稳定回显：

| 次序 | 总耗时 | C++ 分配次数 |
| --- | ---: | ---: |
| 旧 | 1,301.325 ms | 1,600,000 |
| 新 | 6.116 ms | 0 |
| 新 | 7.038 ms | 0 |
| 旧 | 1,368.187 ms | 1,600,000 |

这是附件列表回显的局部测量，不是整帧、GPU 或全部拖动的速度指标。该专项通过 596 项。证据：`build/abi-state-model-hud/readout-abba-final/report.json`。

## 滑杆绘制与验收边界

七个视角、RGB 和灯光方向滑杆的实际拖动数值及相邻覆盖检查保留。绘制观察区分窗口像素、主题内存 DC、受控 DIB 和额外通知诊断；内存中清除滑块不能证明用户屏幕闪烁。

本批额外采集 custom draw 和父窗口擦除/取色。原始基线不改变原生返回值，诊断单独请求绘制阶段，并检查最终像素、数值及 paint/erase 次数相同。[微软文档](https://learn.microsoft.com/en-us/windows/win32/controls/nm-customdraw-trackbar)定义了 item 通知请求；本机前两轮未收到所需 item 阶段，诊断保持失败，不能据此声明闪动已修复。进一步无采样元数据对照及真实模块身份另行记录。

第三轮确认七个实际控件来自 COMCTL32 v6.16。独立对照不在绘制栈内截图或查询滑杆，消息钩子确认最终父窗口返回值为 32，仍无 item 通知。诊断没有放宽阶段断言。强制 RDW_ERASE 时，真实窗口先全刷为 `#F0F0F0`，再恢复原生滑块与自定义背景；最早暖机已有相同行为，无须受控 PRINT 或焦点变化。已有拖动观察仅直接发送输入并 UpdateWindow，49 次 paint、0 次 erase，未运行完整 UI 调度，不能排除用户实际刷新链另有擦底。证据：`build/abi-state-model-hud/slider-trace-metadata/ordinary/paint/`。补充的真实 UI 队列观测见下段。

普通路径与实际共同历史绑定路径分别执行了 36 次有限调度，均观测到 72 次真实生产时钟推进。每条路径的七个滑杆共 42 次拖动绘制，没有自然擦除；逐次确认调度不改刚提交的七个参数、播放头、历史身份／修订／计数及保留量，整轮确认原 VMD 关键帧池的地址、身份、容量和全部字节不变。证据分别在 `build/abi-state-model-hud/slider-ui-pump-ordinary-first/paint/ui-pump/` 和 `build/abi-state-model-hud/slider-ui-pump-bound-first/paint/ui-pump/`。

两条路径的 42 次 PREPAINT 均保留进入 WM_PAINT 时的实际窗口像素。固定旧滑块区域与上一帧最终结果逐像素相同；绘制前的主题内存 DC 已有背景，但屏幕窗口仍保留旧滑块。42 次取色调用本身也未改动窗口或借用 DC。焦点仅在按下和释放各变化一次。此观测排除了这批样本中的提前擦除、逐步焦点切换和异步参数回跳，仍不能证明桌面合成中没有闪烁。额外 item 阶段观察继续保持失败，不将成功的消息调度检查改写为全部诊断通过。

最后一轮增加输入干扰检测与未分派消息的异常回投保护。实际本机在入场即发现本测试窗口排队的 `WM_MOUSEMOVE`，严格中止为 `INCOMPLETE`；未移除输入，也未把它算作通过。证据为 `build/abi-state-model-hud/slider-ui-pump-guard-ordinary-final/paint/ui-pump/paint-report.txt`。之前两条有限消息白名单的完整观测保留，不能扩展为真实鼠标队列、悬停／离开或桌面合成验收。下一轮需单独让实际光标位置与原生捕获一致，再以固定刻度对照悬停状态，不以放宽门禁取得通过。

只读检查另发现极小窗口的几何边界：本体缺少最小客户区高度约束，`760×160` 的主窗口在特定停靠比例下，显示区域请求可能与 RGB 滑杆相交，场景 viewport 还可能退化为零宽。正常高度下的 D3D9 使用同一 `FramePresentationRect` 作为 source 与 destination，底部与滑杆分隔。这是尚无实际 GPU 覆盖证据的独立小窗口问题，需补真实边界测试，不能据此解释正常窗口闪烁。

## 表情文本提交的滑块回跳

受控 Morph 文本提交曾先由统一回显把 `0.29` 的滑块写到 29，随后又从原解析 double 计算 `int(raw * 100)`，写成 28。下一次回显才恢复 29。本批删除成功后的第二次位置写入；没有变化时仍经同一回显更新。

原来的七字符解析、double 到作者 float 的转换、范围外作者值及 VMD／PMM 数据不变。全部操作模式仍记录一次 Adjustment，仅显式提交模式不新增调整记录。真实 Enter 引发一次自然失焦，并验证单次位置写入、重复提交零重写、原值撤销重做及 OOM 保留 redo 和其他输入草稿。

专项通过 12,358 次检查，证据为 `build/abi-state-model-hud/morph-focus-ansi-final/`。测试观察器保留原 ANSI 控件链与七字符读取，避免辅助 subclass 改变编码后制造精度差异。该修复针对表情文本提交，不作为灯光或视角连续拖动闪烁的根因。
