# 按钮禁用后的焦点与状态回调

## 实现范围

本批补充 `mms.ui.refresh` 1.0 已有按钮 `STATE + SELF` 的焦点处理。原 C 表、结构大小、目标身份、票据和 C++ SDK 保持不变。

STATE 禁用当前聚焦按钮后，宿主选择同一父区域中下一个可见且启用的 Tab 控件。没有可用控件时，选择可见且启用的父窗口；整条父链均不可用时清除焦点。保留槽位隐藏按钮复用同一规则。重新启用或恢复显示不抢回焦点。未聚焦按钮的状态变化不移动其他控件的焦点，同值请求不重复修改原生启用状态。

状态查询与原生状态应用继续保持只读回调保护。原生启用或显隐回调已经移动焦点时，宿主保留该选择。焦点转移可以同步触发 `WM_KILLFOCUS` 和 `WM_SETFOCUS`，因此转移前后重新检查实例、工程代次、几何和就绪状态，并检查目标窗口是否仍然有效。回调内嵌套 STATE 返回 `BUSY`，嵌套 drain 不重新派发。焦点回调中发生工程替换或销毁目标时，票据以 `STALE` 结束，不继续访问旧窗口。

此修改只处理 UI 状态和焦点，不重新布局、不调用场景求值、不改变播放头、不写工程、不增加撤销历史。继续使用 Win7 的窗口与 GDI 路径，不增加显卡或系统接口依赖。

## 验证状态

构建通过，见 `build/abi-curve-refresh-build-1.log`。独立桌面专项通过 **7,961** 项，见 `build/abi-refresh-focus-runtime-2.log`；ABI 契约随九组整合回归通过 **1,804** 项，见 `build/abi-curve-regressions-1.log` 及详细输出。

`tests/plugins/visibility_refresh_checks.inc` 增加以下场景。

- 工作线程提交合并的禁用请求，取消一张贡献，只查询一次状态并转移一次焦点。
- 重复禁用、重新启用、未变化状态和非聚焦按钮不会抢占焦点。
- 无可用相邻按钮时回退到工具栏。
- `WM_ENABLE` 已改变焦点时保留原生回调的选择。
- 状态提供者禁用自己的 HWND 后，宿主仍转移焦点，不重复发送启用通知。
- 焦点回调中读取目标成功，递归 STATE 与命令执行返回 `BUSY`。
- 焦点回调泵出工程代次变化或销毁目标时返回 `STALE`，并结束只读回调保护。

首次独立桌面测试在严格邻居焦点断言处失败，见 `build/abi-refresh-focus-runtime-1.log`。修复改为在禁用或隐藏之前转移焦点，并处理提供者自行禁用导致原生系统清空焦点的情况；原生回调显式选择的新焦点仍保留。第二次运行保留原严格断言并通过。Win7、AMD 与真机键盘焦点验收仍需目标设备。

## DATA 的后续接口候选

DATA 本批仍未实现。现有公共 ABI 没有刷新来源、绑定或接收显示模型的接口，放开请求位无法完成真实数据更新。以下内容是后续设计候选，不是可调用服务。

候选服务 `mms.ui.refresh.bind` 应与原刷新队列共享 owner、元素句柄、实例代次、工程代次和停止规则，提供来源注册、绑定创建、绑定释放和当前来源修订查询。新服务使用独立查询表，不改变旧 `MmsUiRefreshApiV1` 或结构大小。每个新结构保留 `h.size` 版本校验。

来源必须声明稳定 ID 与实际数据版本，并提供 UI 安全点读取已准备快照、释放快照的只读回调。来源修订在其有效生命周期内单调增长，工程替换后重新建立身份；不能借用几何修订或由每张请求随意填写计数。初版只接受有配额上限的不可变字节显示模型，避免在 UI 回调执行文件读取或整个场景求值。

绑定必须引用本插件现存目标、来源身份和目标实例，并提供准备及交换显示模型的回调。读取或准备失败保留上一份显示模型；交换只发布已经准备的数据，不能失败、泵消息或写工程。最后消费的来源修订保存在绑定中。相同修订重复 DATA 直接复用已有模型，不重复调用来源；成功票据的 `sourceRevision` 必须表示实际消费版本。

首版只开放 `SELF`。组合请求按 DATA、STATE、REPAINT 执行，失败时 `completedKinds` 表示实际成功的阶段。合并键加入绑定、来源身份和版本，不得将不同绑定合为同一次读取。插件回调中再次发起 DATA 或 STATE 须受到同一因果批次保护，不能通过下一轮排队形成无限循环。依赖注册、循环检测、`DEPENDENTS` 与 `SUBTREE` 应在后续明确实现后再报告能力。

来源与绑定均计入每插件数量、快照字节、待处理贡献和回调次数配额。注销或工程切换使尚未执行的旧引用以 `STALE` 结束；正在消费的快照与票据引用保留插件 DLL。停止先拒绝新增请求，再排空回调和快照，最后允许卸载。便利 SDK 应包装这些同一底层句柄，不创建另一套来源或刷新队列。
