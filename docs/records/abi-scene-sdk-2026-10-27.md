# 骨架场景 SDK 与能力边界（2026-10-27）

本批基于 `codex/plugin-abi` 的 `5daa219`。新增 C++17 骨架场景便利封装，并让生产来源对尚未实现的表情载荷明确返回 `MMS_E_UNSUPPORTED`。SDK 接口及示例见[求值参考](../../sdk/mms/evaluation.md)。

## C++ 封装

`<mms/cpp/evaluation.hpp>` 提供 `EvaluationServices`、`EvaluationSceneSource` 和 `EvaluationSceneFrame`。封装查询原 1.4 C 函数表，来源和帧持有同一个宿主上下文与原始句柄，不建立第二套对象身份或资源缓存。`Capture` 由宿主检查 UI 线程，求值、读取、保留和释放沿用 C 接口的线程约定。

来源和帧禁止复制及移动赋值，允许移动构造。向已持有句柄的输出对象捕获、求值或保留会返回 `MMS_E_BUSY`。显式 `Release` 失败时保留原句柄供重试；析构只尝试释放一次。插件停止前仍须结束工作线程并显式释放资源，宿主上下文必须长于封装对象。

函数使用局部候选，失败不修改调用方输出。成功取得非零句柄后立即移交所有者，不再执行可能失败的描述查询或分配。C ABI 规定失败不得发布句柄；若失效宿主违反该契约并在失败时写入非零值，封装无法安全判断它是否为有效资源，不会擅自释放该值。C++ 异常在边界转换为错误码。

## 未支持载荷

场景来源的表情定义快照目前只支持 PMX 类型 0–8。PMX 类型大于 8，或 PMX/PMD 存在未知冲量载荷指针时，来源捕获直接返回 `MMS_E_UNSUPPORTED`。不读取未知载荷，也不因权重为零而放行。PMD 的非活动 type 字节仍按原顶点表情语义处理。

预检先验证数量、表指针与预算下界，再遍历活动表情头。损坏的活动表或失效的未来外亲仍返回 `MMS_E_STALE`，预算不足返回 `MMS_E_MEMORY`；失败不发布句柄。该预检没有增加对未声明载荷的读取。

MMS 本体的 PMX 加载器目前只接受 2.0；现有 QDEF 载荷解析与蒙皮也未完整实现。真实宿主测试通过修改已加载模型的活动类型字段覆盖拒绝逻辑，不表示 PMX 2.1 文件已支持。

真实插件通过封装捕获来源、生成帧，在释放来源后读取帧；返回的对象和骨骼身份及矩阵与原生对照一致。未支持载荷专项覆盖 PMX 9、10、255，PMD 非活动 type，两个未知指针、零数量、无效计数与空表、低预算和活动表损坏。每次检查失败输出及恢复前的源表头，恢复后核对姿态、作者数据、播放头和历史；最后验证客户端全部句柄容量仍可用。

独立只读审查未发现封装或生产预检的阻断问题；审查发现的测试盲区已补充恢复前表头比较。没有新增对 DSH 的调用。
