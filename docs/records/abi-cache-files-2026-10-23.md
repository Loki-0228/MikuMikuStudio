# 缓存文件与读租约

本批实现内部 `cache_files` 文件层，供缓存管理器保存不可变文件、取得读租约和执行受控删除。它尚未接入效果编译或纹理加载，也未实现容量预算、索引、工程关联、固定保留和管理窗口，不能计为 main 完整缓存功能已经同步。

## 文件与生命周期

`Directory::Create` 用随机代次生成唯一文件名，写入 MMS 文件头及完整负载，刷新文件后返回身份。文件头固定为 128 字节，记录版本、类型、存储所有者、逻辑键、长度、SHA-256 和代次。负载最多 1 GiB，空负载有效。文件名与头中代次必须一致，尾部多余字节、未知版本、错误摘要和多硬链接文件均被拒绝。

`Inspect` 在打开文件的同一个句柄上验证完整内容。`Acquire` 另将结果与调用方提供的可信身份比较。读租约保留该文件及目录链的句柄，不共享写入或删除权限；调用方销毁 `Directory` 后，原租约仍然有效。租约可以移动到其他线程，但同一对象的调用不得并发。

`Remove` 取得独占文件句柄，在同一句柄上检查身份、文件头和摘要，再设置删除标志。存在读租约时返回 `Busy`，不会绕过租约按路径删除。`DeletePending` 只表示系统接受了删除请求，不能据此提前扣减容量预算。

`FileLock` 用独立打开的文件句柄持有一个字节的独占锁，可以跨线程转移唯一所有权。等待上限为 2,000 毫秒，进程退出后由系统释放锁。`Enumerate` 只返回有界的候选文件名，不表示文件已归入可信索引，也不赋予删除许可。

失败时保持原输出对象。创建失败只通过本次新建文件的原句柄清理；清理失败返回 `Io`，可能留下孤立文件。进程中断后的孤立文件核算及恢复仍由后续管理器负责。

## 目录保护

输入只允许本地绝对盘符路径，拒绝 UNC、设备路径、父目录跳转、重解析点及不规范组件。打开卷根后取得卷 GUID 路径，后续操作使用该路径，失败时不退回原盘符。每级目录持有 `FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES` 句柄，仅共享读取。

首轮实际测试发现，仅申请 `FILE_READ_ATTRIBUTES` 的旧实现仍允许目录重命名和写入打开。该问题已修正，原失败及受控恢复旧实现的反例均保留。先前只验证文件创建的探测和静态审查不能证明目录保护有效。

本机探测中，保护直接目录会阻止向其中创建硬链接；父目录保护也阻止了子目录重命名。保护卷根、祖先及无关目录没有阻止自有目标目录创建硬链接。这不是对所有应用和文件系统操作的保证。上层索引发布不能在持有这些保护句柄时直接套用依赖目录重命名的方案，需要按实际文件操作设计并验证。

## 验证范围

证据目录为 `build/verification/abi-cache-files-20261023`。文件专项使用全新绝对目录，运行真实 Win32 文件操作及自有隐藏子进程，不加载应用、插件或 GPU，不操作全局输入。

- 增强配置的 `full-final` 与 `full-restored` 各通过 839 项，最终 `full-final-all-restored` 通过 841 项；原始兼容 `original-final` 通过 837 项，均无跳过。计数差异来自路径长度影响的分配扫描。覆盖独立文件头解析、已知 SHA-256、跨块及空负载、损坏拒绝、可信身份不匹配、读租约、目录保护、真实 junction、硬链接拒绝和跨进程锁。锁专项分别记录正常退出和绕过 C++ 析构的退出码 23，不代表文件发布中断恢复已通过。
- 普通 `new` 的 Open 与 Create 分配失败扫描验证输出保留及句柄释放。Inspect、ReadAll 和 Lock 覆盖首处分配失败，不宣称扫描了其全部分配点。
- 四个受控反例分别恢复无效目录保护、跳过摘要校验、跳过文件身份校验和允许读租约共享写入，均触发对应断言。源码按原字节恢复后重新构建和运行通过。
- 首轮硬链接夹具与分配扫描中的重命名判断也暴露了测试问题。独立探测后，硬链接改为加保护前建立，叶句柄释放改用经过正反校准的 DELETE 权限打开验证。原重命名保护断言保留。
- I/O 故障专项 `faults-full-first`、`faults-full-restored` 和 `faults-original-final` 各通过 251 项。仅修改本测试 EXE 的三个 IAT 项，按线程、自有目录、合法文件名及观测句柄限定注入范围，结束后恢复。覆盖首写失败、负载写入失败、零进度、真实短写重试、刷新失败、清理失败及删除标记失败。清理成功时没有新增候选；刷新和清理同时失败时保留唯一孤立文件，验证其实际身份、内容及原输出不变。
- 忽略刷新失败、跳过失败清理的两个补充反例均触发明确断言。六个反例完成后，生产源码按原字节恢复，重建并通过最终专项。
- 两套产品构建通过，均为 x64、子系统 6.1，导入表及效果资源 117/118 与各自基线一致。正式 `build/release` 程序散列未变。文件库尚未被生产消费者调用，这些结果不代表完整缓存功能已经启用。

上述通过结果不证明 CNG 故障、断电恢复、索引发布原子性、物理空间回收、实际缓存命中或 Win7、AMD 真机兼容。动态故障测试记录同一观测句柄，生产代码审查另确认没有按路径重新打开后删除的流程；句柄数值比较本身不能排除系统复用句柄值。

专项目标为 `cache_files_tests` 和 `cache_files_fault_tests`，均以 `--store 新绝对目录` 运行。目录必须不存在，父目录必须存在；测试不清理或复用用户目录。构建、运行参数、反例、源码散列及产物结果保留在上述证据目录。

本批开始和最终核对时 main 均为 `fed9768f9fe726c4b5e068849808803f1713ad42`。DSH 的初次宽任务未产出实现并已终止；后续仅完成 `cache_files_crypto.hpp` 的哈希和随机数模块。文件生命周期、测试、整合与文档由 Codex 完成，正式 DSH 结果和独立审查保留在证据目录中。
