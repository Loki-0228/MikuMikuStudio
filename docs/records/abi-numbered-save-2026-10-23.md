# 手动编号保存与插件旁车

日期：2026-10-23。ABI 基线 `b1e7858`；参考 main 已提交 `fed9768`。证据目录为 `build/verification/abi-numbered-save-20261023`。

## 行为与接口

新增独立设置 `autosave.numberedManualVersions`，默认关闭，存入当前安装的 `data/settings.json`。已有显式 INI 测试覆盖及本地旧设置一次性迁移保留；正常运行不新增配置文件。设置对话框增加编号选项、说明和三语言文案，并按现有 MME 菜单状态显示 EMM 保存是否开启。

手动保存的两种保留设置取或；编号设置开启时优先采用十进制编号。旧当前保存到 `.pmm1`，全部已有正规范正整数编号 `n` 移到 `n+1`，按数字降序执行。支持稀疏编号、9 到 10、长十进制进位及孤立 EMM、插件旁车。零、前导零、符号及非数字后缀不参与。两开关关闭时覆盖当前；仅旧设置开启时继续 `.pmm1/.pmm11` 规则。首次当前不存在时不重排已有历史。

`SceneSnapshot` 在 UI 线程捕获两开关，后台写入只使用快照；周期及崩溃副本的 `backup` 路径不采用手动编号。参数经过内部 `ProjectSave::PublishDisk` 和 `PublishProjectPair`，未修改公共 C ABI。原始兼容配置通过两文件 `pmm_versions::Publish` 使用相同编号规则。

增强配置归档 PMM、已有 EMM、`foo.pmmN.mms-plugins.json`。旁车原始字节及旧 projectId、saveId、mainSha256 保留，不将后缀错误附到 JSON 名称之后。文件位于用户工程目录；工程锁与恢复记录继续随工程保存。

## 文件发布与失败处理

编号扫描识别三类成员，收集全部源、目的版本及第一代，取得已有协议的独占保存锁并拒绝未完成 journal。锁后重新扫描，编号集合改变即拒绝本次计划。执行移动前准备路径、日志容量和存在性检查，目录及重解析点拒绝，不覆盖突然出现的目标。移动和复制执行阶段不再复制路径或扩容容器。

原工程 PMM/旁车的持久化恢复 journal 继续工作。journal 前的普通异常使用逆序回滚；journal 后允许原恢复协议向前完成，并保留对应归档。首次当前替换失败且旧对完整的已有清理规则保持。恢复重复执行不再递增版本。

这不代表版本链的断电原子性。版本轮转发生在当前文件 journal 发布前，进程硬中断仍需后续持久化轮转日志；回滚自身再次遭遇 IO 错误仍为既有尽力恢复。已有 EMM 随历史归档，新 EMM 仍依赖 MME 的异步消费，不属于 PMM/插件旁车的新快照事务。原始配置不拥有增强配置的插件锁和三文件恢复协议。
