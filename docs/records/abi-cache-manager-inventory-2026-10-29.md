# 效果／纹理生产缓存的完整占用与写入峰值

本批将此前的有界文件盘点接入现有缓存管理器与两条真实生产路径。它是视频统一预算的前置工作，不代表 SourceJournal、视频加载或视频共同历史已经接入。main 本轮仍为 `6facf91`；目标范围不变，阴影同步暂缓。

## 计费与写入规则

- 在现有跨进程互斥量及进程状态锁内盘点整个受管根，包含未登记文件、临时文件、索引和文件／目录的命名数据流。以卷及文件身份合并硬链接，重复观测不一致则拒绝新的写入。
- 每个物理对象按全部数据流的逻辑长度与分配长度两者较大值计费。管理界面的总量表示已经观测到的占用；写入审批另加尚未落实的预留，不把未来预留显示成已存在文件。
- `WriteReservation::TrackTemporary` 在生产者独占创建空临时文件之后、写入正文之前登记其身份。实际临时文件与尚未写出的预留按较大者收费，仍存在的旧目标另计。预留按当前卷的分配粒度取整。
- 所有并存的正文预留共用一次完整未来索引发布的预算。索引先在内存中编码，再批准旧索引与新临时索引同时存在的峰值；临时索引用唯一名称和 `CREATE_NEW` 创建，不能截断遗留的同名文件。
- 观测、额度或索引发布失败时拒绝新增缓存写入；已发布但登记未成功的正文保留责任。失败清理留下的实际文件仍占额度，不按删除请求成功推断物理空间已释放。
- 新快照中缺席的已登记条目及此前观测过的未知文件／临时文件，必须再确认“文件或路径不存在”；拒绝访问等不确定结果保留旧账、报告错误并拒绝写入。未知名字使用原始拼写与扩展路径检查，避免尾随点等被规范化后误认缺失。
- 未登记文件不会因路径和头部看起来合法就被收编为可清理条目。读取未知缓存也不授予删除权限；已有持久索引条目及成功登记的真实发布继续沿用工程归属和清理规则。

效果与纹理入口均接入上述流程。缓存失败保留原来的编译／纹理结果；只有登记成功才报告一次缓存保存成功。失败临时文件优先通过原创建句柄清理，关闭后重开清理须核对原物理身份、创建时间、单链接及非重解析属性，避免误删临时名字处的替换文件。

固定工程等索引操作区分发布前失败与发布后检查失败：发布前失败恢复原内存状态；重命名已经成功时，先按本次候选的身份、创建时间和长度重读索引确认结果，不能把旧值反写回去。无法确认时保留未决状态并拒绝新写入。

明确“清空全部”仍能恢复本进程此前成功验证或写入、且身份未变的损坏索引。恢复走同一索引峰值审批；首次遇到的坏索引、外来替换及未决发布不自动覆盖。普通清理不借此绕过归属检查。

## 边界

盘点不是全树原子快照。共同锁协调遵守协议的写者，不能保证外部程序不会在观测后修改文件。旧索引仍以路径保存条目归属，本批没有把它升级为持久的逐文件身份账目，不能宣称全面抵御已登记路径被外部替换后的清理风险。

本批只统一现有受管效果／纹理根。单独指定的未托管缓存覆盖目录保持原有预算策略；来源事务尚未与管理器共享持久预算及锁顺序。占用数值不包含 MFT 等卷内部开销，也不是分区物理空间回收证明。

Win7 SP1 x64、CPU 基础路径及 AMD 要求保持；没有新增真实鼠标、Win7 或 AMD 真机通过结论。
