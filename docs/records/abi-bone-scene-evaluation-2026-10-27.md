# 跨模型骨架场景求值

本批已实现内部跨模型骨架场景求值，并完成原生对照及真实宿主验证。公开帧租约、蒙皮、历史物理和渲染器仍待实现。

`BoneSceneSource` 在同一 UI 安全点捕获完整模型集合，包括被外部父级引用的目标动作。`BoneSceneFrame` 持有每个模型的不可变骨架帧。该内部入口继续使用原骨骼求解和尺度算法，公开 `mms.scene.evaluate` 1.2 的范围暂不变化。

## 捕获边界

调用方提供原槽号、现有宿主对象身份和模型指针。身份字段复制 `MmsObjectRef` 的 `lo`、`hi`、`generation`，不建立第二套身份注册表。源保存槽号、计算顺序和冻结数据，完成后不保留原模型指针。

所有可达显示键中的活动外亲都必须指向本次集合中的有效目标骨骼，包括当前帧之后才会启用的父级。缺少目标、重复槽号、重复对象 ID 或重复模型指针使整个捕获失败。源不在后台重新解释当前宿主槽位。

原生 `-1` 表示保留父级继承，`-2` 表示地面，均无需目标模型。局部 selector 的 `-2` 会跳过父级或全局外亲继承，因此不能将两者合并。场景源保留原始值及窗口，拒绝更小的负目标槽号。

## 原生阶段顺序

原宿主 `physics_frame.cpp` 的两次模型扫描均按 `comboSelIndex2` 排序，同序号按原槽号排序。第一次扫描完成全场物理前阶段，第二次扫描完成全场物理后阶段。这里采用模式 0，不模拟物理。

每个模型创建自有工作区。场景槽表直接指向这些工作区，包含模型自身的槽位。外亲读取目标此时的静止位置和 `matExtra`，不是预先计算的最终矩阵。

例如模型 A 先于 B，二者互相引用。第一阶段 A 读取 B 的初值，B 读取 A 第一阶段的结果。第二阶段 A 读取 B 第一阶段的结果，B 再读取 A 第二阶段的结果。算法不拓扑排序、不拒绝所有循环，也不额外迭代到收敛。自模型外亲可以读取同一轮较早骨骼、层级或 IK 更新后的矩阵。

全部模型完成两轮后才生成尺度结果。确定初值来自加载器，因此这里验证的是从新工作区开始的原生两次扫描。依赖上一帧残留矩阵的连续播放和历史物理需要另行提供状态，不能据此声明等价。

## 所有权与预算

场景源和结果按输入顺序枚举，计算顺序单独保存。结果拥有所有子帧，来源、原模型及数学上下文销毁后仍可读取。内部 `ModelFrame()` 返回的借用指针仅在所属场景帧存活期间有效，未来 C ABI 必须通过句柄和租约提供访问。

保留预算汇总场景外壳、容器容量和全部子对象。工作预算共享于同时存活的所有模型，包含工作区、槽表和排序索引。嵌套算法瞬时分配不作为进程峰值上限。任何模型失败都不发布部分场景结果。

## 公开通道待修问题

审查发现现有 `mms.scene.evaluate` 1.2 的显示捕获仅将 `-1` 作为非模型父级，`scene_host.cpp` 会把地面 `-2` 判为过期目标。`evaluation_store.cpp` 也只接受 `MMS_EVALUATION_PARENT_ACTIVE` 输出标记，不能只放宽捕获校验。

后续须在同一来源和租约体系中明确表达继承、地面及模型目标。地面不应生成假对象身份，也不能静默等同继承。旧接口不能表达该状态时应明确报告不支持并保留输出，新接口须有实际宿主及 DLL 契约验证。本批只补齐内部场景语义，未修复该公开通道缺口。

main 核对仍为 `d551f1f`，无新增已提交更新。此前阴影同步记录保留，本批不修改阴影，也不回退已有实现。后续阴影同步按用户要求暂缓。VMD 协议、原始兼容配置行为和正式 release 均不在本批修改范围。
