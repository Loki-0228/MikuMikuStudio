# 相机跟随开关共同历史方案

状态：待实现。依据 `codex/plugin-abi` 的 `dcfe98c` 静态分析编写，未执行功能验收。本文件不表示 `535` 复选框和 `247` 菜单已完成迁移。

目标约束保持 Win7 SP1 x64、CPU 基础路径及 AMD 兼容。本方案复用现有 CPU 数学和数据接口，不增加显卡厂商依赖。

## 旧入口的完整行为

两个入口是 [`CmdControl500` 的 `535`](../../src/window/command_control_500.cpp#L634) 和 [`CmdFileMenu` 的 `247`](../../src/window/command_file_menu.cpp#L2370)。复选框读取目标勾选值，菜单切换当前值。

启用会依次求值相机、灯光、阴影、重力和全部已加载附件，再应用相机视图。求值会覆盖这些对象的未登记姿态，因此完整迁移必须包含这些前后值，不能只记录 `followCameraEnabled`。

`ReloadModels` 实际只求值相机，见 [`timeline_advance.cpp:188`](../../src/app/timeline_advance.cpp#L188)。上述调用链不执行模型关键帧求值，也不推进骨骼、物理或随机风。`ApplyGravityTrack` 只写重力参数和对话框，见 [`track_apply.cpp:101`](../../src/model/track_apply.cpp#L101)。最低完整范围是一个包含视图和各轨道当前姿态的复合事务，无需为此增加全场景求值事务。

| 分支 | 需要保留的结果 |
| --- | --- |
| 启用 | `follow=1`。按当前帧私有求值全部四类全局轨道和已加载附件。随后按 `ApplyCurrentCameraView` 清零偏移及抑制标志，并设置附件基矩阵。 |
| 启用且相机有父骨骼 | 基矩阵取当前父骨骼 `matInit` 的左上角转置，保持其余单位矩阵项。偏移取相机位置 X、Y，距离取相机位置 Z。读取当前骨矩阵，不从关键帧重新求值模型。 |
| 关闭 | `follow=0`。不重新求值上述轨道。用旧、新焦点补偿偏移和距离，使视图按旧实现转换。模型模式且相机父模型等于所选模型时，另清零抑制标志。 |

基矩阵和偏移行为见 [`ApplyCurrentCameraView`、`PostModelReload`](../../src/window/ui_model_reload.cpp#L79)。关闭后的模型模式使 `PostModelReload` 提前返回，不能把这次调用理解成模型重载。

焦点规则见 [`ResolveFrameFocus`](../../src/render/debug_geometry.cpp#L1575)：跟随视图取父骨骼世界点或相机位置，自由模型视图取原点、模型根或选中骨骼。关闭时的补偿见 [`CarryEyeForFocusChange`](../../src/app/frame_modes.cpp#L1335)，按关闭跟随后的 `RotY * RotX * RotZ` 计算，不乘旧父骨骼基矩阵。不能替换成另一种相机保持算法。

## 事务字段和原生求值规则

拟新增独立的 `native_camera_follow.hpp/.cpp`，不把跟随行为塞入只处理小键盘的计算函数。一个 `HistoryChange` 持有受影响对象的 `before`、`after` 和逐字段变化掩码。本方案新增内部参与者，不新增公共 C ABI。

| 对象 | 纳入快照的字段 | 必须保留的细节 |
| --- | --- | --- |
| 跟随和视图 | `followCameraEnabled`、`ViewportPresetState` 的相机位置、欧拉角、距离、FOV、投影、父模型、父骨骼、偏移、基矩阵、抑制标志。 | 启用的父矩阵来自当前骨姿态。关闭只修改补偿涉及的字段。 |
| 灯光 | 方向三分量、颜色三分量，以及 `SceneLight` 的 `Type`、`Direction`、`Specular.rgb`、`Ambient.rgb`。 | [`RefreshLightPanel`](../../src/window/ui_frame_refresh.cpp#L109) 会覆盖未登记值。[`ApplyTimelineLightState`](../../include/mikudancestudio/mmd_app.hpp#L738) 还会写这些设备灯光字段。`Diffuse`、alpha、Range 及其他未修改字段不随撤销恢复。 |
| 阴影 | `ShadowMode()`、`ShadowDistance()`。 | [`RefreshSelfShadowPanel`](../../src/window/ui_frame_refresh.cpp#L195) 按左侧键保持。`ShadowDistance()` 与 `PhysicsInterval()` 是同一存储，只保存一份，见 [`mmd_app.hpp:1381`](../../include/mikudancestudio/mmd_app.hpp#L1381)。 |
| 重力 | 强度、方向三分量、`gravityNoise`、`GravityNoiseModeWord()`。 | 噪声模式按原生整四字节复制，含低位标志和三个填充字节。两键之间取右键模式，不能套用左键步进规则。作者层只覆盖低位标志，不能清掉其余字节。 |
| 每个已加载附件 | 可见、阴影、父模型、父骨骼、位置三分量、旋转三分量、缩放、透明度。 | [`ApplyAccessoryTrack`](../../src/window/accessory_paste.cpp#L121) 在两键之间保持左键变换，只线性计算缩放和透明度。`additiveBlend`、行选择、资源和关键帧池不写。 |

启用以原生求值为基础，再用同一轨道的作者层覆盖，与旧 `curve_host::Apply` 顺序一致。每种原生计算保留原有浮点运算次序，尤其是相机的单精度十二步反算、重力的整数噪声插值、附件的缩放与透明度计算。不能统一改用 double 线性公式。

现有 [`CaptureViewportResetCamera`](../../src/plugins/native_viewport_reset_camera.cpp#L204) 已提供相机原生及作者层的私有采样，可作为相机来源。其他轨道需要补齐等价的只读采样器。作者层用 [`TrackAuthoring::Prepare(NativeKeyView)` 和 `Target::Sample`](../../include/mikudancestudio/animation_curve_host.hpp#L253) 读取私有目标。临时 `Target` 在捕获结束前销毁，不发布作者层，也不长期持有未经计费的目标。

## 来源冻结和对象生命周期

拟新增 `FollowToggleSource`，只在首次提交前检查来源。来源包含以下数据。

- 当前帧、原跟随值、目标值、相机模式、参考模式、所选模型和选中骨骼，以及输入焦点所属窗口。尚未提交的文本输入不得被刷新覆盖。
- 启用时四类全局池和全部已加载附件池的稳定身份、容量、原生链快照及作者版本。关闭只捕获实际计算所需的视图来源。
- 父骨骼和参考骨骼的稳定对象所有权、骨表身份、索引，以及本次计算读取的 `matInit`、`position`。相机求值前后的父模型可能不同，二者分别检查。
- 启用时完整的已加载附件集合。来源捕获后新增、删除或复用槽位使首次提交失效，不能只检查最终出现变化的附件。

模型及附件采用现有稳定对象所有权，不能用裸地址或槽号替代身份。池可以按既有规则允许同身份增长，但原生来源必须保持一致。纯采样记录用 [`TrackAuthoring::CapturedCurrent()`](../../include/mikudancestudio/animation_curve_host.hpp#L263) 拒绝作者内容或元数据变化，不调用会替换私有种子的重定时接口。

历史计费包含前后姿态容器、原生链容量、作者种子、字段掩码和新增的长期缓存。对象资源沿用现有资源预算规则，避免重复计算共享资源。不得把仍保留的采样 `Target` 遗漏在计费之外。

撤销和重做使用已保存的数字及稳定对象身份，不再次读取原关键帧、当前骨矩阵或文件。当前播放头、选择及参考模式可以与首次操作不同，不能因此把历史重新解释成当前场景上的求值。

## 准备和发布约束

拟新增的计划接口接收明确目标跟随值，并返回一个完整变化。启用请求必须计算完整旧调用链，即使复选框目标恰好等于当前标志，也不能仅按标志相等提前返回。只有最终所有受影响字段均相同才是真正无操作。

准备阶段只写私有副本。任一来源不支持、链损坏、目标不合法、内存不足、预算不足或来源过期，都使整次操作失败。禁止先写跟随标志、逐个安装轨道、调用旧刷新函数取结果，再试图回滚。

发布前检查全部候选和稳定对象。发布阶段不分配内存，不发送窗口消息，不执行插件回调，只按变化掩码写跟随标志和前后值。原生关键帧、作者表、track cursor、active 标志、播放头和最大帧不改。未变化的属性在后续历史操作中保持用户当前值。

操作按 `NativeIntent::Adjustment` 接入共同历史，与现有视图调整一致。「全部操作」模式记录一次完整事务，「仅显式提交」模式不额外生成视图历史节点。真正无操作不清空重做记录。

首次计划和提交使用严格门禁。已发布记录在 [`RunBoundObjectHistory`](../../src/plugins/native_object_commands.cpp#L375) 内往返时，仅在同一应用具有 `NativeObjectPublicationAuthorized` 授权时豁免该函数持有的场景锁和 UI 锁。鼠标捕获、播放、保存、对话框及对象身份检查仍生效。候选不能再建立一套场景锁，或因外层合法持锁而拒绝撤销。

## 入口和派生界面刷新

`535` 和 `247` 在任何实时数据写入之前转入同一受控计划。受控分支包含失败与取消，不能落回旧调用链。原版兼容档保留旧路径。

复选框点击可能已经改变 Win32 勾选状态。计划失败时按当前 `followCameraEnabled` 恢复复选框和菜单勾选，不能留下界面显示开启、实际关闭的状态。菜单的 `dialogFlags[2]` 属于入口输入状态，不作为工程姿态恢复。

提交成功后按实时快照刷新菜单、主窗口和浮动窗口对应复选框、相机、灯光、阴影、重力及附件控件。投影和设备灯光在此阶段更新。可复用 [`RefreshBoundGlobalReadout`](../../src/plugins/native_global_commands.cpp#L990) 的只读刷新方式，但需补齐跟随勾选及相应控件。

刷新不能再调用 `ReloadModels`、`RefreshLightPanel`、`RefreshSelfShadowPanel`、`ApplyGravityTrack` 或 `ApplyAccessoryTrack`，这些函数会再次求值并覆盖刚恢复的历史。窗口失效或刷新失败只进入现有派生界面重试流程，不撤回已提交数据，也不重复添加历史节点。准备前后的焦点变化需要检查，刷新不得隐式提交另一项文本编辑。
