# 配件设置接入共同历史

基准为 `codex/plugin-abi` 的 `7148684`，开发与构建位于 `D:/MMD-Next/MMS-abi-dev`。

## 已实现行为

配件设置菜单 `249` 在受控共同历史下开放。拖拽和上移、下移按钮调整顺序，重命名修改当前项的名称，分界数值决定配件与模型的绘制先后。这三类修改只作用于临时列表，点击「确定」后合为一次显式提交；两种历史记录模式均记录一次。「取消」不修改场景，确认无变化不增加历史、不清空 redo，也不改变 dirty 状态。

新计划在打开对话框之前捕获完整配件集合、稳定身份、顺序、原始名称字节和绘制分界。确认时从临时指针数组读取对象与行的对应关系，不按重复标题推断身份。关闭对话框、释放临时编辑数组后，才准备并发布共同历史。失败不回退旧写入路径。

未修改的名称保留原字节及填充；新名称沿用 MMS 编码规则，不能完整编码时拒绝整次提交。准备检查完整排列、名称范围、分界、源数据及对象代次。分配失败、预算不足或来源过期均不修改实时元数据。记录计费包含前后元数据和容器容量，对象资源仍沿用已有删除、导入记录的计费规则。

撤销与重做只恢复实际变化的顺序、名称和分界。未修改字段保留后来的用户值，不读取源文件、不重新求值姿态或移动播放头。配件经共同历史删除、恢复后，稳定身份相同的新代次仍可参与往返；单个已准备候选则拒绝准备后的代次变化。

场景 API 的附件 `name` 读取当前显示名称，来源路径单独保留。改名后的新快照更新名称与结构修订，已有快照租约保持原值。空的旧名称回退到文件名；未终止名称拒绝获取快照。

## 界面与错误处理

提交前按稳定身份保留当前操纵配件和独立登记范围，提交后重建对应列表。历史包装新增名称、顺序和分界变化检测：对象指针不变时也更新列表，插件延期通知同样使用待刷新状态。原生控件写入失败后保留已提交历史，阻止后续编辑并重试界面，不重复提交。

改名和排序还立即重建相机模式时间轴的标签缓存与行映射，避免列表正确而时间轴仍显示旧内容。元数据节点声明无需重置物理；普通撤销及插件延期发布沿同一声明处理，未知原生节点与插件数据参与者继续保守重置物理。

重命名的临时列表更新改为先插入、复制 item data，再删除旧行。插入、项数据或删除失败时撤回新行，保留旧文本、选择、对象身份及已输入的新名称。编码分配异常不会越过 Win32 回调。此修复也用于未绑定模式及原版兼容配置。

播放、其他编辑器、保存、回调重入及待刷新状态继续拒绝打开受控对话框。普通宿主的公共 `mms.edit` 仍未开放；本批只迁移此原生入口，没有新增公共 C ABI。

## 验证

专项通过 **8,819** 项，见 `build/abi-accessory-settings-focused-7.log`。范围包括无分配发布、名称字节、未变化字段、不同播放头、无变化保留 redo、过期源与身份、非法临时排列、预算拒绝和逐个 C++ 分配失败点。还覆盖对象删除恢复交错、真实列表失败后的 UI 重试、场景快照名称及物理影响声明。

最终三语言真实宿主结果见 `build/abi-accessory-settings-runtime-3/report.json`。`history` 与 `all` 两组均通过：两种历史模式、组合设置、取消、无变化、延期撤销刷新、时间轴行映射与标签缓存、物理标志保持，以及 PMM 保存重开；完整模式继续覆盖原有绘制分界、未绑定拖拽、按钮排序、删除和重新导入。原生列表子类验证三类写入失败的重命名回退及 item data 保留。

完整配置构建通过，最终整合见 `build/abi-curve-full-build-1.log`、`build/abi-curve-host-build-4.log` 及 `build/abi-curve-final-link-1.log`。原版兼容产品与 I/O、状态目标构建通过，见 `build/abi-curve-original-build-2.log`。两种配置均保持 Win7 基线开启、DX12 关闭。

完整配置回归见 `build/abi-curve-regressions-1.log` 及详细输出。其中共同历史 **208,941** 项、ABI 契约 **1,804** 项，场景历史 UI、统一设置与产品可选图形导入均通过。原版兼容 I/O、状态、导入及独立曲线传输四组也通过，见 `build/abi-curve-original-tests-1.log`。

原名与中文改名的实际产品通过独立隐藏启动、真实插件队列、菜单、双面板、侧栏调整和关闭，见 `build/abi-accessory-settings-smoke-1.log`。产物只更新 ABI 工作区的构建目录。

最初专项夹具在模型模式下断言相机模式的登记范围；调整为正确模式后通过。故障扫描还暴露测试包装在保护边界之外分配历史标签，已改为与生产入口一致的异常边界。初次失败及异常退出日志保留在 `focused-1..3`，不作为产品通过证据。分配扫描覆盖 C++ `new`，未注入系统 `calloc` 失败。

Win7 SP1 x64、CPU 基础路径及 AMD 约束保留。测试使用实际隐藏窗口与原生拖拽通知，没有冒充物理鼠标、多 DPI 或目标硬件验收。
