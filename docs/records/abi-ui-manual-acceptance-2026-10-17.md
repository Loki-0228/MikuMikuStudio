# IME、缩放与真实鼠标验收

验收对象为 `codex/plugin-abi` 的独立程序副本，以及原创生命周期测试插件。用户环境为单屏、微软拼音。程序位于本记录对应的 `build/manual-ui-acceptance-2026-10-17` 目录；与稳定版目录完全分开。设置写入副本旁的 `data`。不修改系统缩放、不关闭用户原有实例，不带入 MME 或其他第三方插件。

## 当前结论

真实微软拼音、单屏不同缩放及真实鼠标结果均待用户操作。不同 DPI 显示器之间的移动在单屏设备上无法验收。隐藏窗口消息分派、人工传入 144 DPI 或模拟 1/1.5/2 倍绘制均只能作为自动回归证据。

## 自动验证记录

本轮 `build/abi-ime-dpi-contract.log` 中 ABI 契约 1,694 项通过，包含 surface 的 96/144 DPI 参数、焦点及生命周期。`build/abi-ime-dpi-panels.log` 中普通名称和中文改名两个隐藏生产宿主均通过双面板挂载、切换、焦点与卸载。它们不证明真实候选窗或鼠标操作已通过。

`build/abi-ime-dpi-fullscreen/report.json` 中 DPI-unaware 与 system-aware 两种上下文的独立隐藏窗口全屏往返均通过（每种两次往返）。这不代表运行中系统缩放变化、混合 DPI 跨屏或真实鼠标命中已验证。测试原先直接调用 `GetDpiForWindow`，在 Win7 目标下无法编译；现在仅该测试改为动态查询并提供窗口 DC 回退，同时避免大型状态栈临时对象。最终构建日志为 `build/abi-ime-dpi-fullscreen-final-build.log`。

HUD 的 1/1.5/2 倍绘制检查在 `build/abi-ime-dpi-hud.log` 和本机重试的 `build/abi-ime-dpi-native-hud.log` 均返回 `FAIL GPU device`，未进入绘制验证，不归为通过。合并构建在首次资源生成及 HUD 目标构建完成后，对全屏目标再次重复编译同一份效果资源；该重复任务已停止，使用本轮确认 byte-identical 的资源缓存完成全屏单独重建。保留初次构建及失败日志，不用消息测试补写 GPU 检查结果。


## 启动测试副本

打开测试目录中的 `MMS-UI-Acceptance.exe`。插件区域应出现「自定义面板一」「自定义面板二」，其中有写着「中文输入测试」的编辑框。缩窄窗口导致控件折叠时先放大窗口。若测试副本提示错误或面板未出现，记录原文，不继续判断输入法结果。

## 验证微软拼音

1. 点击面板一的中文输入框，Ctrl+A 清空；切换微软拼音中文模式，键入 `zhongwenceshi`，保留候选状态，检查候选窗贴近插入点且不被面板裁切。
2. 先用空格选词，上屏「中文测试」；再输入拼音，用鼠标点击候选。检查只出现一份文本，不触发其他菜单或视口操作。
3. 再输入 `ceshi`，先按 Enter 确认当前输入，再继续输入。Enter 不应在仍有候选时被宿主抢走；最终内容可能按拼音规则上屏为字母，不要求每次 Enter 都选出汉字。
4. 再输入拼音后按 Esc，应取消组合而不删除原有已上屏文字。分别用 Tab、点击面板二及点击视口切换焦点；组合应按输入法规则提交或取消，不应重复插入、卡住候选窗或把按键传给视口。
5. 切回面板一，确认已上屏文本仍在。关闭并重开后的文本保存不是该样例插件的承诺，不据此判断失败。
6. 在原生数值输入框额外检查组合中 Enter 是否意外失焦。全角数字、中文不是合法工程数值；非法输入被拒绝不算 IME 故障，组合过程中抢焦点或执行其他命令算失败。

静态 review 发现全局插件快捷键优先于普通编辑框按键处理，以及原生数字框 Enter 直接移焦的风险。目前未据此宣称已复现或已修复。普通测试插件没有占用字母／Enter 快捷键，验证该风险需要额外带冲突快捷键的插件用例。

## 验证单屏缩放

由用户在 Windows 显示设置中分别选择可用的 100%、150%、200% 缩放；不要求机器支持全部比例。每次先退出测试副本，改变缩放后重新打开，再执行上一节输入法及下一节鼠标步骤。系统要求注销时按系统提示处理；不要为了本测试关闭未保存的其他工作。

每档检查文本、按钮、候选窗、边界点击是否正确，缩窄／放大后是否有重叠、裁切或不可达的操作区。另在测试副本打开时改变一次缩放，观察是否出错；重启后复核是否恢复。记录具体缩放和启动／运行中切换方式。

当前 MMS 采用 DPI-unaware 窗口，Windows 可能进行位图缩放。文字没有达到原生每屏 DPI 锐度不等于坐标测试失败；坐标错位、裁切、无法点击或重启后布局错误需要报告。单屏切换缩放不能替代真实混合 DPI 跨屏验收。

## 验证真实鼠标

使用鼠标或触控板实际按下、移动、松开，不用发送 WM_HSCROLL 或 SetCapture 代替。

1. 在不同缩放比例下，点击按钮中心及四边附近、切换两个插件页签、点击输入框左右端，确认命中目标且不会点到相邻控件。
2. 拖动主侧栏和底部区域的分隔线，慢拖、快拖、反向拖，至少各 5 次。拖到最小／最大边界再返回；内容应跟手，松手停住，不残留旧内容或遮挡。
3. 将视口切为浮动窗口，拖动其边框和窗口位置，再恢复嵌入。检查主窗口与浮窗的点击、缩放及输入焦点，至少往返 3 次。这里是本体现有浮动视口，不代表插件已提供任意独立浮窗。
4. 先截图或记下自阴影距离原始刻度。按住自阴影滑杆的滑块，向两侧连续拖动，拖出滑杆后返回再松手。检查刻度实时变化，松手后继续移动鼠标不会再改值。有模型且阴影模式开启时检查视觉反馈。
5. 再拖动一次，中途 Alt+Tab 到别的窗口，松开鼠标后返回；不应留下持续捕获。随后再次拖动，确认仍能工作。也检查窗口失焦、最小化再返回的情况。
6. 移动窗口遮挡测试副本，再移开；反复缩放窗口。检查重绘无拖影、旧按钮残片或黑块。只在副本中操作，不覆盖原工程。

普通程序仍未开放 `mms.edit`，不能以普通副本 Ctrl+Z 是否恢复每个滑杆位置来判断本次共同历史迁移。逐位置撤销／重做已有专用宿主自动验证；要做它的真实鼠标验收，还需带受控历史绑定的交互测试入口。

## 回报格式

按实际操作回复，例如：`100%：IME pass，鼠标 pass；150%：候选窗偏右；200% 未测`。失败需补充控件、操作顺序及实际表现。未测试的档位和跨屏项目保留未验收，不填写 pass。
