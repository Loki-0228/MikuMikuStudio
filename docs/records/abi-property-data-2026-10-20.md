# INPUT 默认属性 DATA 刷新

未绑定显示数据源的原生 INPUT 已接入原 `mms.ui.refresh` 1.0。请求、对象句柄、票据、权限和生命周期共用原实现，公共 C 表及结构大小不变。开发用法见 [INPUT](../../sdk/mms/input.md)、[刷新接口](../../sdk/mms/refresh.md)和 [C++ 包装](../../sdk/mms/cpp-refresh.md)。

## 请求与执行

SELF 的 `binding=0`、`sourceRevision=0` 表示在 UI 安全点读取属性当前值，不表示捕获某个已发布版本。目标须实际报告 DATA 能力；仅查询服务的全局 DATA 位不足以判断。只填一个零值返回 ARGUMENT，默认请求遇到已有显式绑定返回 CONFLICT。默认读回成功后的票据版本仍为 0，成功依据为 DATA 完成位。

SUBTREE 一次捕获全部显式绑定及其不可变版本，再将未绑定的原生 INPUT 加入属性读回。显式绑定优先，不重复读取属性；默认成员也参与绑定集合校验，排队后增加、删除或替换绑定使旧票据过期。显式绑定字节仍是插件自己的显示模型，不自动解释成原生字段。

后台请求只读取宿主保留的目标快照，不访问 HWND、注册表或属性回调。UI 消费时检查原呈现实例、工程代次、准确属性记录及绑定集合。相同公开句柄的属性替换也会使旧请求失效。DATA、STATE、LAYOUT、REPAINT 沿用原顺序；本批没有新增 INPUT STATE、自动订阅或 DEPENDENTS。

`RefreshPropertyCurrent` 与 `RefreshPropertyElementCurrent` 只组合原 SELF 请求，不注册另一个属性、控件或数据源。已捕获的目标引用可由后台提交，普通生产程序也可读回只读属性；可写属性仍限已绑定编辑宿主的受控路径。

## 显示、草稿与失败

原生读回在写窗口前准备完整值、UTF-16 文本、原文本、选区和校验存储。正常 DATA 不重建字段、不改标签、不重算布局、不移动焦点。写入失败时恢复已尝试的字段；无法恢复时暂停几何和刷新目标并返回失败，不报告 DATA 完成。

最新规范值缓存与草稿起始值分别保存。活动草稿的原始文本和选区不被 DATA 覆盖；提交仍核对起始值和修订，Escape 恢复最新缓存。普通刷新中的暂时读取失败同样保留草稿，但撤销旧提交意图，防止旧候选继续发布。

首次读取失败时，普通挂载先按注册类型建立只读空字段，没有伪造规范值或编辑基线。后续 DATA 成功即可填入真实值，保留原 HWND 和几何。超长 BYTES 显示只读摘要；取消草稿、恢复较小值及切换只读属性时同步更新原生可编辑状态。

整个 DATA 回调及原生应用受原只读因果保护，不求值场景、不改变播放头、不写工程、不新增历史。SUBTREE 仍不承诺回滚此前已完成的兄弟显示更新。
