# 参数回显、导出状态及效果路径修复

本批以 ABI 分支 `53d6dae` 为起点，按函数核对 MMS main 的 `04ce98c`。仅同步本记录所列的渲染、效果路径及故障诊断内容；main 工作区未修改。公共 ABI、VMD 和 PMM 标准字段保持原有定义。

## 参数回显

用户已明确轻微闪动发生在灯光、视角等参数滑杆。前一批已经减少同值 `TBM_SETPOS`，本批继续移除 `PostViewRefresh` 对七个相机数值的重复文本写入。附件父模型槽号与模型下拉列表行号分开处理，稳定父模型不再因此重复清空骨骼列表；列表内容、语言、骨过滤及条目身份发生变化时仍更新。复选框与骨骼选择也只在变化时写入。

骨名核对或列表准备发生 C++ 分配失败时，数字及复选框回显仍继续。重建先准备全部名称及骨索引，再清空旧列表。原生控件发布条目失败时停止后续父模型和骨骼选择，下次刷新重试；该情况不承诺保留原生控件的完整旧列表。自阴影范围使用限位后的显示刻度比较，越界作者值不会在后续刷新中反复回写滑杆，也不会随显示限位修改作者数据。

稳定父模型目前仍逐骨核对，复杂度为 O(N)，包含 C++ 分配。4000 骨、100 次稳定刷新有独立计时及分配计数，测试不设与机器速度相关的通过阈值。这不是无分配回显，也不是性能提升的对照测量。

以上改动减少确定的重复消息，不能证明肉眼闪动已经消失。受控参数编辑仍请求主窗口刷新；主窗口已有子窗口裁剪和缓冲绘制，暂未更改其绘制策略，也未替换原生滑杆绘制。下一次视觉复验应连续拖动灯光 RGB、方向及视角，检查滑块、相邻读数和场景实时响应，再检查松手、键盘改值及撤销重做。

## 图片导出与阴影状态

图片序列首帧在原生采样后检查尚未初始化的骨矩阵。确有零矩阵的模型按原依赖顺序完成姿态准备，不推进输出时钟或物理模拟。该处理不改模型编辑姿态的作者字段、关键帧及历史。

设备重置后，普通录制捕获目标在进入阴影绘制前准备。阴影过程保存进入时实际的 RT0、深度、viewport 和投影；成功和提前失败均恢复同一组对象及状态。切换非多重采样阴影目标前先解绑深度，避免与进入时的 MSAA 深度形成不兼容组合。旧的按窗口缓存选择恢复目标的方式已移除。

真实设备测试包含冷启动 PNG 的几何及透明背景、录制中设备重置后的 BMP，以及普通与 checked 阴影入口的目标、深度、清屏和 viewport 失败。测试不涵盖恢复 API 自身再次失败，也不把本机图形结果推定为 Win7 或 AMD 真机验收。

## EMM 路径与故障诊断

EMM 相对路径按 EMM 所在目录解释，优先于程序目录的同名文件。多字节路径先解码再解释分隔符，避免把 CP932 字符内部的 `0x5c` 当作目录分隔。兼容层不改写 EMM，读取上限为 16 MiB。工程重置及无 EMM 的新工程清除旧路径；模型加载通知不替换现有工程的路径。

项目路径替换仅用于已知读取操作；通用编码转换不再将路径替换为项目副本。同步 EMM 读取复用已经成功打开的句柄，并保留调用方文件位置；异步句柄跳过探读并清除旧路径。选中的项目文件读取失败时保留对应错误，不改读程序目录的同名文件。MMEffect 的导入表补丁仅作用于已加载模块；效果编译保留原编译器、HRESULT 与 LastError，并记录实际文件和可安全读取的 COM 调度地址。单个转发入口只绑定一种编译器地址，其余版本保持原入口，因此该入口的项目路径替换及编译诊断也仅覆盖绑定的版本；多版本实际加载尚未独立验证。

故障报告在恢复前固定异常记录、寄存器及调用点附近字节，使用可读性检查和受保护读取。模块头损坏、不可读或带 guard 时仍记录模块路径及基址，无法获取的映像字段标记为不可用。报告的静态暂存区只允许首个报告线程使用，不在故障分支临时分配或加载 DLL。

当前栈溢出验证只覆盖初始化线程，不等于全部工作线程均设置了栈保证。异常栈指针落在 guard 页后的系统展开行为仍未独立验证。本批路径及诊断修复也不解决 MME 保存队列的同步完成、待消费旧备份或立即退出问题。
