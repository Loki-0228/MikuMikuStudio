# 视频来源持久事务与明确恢复

本批只修改 ABI 工作区。main 已提交 HEAD 仍为 `6facf91`；阴影同步继续暂缓，目标范围不变。没有修改 main、覆盖正式稳定版或增加公共插件 ABI。

## 已实现的行为

内部 `src/io/cache_source_journal.hpp/.cpp` 将真实文件捕获与同一个业务 catalog 串联起来，保留原业务页、工程引用及其他来源记录。声明的预留字节只表达本次操作责任，**不批准磁盘额度**，尚未接视频菜单、PMM 或共同历史。

| 操作 | 行为 |
| --- | --- |
| `Open` | 绑定已存在且物理身份不同的 control、pages、raw、control/catalog，读取真实业务页；不初始化或认领未知目录。 |
| `OpenForRecovery` | 显式允许现有 catalog 的可信 intent 恢复协议，再核验业务和目录绑定；支持新进程打开，未知／损坏记录仍拒绝。 |
| `CreateCapture` / `Reserve` | 先创建有界本地操作对象，再持久记录操作及来源 ID、完整声明字节。重复 ID、错误线程和重入明确拒绝。 |
| `Prepare` | 实际创建空候选，先持久记录确切身份及计划；实际大小不得超过声明，可缩至实际大小。登记失败保留写句柄或清理回执。 |
| `Complete` | 有界流式复制、完整摘要及只读租约验证后登记 Captured。控制锁贯穿复制、句柄切换和登记，另一进程不能抢走读取重开间隙。 |
| `Publish` | 单次 CAS 以 Published 来源替换操作记录，核验真实工程 owner，确认成功后才交付租约。 |
| `Cancel` / `Recover` | 先持久记录 Abort 阶段，再清理确切文件；确认目录项消失后才移除操作记录。失败、Busy 和删除待完成均保留责任。 |
| `Resolve` / `ResolveRetirement` | 不确定提交阻止盲重试，恢复后逐字段比对操作前后记录；回滚返回 Conflict，不能冒充提交成功。 |
| `Acquire` / `Retire` | 按已登记身份及摘要取得租约；退休只修改状态并保留 owner，不删除文件、不撤销现有租约、不减少额度。 |

同进程未完成对象销毁不自动删除文件，仍持有的句柄和未决尝试由共享状态保留，可重新打开同一绑定显式恢复。旧对象只能移除自己对应的本地节点，不能误删复用 ID 的新对象。已确认 Published 的对象销毁则释放未交付租约，持久来源记录继续承担文件责任。

完整文件恢复新增 `Directory::RecoverRawSourceCleanup(expectedRoot, RawSourceInfo, out)`：独占句柄下核对根、身份、单链接、精确长度和完整 SHA-256，然后交付可重试清理句柄；取得句柄本身不删除。缺失确认采用 Windows ordinal 忽略大小写比较，比较失败也不视为缺失。

## 崩溃及并发边界

- 创建文件后、Prepared 计划持久化前进程退出，文件可能成为 unknown。恢复 Reserved 时有界检查目录名称；任何不在可信来源／计划中的条目都会返回 NeedsCleanup，保留未知文件和预留记录。此检查不读取正文、不测量总占用，也不授权删除 unknown。
- 完整持久计划可在新进程中精确恢复，不需要重新读取原文件。catalog 本身的不确定写入必须先走明确恢复入口。
- 复制期间持控制锁是本批防止跨进程误清理的取舍。调用必须由合适的后台协调器安排；这不是已经实现非阻塞 UI。后续若缩短锁区间，须先增加覆盖整个捕获生命周期的跨进程所有权保护。
- catalog 的容量／提交数量限制原样返回，保留责任；没有自动 checkpoint、清扫未知目录或绕过额度。
- 所有 Journal 对象限定创建线程调用和销毁；后台并发、统一额度及生产迁移仍由后续协调器承担。
