# 模型 VMD 曲线尾段：独立审查与集成回归

本记录核对 `25381ce` 之后开发中的模型 VMD 导入迁移。本轮负责独立审查和新增集成用例；生产实现与最终构建由主任务及骨骼、表情子任务负责。

## 已核对的旧加载规则

依据 `src/model/vmd_load.cpp` 的实际加载路径，文件尾段按以下顺序识别：

1. Unicode 名称字典。字典的校验信息绑定前面的标准记录；骨骼、表情和 IK 的记录所有者数量必须一致。
2. `MMSMCRV1` 表情曲线。只有整个块存在且 CRC 正确时才前移读取位置。损坏的表情块会遮住后面的骨骼曲线和缩放尾段，不能仅凭长度跨过去。
3. `MDSBCRV1` 骨骼曲线。该层只有有界长度封装，没有表情块那样的外层 CRC。长度有效时即前移读取位置，即使内部曲线数据稍后不能应用。
4. 缩放尾段。其前缀边界和 CRC 包含已经识别的字典、表情块及骨骼块。

标准关键帧登记完成后，实际应用顺序为“表情曲线 → 缩放 → 骨骼自由曲线”。骨骼自由曲线生成原生镜像时，需要使用本次导入的缩放矩阵作为基底。

VMD1 与 VMD2 的标准模型记录布局保持不变。帧偏移同时作用于标准记录和尾段；骨骼曲线需要时补帧零锚点，表情曲线的帧零值则来自目标原有轨道。

旧加载器在应用曲线尾段之前更新最后登记帧。因此，尾段新增的帧可以扩大模型 `maxFrame`，但不能追溯扩大 `LastRegisteredFrame`。自由骨骼曲线完成后，共用分配游标回到骨骼头数量。

表情曲线要求每个导入帧都有本次标准导入产生的选中记录，且数值在原生 `float` 精度下一致。不符合条件的表情轨道独立跳过。骨骼自由曲线若与其他原生帧冲突，应跳过整个骨骼作者块，保留标准数据以及已成立的表情、缩放结果，并反馈兼容提示。内存不足与该兼容跳过不同，必须拒绝整个尚未发布的导入。

## 本轮独立审查发现

- 表情头文件原有注释称损坏块仍可按长度跨过，与真实加载器不符。已通知表情子任务修正文档注释，保留实际旧消费规则。
- 汇总层新增跨模型存储检查后，初版仅在准备时检查其他模型；短事务准备后若另一个模型改指向本模型的池，旧 `IsCurrent` 仍可能通过。已通知主任务修复，并增加“准备 → 其他模型产生别名 → 提交拒绝”的独立集成用例。之后只读确认 `Layout` 已保存其他模型的槽位、指针及完整范围序列，`PeersCurrent` 在最终检查中逐项无分配复核。
- 解码器按两种曲线各自的真实大小限制处理。表情块不能错误套用骨骼块的 16 MiB 上限。
- 兼容提示只在规划成功后报告；内存、预算和其他失败使用失败路径，不能声称标准数据已经导入。
- 公共源对象保留原始曲线块及显式 Unicode 所有者映射。已解析但为空的映射表示没有匹配，不能回退到 CP932 名称匹配；导入过程不借用线程局部名称映射。
- 骨骼子任务的独立审查发现，表情尾段初版套用了编辑器写入路径的 `float` 控制点包围盒限制，会跳过旧写入器合法导出的有限 `double` 曲线。已修复该兼容回归。新增用例保留 `1.8e38` 大切线，通过实际旧 `CaptureVmd`、`ApplyVmd`、解析极值及密集采样确认曲线取值仍可表示，并验证新导入的作者层、当前权重和离线历史往返。未改旧 codec 或引入新的尾段限制。

本记录没有确认新增系统或图形依赖。该路径使用现有 CPU 数据处理和 Win32 文件接口，继续遵守 Win7 SP1 x64、CPU 基础路径及 AMD 兼容要求。真机兼容性不由这些隐藏窗口或数据用例证明。

## 新增集成用例

文件：`tests/native_model_vmd_curves_checks.inc`，入口：`NativeModelVmdCurvesChecks()`。测试主文件由主任务接入。

完整路径为“实际 VMD 文件 → `DecodeModelVmdSource` → `ResolveModelVmdTargets` → `PlanModelVmdImport` → `SharedHistory` 准备及提交”。对照路径调用实际未绑定共同历史的 `LoadVmdMotion`，不以另写一份解析器充当旧加载器。仅给旧入口提供零初始化渲染器结构，没有创建设备；临时清空窗口句柄以避免兼容警告弹出。

覆盖内容：

- VMD1/VMD2、CP932/Unicode、零偏移/非零偏移，骨骼、表情、缩放同时存在；核对原生池、标记、作者切线、缩放矩阵、分配游标、最大帧和登记范围。
- 表情 CRC 损坏、表情封装截断、骨骼封装截断、骨骼内部数据损坏、未知分隔字节；对照旧入口的消费与跳过结果。
- 无标准记录的骨骼尾段；标准原生数据完全相同而仅表情作者数据变化；完整重复导入不新增历史。
- 逐分配注入失败、历史字节预算不足、准备后取消、撤销和重做准备失败；失败保留所有原生、作者和历史状态。
- 首次提交前删除源文件；模型、模式及当前帧变化后的撤销与重做；只依赖历史自身保留的数据。
- 两种历史模式下，曲线 VMD → 第二模型真实显示/IK 登记 → 再次作者 VMD，三次共同撤销/重做；分别核对目标模型及其他模型的原生数据，并保留无关骨骼的临时姿态。
- 共享其他模型的表情池、骨骼游标指向表情权重、IK 链链接指向关键帧池，均应整批拒绝；准备后出现的跨模型别名也应拒绝发布。

## 真实受控宿主验收

新增 `tests/plugins/vmd_model_curves_host_checks.inc`，接入现有 `edit_history_host_checks.inc`。它复用已加载的实际 PMX/PMD 模型、实际插件 DLL、`LoadVmdFile` 入口和共同历史绑定，覆盖 VMD1/VMD2、两种历史模式及零/非零偏移。现有 `run_edit_history_probe.py` 分别提供 PMX 和 PMD 模型及原名、中文改名的进程。

该用例使用现有骨骼回归的 `Original` 生命周期夹具保留并恢复原生池身份，另外保留表情权重、游标和原始作者层。源文件由已有标准 VMD 写入夹具追加原格式表情块、九道稀疏骨骼块及前缀 CRC 绑定的缩放尾段。验证 Free 控制柄、欧拉角多圈值、偏移锚点、缩放矩阵基底和标准镜像，随后验证同值不新增历史、删除源文件、与前后两个实际插件事务交错的撤销和重做，以及当前播放头保持原位。

缩放期望由完全私有、拥有独立骨骼表、游标和注册关键帧池的模型计算：调用实际旧 `ApplyImportedExtension` 后，再调用实际旧 `bone_curve::Write`，取得两个目标键的九个矩阵元素及四个控制字节。矩阵逐元素使用精确 `==`，控制字节逐项相等，没有使用 epsilon 或其他容差。临时模型结束时清理骨骼曲线、缩放 side table 和关键帧池，不写入实际应用模型。

该期望保留旧非线性 `CurveTime` 的 12 步 `float` 行为，包括输入零时仍可能得到非零比例。因此，自由曲线镜像矩阵不能简单视为源尾段矩阵原值。用例另行精确核对源尾段，并在生命周期夹具保护下把帧零缩放基底设为首个导入基底，使重复导入确实产生相同数据；原始缩放由总 RAII 恢复。全部无变化断言保持严格比较，没有修改生产浮点计算。

完整旧宿主链中的 `frame_line_curve_host_checks`、`numpad_view_host_checks` 和 `sparse_registration_host_checks` 三处夹具也已修正准备边界。它们直接调用的全局 `curve_host::Write` 已在此前迁移中正确接入共同历史，因此准备数据本身会产生历史节点。每次准备后显式 `Reset`、`Collect`，保留准备好的数据并确认撤销、重做均为空，再执行原来的门禁和编辑断言；所有原断言保留。另一个全局登记用例在共同历史绑定前准备数据，不需同类修正；独立 `bone_curve::Write` 也不是该受控全局入口。

实际 PMD 夹具的 root 骨型字节为 0，PMD 加载器直接读入，当前枚举对应 `BoneType::RotateMove`；新的尾段用例筛选包含该真实骨型，无需转换模型数据。

最终 `host-4` 中，PMX 的 `MikuMikuDance.exe` 与 PMD 的 `自定义名称.exe` 各完成 8 组 VMD1/VMD2 × 两种历史模式 × 0/947 偏移。两份 `result.log` 均通过新增双曲线尾段、严格缩放对照、无变化、删除源文件后的插件交错历史检查；全部旧宿主用例继续执行到 PMM 保存、重新打开、运行时重建和关闭并通过。`report.json` 两个 `exitCode` 均为 0。
