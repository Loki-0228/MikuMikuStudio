# 设备重置前的插件资源释放

日期：2026-10-26。工作区 `D:/MMD-Next/MMS-abi-dev`，分支 `codex/plugin-abi`。

## 实现

RenderService 将设备丢失分为立即标记和安全释放两个步骤。`MarkDeviceLost` 立即禁止新租约，但不运行插件代码；`FlushDeviceLost` 在回调外释放资源。待释放时拒绝恢复，避免提前允许申请新资源。原有 `DeviceLost` 保留为组合入口。

生产 integration 用 `Manager::InCallback` 隔离普通插件回调。设备丢失后即使事件分配或投递失败，释放义务仍独立保留。安全消息入口、重试定时器、下一帧入口和 Reset 准备入口均可完成释放。重复丢失不重复释放，重复恢复不增加设备代次。初始化和关闭时清除设备状态、业务事件及临时属性标识。

`PostDeviceReset` 在建立恢复状态后、释放任何本体资源前调用 `PluginPrepareDeviceReset`。如果仍在插件回调内，立即返回失败，保留下一帧重试所需的 `resetRequired`；不会在回调中调用 Reset。正常入口先释放插件登记的默认池资源，再执行原有设备重置。原始兼容配置无插件运行时时直接继续原流程。

设备恢复等待也补齐无需 Reset 的 D3D_OK 路径。等待函数先建立活动保护和设备、录制资源身份快照，再通知丢失。释放回调返回后重新检查身份与待 Reset 状态，防止清除回调期间产生的新恢复请求。短暂丢失恢复后重新允许插件申请租约。

## 剩余范围

业务事件在分配或投递失败时仍可能丢失，快速连续恢复时队列事件代次也可能早于当前设备状态。本批保证释放义务独立保留，但恢复通知可靠性仍需补齐。插件处理恢复事件后申请资源时必须检查返回值。

post、租约分类、完整多视图渲染、DX12 原生及 BakePreview 独立呈现路径仍未统一。测试使用真实 DX9 设备和资源，但部分驱动结果由注入控制；没有验证真实硬件掉线、Win7、AMD、多显示器或长时间运行。

main 本批开始和最终核对均为 `d551f1f`，没有新的已提交更新。后续阴影同步继续按用户要求暂缓。整个 ABI 目标仍未完成。
