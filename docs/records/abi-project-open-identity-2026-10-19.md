# 工程打开失败时保留保存目标

记录日期：2026-10-19。对应 [main 审查对照表第 8 项](abi-main-review-comparison-2026-10-18.md)。实施起点为 `codex/plugin-abi` 的 `696959db509c4761eb1ae1b32c4779e1f05c5368`。

当前状态：完整配置和原版配置正式程序已重建，独立身份测试分别通过 430 项和 241 项检查。真实 PMX/PMD 宿主的正常 PMM 保存、重开和插件状态恢复也通过；全部版本及四个入口的实际正文组合仍待补足。

## 缺陷和结果

旧入口先把待打开的路径写入 `EnvFileName()`，再调用加载器。若文件不存在、文件头无效、版本不受支持，或插件工程准备被拒绝，原场景仍在，但快速保存已指向被拒绝的文件。打开菜单还提前修改工程相对路径和记忆目录。

新增的 `bool LoadSceneFile(const wchar_t* candidate)` 将候选路径与当前保存目标分开。加载器只有成功加载工程后才保留候选路径。替换场景前失败时，原工程继续使用原路径。已经开始替换场景后失败时，加载器保留现有空场景复位行为，并清空保存目标。

main 参考源码、SHA256 和逐文件差异已固定在 `build/abi-review-fixes/project-open-main-20261019/`。移植按函数调整，没有用 main 文件覆盖 ABI 的共同历史和插件事务实现，也没有修改 main 工作区。

## 四个打开入口

| 入口 | 实现位置 | 当前行为 |
| --- | --- | --- |
| 打开菜单 `205` | [`CmdOpenScene`](../../src/window/command_impl.cpp) | 对话框返回局部候选路径。只有加载成功才修改 `DirUser()`，不再借用工程相对路径作临时缓冲。 |
| 最近工程 | [`recent_projects::HandleMessage`](../../src/window/recent_projects.cpp) | 将选中路径直接传给候选接口，不提前写入 `EnvFileName()`。此菜单仅在完整配置提供。 |
| 拖入 PMM | [`HandleDropFiles`](../../src/window/ui_dropfiles.cpp) | 将拖入路径传给候选接口。成功后才更新记忆目录，不再把 `PathWorkspace().executableDirectory` 当作目录提取缓冲。 |
| 启动命令行 PMM | [`InitMainWindowAndD3D`](../../src/window/window_init.cpp) | 先把命令行复制到局部缓冲，再清空暂存命令行的 `EnvFileName()`。失败时保持未命名场景，成功后更新记忆目录。 |

旧的无参数 `void LoadSceneFile()` 和 `void LoadSceneV1/V2(...)` 继续保留。无参数接口只能把当时的 `EnvFileName()` 当候选读取，不能恢复调用者此前自行覆盖的旧路径。仓库中的四个实际打开入口均已改用候选接口。

## 场景替换边界

[`pmm_load_shell.cpp`](../../src/io/pmm_load_shell.cpp) 先冻结候选路径，并捕获原 `EnvFileName()`、工程相对路径、脏标志和布局就绪标志。候选可以与 `EnvFileName()` 指向同一缓冲，冻结后不会因赋值而改变。

替换前的处理保留既有插件事务顺序。`PrepareProjectLoad` 负责 PMM 与侧车配对恢复、主文件读锁、插件数据准备和共同历史重置准备。文件打开、完整文件头和版本检查通过后，加载器才建立原生场景修改作用域，并临时将候选路径交给正文解析器作资源读取上下文。

[`TryLoadSceneV1`](../../src/io/pmm_load_v1.cpp) 和 [`TryLoadSceneV2`](../../src/io/pmm_load_v2.cpp) 返回加载结果，并通过 `replaced` 标志报告是否已越过替换边界。只有 `BeginProjectSceneReplacement` 成功后才设置该标志，随后调用 [`AcceptProjectSceneReplacement`](../../src/io/project_open.hpp)，发送工程打开通知、清除脏标志并设置候选工程的相对路径。该调用发生在第一次原生场景释放之前。

| 失败阶段 | 保存目标和标题 | 插件数据与共同历史 |
| --- | --- | --- |
| 场景替换前拒绝 | 恢复原文件名、工程相对路径、脏标志和布局标志。原标题未被改写。 | 取消本次插件准备并释放读锁，保留原工程数据及历史。 |
| `BeginProjectSceneReplacement` 拒绝 | 临时读取上下文退回原工程身份，不执行空场景复位。 | 原历史尚未提交重置，本次准备由原取消机制清理。 |
| 场景替换已经开始，正文返回失败或异常复位 | 清空文件名与工程相对路径，标题恢复为 `MikuMikuDance`。不得把结果重新附到旧工程或被拒绝的候选文件。 | 保留原生加载器已有的替换、复位和插件取消行为，不恢复已经释放的旧场景。 |
| 完整加载成功 | 保留新工程路径，沿用正文成功尾部的标题和加载通知。 | 沿用原插件提交及共同历史场景边界。 |

这项修改没有把 PMM 正文加载改成完整事务。替换后失败不承诺恢复旧模型、姿态或渲染器。清空保存目标可以防止随后按「保存」把部分加载结果或空场景覆盖回旧工程。

插件准备、提交和取消仍由现有 [`integration.cpp`](../../src/plugins/integration.cpp) 管理，本次没有重复实现插件状态回滚。自动备份名和备份清理时保护的当前原稿均从 `EnvFileName()` 取得身份，因此替换前拒绝也保留这些路径依据。备份保存本身未在本专项中重新执行。

## 独立测试的范围

[`project_open_identity_tests.cpp`](../../tests/project_open_identity_tests.cpp) 使用真实的加载外层、打开菜单、Unicode `HDROP` 和完整配置的最近工程派发。完整配置还使用真实的 PMM 侧车配对存储、全局插件运行时及共同历史。

已执行的检查包括以下情况。

- 缺失文件、短文件头、错误魔数、不支持的版本、文件占用、空路径和过长路径。
- 已有场景修改作用域、错误对话框期间重入、浏览取消及未保存确认取消。
- 完整配置的侧车哈希不匹配、已有工程准备排斥第二次打开，以及准备后取消。
- 替换前失败后，原保存目标、工程相对路径、记忆目录、可执行目录依据、标题、脏标志、布局标志、播放头和测试姿态保持不变。
- 完整配置的原插件工程身份、未知插件数据及共同历史节点保持不变，原记录仍可撤销和重做。
- 拒绝后释放 PMM 描述符与插件读锁。原稿、被拒绝的候选 PMM 及对应侧车均保持原字节。
- 成功接受候选后修改保存目标。模拟替换后取消时清空保存目标，避免重新使用旧文件名。

测试拦截范围如下，不能把这些探针称为真实正文加载验收。

| 被拦截部分 | 测试实际证明的内容 | 未证明的内容 |
| --- | --- | --- |
| 模态消息和打开文件对话框 | 真实入口在给定确认结果下的路径和取消行为。 | 用户手动操作对话框的交互。 |
| 最终 `SaveSceneFile` 调用 | 真实快速保存命令 `207` 仍选择原工程路径。 | 原生 PMM 保存、短写及原子替换。测试没有真正覆盖原稿。 |
| effect 通知和 `LocalizeUI` | 替换前拒绝不发送接受工程后的通知。 | 实际 MME 回调、效果资源和布局刷新结果。 |
| 成功与替换后取消的原生正文 | 外层根据 `replaced` 处理保存身份，插件提交、取消和历史边界仍真实执行。 | 有效 PMM 正文的模型、附件、物理和资源解析。 |
| 替换前异常 | 外层处理模拟内存异常、短读和无效记录异常时保留原身份。 | 真实正文每个分配点或读入点的故障覆盖。 |

完整配置的边界拒绝探针会进入真实 V1、V2 函数和上下文构造，再拒绝 `BeginProjectSceneReplacement`。原版的该函数是恒真兼容实现，测试不强行挂接短函数，而是在正文入口模拟同阶段异常。插件测试覆盖配对失败和准备取消，没有装载专门拒绝 `prepareLoad` 的第三方插件。

启动入口已完成源码核对，但本独立程序没有调用完整的 `InitMainWindowAndD3D`。真实启动载入仍属于待补整合范围。

## 尚未完成的验收

仍需用真实有效的 PMM V1、V2 及完整配置支持的 V3，分别经菜单、最近工程、拖放和启动入口加载，核对成功后的路径、标题、资源相对路径及 PMM 侧车配对。正文已经开始替换后的真实失败还需覆盖缺失资源、读入异常与既有复位流程，并确认保存不会指向原稿。

真实插件 `prepareLoad` 拒绝和取消回调的整合验收尚未补足。启动命令行的失败身份目前仅静态核对，不能记为用户操作验收。构建、正式程序哈希及共同历史整合结果见同批跟随迁移记录。

独立审查还确认了一项既有文件描述符缺口：V1/V2 关闭流后，成功尾部若分配失败，外层异常处理仍会再次关闭原整数描述符。本次没有修复或验证这一异常尾链，也不以已通过的保存目标测试声称该尾链安全；后续须统一流所有权并注入关闭后异常。

本项未改变 PMM、插件侧车或 VMD 的文件布局，也未改变 `data` 路径规则。Win7 SP1 x64、CPU 基础路径和 AMD 兼容约束保持不变。两种配置在当前机器通过测试，不构成 Win7 真机或 AMD 真机验收。
