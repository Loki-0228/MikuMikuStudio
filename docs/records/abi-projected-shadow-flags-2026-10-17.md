# 地面投影开关共同历史验证（2026-10-17）

本批基于 `codex/plugin-abi` 的 `d12741d`，仅修改 `D:/MMD-Next/MMS-abi-dev`。地面投影显示菜单 `221` 与透明地面阴影菜单 `254` 接入受控共同历史，普通 `mms.edit` 仍关闭。

## 行为与接口

菜单 `221` 控制既有地面投影绘制是否启用，菜单 `254` 控制该流程中的透明混合。它们分别写 `GroundShadowEnabled` 和 `ProjectedShadowBlendEnabled`，均为 PMM 已保存的工程字段，与自阴影模式和阴影浓度分开。本批沿用原绘制流程，不修改渲染器或浓度对话框。

`TryToggleBoundProjectedShadowFlag(MMDApp*, field)` 接管两条菜单写入。内部 `ApplyBoundProjectedShadowFlag(MMDApp&, field, enabled, changed)` 的字段 0 为显示，1 为透明混合，目标写 0 或 1。原生点击依据作者值保持零变 1、非零变 0，不按菜单勾选决定方向。历史保存原始字节，支持恢复 7 等非标准非零值。内部显式设值比较目标字节，同值不创建历史、不标 dirty、不截断 redo。这些入口是 C++ 内部接口，不是公共 C ABI。

播放、事务忙碌、准备失败或阴影颜色对话框打开时，作者数据、dirty、选择及 redo 保持，菜单从当前作者值恢复，不回落旧切换。菜单 `221` 原有 `dialogFlags[8]` 输入消费信号仍在尝试编辑前设置，拒绝时也保留原行为；它是临时输入状态，不是场景修改，不进入撤销记录。菜单 `254` 不添加该输入信号。没有独立取消对话框，取消待提交插件事务后可重试，已提交开关通过共同撤销恢复。

## 共享记录与复核

将原内部 `GridDisplayChange` 扩展为 `ProjectDisplayChange`，坐标显示、地面投影和透明混合共用一套记录。短期候选核对三个字段、相机键池身份、帧号与记录代次；首次准备还核对原始来源。每条记录只写本次字段，撤销或重做保留其他后来改变的显示值，不改变当前模型、轨道选择、播放头、相机参数、附件姿态、关键帧或旧模型环。

记录以相机键池身份作为既有工程来源标记，不持有模型、网格或 GPU 资源。正常扩容保持身份，替换工程来源使旧记录过期且不移动历史游标。发布只写作者字节及记录状态，不分配、不调用窗口、插件、GPU 或文件，不求值场景。完成发布后才同步三个菜单及已有坐标复选框；插件历史回调沿用安全刷新。可选通知失败不把已完成编辑报告成失败。

受控路径使用同一个公共历史，不新增渲染开关撤销栈。原始兼容 profile 和未绑定路径保留旧行为；相关菜单注释统一为地面投影与透明混合，避免误读成模型面板或物理显示。
