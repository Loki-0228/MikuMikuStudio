# PMM 预读、聚焦阴影与附件绑定历史

本批在 `codex/plugin-abi` 的 `c71b2dc` 上继续迁移。DSH 由用户暂停，代码和验收均由 Codex 处理。完整及原始兼容配置已构建，本机定点结果如下；不表示全部 ABI 需求完成。

## PMM 预读

V1、V2 在工程替换门禁接受后，为普通文件的既有输入所有者启用 64 KiB 窗口。非普通文件或无法获得位置时保留原读取。`Input` 仍独占同一个 CRT 描述符；预读只借用它，不重新打开文件，也不另设关闭所有者。V1 保留可选尾段的普通 EOF，V2 保留原来的严格读取入口。

逻辑位置只随实际交付的字节推进。错误诊断使用该位置。MMS 尾部读取前，先把同一描述符回退到标准体已消费的位置；回退失败就拒绝尾部交接。原始兼容配置继续忽略扩展。短读、非法长度、失败定位、嵌套作用域与描述符数字复用均需独立检查。

关闭先消费所有权，退役该描述符的全部严格读取及预读上下文，再执行真实关闭。即使关闭回调立即复用相同数字，较外层作用域也不得恢复旧检查、回退或误关新文件。独立借用的 `ReadAhead` 析构仅尽力同步；需要后续原始读取的调用方必须先检查显式同步成功，不能依赖析构处理定位错误。

预读的统计和 A/B 开关仅用于内部诊断，不是新的用户设置。真实 CRT 调用数量减少不能单独证明加载耗时改善。

## 大场景阴影

只参考 main 已提交的 `0fe9fe0`。小场景继续使用原拟合网格和透视变形。整个场景过大、额外分辨率仍不能补偿精度时，根据相机覆盖范围拟合近处光照平面；深度范围仍包含整个场景，使光线方向上远处物体可以投影到近处接收面。

实际 `UpdateAdaptiveShadowMap` 接入该投影。未修改着色器，也未修改原始兼容配置的实现。数值检查和本机 D3D9 检查不替代 AMD 或 Win7 真机验收。

## 附件父模型和父骨骼

实际组合框 474、475 进入同一个成对绑定参与者。更换父模型保留原操作的存储规则：附着时父骨骼设为 0，界面选择首个可选骨骼；解除附着时保留原父骨骼数字。骨骼下拉框按项目数据解析真实骨骼编号，不能按重复名称或显示行号修改绑定。

在全部操作模式下，每次有效调整形成一个共同历史节点；显式提交模式按既有策略处理调整。同值操作不增加空节点或清除 redo。准备、身份、预算或内存失败不得回退到原来的直接写入路径；拒绝后只恢复这两个组合框，保留其他数值输入草稿。

参与者保活并计费附件及前后父模型。短期发布候选冻结身份、表和修订；长期撤销重做要求当前绑定符合该参与者的预期，接受合法的同对象删除恢复，不重新读取来源文件。全部操作模式的附件 HUD 和绑定调整按同一队列顺序遍历。模式切换后，未登记草稿与更早历史参与者之间的统一合并策略未在本批验收。

大型标准体来自实际保存器写出的 2,501 个相机键，共 206,271 字节，不是填充字节。有效未知扩展大于 64 KiB，实际发生一次标准体回退交接，保存后原值及标准边界仍相同。相同 77,658 次字段请求对应的真实 CRT 调用从 77,659 次变为 5 次；未据此报告耗时提升。

保留了以下失败及边界证据。

- 初次构建缺少直接包含的语言和保存声明头，已修正。后续资源测试的宽字符资源类型声明也已修正。
- 真实管道的 CRT tell／seek 可以返回 0，最初仅按位置判断的回退不足；现额外通过 `_fstat64` 判断普通文件。原始兼容产物仅新增既有 CRT 文件系统库中的该符号，两种产物移除旧 `_tell`，没有新增系统 DLL，PE 均为 x64、子系统 6.1。
- 宿主测试原先误把 `SaveSceneCopy` 的备份名称尾部算作标准体，并把截断恢复中的原始配置刷新误认成成功尾链。这两处测试判断已按真实格式边界及 `IncompleteProjectFile` 分支修正，生产解析流程未为测试改变。
- 旧 HUD 全集曾在系统鼠标定位处失败；保留该记录，新增明确的核心入口，未重跑系统鼠标用例。已为未知历史测试参数加入显式错误分支，避免意外进入全集。该补充入口的受限环境运行在 15 秒超时，后续运行被自动审批以可能进入旧全集、影响系统鼠标为由拒绝；未继续执行，也不计为动态验收通过。
- 原来的 SM3 源码即时编译在 240 秒超时；当时实际进程仍消耗 CPU。该路径未声明通过。实际产品已经嵌入的相同着色器字节码绘制通过。旧参考着色器的 16 组横向越界材质探针仍失败，98 组原生采样比较为零差异；这是保留的旧行为反例，未把原始兼容着色器改成完整配置。
