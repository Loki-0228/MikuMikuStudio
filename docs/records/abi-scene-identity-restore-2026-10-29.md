# 场景身份恢复：避免重复复制全部历史 ID

2026-10-29，背景图片共同历史的扩大回归发现了 `SceneIdentity::Replace` 的生产性能缺陷。本批已实现修复并完成独立代码审查，两配置构建及 ABI 契约各 45,133 项通过；新增大历史 ID 专项和实际恢复分配扫描也已在全集中越过。**全量原生历史仍未通过：后续相机 HUD 测试无法移动实际系统鼠标，待用户桌面补验。** 目标范围不变，main 仍为 `6facf91`，阴影同步继续暂缓。

## 原因与已有证据

旧实现每次恢复场景身份都执行 `auto known = known_`，复制进程中全部曾用 ID。该集合用于防止 ID 重用，会随历史场景和已退休对象累积；恢复少量当前对象也因此发生大量无关分配。

同一测试程序（SHA-256 前缀 `90363a435e1747d71`）的结果不同：

- 独立身份专项（本地证据，未随本文发布）通过 9,082 项，独立环境中的恢复在 84 次分配处成功。
- 全量历史回归（本地证据，未随本文发布）先累积了大量已用身份；其 `native-history/result.log` 显示身份恢复故障注入扫描失败 8,192 次，`successLimit=-1`，未在原上限内到达成功路径。

这不是放宽测试上限的理由：真实宿主长时间运行后也会承受同样的全量集合复制成本。原故障注入的 8,192 上限保持不变。

## 修复

`src/plugins/scene_identity.cpp` 继续私下准备新的活动对象表，但只为尚未存在于 `known_` 的输入对象 ID 和本次需要退休的元素 ID 建立 `pending` 集合。所有验证、节点分配和容量预检先完成，之后交换活动表，再通过 `std::set::merge` 转移已准备的节点，最后发布新代次。

提交使用相同的标准分配器，并把 `src/plugins/scene_store.hpp` 的整数 ID 比较器 `IdLess::operator()` 标记为 `noexcept`。合并前检查 `max_size()` 剩余容量，避免活动表已交换后才因容量条件失败。

全部历史 ID 继续保留，不删除旧身份、不允许对象地址或位置元素复用退休 ID。准备失败不提前发布新对象、退休元素或代次。本批只消除对全部历史节点的重复分配；集合查询和合并仍有比较成本，没有测量或宣称总耗时为常数。

## 新回归与最终证据

`tests/native_model_adaptation_identity_checks.inc` 新增有限规模的真实 `SceneIdentity::Replace` 专项：

- 对相同输入分别预置 0 和 8,192 个历史 ID，要求分配次数相等；本专项的少量对象／元素恢复须在 64 次分配以内成功。
- 对准备阶段逐项注入内存失败，要求活动对象、元素及代次完全不变。
- 未知输入对象和本次退休元素不能在失败时提前进入已知集合；成功后一次发布，并保留全部既有历史 ID。
- 复用对象地址和重新生成元素都不能获得退休 ID；原适配恢复的 8,192 次扫描上限及严格断言继续保留。

已核对最终运行汇总（本地证据，未随本文发布）及各项 `result.log`：

| 项目 | 最终结果 |
| --- | --- |
| 完整配置 ABI 契约 | 退出码 0，`PASS checks=45133` |
| 原始兼容配置 ABI 契约 | 退出码 0，`PASS checks=45133`；不改变原始配置的 ABI 开放范围 |
| 新增大历史 ID 测试 | 全集已越过 0／8,192 历史 ID 的等分配次数、64 次内成功及失败原子性断言 |
| 实际适配恢复故障扫描 | `failures=80 successLimit=80`，随后输出实际身份适配、保存／重开及旧元素不复活通过；原上限仍为 8,192 |

两配置构建已成功，日志为 完整配置（本地证据，未随本文发布）和原始兼容配置（本地证据，未随本文发布）。已有构建警告不视为本批已修复。

该轮全集停止点的日志明确为 `SetCursorPos` 未成功（`positioned=0`）：期望屏幕坐标 `(108,138)`，实际仍为 `(1263,786)`，取鼠标位置及坐标转换均成功。用户随后在桌面复现同类失败，不能只归因于自动执行环境。后续新增严格隐藏窗口坐标夹具后，相机专项通过 8,666 项，全集通过 713,350 项；仍不代表真实鼠标 warp 验收。生产定位失败保护及最新证据见[后续记录](abi-picture-gesture-history-2026-10-29.md)。

鼠标阻断后的独立补验（本地证据，未随本文发布）三项均通过，使用与上述全集相同的程序哈希：`accessory-parent` 6,486 项、`accessory-hud-core` 5,925 项、`same-model-follow` 2,539 项。它们补充相应功能的独立证据，不能替代全集通过或真实鼠标验收。

ABI 开发程序已于 2026-10-29 构建为 `build/cmake/Release/MikuMikuDance.exe`，见应用构建日志（本地证据，未随本文发布）。`python tests/optional_graphics_imports.py` 输出 `optional startup imports=[]`，表示被检查的可选图形库没有成为该程序的启动导入；不等于真机 Win7／AMD 验收。没有覆盖 MMS main 或稳定版程序。

## 其他回归状态

此前 `NativeModelPhysicsUiChecks` 的失败已确认是测试混计两类请求：预览退休的刷新请求，以及成功历史发布后的场景刷新请求。现分别严格计数，仍要求只投递一次合并后的 wake；后续全集已越过该点，才暴露本次身份恢复问题。没有放宽“只清理一次”的生产约束。

图片快照新增契约双配置各 362 项、0 失败，证据为 picture-snapshot-contract-pe1q2xcr（本地证据，未随本文发布）。图片背景 19 组通过状态见[图片共同历史记录](abi-native-picture-history-2026-10-29.md)；这些专项和双配置 ABI 契约通过，均不替代尚未完成的全量原生历史与实际鼠标验收。

Win7 SP1 x64、CPU 基础路径和 AMD 兼容要求不变；本次采用已有 C++17 容器与内部身份逻辑，没有引入新的系统或显卡依赖。图片摆放历史已在[后续批次](abi-picture-gesture-history-2026-10-29.md)接入；视频资源 owner、总体资源预算及完整设备恢复仍未完成。
