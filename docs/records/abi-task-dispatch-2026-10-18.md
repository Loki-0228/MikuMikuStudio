# 后台 UI 任务恢复调度

基准为 `codex/plugin-abi` 的 `ba23f9d`，工作区为 `D:/MMD-Next/MMS-abi-dev`。本批按 ABI 需求检查已开放的后台 UI 队列、共同历史和插件生命周期。

## 问题与修复

`enqueueUi` 接受任务后发送窗口消息。工程数据准备阶段或只读 UI 回调可能运行嵌套消息循环，此时分发器收到消息，但因重入保护而不执行任务。旧实现没有保留重试信号。所有唤醒消息消费完后，即使准备或回调已结束，任务仍可能无限期等待下一次主动排空或新任务。

分发器现在为仍有任务的队列保留 16 ms 定时重试。每次分发前清除旧定时器，原有准入检查仍决定是否执行；窗口回调退出后再按剩余任务安排重试。队列为空时撤销定时器。不在等待期间递归调用插件，也不为等待任务循环投递即时消息。

取消、每批 64 个任务、停止时拒绝新任务和代码保活规则不变。定时器创建失败会记录错误并保留任务，不提前释放插件上下文。此修复不增加独立后台作业服务，也不改变公共 C ABI、线程要求或普通宿主的 `mms.edit` 开放状态。

## 验证方法

测试加载独立构建的真实 lifecycle DLL，从工作线程注册一个执行任务和一个取消任务。只通过窗口消息泵驱动分发，不调用 `Manager::Drain()` 帮助恢复。

- 工程数据准备期间消费原始唤醒消息，确认两个回调均未执行；取消准备后，执行和取消回调各发生一次。
- 在真实按钮的只读状态应用回调中泵消息，确认任务不借用只读回调的执行时机；退出回调后自动恢复。
- 已安排重试但尚未执行时停止插件，两个任务均取消；DLL 卸载后继续泵消息，不再访问旧回调。
- 真实编辑 DLL 通过队列提交共同历史。准备期间保留原值、修订、redo 和通知次数，恢复后只产生一个历史节点，并可撤销、重做。抛异常的队列编辑取消候选，不增加历史或通知，后续重试不重复取消。

原实现已在新增测试中复现失败，见 `build/abi-task-retry-red-1.log` 和 `build/abi-task-retry-red-detail-1.log`。修复后同一测试通过，随后加入共同历史恢复和异常用例。失败日志保留，不将首次复现记为成功。

## 验证结果

完整 ABI 产品、契约、共同历史和场景历史 UI 目标构建通过，日志为 `build/abi-task-retry-build-3.log`。原版兼容的产品、I/O 和状态目标构建通过，日志为 `build/abi-task-retry-original-build-1.log`。两种配置均保持 Win7 基线开启、DX12 关闭。测试新增代码最初的混合类型 `auto` 声明已修正，旧构建错误日志保留。

五组完整配置回归通过，见 `build/abi-task-retry-regressions-1.log` 和详细输出 `build/abi-task-retry-regressions-detail-1.log`。其中 ABI 契约 **1,775** 项、原生共同历史 **200,122** 项通过，另外三组为场景历史 UI、系统设置和产品可选图形导入。新增四类任务恢复用例全部通过。

私有桌面刷新专项 **7,761** 次断言通过，见 `build/abi-task-retry-refresh-1/report.json`、`result.log` 和 `plugin.log`。范围包含局部重绘、按钮状态、槽位显隐、真实 Manager 及停止保活；刷新定时器和新增任务定时器各自工作。

实际生产宿主在独立目录以原名和中文名启动，使用 `gui-panel-queue` 真实 DLL。菜单、工具栏、双面板、面板跟随侧栏及关闭通过，见 `build/abi-task-retry-host-1.log`。两组各自的 `probe.log` 均有一次 `TASK_RUN`、一次 `TASK_CANCEL` 和一次 `DESTROY`；启动及测试未操作用户已有编辑器。该验收没有模拟新的 IME、物理鼠标或跨屏 DPI 组合。

原版兼容 I/O、状态与可选图形导入三组通过，见 `build/abi-task-retry-original-tests-1.log`。本批没有新增运行库、图形后端或厂商依赖；原版构建仍有未使用 `vcomp140.dll` 延迟加载的链接警告。

本批只修改 ABI 工作区，保留 Win7 SP1 x64、CPU 基础路径和 AMD 兼容约束。本机验证不替代 Win7 或 AMD 真机验收。
