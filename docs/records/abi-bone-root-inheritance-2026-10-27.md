# 根骨骼在 IK 后继承阶段的越界修复

## 问题与改动

准备独立骨架求值时，审查发现原生 `BoneTransform_PostIkPass` 无条件读取 `boneRecords[bone.parent]`。合法根骨骼的 `parent == -1`；当它继承 IK 结果、`hasFlag != 0` 且符合层级和物理阶段时，会读取骨骼表之前的数据，导致世界矩阵错误或越界访问。

这不是只由人工夹具构造的非法组合。PMD 加载器会为指向 `Ik`／`UnderIk` 的 `RotateGrant` 设置该标志；PMX 加载器也会为指向 `UnderIk` 的继承骨骼设置标志，两条路径均不要求存在普通父骨骼。

从阶段 C 抽出单骨世界变换函数 `ResolveBoneWorld`。阶段 C 继续使用原来的条件、公式和顺序；阶段 E 只在根骨骼上复用该函数，非根骨骼仍调用原来的 `WorldFromParent`。两个阶段的物理复制条件仍各自保留在原位置。

- 无外部父级时，根的世界矩阵等于局部矩阵，父级旋转镜像为单位矩阵。
- 有逐骨外部父级时，保持原来的静止位置补偿和目标骨骼变换。
- 逐骨选择回退时，保持全局外部父级的既有规则；逐骨和全局分支的公式没有合并。
- 非根阶段 E 对普通父级的使用方式不变，包括同时设置外部选择器的情况。

没有修改阶段 A、B、D、CCD 索引回退、数学后端、尺度恢复或 VMD 读写。公开函数签名与 C ABI 均未改变。该修复不等于已经提供完整独立姿态求值。

## 后续独立骨架上下文

仍需将同一套五阶段求解器接到自有骨架工作区，不能直接借用活动模型或 `physics_bake::ModelCopy`。数学函数表须独立持有 DLL 生命周期且发布后只读，后台求值不得调用会改写全局函数表的 `d3dx::Get().Load()`，也不得访问全局尺度状态或诊断探针。

当前纯 C++ 四元数矩阵回退与 D3DX 路径的旋转方向存在待核对差异，不能将二者宣称为逐位等价。提取上下文时应保留旧入口行为，明确私有后端的支持范围，分别验证。跨模型目标、动作和表情装配、尺度、完整 IK、蒙皮及物理仍是后续工作。
