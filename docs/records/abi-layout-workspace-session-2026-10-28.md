# 工作区面板临时布局会话

本批在 `codex/plugin-abi` 将已有临时布局会话扩展到工作区 PANEL。目标范围未变；未修改 main 或覆盖稳定版程序。

## 行为及版本

- `mms.ui.layout.session` 1.1 增加本插件直属 `mms.workspace.tabs.extensions` 的 PANEL。显隐、首选尺寸及页签顺序复用原元素、surface、布局偏好和会话句柄。
- 1.0 挂点掩码仍为 15，拒绝 PANEL 的能力查询及会话创建；1.1 为 31。表大小仍为 88 字节、9 个函数，所有记录的 header 仍为 1.0。两版共用会话状态；SDK 默认查询 1.0，显式传入 minor=1 才查询工作区能力。
- 未选中过的页面仍按需创建。临时隐藏已选中页时保留其视图和内容，自动选择可见页；撤回时核对注册 handle、HWND、实例、持久可见状态及插件生命周期后恢复，不主动抢焦点。
- 用户切页先捕获页签中的元素 handle，再接管工作区字段、重建页签并按身份选择。其他挂点的会话字段继续有效。用户意图取消自动恢复；仅由临时预览显示的页面在接管后隐藏时保留可见候选页。
- 侧栏拖拽接管全部五个区域，底部拖拽仍只接管属性区。临时应用和回退不写布局偏好；正式提交进入原布局历史一次，支持撤销。

## 审查与测试修正

首轮新面板测试错误地假定所有页面立即创建，并比较允许复用的实例地址。按生产的惰性创建规则修正为先通过真实页签通知逐页打开，再捕获基线；同名重建检查注册身份及实际销毁、创建次数。原始失败记录保留于 `本地验收记录（未随本文发布）`。

综合 ABI 回归发现真实回归：用户切页取得接管令牌会推进注册表修订，只重建页签未同步界面适配层，后续 STATE＋LAYOUT 请求被拒绝。修复通过完整 Refresh 同步原控件树，再核对修订与目标身份，不直接赋值掩盖中间注册变化。失败证据保留于 `本地验收记录（未随本文发布）`；其中两配置的面板 660、C 表 316、SDK 239 及其他布局专项通过，但完整 ABI 失败，不能作为整批通过证据。

## 验证边界

面板专项使用真实隐藏窗口、页签、三个独立 surface 工厂和 EDIT，检查身份、未提交文字、焦点回调、布局偏好历史及失败恢复。切页由 `TCM_SETCURSEL` 和 `TCN_SELCHANGE` 注入，不是物理鼠标或像素验收；该夹具没有 MMD 场景，不能单凭它证明场景历史未变化。
