# 界面布局保存

宿主把通过 `mms.ui` 布局事务和 `mms.ui.layout.stageHints` 提交的用户覆盖保存到 `data/plugins/ui-layout.json`。各程序目录独立保存；该路径不依赖 EXE 名称、工作目录或当前工程。插件不需要自行读写此文件，也不需要新增服务调用。

## 保存范围

| 用户覆盖 | 保存内容 |
| --- | --- |
| 移动 | 父元素 ID、同级顺序。 |
| 显隐和尺寸 | 用户隐藏状态、显式尺寸。 |
| 快捷键 | 按键、修饰键、作用域。 |
| 布局提示 | 与插件默认值不同的提示分量。未覆盖的分量跟随新默认值。 |
| 用户组 | 稳定 ID、所有者、名称、父元素和布局覆盖。 |

文件采用版本 1 的 JSON。记录通过元素 `id`、`ownerPlugin` 和元素类型匹配，不保存运行时句柄、代次、HWND、回调或插件数据。插件更新后继续使用同一组稳定 ID，已有用户布局才能匹配。

插件仍通过 `registerElement` 声明默认父元素，通过 `setDefaultHints` 声明默认布局。宿主先合并默认值与用户覆盖，再排版。单项恢复默认会移除对应元素的覆盖；全局恢复默认还会清除当前未加载插件的覆盖。

显式尺寸不能小于有效布局提示的最小尺寸。事务内修改提示、或插件更新默认提示后违反该限制时，操作返回 ARGUMENT，保留原布局和已保存覆盖。

## 加载与缺失插件

宿主在插件启动完成后、发送 `UI_READY` 前恢复布局。运行期间注册或更新元素时，也会匹配保存的覆盖。旧快照继续持有原数据，不能据其代次提交新布局。

未加载插件的记录继续保留。缺失的目标父容器恢复注册后，子元素重新匹配保存的位置。用户创建的组不持有插件回调，创建该组的布局编辑插件退出后，组仍可保留。

导入先验证整份文档和候选布局。重复 ID、无效尺寸、快捷键冲突、循环父级或未知版本会拒绝导入，不发布部分布局。原文件继续保留，本次进程不覆盖该文件。

## 保存与失败

宿主在界面刷新后的安全位置保存，并在插件退出前保存尚未写出的覆盖。仅用户覆盖修订变化时尝试写入，普通窗口布局和几何更新不会反复写文件。

保存先写同目录临时文件，刷新内容后替换原文件。写入或替换失败时保留原文件，清理本次临时文件。多个 MMS 进程通过文件锁协调写入；检测到文件已由其他进程修改时返回冲突，不覆盖对方数据。文件最多为 1 MiB。

布局提交成功表示本次进程已应用布局。磁盘保存失败不会撤销已应用的界面，宿主会记录失败。布局文件与工程数据分开；当前尚无布局撤销历史，DOCK 和未开放的挂载位置仍不支持。
