# 编辑事务与撤销粒度

本页定义 [edit.h](include/mms/edit.h) 的使用契约。当前分支已在显式启用的隔离宿主中验证真实插件与原生命令共用历史。主窗口尚未完整迁移，普通启动的 `queryService("mms.edit", 1, 0, ...)` 仍返回 NOT_FOUND。插件须检查查询结果，不得假定服务已启用。开发环境与构建方法见 [SDK README](README.md)。

模型及附件的资源保留、整批导入和删除候选已在宿主内部实现，并验证源文件不可用时的撤销和重做。这些 C++ 组件不属于公共 ABI；插件导入、删除物体仍须等待对应宿主编辑服务开放。可写 UI 属性当前仍返回 NOT_READY。

受控原生删除命令已将同一模型的骨骼、表情和显示／IK／外亲键合为一次事务；当前选中的模型不改变撤销次序。插件可以通过同一 `mms.edit` 历史接口撤销该记录，但暂不能调用内部 C++ 计划函数或取得可写键池指针。

## 一次事务对应一次撤销

受控相机模式删除命令现将相机、灯光、自阴影、重力和多个附件合为一次显式事务；相机 HUD 六轴在“全部操作”模式按整次手势记录，在“仅显式提交”模式不自动登记姿态调整。它们仍使用同一内部共同历史，不授予插件原生指针写权限。

一个成功提交的事务产生一条工程历史。事务可以涉及多个模型、原生属性、导入或删除物体，以及多个插件的私有状态。宿主把这些内容一起撤销或重做，当前选中的模型不影响顺序。原生场景写入、导入和删除仍须通过对应宿主编辑服务；`edit.h` 不授予插件修改原生指针或直接调用加载器的权限。

| 插件工作方式 | 事务边界 | 用户撤销结果 |
| --- | --- | --- |
| 批量修正 20 个模型的姿势 | 计算全部候选后提交一个事务 | 一次恢复全部模型。 |
| 向导分为导入、对齐、平滑三步 | 每一步分别提交 | 按平滑、对齐、导入的顺序撤销。 |
| 拖动参数时持续预览 | 预览保留在候选，松手提交一次 | 一次恢复拖动前的值。 |

该选择由插件的事务组织方式表达，无需增加 ABI 标志。已经提交的多个事务不自动合并；取消当前事务只丢弃尚未发布的候选。长任务或多步向导每次开始新事务前须读取最新修订号，不能连续复用第一步的 expectedRevision。

## 调用顺序

1. 查询服务并检查返回值及函数表版本。
2. 在已启用编辑服务的宿主获取 `mms.scene` 快照的 `sceneRevision`。受控宿主使该值与共同历史一致；普通宿主仅提供只读绑定快照，不能据此调用编辑。
3. 调用 `begin(label, expectedRevision, &transaction)`。标签描述本次用户操作，例如「平滑所选动作」。
4. 通过宿主编辑服务暂存原生变更。需要修改插件工程状态时，加入本插件的 `MmsTransactionParticipantV1`。
5. 调用 `prepare(transaction)`。此时正式工程和插件当前状态保持不变。
6. 准备成功后调用 `commit(transaction)`。不继续执行时调用 `cancel(transaction)`。

参加别人创建的事务时，插件通过自己的 edit 上下文调用 join，并使用自己的 pluginId。事务创建者负责 prepare、commit、cancel。宿主 EDIT 命令已提供事务时，回调只暂存变更并 join，由宿主完成提交；插件不能另开事务绕过该命令的边界。

## 插件状态参与者

每个插件在同一事务中最多注册一个 participant。插件须先注册自己的 `mms.serializer`，详见 [工程序列化参考](storage.md)。participant 可以持有多个内部候选，但须将它们作为一次整体准备与发布。

| 回调 | 必须遵循的行为 |
| --- | --- |
| `prepare` | 分配并验证全部候选。失败返回错误码，不改正式状态。 |
| `getUndoState` | 返回变更前、变更后的完整插件恢复数据、非零 schema 和租约。该数据必须能由本插件 serializer 的 `prepareLoad` 读取。 |
| `releaseUndoState` | 释放借出的两个数据视图。宿主成功取得数据后，深复制并恰好调用一次释放，即使复制失败。 |
| `commit` | 只交换已准备好的状态。不能失败、抛异常、显示对话框、进入消息循环或重新调用编辑接口。消费 participant context。 |
| `cancel` | 释放尚未提交的候选；不能改正式状态。宿主也可能对尚未调用 prepare 的已接受 participant 调用 cancel。消费 context。 |

每个 before 或 after 数据块最多 64 MiB；同一事务最多 4096 个 participant。统一历史另有总保留预算，超出预算的单条操作在准备阶段拒绝。插件不应使用磁盘路径代替恢复所需的数据，文件可能在撤销前被修改或删除。

## 失败与生命周期

接口在 UI 线程的顶层命令回调或本插件的 UI 队列执行回调中调用。工作线程可以计算私有候选，但须通过 `enqueueUi` 回到宿主后重新获取 revision 并提交。getState、属性读取、事件、嵌套调用、serializer、participant、取消及停止回调不能发起或重入编辑。

失败命令和抛异常的队列执行回调会取消本插件发起的未完成事务。其他插件创建、由本插件参与的事务仍归原创建者负责。存在 pending 事务时新建或重开工程返回 BUSY，插件须先完成或取消；关闭宿主则在卸载插件前取消。分离编辑服务后，已缓存的函数表返回 NOT_READY。

prepare 失败会取消所有已接受 participant 并消费事务。已经准备的 commit 尝试无论成功或失败也会消费事务；重复提交返回 STALE。未经 prepare 的 commit 返回 CONFLICT，事务仍可继续准备或取消。重复 cancel 不产生影响。

撤销或重做时，宿主先准备节点中的全部原生恢复数据和插件 serializer 候选。缺失插件、schema 不接受或原生引用失效时，整个操作失败，历史游标不移动。宿主不会跳过该节点中的插件状态。

对象删除使旧引用失效。撤销删除后对象保留稳定 ID，但获得新的 generation；插件须重新获取快照与引用。已取得的旧快照继续只读，不能用旧引用写入恢复后的对象。

当前原生接入进度与验证范围见[编辑事务实现记录](../../docs/PLUGIN_EDIT_INTEGRATION.md)。
